# 25 Most Common Terraform Associate Exam Traps

---

# 1. Terraform Workflow Traps

### 1️⃣ Thinking `terraform plan` changes infrastructure

**Trap:** Many candidates think `terraform plan` modifies resources.

✔ Reality:

- `terraform plan` **only shows the execution plan**
- It **never changes infrastructure**

---

### 2️⃣ Forgetting that `terraform apply` runs `plan` first

Even if you don't run plan:

```bash
terraform apply
```

Terraform will **automatically run plan internally** before applying.

---

### 3️⃣ Confusing `terraform validate` and `terraform fmt`

| Command              | Purpose                                  |
| -------------------- | ---------------------------------------- |
| `terraform validate` | Checks syntax and configuration validity |
| `terraform fmt`      | Formats code                             |

Many exam questions test this difference.

---

### 4️⃣ Not understanding `terraform init`

`terraform init` is required when:

- First run in a directory
- Providers change
- Modules change
- Backend changes

Many people think it only installs providers.

---

### 5️⃣ Confusing `terraform destroy` with state removal

`terraform destroy`:

✔ **Deletes infrastructure**

NOT:

❌ deletes state file

---

# 2. State File Traps

### 6️⃣ Thinking Terraform discovers infrastructure automatically

Terraform **does not auto-discover infrastructure**.

It only manages what is in:

```
terraform.tfstate
```

---

### 7️⃣ Thinking sensitive outputs are removed from state

Example:

```hcl
sensitive = true
```

✔ hides from CLI output
❌ **still stored in state file**

---

### 8️⃣ Forgetting state may contain secrets

State files often contain:

- passwords
- database endpoints
- private IPs
- credentials

That’s why remote secure storage is recommended.

---

### 9️⃣ Confusing `terraform state rm`

This command:

✔ removes resource **from state only**

❌ does **not destroy infrastructure**

---

### 🔟 Thinking Terraform state is optional

Terraform **requires state** to track resources.

Without state:

Terraform may **recreate existing infrastructure**.

---

# 3. Providers Trap

### 11️⃣ Thinking provider blocks are always required

Terraform can **infer providers from resource types**.

Example:

```hcl
resource "aws_instance" "web" {}
```

Terraform automatically knows you need the \*\*Terraform AWS provider.

---

### 12️⃣ Forgetting about `terraform.lock.hcl`

This file:

✔ locks provider versions
✔ ensures consistent builds

It **should be committed to Git**.

---

# 4. Modules Trap

### 13️⃣ Thinking modules must come from the registry

Modules can come from:

- local path
- Git repository
- Terraform Registry
- HTTP source

---

### 14️⃣ Forgetting module output syntax

Correct:

```hcl
module.network.vpc_id
```

Wrong answers appear often in exams.

---

### 15️⃣ Thinking modules create separate state files

Modules **share the same state** as the root module.

Only **workspaces** separate state.

---

# 5. Variables Trap

### 16️⃣ Not knowing variable precedence

Order (highest → lowest):

1. CLI `-var`
2. CLI `-var-file`
3. `*.auto.tfvars`
4. `terraform.tfvars`
5. environment variables
6. defaults

Exam loves this topic.

---

### 17️⃣ Forgetting Terraform prompts for variables

If variable has no default:

Terraform will **prompt interactively**.

---

### 18️⃣ Confusing environment variables format

Correct format:

```
TF_VAR_region=us-east-1
```

This sets:

```
var.region
```

---

# 6. Expressions Trap

### 19️⃣ Confusing `merge()` vs `concat()`

| Function   | Use   |
| ---------- | ----- |
| `merge()`  | maps  |
| `concat()` | lists |

This appears often.

---

### 20️⃣ Not recognizing conditional expressions

Example:

```hcl
var.env == "prod" ? 3 : 1
```

This is **ternary conditional expression**.

---

# 7. Count vs For_each Trap

### 21️⃣ Using `count` with changing lists

When items are removed:

Indexes shift → resources recreated.

`for_each` avoids this.

Exam often asks this.

---

### 22️⃣ Forgetting `for_each` key referencing

Example:

```
each.key
each.value
```

---

# 8. Backend Trap

### 23️⃣ Forgetting `terraform init` after backend change

When backend config changes:

You **must re-run init**.

Terraform will ask to **migrate state**.

---

### 24️⃣ Not understanding state locking

Example with AWS:

- Backend: **S3**
- Locking: **DynamoDB**

This prevents **concurrent applies**.

---

# 9. Drift Trap

### 25️⃣ Thinking Terraform prevents manual changes

Terraform **does NOT prevent manual changes**.

Manual changes cause:

👉 **configuration drift**

Detected during:

```
terraform plan
```
