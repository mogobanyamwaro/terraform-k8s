Here's a comprehensive guide to **Preconditions and Postconditions in Terraform** (introduced in Terraform v1.2+):

## 1. Overview

Preconditions and postconditions are **validation checks** that run during the plan and apply phases, allowing you to enforce requirements before resources are created or modified.

### Key Concepts

- **Preconditions**: Check conditions **before** Terraform performs an action
- **Postconditions**: Check conditions **after** Terraform performs an action
- Both can be defined in `lifecycle` blocks or as `check` blocks

## 2. Precondition Syntax

### In Resource Lifecycle

```hcl
resource "aws_instance" "web" {
  ami           = "ami-0c55b159cbfafe1f0"
  instance_type = "t2.micro"

  lifecycle {
    precondition {
      condition     = var.environment != "prod" || var.backup_enabled == true
      error_message = "Production environments must have backups enabled."
    }

    precondition {
      condition     = can(regex("^t[2-3]\\.[a-z]+$", var.instance_type))
      error_message = "Instance type must be t2.* or t3.*"
    }
  }
}
```

### In Module Block

```hcl
module "vpc" {
  source = "./modules/vpc"
  cidr_block = var.vpc_cidr

  lifecycle {
    precondition {
      condition     = can(cidrhost(var.vpc_cidr, 0))
      error_message = "Invalid CIDR block format: ${var.vpc_cidr}"
    }
  }
}
```

### In Data Source

```hcl
data "aws_ami" "latest" {
  owners = ["amazon"]
  most_recent = true

  filter {
    name   = "name"
    values = ["amzn2-ami-hvm-*"]
  }

  lifecycle {
    precondition {
      condition     = length(data.aws_ami.latest.id) > 0
      error_message = "No matching AMI found in the specified filters."
    }
  }
}
```

## 3. Postcondition Syntax

### Check Resource Output After Creation

```hcl
resource "aws_lb" "main" {
  name               = "main-lb"
  load_balancer_type = "application"
  subnets           = var.subnet_ids

  lifecycle {
    postcondition {
      condition     = self.dns_name != null && can(regex("elb.amazonaws.com", self.dns_name))
      error_message = "Load balancer DNS name is invalid or missing."
    }

    postcondition {
      condition     = self.arn != null
      error_message = "Load balancer ARN was not created successfully."
    }
  }
}
```

### Check Data Source Validity

```hcl
data "aws_subnet" "selected" {
  id = var.subnet_id

  lifecycle {
    postcondition {
      condition     = self.available_ip_address_count >= 10
      error_message = "Subnet ${var.subnet_id} has insufficient IP addresses (only ${self.available_ip_address_count} available)."
    }
  }
}
```

## 4. Check Blocks (Standalone Validation)

Terraform 1.5+ introduced standalone `check` blocks for validation without affecting resource state.

```hcl
# Check block that runs independently
check "security_compliance" {
  data "aws_iam_policy" "admin_policy" {
    arn = "arn:aws:iam::aws:policy/AdministratorAccess"
  }

  assert {
    condition     = data.aws_iam_policy.admin_policy.arn != null
    error_message = "Admin policy not found"
  }

  assert {
    condition     = !var.allow_admin_access
    error_message = "Admin access is not allowed per security policy"
  }
}

# Check block with custom logic
check "database_backup" {
  data "aws_rds_cluster" "main" {
    cluster_identifier = var.cluster_id
  }

  assert {
    condition     = data.aws_rds_cluster.main.backup_retention_period >= 7
    error_message = "Database backup retention must be at least 7 days (current: ${data.aws_rds_cluster.main.backup_retention_period})"
  }
}
```

## 5. Common Use Cases

### Input Validation

```hcl
variable "instance_config" {
  type = object({
    name   = string
    type   = string
    volume_size = number
  })

  validation {
    condition     = length(var.instance_config.name) <= 63
    error_message = "Instance name must be 63 characters or less"
  }
}

resource "aws_instance" "app" {
  ami           = data.aws_ami.amazon_linux.id
  instance_type = var.instance_config.type

  lifecycle {
    precondition {
      condition     = var.instance_config.volume_size >= 8
      error_message = "Root volume size must be at least 8GB"
    }
  }
}
```

### Cross-Resource Validation

```hcl
resource "aws_security_group" "web" {
  name = "web-sg"
  vpc_id = var.vpc_id

  ingress {
    from_port = 80
    to_port   = 80
    protocol  = "tcp"
    cidr_blocks = ["0.0.0.0/0"]
  }

  lifecycle {
    precondition {
      condition     = var.vpc_id != null
      error_message = "VPC ID must be specified for security group"
    }

    postcondition {
      condition     = length(self.ingress) > 0
      error_message = "Security group must have at least one ingress rule"
    }
  }
}

resource "aws_instance" "web" {
  ami = "ami-0c55b159cbfafe1f0"
  instance_type = "t2.micro"
  vpc_security_group_ids = [aws_security_group.web.id]

  lifecycle {
    precondition {
      condition     = length(aws_security_group.web.ingress) > 0
      error_message = "Cannot create instance: referenced security group has no ingress rules"
    }
  }
}
```

### Provider Configuration Validation

```hcl
provider "aws" {
  region = var.aws_region

  # Validate region format
  lifecycle {
    precondition {
      condition     = can(regex("^[a-z]{2}-[a-z]+-[0-9]$", var.aws_region))
      error_message = "Invalid AWS region format: ${var.aws_region}"
    }
  }
}

resource "aws_s3_bucket" "data" {
  bucket = var.bucket_name

  lifecycle {
    precondition {
      condition     = length(var.bucket_name) >= 3 && length(var.bucket_name) <= 63
      error_message = "Bucket name must be between 3 and 63 characters"
    }

    precondition {
      condition     = can(regex("^[a-z0-9.-]+$", var.bucket_name))
      error_message = "Bucket name can only contain lowercase letters, numbers, dots, and hyphens"
    }
  }
}
```

### Environment-Specific Validation

```hcl
resource "aws_rds_cluster" "aurora" {
  cluster_identifier = "aurora-cluster"
  engine            = "aurora-mysql"

  # Production-specific requirements
  lifecycle {
    precondition {
      condition     = var.environment != "prod" || var.multi_az == true
      error_message = "Production Aurora clusters must be Multi-AZ enabled"
    }

    precondition {
      condition     = var.environment != "prod" || var.backup_retention_period >= 7
      error_message = "Production clusters require backup retention of at least 7 days"
    }

    postcondition {
      condition     = self.arn != null
      error_message = "Cluster failed to create"
    }

    postcondition {
      condition     = var.environment != "prod" || self.backup_retention_period >= 7
      error_message = "Backup retention is less than required 7 days"
    }
  }
}
```

## 6. Advanced Patterns

### Using Functions in Conditions

```hcl
resource "aws_iam_policy" "custom" {
  name = var.policy_name
  policy = jsonencode(var.policy_document)

  lifecycle {
    precondition {
      condition = alltrue([
        can(jsondecode(var.policy_document)),
        length(var.policy_name) <= 128,
        contains(["allow", "deny"], keys(jsondecode(var.policy_document))[0])
      ])
      error_message = "Invalid policy: check name length (max 128) and JSON structure"
    }
  }
}
```

### Dynamic Precondition Based on Count

```hcl
resource "aws_instance" "cluster" {
  count = var.cluster_size

  ami = "ami-0c55b159cbfafe1f0"
  instance_type = var.instance_type

  lifecycle {
    precondition {
      condition     = var.cluster_size > 0
      error_message = "Cluster size must be greater than 0"
    }

    precondition {
      condition     = count.index < length(var.subnet_ids)
      error_message = "Not enough subnets for all instances in cluster"
    }
  }
}
```

### Precondition with Custom Error Messages

```hcl
resource "aws_route53_record" "app" {
  zone_id = data.aws_route53_zone.main.zone_id
  name    = var.domain_name
  type    = "A"

  alias {
    name                   = aws_lb.main.dns_name
    zone_id               = aws_lb.main.zone_id
    evaluate_target_health = true
  }

  lifecycle {
    precondition {
      condition = alltrue([
        can(regex("^[a-zA-Z0-9.-]+\\.com$", var.domain_name)),
        aws_lb.main.dns_name != null,
        data.aws_route53_zone.main.zone_id != null
      ])
      error_message = join("\n", [
        "DNS record validation failed:",
        "  - Domain must end with .com",
        "  - Load balancer must be created first",
        "  - Route53 zone must exist"
      ])
    }

    postcondition {
      condition     = self.fqdn != null
      error_message = "DNS record creation failed - no FQDN generated"
    }
  }
}
```

## 7. Comparison: Preconditions vs Postconditions

| Aspect      | Preconditions                                             | Postconditions                                     |
| ----------- | --------------------------------------------------------- | -------------------------------------------------- |
| **When**    | Before resource creation/modification                     | After resource creation/modification               |
| **Access**  | Can access input variables, data sources, other resources | Can also access `self` (resource's own attributes) |
| **Purpose** | Validate inputs and dependencies                          | Validate results and outputs                       |
| **Failure** | Prevents action from occurring                            | Shows error but resource was created               |
| **State**   | Doesn't affect state                                      | Resource is in state even if fails                 |

## 8. Best Practices

### 1. Combine with Variable Validation

```hcl
variable "environment" {
  type = string

  validation {
    condition     = contains(["dev", "staging", "prod"], var.environment)
    error_message = "Environment must be dev, staging, or prod"
  }
}

resource "aws_instance" "app" {
  # Additional precondition for cross-resource validation
  lifecycle {
    precondition {
      condition     = var.environment != "prod" || var.backup_enabled
      error_message = "Production requires backup enabled"
    }
  }
}
```

### 2. Use Self-Aware Postconditions

```hcl
resource "aws_autoscaling_group" "asg" {
  name = "web-asg"
  min_size = 2
  max_size = 10

  lifecycle {
    postcondition {
      condition     = self.arn != null && self.min_size >= 2
      error_message = "Auto Scaling Group created but doesn't meet minimum size requirement"
    }

    postcondition {
      condition     = self.status != "failed"
      error_message = "Auto Scaling Group entered failed state"
    }
  }
}
```

### 3. Fail Fast with Preconditions

```hcl
# Check early dependencies
resource "aws_lambda_function" "api" {
  filename         = data.archive_file.lambda.output_path
  function_name    = "api-handler"
  role            = aws_iam_role.lambda.arn

  lifecycle {
    precondition {
      condition = alltrue([
        fileexists(data.archive_file.lambda.output_path),
        fileexists("${path.module}/handler.py"),
        aws_iam_role.lambda.arn != null
      ])
      error_message = "Missing required files or IAM role for Lambda"
    }
  }
}
```

### 4. Use Descriptive Error Messages

```hcl
lifecycle {
  precondition {
    condition     = length(var.subnet_ids) >= 2
    error_message = format(
      "VPC requires at least 2 subnets for high availability, but only %d provided",
      length(var.subnet_ids)
    )
  }
}
```

## 9. Limitations and Considerations

### What Pre/Postconditions CAN'T Do:

- Modify resources or state
- Access computed values before they're computed (for preconditions)
- Prevent resource creation after it's already started (postconditions)
- Run on every plan if nothing changes (only on actions)

### Performance Impact:

- Conditions are evaluated during plan and apply
- Complex conditions with data sources may add latency
- Use `can()` function to safely handle potential errors

## 10. Example: Complete Implementation

```hcl
# Variable validation
variable "application" {
  type = object({
    name        = string
    environment = string
    region      = string
    vpc_cidr    = string
    instance_config = object({
      type = string
      count = number
      volume_size = number
    })
  })

  validation {
    condition     = length(var.application.name) >= 3
    error_message = "Application name must be at least 3 characters"
  }
}

# Resource with multiple checks
resource "aws_vpc" "main" {
  cidr_block = var.application.vpc_cidr

  tags = {
    Name        = var.application.name
    Environment = var.application.environment
  }

  lifecycle {
    precondition {
      condition     = can(cidrhost(var.application.vpc_cidr, 0))
      error_message = "Invalid VPC CIDR: ${var.application.vpc_cidr}"
    }

    postcondition {
      condition     = self.id != null
      error_message = "VPC creation failed"
    }
  }
}

# Check block for compliance
check "vpc_compliance" {
  assert {
    condition     = aws_vpc.main.enable_dns_hostnames == true
    error_message = "VPC must have DNS hostnames enabled"
  }

  assert {
    condition     = length(aws_vpc.main.cidr_block) > 0
    error_message = "VPC must have a CIDR block defined"
  }
}
```

Preconditions and postconditions provide a powerful way to enforce infrastructure requirements at the right time, improving reliability and preventing misconfigurations before they cause problems.
