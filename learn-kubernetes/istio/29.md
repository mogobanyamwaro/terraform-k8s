# 29. istioctl analyze, Validation, and Config Errors

## Concept Refresher

`istioctl analyze` is the static checker. It reads Kubernetes + Istio resources and reports semantic errors Envoy would hit later: missing subsets, host mismatches, conflicting AuthorizationPolicies, deprecated fields.

```bash
istioctl analyze
istioctl analyze -n demo
istioctl analyze -A
istioctl analyze -f vs.yaml
istioctl analyze --failure-threshold ERROR
```

Exit code is non-zero when issues at or above the threshold exist. Use that in the exam before you call a task done.

### Validation webhook vs analyze

| | Validating webhook | `istioctl analyze` |
| --- | --- | --- |
| When | At `kubectl apply` | On demand |
| Catches | Schema, unknown fields, some referential checks | Mesh-wide semantics |
| Misses | "subset v2 not defined" often **applies fine** | That is exactly what analyze is for |

A VirtualService that references subset `v2` with no DestinationRule **applies**. Analyze reports `ReferencedSubsetNotFound` (message code like `IST0101`). Grader still sees 503.

### Message codes

```bash
istioctl analyze -A --output-threshold INFO
istioctl experimental precheck
```

Common codes you will see (numbers drift by version; read the **text**):

- Gateway/VirtualService host mismatch
- VirtualService attached to a Gateway that does not exist
- Subset not found
- Schema validation warnings
- Conflicting mTLS PeerAuthentication / DestinationRule
- Deprecated `networking.istio.io/v1alpha3` (info)

### Other validators

```bash
istioctl validate -f vs.yaml          # schema of a file
kubectl apply --dry-run=server -f vs.yaml
istioctl proxy-status                 # runtime, not static
```

`validate` does not replace `analyze`. Run both when YAML is new.

## Tasks

1. Apply a VirtualService that routes to `reviews` subset `v9` (does not exist). Catch it with analyze, then fix.
2. Bind a VirtualService to Gateway `shop/shop-gw` that does not exist. Find the error.
3. Save a bad YAML file with `protocol: HTPP` on a Gateway port and show webhook vs analyze.
4. Analyze only namespace `bookinfo` and produce YAML output.

## Solutions

### 1. Missing subset

```bash
kubectl apply -f - <<'EOF'
apiVersion: networking.istio.io/v1
kind: VirtualService
metadata:
  name: reviews-bad
  namespace: bookinfo
spec:
  hosts: [reviews]
  http:
    - route:
        - destination:
            host: reviews
            subset: v9
EOF

istioctl analyze -n bookinfo
```

Fix: add subset `v9` (wrong) or change to `v1` (right). Delete the bad VS.

### 2. Missing Gateway

```yaml
spec:
  hosts: ["shop.example.com"]
  gateways:
    - shop/shop-gw
```

Analyze: gateway not found. Create the Gateway or correct the name `namespace/name`.

### 3. Typo protocol

```yaml
        protocol: HTPP
```

Webhook should **reject** apply. If it does not (typo still a string), analyze/validate will warn that HTTP routing will not attach. Fix to `HTTP`.

### 4. Scoped analyze

```bash
istioctl analyze -n bookinfo -o yaml
istioctl analyze -n bookinfo -o json | jq '.[].message'
```

## Verify

```bash
istioctl analyze -A
echo $?    # 0 is clean
```

## Exam Tips

- Run **`istioctl analyze -A`** in the last two minutes of the exam. It is the cheapest bug hunt.
- Analyze needs RBAC to read the resources. On the exam it is preconfigured.
- `--suppress` hides known noise. Do not suppress on the exam unless the task says to ignore a warning.
- Docs: [istioctl analyze](https://istio.io/docs/istioctl/analyze/).
