# 27. Securing Edge Traffic with TLS

## Concept Refresher

North-south TLS is configured on the **Gateway** resource (`servers[].tls`), not on the VirtualService. The VS still routes after the handshake (except PASSTHROUGH).

```yaml
apiVersion: networking.istio.io/v1
kind: Gateway
metadata:
  name: shop
  namespace: shop
spec:
  selector:
    istio: ingressgateway
  servers:
    - port:
        number: 443
        name: https
        protocol: HTTPS
      hosts:
        - shop.example.com
      tls:
        mode: SIMPLE
        credentialName: shop-tls
```

### Modes

| Mode | Handshake | Envoy sees HTTP? | Certs |
| --- | --- | --- | --- |
| `SIMPLE` | Server TLS | Yes, then VS HTTP routes | `credentialName` or `serverCertificate`+`privateKey` |
| `MUTUAL` | Client cert required | Yes | Plus `caCertificates` / `credentialName` with `ca.crt` |
| `OPTIONAL_MUTUAL` | Client cert optional | Yes | Same as MUTUAL |
| `PASSTHROUGH` | No TLS terminate | No. Route by **SNI** on `tls:` VS | None on gateway |
| `AUTO_PASSTHROUGH` | SNI must match a known mesh service | Used in multi-cluster | None |
| `ISTIO_MUTUAL` | Mesh mTLS | Used on **egress** or east-west gateways | Istio-issued |

ICA cares most about **SIMPLE**, **MUTUAL**, and **PASSTHROUGH**.

### credentialName (SDS)

The Secret must be in the **same namespace as the gateway workload** (`istio-system` for the default ingress), unless you use the `istio-remote` / Gateway API secret ref pattern.

```bash
kubectl -n istio-system create secret tls shop-tls \
  --cert=shop.crt --key=shop.key
```

For MUTUAL, use `kubectl create secret generic` with keys `tls.crt`, `tls.key`, `ca.crt` (and optionally `crl.pem`). The Istio docs specify the exact keys; copy them during the exam.

`httpsRedirect: true` on an HTTP server sends 301 to HTTPS.

### PASSTHROUGH routing

```yaml
# Gateway
      tls:
        mode: PASSTHROUGH
# VirtualService
spec:
  hosts:
    - shop.example.com
  gateways:
    - shop
  tls:
    - match:
        - port: 443
          sniHosts:
            - shop.example.com
      route:
        - destination:
            host: frontend
            port:
              number: 443
```

The backend must speak TLS. HTTP matches on this Gateway will not run.

### Double TLS

App already serves HTTPS, gateway SIMPLE: gateway decrypts, then you must originate TLS again with a DestinationRule `tls.mode: SIMPLE` to the backend, or set the Service port protocol so Istio knows. Common 404/503 source.

## Tasks

1. Terminate TLS for `httpbin.example.com` on the ingress gateway using Secret `httpbin-tls` in `istio-system`. Redirect HTTP to HTTPS.
2. Require **client certificates** (MUTUAL) for that host.
3. Passthrough TLS for `legacy.example.com` to Service `legacy` port 443.
4. Show what happens if `credentialName` is in the wrong namespace.

## Solutions

Generate a lab cert if needed:

```bash
openssl req -x509 -newkey rsa:2048 -keyout key.pem -out cert.pem -days 7 -nodes \
  -subj "/CN=httpbin.example.com"
kubectl -n istio-system create secret tls httpbin-tls --cert=cert.pem --key=key.pem
```

### 1. SIMPLE + redirect

```yaml
apiVersion: networking.istio.io/v1
kind: Gateway
metadata:
  name: httpbin
  namespace: demo
spec:
  selector:
    istio: ingressgateway
  servers:
    - port:
        number: 80
        name: http
        protocol: HTTP
      hosts:
        - httpbin.example.com
      tls:
        httpsRedirect: true
    - port:
        number: 443
        name: https
        protocol: HTTPS
      hosts:
        - httpbin.example.com
      tls:
        mode: SIMPLE
        credentialName: httpbin-tls
---
apiVersion: networking.istio.io/v1
kind: VirtualService
metadata:
  name: httpbin
  namespace: demo
spec:
  hosts:
    - httpbin.example.com
  gateways:
    - httpbin
  http:
    - route:
        - destination:
            host: httpbin
            port:
              number: 8000
```

Gateway in `demo` with `credentialName` still reads the Secret from **`istio-system`** (workload namespace). This is the gotcha.

### 2. MUTUAL

```yaml
      tls:
        mode: MUTUAL
        credentialName: httpbin-mtls
```

Create the secret with `tls.crt`, `tls.key`, `ca.crt` as in [Secure Gateways](https://istio.io/docs/tasks/traffic-management/ingress/secure-ingress/).

Curl: `curl --cert client.crt --key client.key --cacert ca.pem https://httpbin.example.com/get`.

### 3. PASSTHROUGH

```yaml
apiVersion: networking.istio.io/v1
kind: Gateway
metadata:
  name: legacy
  namespace: demo
spec:
  selector:
    istio: ingressgateway
  servers:
    - port:
        number: 443
        name: tls
        protocol: TLS
      hosts:
        - legacy.example.com
      tls:
        mode: PASSTHROUGH
---
apiVersion: networking.istio.io/v1
kind: VirtualService
metadata:
  name: legacy
  namespace: demo
spec:
  hosts:
    - legacy.example.com
  gateways:
    - legacy
  tls:
    - match:
        - port: 443
          sniHosts:
            - legacy.example.com
      route:
        - destination:
            host: legacy
            port:
              number: 443
```

`protocol: TLS` + `PASSTHROUGH`. Using `HTTPS` + PASSTHROUGH is a common mismatch.

### 4. Wrong namespace

Secret in `demo` while ingress pods are in `istio-system`: gateway logs `no secret named httpbin-tls`, clients get TLS handshake errors. Move the Secret or use Gateway API `CertificateRef` in the Gateway's namespace with allowed ReferenceGrants.

## Verify

```bash
curl -sk -o /dev/null -w "%{http_code}\n" --resolve httpbin.example.com:443:127.0.0.1 https://httpbin.example.com/get
curl -s -o /dev/null -w "%{http_code} %{redirect_url}\n" --resolve httpbin.example.com:80:127.0.0.1 http://httpbin.example.com/get

kubectl -n istio-system logs -l istio=ingressgateway --tail=30
istioctl proxy-config secret deploy/istio-ingressgateway.istio-system | grep httpbin
istioctl analyze -n demo -n istio-system
```

## Exam Tips

- **Secret lives with the gateway pod, not the Gateway CR.** Default ingress = `istio-system`.
- `httpsRedirect` belongs on the **HTTP** server, not the HTTPS one.
- PASSTHROUGH uses VirtualService `tls:` and `sniHosts`, not `http:`.
- `credentialName` is SDS. File-mounted `serverCertificate` paths are legacy; prefer `credentialName`.
- Docs: [Secure ingress](https://istio.io/docs/tasks/traffic-management/ingress/secure-ingress/).
