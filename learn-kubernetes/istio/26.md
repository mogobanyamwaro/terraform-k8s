# 26. AuthorizationPolicy Advanced Patterns

## Concept Refresher

Once ALLOW/DENY basics are solid (`25.md`), ICA tasks combine sources, hosts, DENY overrides, ingress policies, and L4-only ambient rules.

### DENY vs ALLOW together

```text
1. Match any DENY  -> 403, stop
2. If no ALLOW policies select this workload -> allow
3. If ALLOW policies exist -> allow only if one matches
```

Use DENY for "never this path, even if an ALLOW would permit it":

```yaml
apiVersion: security.istio.io/v1
kind: AuthorizationPolicy
metadata:
  name: deny-admin
  namespace: demo
spec:
  selector:
    matchLabels:
      app: httpbin
  action: DENY
  rules:
    - to:
        - operation:
            paths: ["/admin*"]
```

An ALLOW for `sleep` still cannot hit `/admin`.

### not* inverses

```yaml
      to:
        - operation:
            notMethods: ["GET"]
            notPaths: ["/public"]
      from:
        - source:
            notNamespaces: ["demo"]
```

A DENY with `notNamespaces: ["demo"]` denies everyone **outside** demo — equivalent to "only demo may call" when combined with default allow, without creating a default-deny ALLOW.

### Ingress gateway policies

Policies on the gateway use **`operation.hosts`**, `methods`, `paths`, and JWT `requestPrincipals`. They do **not** use `principals` of the original client unless you use a waypoint or propagate identity; at the gateway the peer is often the internet (no SPIFFE).

```yaml
apiVersion: security.istio.io/v1
kind: AuthorizationPolicy
metadata:
  name: ingress
  namespace: istio-system
spec:
  selector:
    matchLabels:
      istio: ingressgateway
  action: ALLOW
  rules:
    - to:
        - operation:
            hosts: ["httpbin.example.com"]
            methods: ["GET"]
            paths: ["/get"]
```

### Custom conditions

```yaml
    - when:
        - key: request.headers[x-token]
          values: ["letmein"]
        - key: destination.port
          values: ["8000"]
        - key: source.ip
          values: ["10.0.0.0/8"]
```

All `when` entries in one rule are AND.

### L4 vs L7

If Envoy only sees TCP (wrong port name, protocol TCP), **paths and methods are ignored**. Authorization falls back to principals, namespaces, IPs, ports. Ambient **without** a waypoint is L4 only: `paths` / `methods` / JWT conditions do not apply. That is a standard "policy does nothing" cause.

### serviceAccounts field

Istio 1.22+:

```yaml
        source:
          serviceAccounts:
            - "demo/sleep"
```

Equivalent to the SPIFFE principal for that SA. Prefer this if the docs on the exam version show it; `principals` always works.

## Tasks

1. Allow `sleep` to call `httpbin`, but **DENY** path `/delete` even from sleep.
2. On the ingress gateway, allow only host `shop.example.com` path prefix `/api`.
3. Allow requests that carry header `x-canary: true` OR come from namespace `bookinfo`.
4. Deny all TCP to port `3306` on a meshed `mysql` workload except from `app=frontend`.
5. In ambient namespace `shop` (no waypoint), try an L7 path rule and then fix it the ICA-expected way.

## Solutions

### 1. ALLOW + DENY

```yaml
apiVersion: security.istio.io/v1
kind: AuthorizationPolicy
metadata:
  name: httpbin-allow-sleep
  namespace: demo
spec:
  selector:
    matchLabels: { app: httpbin }
  action: ALLOW
  rules:
    - from:
        - source:
            principals:
              - cluster.local/ns/demo/sa/sleep
---
apiVersion: security.istio.io/v1
kind: AuthorizationPolicy
metadata:
  name: httpbin-deny-delete
  namespace: demo
spec:
  selector:
    matchLabels: { app: httpbin }
  action: DENY
  rules:
    - to:
        - operation:
            paths: ["/delete"]
```

### 2. Ingress host and path

```yaml
apiVersion: security.istio.io/v1
kind: AuthorizationPolicy
metadata:
  name: shop-gw
  namespace: istio-system
spec:
  selector:
    matchLabels:
      istio: ingressgateway
  action: ALLOW
  rules:
    - to:
        - operation:
            hosts: ["shop.example.com"]
            paths: ["/api*"]
```

Putting this on the gateway **default-denies every other host** served by that gateway. If the exam still needs Bookinfo on the same gateway, add a second rule for `productpage` hosts. Safer pattern: `targetRef` a specific Gateway resource when using Gateway API.

### 3. OR across rules

```yaml
  action: ALLOW
  rules:
    - when:
        - key: request.headers[x-canary]
          values: ["true"]
    - from:
        - source:
            namespaces: ["bookinfo"]
```

Two rules = OR. One rule with two `when` entries = AND.

### 4. L4 DENY with exception

```yaml
apiVersion: security.istio.io/v1
kind: AuthorizationPolicy
metadata:
  name: mysql
  namespace: shop
spec:
  selector:
    matchLabels: { app: mysql }
  action: ALLOW
  rules:
    - from:
        - source:
            principals: ["cluster.local/ns/shop/sa/frontend"]
      to:
        - operation:
            ports: ["3306"]
```

Port is a **string**. Principals require mTLS.

### 5. Ambient L7

Path-based AuthorizationPolicy in ambient **requires a waypoint** for that service or namespace (`05.md`):

```bash
istioctl waypoint apply -n shop --for service
kubectl label svc httpbin -n shop istio.io/use-waypoint=waypoint
```

Until then, only L4 fields (principals, namespaces, IPs, ports) work.

## Verify

```bash
kubectl -n demo exec deploy/sleep -c sleep -- curl -sS -o /dev/null -w "%{http_code}\n" http://httpbin:8000/get
kubectl -n demo exec deploy/sleep -c sleep -- curl -sS -o /dev/null -w "%{http_code}\n" -X DELETE http://httpbin:8000/delete

istioctl analyze -A
kubectl get authorizationpolicy -A
```

## Exam Tips

- **OR = multiple rules. AND = fields inside one rule.**
- Path matching: `/api*` and `/api/*` are different. The docs table is worth a 20-second look during the exam.
- A namespace-wide ALLOW in `istio-system` can lock the ingress gateway. Scope with `selector: { istio: ingressgateway }` or a named Gateway `targetRef`.
- `ipBlocks` is the **direct peer IP** (often the sidecar or node, not the original client). `remoteIpBlocks` uses `X-Forwarded-For` / PROXY protocol. For "only this pod can call", use **principals**, not IPs.
- Docs: [Authorization policy](https://istio.io/docs/reference/config/security/authorization-policy/).
