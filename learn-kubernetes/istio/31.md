# 31. istioctl proxy-config: Clusters, Listeners, Routes, Endpoints

## Concept Refresher

`proxy-config` (`pc`) dumps **what Envoy actually has**, which is the source of truth. YAML is only a wish.

```bash
istioctl proxy-config cluster  deploy/sleep.demo
istioctl proxy-config listener deploy/sleep.demo
istioctl proxy-config route    deploy/sleep.demo
istioctl proxy-config endpoint deploy/sleep.demo
istioctl proxy-config secret   deploy/sleep.demo
istioctl proxy-config bootstrap deploy/sleep.demo
istioctl proxy-config log      deploy/sleep.demo
istioctl proxy-config all      deploy/sleep.demo -o json
```

Workload syntax: `podname.namespace` or `deploy/name.namespace` or `-n ns podname`.

### Mapping YAML -> dump

| You applied | You inspect |
| --- | --- |
| Service, ServiceEntry, DestinationRule subsets | `cluster` (`pc c`) |
| Endpoint slices, pod IPs | `endpoint` (`pc ep`) |
| Gateway servers, Sidecar ingress, inbound | `listener` (`pc l`) |
| VirtualService HTTP | `route` (`pc r`) |
| mTLS / gateway certs | `secret` (`pc s`) |

### Cluster names

```text
outbound|8000||httpbin.demo.svc.cluster.local
outbound|8000|v1|httpbin.demo.svc.cluster.local
inbound|8000||
BlackHoleCluster
PassthroughCluster
```

Pattern: `direction|port|subset|hostname`. Missing subset cluster while VS references it = **503 NR**.

### Useful filters

```bash
istioctl pc c  deploy/sleep.demo --fqdn httpbin.demo.svc.cluster.local
istioctl pc c  deploy/sleep.demo --direction outbound
istioctl pc r  deploy/sleep.demo --name http.8000
istioctl pc l  deploy/sleep.demo --port 8080
istioctl pc ep deploy/sleep.demo --cluster "outbound|8000||httpbin.demo.svc.cluster.local"
istioctl pc c  deploy/sleep.demo -o json | jq '.[].name'
```

`--name` on routes is the listener/route config name. If unsure, dump without filter and grep.

### Envoy admin (same data)

```bash
kubectl -n demo exec deploy/sleep -c istio-proxy -- curl -s 127.0.0.1:15000/config_dump | jq '.configs | length'
kubectl -n demo exec deploy/sleep -c istio-proxy -- curl -s 127.0.0.1:15000/clusters | grep httpbin
kubectl -n demo exec deploy/sleep -c istio-proxy -- curl -s 127.0.0.1:15000/listeners
```

Prefer `istioctl` on the exam unless you need a raw admin endpoint.

## Tasks

1. Show the outbound cluster list on `sleep` and find `httpbin`.
2. Prove subset `v2` exists as a cluster after applying a DestinationRule; then delete the DR and show it vanish.
3. Dump routes and find the weighted clusters for a 80/20 VirtualService.
4. List endpoints for `httpbin` and match them to pod IPs.
5. Inspect gateway listeners on `istio-ingressgateway` for port 443.

## Solutions

### 1. Clusters

```bash
istioctl pc cluster deploy/sleep.demo | grep httpbin
istioctl pc c deploy/sleep.demo --fqdn httpbin.demo.svc.cluster.local
```

### 2. Subset cluster lifecycle

```bash
kubectl apply -f - <<'EOF'
apiVersion: networking.istio.io/v1
kind: DestinationRule
metadata:
  name: httpbin
  namespace: demo
spec:
  host: httpbin
  subsets:
    - name: v2
      labels: { version: v2 }
EOF
istioctl pc c deploy/sleep.demo | grep '8000|v2|httpbin'
kubectl -n demo delete destinationrule httpbin
istioctl pc c deploy/sleep.demo | grep 'v2|httpbin' || echo gone
```

### 3. Weighted routes

```bash
istioctl pc route deploy/productpage-v1.bookinfo -o json \
  | jq '.. | .weightedClusters? // empty'
```

### 4. Endpoints vs pods

```bash
istioctl pc endpoint deploy/sleep.demo --cluster "outbound|8000||httpbin.demo.svc.cluster.local"
kubectl -n demo get pod -l app=httpbin -o wide
```

IPs must match. Empty endpoints = selector mismatch, 0 ready pods, or wrong cluster name.

### 5. Gateway listeners

```bash
istioctl pc listener deploy/istio-ingressgateway.istio-system --port 443
istioctl pc l deploy/istio-ingressgateway.istio-system -o json \
  | jq '.[] | select(.name|test("443")) | {name, address}'
```

SIMPLE TLS shows a TLS inspector / filter chain. PASSTHROUGH looks different (SNI). Missing 443 = Gateway resource not attached (`selector` wrong).

## Verify

```bash
istioctl pc all deploy/sleep.demo >/tmp/sleep-pc.txt
wc -l /tmp/sleep-pc.txt
istioctl analyze -n demo
```

## Exam Tips

- **503 NR:** `pc route` has the subset, `pc cluster` does not → add DestinationRule. Route missing → VS host/gateway bind.
- **no healthy upstream:** `pc ep` empty or all unhealthy → pods, labels, outlier ejection.
- JSON + `jq` is faster than eyeballing the table once dumps get large.
- Docs: [Debugging Envoy](https://istio.io/docs/ops/diagnostic-tools/proxy-cmd/).
