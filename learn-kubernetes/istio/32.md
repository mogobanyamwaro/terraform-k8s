# 32. Troubleshooting the Mesh Control Plane

## Concept Refresher

Control plane troubleshooting is **istiod**: process health, webhooks, xDS, CA, and the install revision.

```text
Symptoms that are CONTROL PLANE until proven otherwise
- New pods stuck 0/2 or 1/2, never Ready
- istioctl proxy-status empty or all STALE
- kubectl apply of VirtualService rejected by webhook
- istiod CrashLoop, OOM, or 0 replicas
- Injection not happening (pods 1/1 in a labelled ns)
```

Existing traffic can still work while istiod is dead (`01.md`). **New** config and **new** pods will not.

### Checklist

```bash
kubectl -n istio-system get po,svc,deploy,hpa
kubectl -n istio-system logs deploy/istiod --tail=80
kubectl -n istio-system describe deploy istiod

# Webhooks
kubectl get mutatingwebhookconfiguration | grep istio
kubectl get validatingwebhookconfiguration | grep istio
kubectl get svc -n istio-system istiod

# Revision
kubectl get ns --show-labels
kubectl -n istio-system get po -l app=istiod --show-labels
istioctl version
istioctl verify-install
istioctl proxy-status
```

### Injection failures

| Check | Healthy |
| --- | --- |
| Namespace label | `istio-injection=enabled` **or** `istio.io/rev=...`, not both in conflict |
| Mutating webhook | Endpoints on `istiod` port 443 / 15017 |
| `istio-proxy` in pod spec | Two containers after create |
| `istio-cni` | If used, CNI DaemonSet Ready; otherwise init container `istio-init` |

Both `istio-injection=enabled` **and** a stale `istio.io/rev` can skip injection. `04.md` / `07.md`.

```bash
kubectl get ns demo --show-labels
kubectl -n demo get pod -l app=httpbin -o jsonpath='{.items[0].spec.containers[*].name}{"\n"}'
```

### Webhook failures

```text
Error from server: failed to call webhook ... connection refused
```

istiod down, or NetworkPolicy, or `istiod` Service selector does not match pods after a canary (revisioned webhook vs old Service).

```bash
kubectl -n istio-system get endpoints istiod
kubectl get mutatingwebhookconfiguration istio-sidecar-injector -o yaml | grep -A20 clientConfig
```

Revisioned installs create `istiod-1-26-0` Services. The webhook must point at the matching Service.

### CA failures

Pods Ready then flip, logs `failed to generate secret`, SDS errors: `cacerts` malformed (`28.md`), clock skew, or istiod cannot sign.

### Install / upgrade

```bash
istioctl verify-install
istioctl manifest generate --set revision=canary > /tmp/canary.yaml   # compare, don't apply blindly
kubectl get iop -A   # IstioOperator CRs if using operator
```

## Tasks

1. Diagnose why a new `debug` namespace labelled for injection still produces 1/1 pods.
2. istiod has 0 ready pods. Recover enough to list proxies again (lab: scale it back up).
3. After canary, `default` revision webhook still targets old istiod that you deleted. Point out what to inspect (do not destroy the exam cluster).
4. `verify-install` reports a missing egress gateway you expected. Enable it.

## Solutions

### 1. Injection miss

Typical causes and fixes:

```bash
kubectl label ns debug istio-injection=enabled --overwrite
kubectl label ns debug istio.io/rev-          # remove conflicting rev
# recreate pods; injection is at CREATE time
kubectl -n debug rollout restart deploy
```

If webhook has no endpoints, fix istiod first.

### 2. Scale istiod

```bash
kubectl -n istio-system get deploy
kubectl -n istio-system scale deploy/istiod --replicas=1
kubectl -n istio-system rollout status deploy/istiod
istioctl proxy-status
```

If it crashloops, `describe` + logs: bad `meshConfig`, missing `cacerts` key, wrong image.

### 3. Canary webhook

```bash
kubectl get mutatingwebhookconfiguration
kubectl get svc -n istio-system | grep istiod
```

You want `istioctl tag set prod-stable --revision 1-27-0` and namespace labels `istio.io/rev=prod-stable`, then **restart workloads**. Deleting old istiod before migrating webhooks is the outage.

### 4. Egress missing

```bash
istioctl install -y --set spec.components.egressGateways[0].enabled=true \
  --set spec.components.egressGateways[0].name=istio-egressgateway
istioctl verify-install
```

## Verify

```bash
istioctl version
istioctl verify-install
kubectl -n istio-system get po
kubectl get mutatingwebhookconfiguration,validatingwebhookconfiguration
```

## Exam Tips

- **Injection is not retroactive.** Label then `rollout restart`.
- Never `istioctl uninstall --purge` on the exam.
- If `kubectl apply` hangs on webhooks, check istiod first, not your YAML.
- Docs: [Component troubleshooting](https://istio.io/docs/ops/diagnostic-tools/component-logging/) and [Sidecar injection](https://istio.io/docs/setup/additional-setup/sidecar-injection/).
