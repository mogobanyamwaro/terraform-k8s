# 15. Egress Gateways and outboundTrafficPolicy

## Concept Refresher

An **egress gateway** is a dedicated Envoy at the mesh edge that **all outbound traffic is forced through**. You use it so egress can be observed, TLS-terminated or originated in one place, and restricted by network policy to a single set of IPs.

Default Istio (`default` profile) **does not install** an egress gateway. `demo` does. On the exam, check first:

```bash
kubectl -n istio-system get deploy istio-egressgateway
kubectl -n istio-system get svc istio-egressgateway
```

If it is missing, enable it:

```bash
istioctl install --set profile=demo -y
# or overlay
istioctl install -y -f - <<'EOF'
apiVersion: install.istio.io/v1alpha1
kind: IstioOperator
spec:
  components:
    egressGateways:
      - name: istio-egressgateway
        enabled: true
EOF
```

### The four-object recipe

Forcing HTTP through egress to `edition.cnn.com` is the canonical pattern. You always need **all four**:

```text
sleep  --(mesh mTLS)-->  egressgateway  --(plain or TLS)-->  edition.cnn.com
         VirtualService     Gateway
         DestinationRule    ServiceEntry
```

1. **ServiceEntry** - register the external host, so it exists.
2. **Gateway** - open a port on the egress gateway pod (`selector: istio: egressgateway`).
3. **DestinationRule** - mTLS from sidecars **to the egress gateway**, and (often a second DR) TLS mode to the external host.
4. **VirtualService** - bind to **both** `mesh` and the egress Gateway: mesh traffic destined for the host is rerouted to the egress gateway, then the gateway forwards to the real host.

Skip any one of these and you get 404 (VS not bound), plaintext to the gateway (DR missing), or passthrough that never hits egress (VS `gateways` wrong).

### outboundTrafficPolicy

| Mode | Unknown destination |
| --- | --- |
| `ALLOW_ANY` (default) | Sidecar sends it via `PassthroughCluster` |
| `REGISTRY_ONLY` | Sidecar sends it to `BlackHoleCluster` (fail) |

Set mesh-wide in MeshConfig, or per-workload with a Sidecar (`14.md` task 4). Egress-gateway designs almost always use `REGISTRY_ONLY` so apps cannot bypass the gateway.

## Tasks

1. Confirm whether an egress gateway is installed. Install one if not.
2. Force HTTP traffic from `demo/sleep` to `httpbin.org:80` through `istio-egressgateway`.
3. Originate TLS at the egress gateway for `httpbin.org:443` so the app can call `http://httpbin.org:80` internally and the gateway upgrades to HTTPS.
4. Set `demo` to `REGISTRY_ONLY` and prove an unlisted host fails while `httpbin.org` still works through egress.

## Solutions

### 1. Install egress gateway

```bash
kubectl -n istio-system get pod -l istio=egressgateway
istioctl install --set spec.components.egressGateways[0].enabled=true \
  --set spec.components.egressGateways[0].name=istio-egressgateway -y
```

### 2. HTTP via egress

```bash
kubectl apply -f - <<'EOF'
apiVersion: networking.istio.io/v1
kind: ServiceEntry
metadata:
  name: httpbin-ext
  namespace: demo
spec:
  hosts:
    - httpbin.org
  ports:
    - number: 80
      name: http
      protocol: HTTP
  location: MESH_EXTERNAL
  resolution: DNS
---
apiVersion: networking.istio.io/v1
kind: Gateway
metadata:
  name: httpbin-egress
  namespace: demo
spec:
  selector:
    istio: egressgateway
  servers:
    - port:
        number: 80
        name: http
        protocol: HTTP
      hosts:
        - httpbin.org
---
apiVersion: networking.istio.io/v1
kind: DestinationRule
metadata:
  name: httpbin-egress-mtls
  namespace: demo
spec:
  host: istio-egressgateway.istio-system.svc.cluster.local
  trafficPolicy:
    tls:
      mode: ISTIO_MUTUAL
      sni: httpbin.org
---
apiVersion: networking.istio.io/v1
kind: VirtualService
metadata:
  name: httpbin-egress
  namespace: demo
spec:
  hosts:
    - httpbin.org
  gateways:
    - mesh
    - httpbin-egress
  http:
    - match:
        - gateways:
            - mesh
          port: 80
      route:
        - destination:
            host: istio-egressgateway.istio-system.svc.cluster.local
            port:
              number: 80
    - match:
        - gateways:
            - httpbin-egress
          port: 80
      route:
        - destination:
            host: httpbin.org
            port:
              number: 80
EOF
```

Read the VirtualService as two hops. **Hop 1 (mesh):** intercept `httpbin.org` and send to the egress Service. **Hop 2 (egress Gateway):** the gateway receives it and sends to the real `httpbin.org`.

### 3. TLS origination at egress

Change the egress Gateway to HTTPS on 443, add a DestinationRule for `httpbin.org` with `tls.mode: SIMPLE`, and route hop 2 to port 443. The app still dials port 80 HTTP. Full working example is in the Istio task [Egress gateways with TLS origination](https://istio.io/docs/tasks/traffic-management/egress/egress-gateway-tls-origination/). Copy it and change the host. Do not invent the hop ports from memory.

### 4. Block bypass

```yaml
apiVersion: networking.istio.io/v1
kind: Sidecar
metadata:
  name: default
  namespace: demo
spec:
  outboundTrafficPolicy:
    mode: REGISTRY_ONLY
  egress:
    - hosts:
        - "demo/*"
        - "istio-system/*"
        - "default/*"
```

`curl http://httpbin.org/get` works. `curl http://never.example` fails.

## Verify

```bash
# Access log on the EGRESS gateway, not the sidecar
kubectl -n istio-system logs -l istio=egressgateway --tail=20 -f

kubectl -n demo exec deploy/sleep -c sleep -- curl -sS -o /dev/null -w "%{http_code}\n" http://httpbin.org/get

# Client cluster should point at the egress gateway, not PassthroughCluster
istioctl proxy-config route deploy/sleep.demo -o json | jq '.. | .domains? // empty'
```

If sleep's access log shows the request but the egress gateway's does not, hop 1 is wrong (`gateways`, host, or DR to the egress service).

## Exam Tips

- **`selector: istio: egressgateway`** on the Gateway resource. Copy-pasting `ingressgateway` is a silent miss: the Gateway attaches to the wrong pods and sleep's traffic never arrives.
- DestinationRule host for hop 1 is the **egress gateway Service FQDN**, not `httpbin.org`.
- `demo` profile already has egress. `default` does not. `istioctl install --set profile=default` after you enabled egress can disable it again. Re-check the Deployment after any install command.
- Docs: [Egress gateway](https://istio.io/docs/tasks/traffic-management/egress/egress-gateway/). Use the sample YAML and substitute hosts.
