# 10. DevOps and DevSecOps

**Domain:** Related Practices (16%)

## Concept Refresher

**DevOps:** culture and practices that shorten the path from change to production with shared ownership, automation, feedback (CALMS: Culture, Automation, Lean, Measurement, Sharing — know the idea).

**DevSecOps:** security is **in the pipeline and the platform**, not a gate at the end. Image scanning, policy as code (OPA/Kyverno), signed artifacts, least privilege, secret hygiene, admission control.

GitOps **helps** DevOps: same Git workflow for ops as for app code, PR review, audit trail, faster recovery (rollback).

GitOps **helps** DevSecOps:

- Desired state is reviewable
- Cluster-admin not on every CI job (pull model)
- Policy-as-code in Git, enforced by admission + reconciler
- Signed commits / signed images (cosign) as extra, not the four principles themselves

GitOps is **not** a replacement for DevOps culture. You can GitOps-deploy insecure `:latest` root containers.

## Hands-on

Open a PR that adds a dummy secret in plaintext, then one that uses a SealedSecret or ExternalSecret reference. Only the second is DevSecOps-shaped GitOps.

## Exam tips

- GitOps ⊂ tools/practices that **support** DevOps/DevSecOps, not the whole of them.
- Pull + Git review + policy-as-code = exam security story.
