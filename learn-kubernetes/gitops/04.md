# 04. Rollback

**Domain:** GitOps Terminology (20%)

## Concept Refresher

**Rollback** in GitOps: make **desired state** a previously known-good version, then let reconciliation apply it.

Typical:

```bash
git revert <sha>   # or revert a merge, or checkout old tree into a new commit
git push
# agent pulls and reconciles
```

**Not** GitOps-native:

- `kubectl rollout undo` **without** updating Git → cluster and Git diverge; the agent may **re-apply the bad version** (self-heal fights you)
- Restoring etcd behind Git’s back
- Redeploying `:latest` and hoping

Because desired state is **versioned and immutable**, history **is** the rollback mechanism. Immutable means you do not rewrite `main` as the normal rollback; you add a **new** commit that restores old content.

Progressive delivery: rollback can be flipping a flag, reducing a canary weight, or reverting the Git change that introduced the canary.

## Hands-on

Commit a bad replica count, sync, then `git revert` and watch the agent restore.

## Exam tips

- **Rollback = new desired state in Git**, not a cluster-side secret undo.
- Self-heal will **undo your undo** if Git is not updated.
