# 09. Configuration as Code and Infrastructure as Code

**Domain:** Related Practices (16%)

## Concept Refresher

**Configuration as Code (CaC):** system/app configuration in files treated like code (review, version, test). App `application.yml`, feature flags, Kubernetes ConfigMaps as files.

**Infrastructure as Code (IaC):** **infrastructure** (networks, VMs, clusters, IAM, load balancers) declared in code (Terraform, Pulumi, CloudFormation, Crossplane, Cluster API).

GitOps **uses** CaC/IaC as the *content* of desired state. **IaC without GitOps**: a human runs `terraform apply` from a laptop. **GitOps + IaC**: an agent reconciles Terraform/Crossplane from the state store.

CaC/IaC are **not synonyms** for GitOps. GitOps adds **pull + continuous reconciliation + Git-like store properties**.

## Hands-on

Put a ConfigMap in Git and reconcile it. That is CaC. GitOps is the agent that keeps applying it, not the file alone.

## Exam tips

- **IaC/CaC = content. GitOps = how it is stored and reconciled.**
- Laptop `terraform apply` is the distractor.
