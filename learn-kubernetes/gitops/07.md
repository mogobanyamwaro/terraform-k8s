# 07. Principle: Pulled Automatically

**Domain:** GitOps Principles (30%)

## Concept Refresher

Official: *Software agents automatically pull the desired state declarations from the source.*

**Pull** is contrasted with traditional CI **push** (`kubectl apply` from the pipeline into the cluster).

The **cluster (or management plane) reaches out** to the state store. Credentials: the agent has read access to Git; CI does **not** need admin kubeconfig to prod.

**Webhooks** (GitHub → Argo/Flux) may **notify** “please pull now”. That is an **optimization**. If the webhook is down, the agent must still **poll** on an interval. A system that **only** deploys when CI pushes manifests is **not** Pulled Automatically.

External reconciler that still **pulls Git** and applies can be GitOps. Jenkins that **pushes** on git webhook **without** a pull loop is not.
