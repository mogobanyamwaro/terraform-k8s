# 05. Principle: Declarative

**Domain:** GitOps Principles (30%)

## Concept Refresher

Official: *A system managed by GitOps must have its desired state expressed declaratively.*

If humans or CI **tell the system how** (scripts of API calls) as the source of truth, it is not GitOps even if the scripts live in Git.

Git can store imperative scripts; storing them does **not** satisfy Declarative. The **managed system’s desired state** must be a description of the end state.

Kubernetes is a friendly runtime because the API is declarative. GitOps also applies to Terraform-managed cloud, if a reconciler applies Terraform state from Git (Atlantis is closer to PR automation; still map carefully). Exam: Kubernetes YAML is the usual example.

Violations:

- Desired state = Jenkins “build steps” that kubectl apply ad-hoc objects not in Git
- ClickOps in a cloud console as the real source of truth
- Wiki checklists

## Hands-on

Write a Deployment YAML and apply it. Then try to capture the same outcome as a shell script of `kubectl` flags. Git should hold the YAML, not the script, as desired state.

## Exam tips

- **Git ≠ GitOps.** Git + imperative runbooks is still not Declarative.
- Controllers (k8s, Crossplane, Terraform reconcilers) consume declarations.
