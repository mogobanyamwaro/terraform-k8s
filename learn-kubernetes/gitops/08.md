# 08. Principle: Continuously Reconciled

**Domain:** GitOps Principles (30%)

## Concept Refresher

Official: *Software agents continuously observe actual system state and attempt to apply the desired state.*

The agent must know **both** actual and desired. Whenever they differ — **new Git** or **drift** — it **attempts** to apply. “Attempt” matters: it may fail (quota, admission); **feedback** decides retry/alert/rollback.

A one-shot `kubectl apply` on merge, with **no** ongoing compare, fails this principle even if Git holds YAML.

Self-heal / prune in Argo CD, Flux reconciliation loops, Terraform controllers with periodic plans: implementations.

Together the four pillars:

```text
Declare what  ->  store versions  ->  agents pull  ->  loop until actual == desired
```

Missing any one: not GitOps (per OpenGitOps).

## Hands-on

After the lab app is synced, `kubectl scale` it. Wait for reconcile (or `flux reconcile` / Argo refresh). Watch it return to Git.

## Exam tips

- **Know both states. Apply the difference. Keep doing it.**
- Manual-only sync is a common “almost GitOps” distractor.
- Memorise all **four official sentences**.
