# 19. Notifications, Observability, and CI Interoperability

**Domain:** Tooling (14%)

## Concept Refresher

GitOps is a **closed loop**. Tooling around the loop:

**Notifications:** Slack/Teams/email/PagerDuty when sync fails, health degraded, drift detected. Flux Notification Controller, Argo CD notifications. This is **feedback** to humans.

**Observability:** is the Application **Healthy**? Metrics (Prometheus), logs, traces, Argo health, Kubernetes conditions. Progressive delivery **analysis** uses this. Observability does not replace Git as desired state.

**CI interoperability:**

- CI produces images, runs tests, **opens PRs** or **commits tags** to the config repo
- CI should **not** be the cluster applier
- Status checks on the config repo (conftest, kubeconform, kyverno CLI) before merge
- GitHub Checks / GitLab pipelines on the **config** repo

**GitOps ≠ no humans.** Alerts ask humans when the loop cannot converge.
