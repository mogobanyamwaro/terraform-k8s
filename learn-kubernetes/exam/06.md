## Tasks

1. Create a namespace called `exercise-06`
2. Create a Deployment named `webapp` with:
   - 3 replicas
   - Image: `nginx:1.28`
   - Strategy: RollingUpdate with maxSurge=1, maxUnavailable=0
   - Record the change cause
3. Verify all 3 replicas are running
4. Update the image to `nginx:1.29` and record the change
5. Watch the rollout status
6. Check rollout history — you should see 2 revisions
7. Rollback to the previous version (nginx:1.28)
8. Verify the rollback worked by checking the image

---

# Solution

Here's the **best way** to tackle this on the CKA exam – no alternatives, just what works efficiently under time pressure.

---

## 1. Create namespace

```bash
kubectl create namespace exercise-06
```

---

## 2. Create Deployment with RollingUpdate strategy

```bash
kubectl create deployment webapp -n exercise-06 \
  --image=nginx:1.28 \
  --replicas=3 

 kubectl annotate deployment webapp  -n exercise-06 \
kubernetes.io/change-cause="Initial nginx deployment"
```

**Then edit the deployment to set the rolling update strategy:**

```bash
kubectl edit deployment webapp -n exercise-06
```

**Find `strategy:` section and replace with:**

```yaml
strategy:
  rollingUpdate:
    maxSurge: 1
    maxUnavailable: 0
  type: RollingUpdate
```

**Verify the strategy is set:**

```bash
kubectl get deployment webapp -n exercise-06 -o yaml | grep -A5 strategy
```

---

## 3. Verify all 3 replicas are running

```bash
kubectl get pods -n exercise-06 -l app=webapp
```

**Expected output:** 3 pods with `Running` status

**Also check deployment status:**

```bash
kubectl get deployment webapp -n exercise-06
```

---

## 4. Update image to nginx:1.29 and record change

```bash
kubectl set image deployment/webapp webapp=nginx:1.29 -n exercise-06 --record
```

**Note:** The container name is `webapp` (same as deployment name by default)

---

## 5. Watch the rollout status

```bash
kubectl rollout status deployment webapp -n exercise-06
```

**Wait for:** `deployment "webapp" successfully rolled out`

---

## 6. Check rollout history

```bash
kubectl rollout history deployment webapp -n exercise-06
```

**Expected output:** 2 revisions

```
REVISION  CHANGE-CAUSE
1         kubectl create deployment webapp --image=nginx:1.28 --replicas=3 --record=true
2         kubectl set image deployment/webapp webapp=nginx:1.29 --record=true
```

**View specific revision details:**

```bash
kubectl rollout history deployment webapp -n exercise-06 --revision=1
kubectl rollout history deployment webapp -n exercise-06 --revision=2
```

---

## 7. Rollback to previous version (nginx:1.28)

```bash
kubectl rollout undo deployment webapp -n exercise-06
```

**To rollback to specific revision (if needed):**

```bash
kubectl rollout undo deployment webapp -n exercise-06 --to-revision=1
```

**Watch the rollback:**

```bash
kubectl rollout status deployment webapp -n exercise-06
```

---

## 8. Verify rollback worked by checking image

```bash
kubectl get deployment webapp -n exercise-06 -o jsonpath='{.spec.template.spec.containers[0].image}'
```

**Expected output:** `nginx:1.28`

**Verify all pods are running the correct image:**

```bash
kubectl get pods -n exercise-06 -l app=webapp -o jsonpath='{range .items[*]}{.spec.containers[0].image}{"\n"}{end}'
```

**Check rollout history now shows 3 revisions:**

```bash
kubectl rollout history deployment webapp -n exercise-06
```

## Exam Critical Notes

| Command           | Purpose                        | When to use                 |
| ----------------- | ------------------------------ | --------------------------- |
| `--record`        | Saves change cause in revision | During create and update    |
| `rollout status`  | Wait for rollout to complete   | After every update/rollback |
| `rollout history` | See revisions                  | To verify changes tracked   |
| `rollout undo`    | Rollback to previous           | When you need to revert     |
| `edit deployment` | Change strategy                | Only once at creation       |

---

## Pro Tips for CKA

1. **Use `--record` every time** – Exam checks for revision history
2. **Always run `rollout status`** – Verify success before moving on
3. **RollingUpdate defaults** – If you don't set strategy, it's still RollingUpdate with `maxUnavailable=25%, maxSurge=25%`
4. **Container name** – With `kubectl create deployment`, container name equals deployment name
5. **No need for YAML** – Imperative commands are faster in exam
