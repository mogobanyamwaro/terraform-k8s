Update TLS configuration to support additional protocol versions for backward compatibility. Tests ConfigMap modification and service restart.

## Tasks

1. A service currently supports only TLS 1.3
2. Add support for TLS 1.2 (make both available)
3. Update configuration file or ConfigMap:
   - Add TLS 1.2 to supported protocols
   - Keep TLS 1.3 enabled
4. ConfigMap is mounted in Deployment as env var or config file
5. Restart Deployment to apply changes
6. Verify service accepts TLS 1.2 connections:
   - Use `openssl s_client -connect <service> -tls1_2`
   - Or curl with explicit TLS 1.2
7. Verify TLS 1.3 still works

## Key Learning

- TLS configuration often in ConfigMaps
- Adding vs replacing: exam specifies "ADD support" (don't remove existing)
- Service restart may be needed after config change
- TLS negotiation must support minimum version
- Testing TLS versions requires understanding openssl commands

## Understanding TLS Configuration

| TLS Version | Status After Task | Why                    |
| ----------- | ----------------- | ---------------------- |
| TLS 1.3     | Enabled (keep)    | Current standard       |
| TLS 1.2     | ADD support       | Backward compatibility |

**Typical scenario:** Ingress controller, API gateway, or application ConfigMap controls TLS versions.

## 1. A service currently supports only TLS 1.3

**First, verify current TLS configuration (baseline):**

```bash
# Check if service exists
kubectl get svc -A | grep -E "ingress|nginx|gateway"

# Check current TLS settings in ConfigMap
kubectl get configmap -A | grep -E "tls|ssl|nginx|ingress"
```

**Test current TLS support (should fail for TLS 1.2):**

```bash
# Get service endpoint
SERVICE_IP=$(kubectl get svc <service-name> -n <namespace> -o jsonpath='{.status.loadBalancer.ingress[0].ip}')
SERVICE_PORT=443

# Test TLS 1.2 (should fail)
openssl s_client -connect $SERVICE_IP:$SERVICE_PORT -tls1_2 2>&1 | grep -E "Protocol|Cipher"

# Test TLS 1.3 (should succeed)
openssl s_client -connect $SERVICE_IP:$SERVICE_PORT -tls1_3 2>&1 | grep -E "Protocol|Cipher"
```

**If service is a simple application, check its current config:**

```bash
# Look for environment variables with TLS settings
kubectl get deployment <app-name> -n <namespace> -o yaml | grep -A10 "env:" | grep -E "TLS|SSL"
```

## 2. Add support for TLS 1.2 (make both available)

**Example scenario: NGINX Ingress Controller**

**Find the ConfigMap controlling TLS versions:**

```bash
kubectl get configmap -n ingress-nginx
```

**Typical ConfigMap name:** `nginx-configuration` or `tls-options`

**View current ConfigMap:**

```bash
kubectl get configmap nginx-configuration -n ingress-nginx -o yaml
```

**Example for NGINX Ingress:**

```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: nginx-configuration
  namespace: ingress-nginx
data:
  ssl-protocols: "TLSv1.3" # Currently only TLS 1.3
```

**Example for a custom application with TLS config file:**

```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: app-config
  namespace: exercise-29
data:
  tls.conf: |
    ssl_protocols TLSv1.3;
    ssl_ciphers HIGH:!aNULL:!MD5;
```

## 3. Update configuration to add TLS 1.2

**Method 1 – Edit ConfigMap directly:**

```bash
kubectl edit configmap nginx-configuration -n ingress-nginx
```

**Change the `ssl-protocols` line to include both versions:**

```yaml
data:
  ssl-protocols: "TLSv1.2 TLSv1.3"
```

**Method 2 – Using kubectl patch:**

```bash
kubectl patch configmap nginx-configuration -n ingress-nginx \
  --patch '{"data":{"ssl-protocols":"TLSv1.2 TLSv1.3"}}'
```

**For a custom application ConfigMap with file content:**

```bash
# Extract current config
kubectl get configmap app-config -n exercise-29 -o yaml > app-config.yaml

# Edit the file
vi app-config.yaml
# Change: ssl_protocols TLSv1.3; -> ssl_protocols TLSv1.2 TLSv1.3;

# Apply updated ConfigMap
kubectl apply -f app-config.yaml
```

**For environment variable based configuration:**

```bash
kubectl patch configmap app-config -n exercise-29 \
  --patch '{"data":{"TLS_VERSION":"TLSv1.2,TLSv1.3"}}'
```

## 4. ConfigMap is mounted in Deployment as env var or config file

**Verify how ConfigMap is mounted:**

```bash
kubectl get deployment <app-name> -n <namespace> -o yaml | grep -A10 "envFrom"
# or
kubectl get deployment <app-name> -n <namespace> -o yaml | grep -A10 "volumes"
```

**Example of ConfigMap as environment variable:**

```yaml
spec:
  containers:
    - envFrom:
        - configMapRef:
            name: app-config
```

**Example of ConfigMap as config file:**

```yaml
volumes:
  - name: config
    configMap:
      name: app-config
```

## 5. Restart Deployment to apply changes

**Method 1 – Rolling restart (recommended):**

```bash
kubectl rollout restart deployment <app-name> -n <namespace>
```

**Method 2 – Scale down/up:**

```bash
kubectl scale deployment <app-name> -n <namespace> --replicas=0
kubectl scale deployment <app-name> -n <namespace> --replicas=1
```

**Method 3 – Patch with annotation (triggers rollout):**

```bash
kubectl patch deployment <app-name> -n <namespace> \
  -p '{"spec":{"template":{"metadata":{"annotations":{"restartedAt":"'$(date +%s)'"}}}}}'
```

**Wait for rollout to complete:**

```bash
kubectl rollout status deployment <app-name> -n <namespace>
```

## 6. Verify service accepts TLS 1.2 connections

**Test TLS 1.2 (should succeed):**

```bash
# Get service IP/port
SERVICE_IP=$(kubectl get svc <service-name> -n <namespace> -o jsonpath='{.status.loadBalancer.ingress[0].ip}')
SERVICE_PORT=443

# Test TLS 1.2
openssl s_client -connect $SERVICE_IP:$SERVICE_PORT -tls1_2 2>&1 | grep -E "Protocol|Cipher|Verify return code"
```

**Expected output:**

```
Protocol  : TLSv1.2
Cipher    : ECDHE-RSA-AES128-GCM-SHA256
Verify return code: 0 (ok)
```

**If service is exposed via Ingress with hostname:**

```bash
openssl s_client -connect example.com:443 -tls1_2 -servername example.com 2>&1 | head -20
```

**Using curl with TLS 1.2:**

```bash
curl -v --tlsv1.2 --cacert /dev/null https://$SERVICE_IP/
```

## 7. Verify TLS 1.3 still works

**Test TLS 1.3 (should still succeed):**

```bash
openssl s_client -connect $SERVICE_IP:$SERVICE_PORT -tls1_3 2>&1 | grep -E "Protocol|Cipher"
```

**Expected output:**

```
Protocol  : TLSv1.3
Cipher    : TLS_AES_128_GCM_SHA256
Verify return code: 0 (ok)
```

**Test both versions side by side:**

```bash
echo "=== TLS 1.2 ==="
openssl s_client -connect $SERVICE_IP:$SERVICE_PORT -tls1_2 2>&1 | grep -E "Protocol:|Cipher:" | head -2

echo "=== TLS 1.3 ==="
openssl s_client -connect $SERVICE_IP:$SERVICE_PORT -tls1_3 2>&1 | grep -E "Protocol:|Cipher:" | head -2
```

## Common Exam Scenarios

### Scenario A: NGINX Ingress Controller

**ConfigMap location:** `ingress-nginx/nginx-configuration`

**Update command:**

```bash
kubectl patch configmap nginx-configuration -n ingress-nginx \
  --patch '{"data":{"ssl-protocols":"TLSv1.2 TLSv1.3"}}'

# Restart ingress controller pods
kubectl rollout restart deployment ingress-nginx-controller -n ingress-nginx
```

### Scenario B: Custom Application with Config File

**ConfigMap with file content:**

```bash
# Create updated ConfigMap
cat <<EOF | kubectl apply -f -
apiVersion: v1
kind: ConfigMap
metadata:
  name: app-tls-config
  namespace: exercise-29
data:
  tls-settings.conf: |
    min_version = TLSv1.2
    max_version = TLSv1.3
    protocols = ["TLSv1.2", "TLSv1.3"]
EOF

# Restart deployment
kubectl rollout restart deployment my-app -n exercise-29
```

### Scenario C: Application with Environment Variables

**Update ConfigMap:**

```bash
kubectl patch configmap app-env-config -n exercise-29 \
  --patch '{"data":{"TLS_MIN_VERSION":"TLSv1.2","TLS_MAX_VERSION":"TLSv1.3"}}'
```

**Restart deployment to pick up env vars:**

```bash
kubectl rollout restart deployment my-app -n exercise-29
```

## TLS Version Testing Cheat Sheet

| Command                                       | Purpose                    |
| --------------------------------------------- | -------------------------- |
| `openssl s_client -connect host:port -tls1_2` | Test TLS 1.2 only          |
| `openssl s_client -connect host:port -tls1_3` | Test TLS 1.3 only          |
| `openssl s_client -connect host:port -tls1_1` | Test TLS 1.1 (should fail) |
| `openssl s_client -connect host:port`         | Negotiate highest version  |
| `curl -v --tlsv1.2 https://host/`             | Test with curl             |
| `nmap --script ssl-enum-ciphers -p 443 host`  | Enumerate TLS versions     |

## Pro Tips for CKA

1. **"ADD support" means don't remove** – Keep existing TLS 1.3, add TLS 1.2
2. **ConfigMap changes don't auto-restart pods** – Must restart deployment
3. **Check ConfigMap mount type** – envFrom vs volumeMounts determines how to update
4. **Rolling restart is safe** – `kubectl rollout restart` preserves availability
5. **Test both versions** – Verify backward compatibility AND existing functionality
6. **Use `kubectl patch` for quick edits** – Faster than edit in exam
7. **Check Ingress Controller logs** – `kubectl logs -n ingress-nginx` for TLS errors

## Troubleshooting

**ConfigMap updated but service still rejects TLS 1.2:**

```bash
# Check if pod restarted
kubectl get pods -n <namespace> | grep <app>

# Check if ConfigMap is mounted correctly
kubectl exec -n <namespace> <pod> -- cat /path/to/config/file

# Check pod logs for TLS errors
kubectl logs -n <namespace> <pod> | grep -i tls

# Verify ConfigMap content in pod
kubectl exec -n <namespace> <pod> -- env | grep -i tls
```

**openssl command not available:**

```bash
# Install openssl (if needed)
apt-get update && apt-get install -y openssl

# Or use test pod
kubectl run tls-test --image=alpine/openssl --rm -it --restart=Never -- \
  s_client -connect $SERVICE_IP:$SERVICE_PORT -tls1_2
```
