## CKA Practice Exam - Set 2 (25 Questions)

### Domain 1: Cluster Architecture, Installation & Configuration (25%) - 6 Questions

#### Question 1: kubeadm Cluster Configuration

**Task:**
Initialize a new Kubernetes cluster using kubeadm with the following specifications:

1. Use pod network CIDR: `10.244.0.0/16`
2. Set the API server advertise address to the node's IP
3. After initialization, set up kubeconfig for a regular user
4. Install a Calico or Flannel CNI plugin

#### Question 2: Certificate Renewal and Verification

**Task:**

1. Check when the API server certificate expires
2. Manually renew all Kubernetes certificates
3. Verify the renewed certificates
4. Restart appropriate control plane components

#### Question 3: API Server Authentication with Token

**Task:**

1. Create a bootstrap token named `07401b.f395accd246ae52d`
2. Create a ClusterRoleBinding that gives this token view-only access to the cluster
3. Generate the kubeconfig file that uses this token for authentication

#### Question 4: Control Plane Component Configuration

**Task:**
Modify the kube-apiserver static pod manifest to:

1. Enable the `MutatingAdmissionWebhook` and `ValidatingAdmissionWebhook` admission plugins
2. Set the `--authorization-mode` to `Node,RBAC`
3. Ensure the API server restarts with the new configuration

#### Question 5: Kubernetes Version Upgrade with Cordon/Uncordon

**Task:**
Perform a minor version upgrade on a worker node:

1. Cordon the worker node `node02`
2. Upgrade kubeadm, kubelet, and kubectl on the worker node
3. Upgrade the node's configuration
4. Uncordon the node and verify it's back to Ready state

#### Question 6: ETCD Snapshot Automation

**Task:**
Create a cron job that:

1. Runs every day at 2 AM
2. Takes an etcd snapshot and saves it to `/backup/etcd-snapshot-$(date +%Y%m%d).db`
3. Keeps only the last 7 snapshots (deletes older ones)
4. Runs on the control plane node only

### Domain 2: Workloads & Scheduling (15%) - 4 Questions

#### Question 7: Blue-Green Deployment with Labels

**Task:**
Implement a blue-green deployment strategy:

1. Create a deployment named `app-blue` with 3 replicas using image `nginx:1.19` and label `version=blue`
2. Create a service named `app-service` that selects pods with label `app=myapp` (which both deployments will have)
3. Create a deployment named `app-green` with 3 replicas using image `nginx:1.20` and label `version=green`
4. Switch traffic from blue to green by updating the service's selector

#### Question 8: Pod Priority and Preemption

**Task:**

1. Create a PriorityClass named `high-priority` with value `1000000` and `globalDefault=false`
2. Create a PriorityClass named `low-priority` with value `100`
3. Create two pods: `high-pod` using high priority and `low-pod` using low priority
4. When resources are limited, ensure high-priority pods preempt low-priority ones

#### Question 9: DaemonSet with Node Selector

**Task:**
Create a DaemonSet named `monitoring-agent` that:

1. Runs on all nodes with label `monitoring=enabled`
2. Uses image `prom/node-exporter`
3. Mounts the host's `/proc` and `/sys` filesystems
4. Uses hostNetwork to access node metrics directly

#### Question 10: Init Containers for Setup Tasks

**Task:**
Create a pod named `app-with-init` that:

1. Has an init container using `busybox` that creates a file `/workdir/data.txt` with content "initialized"
2. The init container should wait for a service named `db-service` to be available (hint: use `nslookup` or a simple loop)
3. The main container uses `nginx` and serves the file from a shared emptyDir volume
4. Verify the file is accessible from the main container

### Domain 3: Services & Networking (20%) - 5 Questions

#### Question 11: ExternalName Service

**Task:**

1. Create an ExternalName service named `external-db` that points to `database.example.com`
2. Create a test pod that can resolve this service to the external domain
3. Verify that the service returns a CNAME record

#### Question 12: MetalLB Configuration (Bare Metal)

**Task:**
Assuming you're on a bare-metal cluster:

1. Install MetalLB
2. Configure it with IP range `192.168.1.240-192.168.1.250`
3. Create a LoadBalancer service named `lb-app` for a deployment with 3 replicas
4. Verify an external IP is assigned

#### Question 13: Ingress with Multiple Paths

**Task:**
Create an Ingress resource named `multi-path` that:

1. Routes traffic for `api.example.com` to service `api-svc` on port 80
2. Routes traffic for `api.example.com/v2/` to service `api-v2-svc` on port 80
3. Routes traffic for `web.example.com` to service `web-svc` on port 80
4. All other traffic returns 404

#### Question 14: NetworkPolicy with Egress Rules

**Task:**
Create a NetworkPolicy named `secure-policy` in the `secure` namespace that:

1. Allows ingress only from pods with label `access=allowed` on port 8080
2. Allows egress only to `10.0.0.0/8` on port 53 (DNS) and to pods in the `database` namespace on port 3306
3. Denies all other egress traffic

#### Question 15: Service Mesh Integration (Istio/Ambient)

**Task:**

### Domain 5: Troubleshooting (30%) - 7 Questions
