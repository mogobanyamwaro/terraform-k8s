Deploy a stateful application using StatefulSet. This exercise teaches ordered pod initialization, persistent storage, and stable network identities—critical for databases and distributed systems on the CKA.

## Context

StatefulSets are for applications that need:

- Stable, predictable pod names (not randomly generated like Deployments)
- Ordered pod startup and shutdown
- Persistent storage per pod replica
- Stable network identities (DNS names with ordinal suffixes)

Unlike Deployments where pod identity doesn't matter, StatefulSets maintain identity across restarts. Example: a MySQL cluster needs predictable names like `mysql-0`, `mysql-1`, `mysql-2` that survive pod recreations.

## Tasks

1. Create a headless Service for the StatefulSet (required for DNS routing)
2. Create a StatefulSet with 3 replicas using the `nginx:1.28` image
3. Verify pods start in order (mysql-0 first, then mysql-1, then mysql-2)
4. Verify each pod has a persistent volume claim attached
5. Delete a pod and observe it respawn with the same name and storage
6. Scale the StatefulSet up and down using `kubectl scale`
7. Delete the StatefulSet and verify PVCs persist (data survives)

## 1. Create headless Service for StatefulSet

```bash
kubectl create service clusterip webapp-svc --tcp=80:80 -n exercise-06 --clusterip=None
```

**Or create with YAML if you need to verify:**

```bash
cat <<EOF | kubectl apply -f -
apiVersion: v1
kind: Service
metadata:
  name: webapp-svc
  namespace: exercise-06
spec:
  clusterIP: None
  selector:
    app: webapp
  ports:
  - port: 80
    targetPort: 80
EOF
```

**Verify headless service:**

```bash
kubectl get svc webapp-svc -n exercise-06
```

Expected: `CLUSTER-IP` shows `None`

## 2. Create StatefulSet with 3 replicas

```bash
cat <<EOF | kubectl apply -f -
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: webapp
  namespace: exercise-06
spec:
  serviceName: webapp-svc
  replicas: 3
  selector:
    matchLabels:
      app: webapp
  template:
    metadata:
      labels:
        app: webapp
    spec:
      containers:
      - name: nginx
        image: nginx:1.28
        ports:
        - containerPort: 80
        volumeMounts:
        - name: data
          mountPath: /usr/share/nginx/html
  volumeClaimTemplates:
  - metadata:
      name: data
    spec:
      accessModes: [ "ReadWriteOnce" ]
      resources:
        requests:
          storage: 1Gi
EOF
```

**Watch pods start in order:**

```bash
kubectl get pods -n exercise-06 -l app=webapp -w
```

## 3. Verify pods start in order (webapp-0, then webapp-1, then webapp-2)

**Check pod names and status:**

```bash
kubectl get pods -n exercise-06 -l app=webapp -o wide
```

**Expected output:** Pods named `webapp-0`, `webapp-1`, `webapp-2`

**Verify creation timestamps:**

```bash
kubectl get pods -n exercise-06 -l app=webapp -o jsonpath='{range .items[*]}{.metadata.name}{"\t"}{.metadata.creationTimestamp}{"\n"}{end}'
```

**Check ordered startup:**

```bash
kubectl logs webapp-0 -n exercise-06
```

## 4. Verify each pod has a persistent volume claim attached

**List PVCs:**

```bash
kubectl get pvc -n exercise-06
```

**Expected output:** 3 PVCs named `data-webapp-0`, `data-webapp-1`, `data-webapp-2`

**Verify PVC to pod binding:**

```bash
kubectl get pvc -n exercise-06 -o wide
```

**Check pod mounts:**

```bash
kubectl describe pod webapp-0 -n exercise-06 | grep -A5 "Volumes"
```

## 5. Delete a pod and observe respawn with same name and storage

**Delete webapp-1:**

```bash
kubectl delete pod webapp-1 -n exercise-06
```

**Watch respawn:**

```bash
kubectl get pods -n exercise-06 -l app=webapp -w
```

**After respawn, verify same name:**

```bash
kubectl get pods -n exercise-06 -l app=webapp
```

Expected: `webapp-1` is back (not a new random name)

**Verify PVC still attached:**

```bash
kubectl get pvc -n exercise-06 | grep webapp-1
```

**Test data persistence:**

```bash
# Write data before deletion
kubectl exec -n exercise-06 webapp-0 -- sh -c "echo 'test data' > /usr/share/nginx/html/test.txt"

# Delete pod
kubectl delete pod webapp-0 -n exercise-06

# Wait for respawn, then verify data
kubectl exec -n exercise-06 webapp-0 -- cat /usr/share/nginx/html/test.txt
```

Expected: `test data` (data survived)

## 6. Scale the StatefulSet up and down

**Scale up to 4 replicas:**

```bash
kubectl scale statefulset webapp -n exercise-06 --replicas=4
```

**Watch ordered startup (webapp-3 created):**

```bash
kubectl get pods -n exercise-06 -l app=webapp -w
```

**Verify new PVC created:**

```bash
kubectl get pvc -n exercise-06
```

Expected: `data-webapp-3` appears

**Scale down to 2 replicas:**

```bash
kubectl scale statefulset webapp -n exercise-06 --replicas=2
```

**Watch ordered termination (webapp-3 deleted first, then webapp-2):**

```bash
kubectl get pods -n exercise-06 -l app=webapp -w
```

**Verify PVCs still exist (even after scaling down):**

```bash
kubectl get pvc -n exercise-06
```

Expected: PVCs for webapp-2 and webapp-3 still present

---

## 7. Delete StatefulSet and verify PVCs persist

**Delete StatefulSet (but leave PVCs):**

```bash
kubectl delete statefulset webapp -n exercise-06
```

**Verify PVCs still exist:**

```bash
kubectl get pvc -n exercise-06
```

**Verify PVs still exist (if you want to check underlying volumes):**

```bash
kubectl get pv | grep data-webapp
```

**Recreate StatefulSet to verify PVC reuse:**

```bash
cat <<EOF | kubectl apply -f -
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: webapp
  namespace: exercise-06
spec:
  serviceName: webapp-svc
  replicas: 2
  selector:
    matchLabels:
      app: webapp
  template:
    metadata:
      labels:
        app: webapp
    spec:
      containers:
      - name: nginx
        image: nginx:1.28
        volumeMounts:
        - name: data
          mountPath: /usr/share/nginx/html
  volumeClaimTemplates:
  - metadata:
      name: data
    spec:
      accessModes: [ "ReadWriteOnce" ]
      resources:
        requests:
          storage: 1Gi
EOF
```

**Verify existing PVCs are claimed:**

```bash
kubectl get pods -n exercise-06 -l app=webapp
kubectl get pvc -n exercise-06
```

## Exam Critical Notes

| Component            | Purpose                   | Key Detail                                |
| -------------------- | ------------------------- | ----------------------------------------- |
| Headless Service     | Stable DNS for pods       | `clusterIP: None`                         |
| StatefulSet          | Manages pods              | `serviceName` must match headless service |
| volumeClaimTemplates | Creates PVC per pod       | Each pod gets its own PVC                 |
| Pod naming           | `{statefulset}-{ordinal}` | Starts at 0, increments                   |
| Scaling up           | Adds highest ordinal      | webapp-3, webapp-4, etc.                  |
| Scaling down         | Removes highest ordinal   | Deletes webapp-4 first, then webapp-3     |
| PVC retention        | Survives pod deletion     | Data persists until PVC deleted           |

---

## Common Exam Traps

| Trap                                | Consequence                | Fix                               |
| ----------------------------------- | -------------------------- | --------------------------------- |
| Regular Service instead of headless | No stable DNS              | Use `clusterIP: None`             |
| Missing serviceName in StatefulSet  | Pods won't get DNS entries | Must match headless service name  |
| Forgetting volumeClaimTemplates     | No persistent storage      | Each pod needs template           |
| Deleting StatefulSet with cascade   | PVCs deleted               | Default is cascade, PVCs survive  |
| Expecting random pod names          | StatefulSets use ordinals  | Names are predictable, not random |

---

## Pro Tips for CKA

1. **Headless Service is mandatory** – StatefulSet won't work correctly without it
2. **PVCs outlive StatefulSet** – Data protection is a key feature
3. **Ordered termination** – Scale down deletes highest ordinal first
4. **Storage class** – If not specified, uses default storage class
5. **Test with nginx** – Simple image like nginx is perfect for exam scenarios
