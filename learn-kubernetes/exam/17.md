Use `kubectl debug` to troubleshoot running pods and access node-level resources. This is GA in v1.35 and directly relevant to CKA troubleshooting tasks.

## Tasks

### Part A: Debug a pod

1. Create a namespace called `exercise-17`
2. Create a pod named `broken-app` with image `nginx:1.27`
3. Attach a debug container to the running pod using `kubectl debug`:
   - Image: `busybox:1.36`
   - Target the `broken-app` container to share process namespace
4. From inside the debug container, list the processes (you should see the nginx process)
5. Check the filesystem and network from the debug container
6. Exit the debug session

### Part B: Debug a node

7. Run `kubectl debug` against a node to get a shell with host filesystem access
8. Use `chroot /host` to access the real node root
9. Check kubelet status from the debug session
10. Exit the debug session

---

Here's the **best way** to tackle `kubectl debug` on the CKA exam – this tests ephemeral containers for pod troubleshooting and node debugging.

## Part A: Debug a Pod

### 1. Create namespace

```bash
kubectl create namespace exercise-17
```

---

### 2. Create pod named broken-app with nginx:1.27

```bash
kubectl run broken-app -n exercise-17 --image=nginx:1.27
```

**Wait for pod to be ready:**

```bash
kubectl wait --for=condition=Ready pod/broken-app -n exercise-17 --timeout=60s
```

**Verify pod is running:**

```bash
kubectl get pods -n exercise-17
```

---

### 3. Attach debug container using kubectl debug

**Share process namespace with target container:**

```bash
kubectl debug -n exercise-17 broken-app \
  --image=busybox:1.36 \
  --target=broken-app
```

**Flag explanation:**

- `--target=broken-app` – Share the process namespace with this container
- `--image=busybox:1.36` – Debug container image
- The debug container will run and give you a shell

**Alternative with custom command:**

```bash
kubectl debug -n exercise-17 broken-app \
  --image=busybox:1.36 \
  --target=broken-app \
  -- sh
```

---

### 4. List processes from inside debug container

**Once in the debug shell, list processes:**

```bash
ps aux
```

**Expected output:** You should see the nginx process (PID 1 or similar) alongside the debug shell

**Alternative with specific process listing:**

```bash
ps -ef
```

**Look for nginx processes:**

```bash
ps aux | grep nginx
```

---

### 5. Check filesystem and network from debug container

**Check filesystem (shared with pod):**

```bash
ls -la /proc/1/root/usr/share/nginx/html/
```

**Or chroot to container root:**

```bash
chroot /proc/1/root /bin/sh
ls -la /usr/share/nginx/html/
exit
```

**Check network interfaces:**

```bash
ip addr
```

**Check network connectivity:**

```bash
cat /etc/resolv.conf
nslookup kubernetes.default
```

**Check routes:**

```bash
ip route
```

**Check socket connections:**

```bash
netstat -tulpn
```

**Test connectivity to service:**

```bash
wget -O- http://localhost:80
```

---

### 6. Exit debug session

```bash
exit
```

**Verify debug container still exists (ephemeral):**

```bash
kubectl get pods -n exercise-17 broken-app -o yaml | grep -A5 ephemeralContainers
```

**Clean up debug container (exits automatically when you exit):**
The debug container stops when you exit, but you can also remove it.

---

## Part B: Debug a Node

### 7. Run kubectl debug against a node

**Get node names:**

```bash
kubectl get nodes
```

**Run debug on a worker node (choose a worker, not control-plane):**

```bash
NODE_NAME=$(kubectl get nodes -o name | grep -v control-plane | head -1 | cut -d'/' -f2)
echo $NODE_NAME
```

**Start node debug session:**

```bash
kubectl debug node/$NODE_NAME -it --image=busybox:1.36
```

**This creates a pod on the node with access to the host filesystem**

---

### 8. Use chroot /host to access real node root

**Check mounted host filesystem:**

```bash
ls -la /host
```

**Chroot into host:**

```bash
chroot /host
```

**Now you're at the real node's root filesystem**

**Verify current directory:**

```bash
pwd
```

Expected: `/`

**List root directories:**

```bash
ls -la /
```

---

### 9. Check kubelet status from debug session

**Check kubelet service status (from chrooted session):**

```bash
systemctl status kubelet
```

**Alternative if systemctl not available:**

```bash
ps aux | grep kubelet
```

**Check kubelet logs:**

```bash
journalctl -u kubelet -n 20 --no-pager
```

**Check kubelet config:**

```bash
cat /var/lib/kubelet/config.yaml
```

**Check container runtime:**

```bash
crictl ps
```

**Check disk usage:**

```bash
df -h
```

**Check node processes:**

```bash
ps aux | head -20
```

---

### 10. Exit debug session

**Exit chroot:**

```bash
exit
```

**Exit debug pod:**

```bash
exit
```

**The debug pod is automatically cleaned up when you exit**

## Advanced kubectl debug Examples

### Debug with specific container in multi-container pod

```bash
kubectl debug -n exercise-17 broken-app \
  --image=busybox:1.36 \
  --target=broken-app
```

### Copy files from the target container

```bash
kubectl debug -n exercise-17 broken-app \
  --image=busybox:1.36 \
  --target=broken-app \
  -- cp /etc/nginx/nginx.conf /tmp/nginx.conf
```

### Debug pod with custom command

```bash
kubectl debug -n exercise-17 broken-app \
  --image=busybox:1.36 \
  --target=broken-app \
  -- sh -c "while true; do sleep 30; done"
```

### Debug pod with different Linux tools

```bash
# Using alpine with more tools
kubectl debug -n exercise-17 broken-app \
  --image=alpine:3.19 \
  --target=broken-app \
  -- apk add curl && sh
```

### Debug a crashed pod

```bash
# Create a crashing pod
kubectl run -n exercise-17 crashing-app --image=busybox:1.36 --command -- sh -c "exit 1"

# Debug crashed pod
kubectl debug -n exercise-17 crashing-app \
  --image=busybox:1.36 \
  -- sh
```

### Debug pod in a specific node

```bash
kubectl debug node/$NODE_NAME \
  --image=ubuntu:22.04 \
  -it \
  -- bash
```

## Node Debugging with Different Images

### Using Ubuntu (more tools)

```bash
kubectl debug node/$NODE_NAME -it \
  --image=ubuntu:22.04 \
  -- bash
```

**Then in the debug pod:**

```bash
chroot /host
apt-get update && apt-get install -y curl net-tools
```

```bash
kubectl debug node/$NODE_NAME -it \
  --image=alpine:3.19 \
  -- sh
```

### Using Fedora (full toolset)

```bash
kubectl debug node/$NODE_NAME -it \
  --image=fedora:39 \
  -- bash
```

## Common kubectl debug Use Cases

| Use Case             | Command                                                                         |
| -------------------- | ------------------------------------------------------------------------------- |
| Debug pod process    | `kubectl debug mypod --image=busybox --target=mypod`                            |
| Debug pod network    | `kubectl debug mypod --image=nicolaka/netshoot --target=mypod`                  |
| Debug pod filesystem | `kubectl debug mypod --image=busybox --target=mypod -- ls -la /proc/1/root`     |
| Debug node           | `kubectl debug node/mynode --image=busybox`                                     |
| Debug crashed pod    | `kubectl debug mypod --image=busybox -- sh`                                     |
| Copy file from pod   | `kubectl debug mypod --image=busybox --target=mypod -- cp /path/file /tmp/file` |

## Exam Critical Notes

| Debug Type                  | Command                     | Key Flag                  |
| --------------------------- | --------------------------- | ------------------------- |
| Pod with process sharing    | `kubectl debug <pod>`       | `--target=<container>`    |
| Pod without process sharing | `kubectl debug <pod>`       | None (new container only) |
| Node debug                  | `kubectl debug node/<node>` | `--image=<debug-image>`   |
| Copy files                  | `kubectl debug <pod>`       | `-- cp` as command        |
| Interactive shell           | `kubectl debug <pod>`       | `-it` or `--stdin --tty`  |

---

## Common Exam Traps

| Trap                         | Consequence                         | Fix                      |
| ---------------------------- | ----------------------------------- | ------------------------ |
| Forgetting `--target`        | Can't see other container processes | Always use `--target`    |
| No shell command             | Debug container exits               | Add `-- sh` or `-- bash` |
| Wrong namespace              | Pod not found                       | Add `-n <namespace>`     |
| Debugging control-plane node | May be restricted                   | Use worker nodes         |
| Exiting without checking     | Missed debugging                    | Investigate before exit  |

---

## Pro Tips for CKA

1. **`--target` is critical** – Without it, you can't see the main container's processes
2. **busybox is your friend** – Small, fast, common for debugging
3. **Node debugging uses chroot** – Need `chroot /host` to access node
4. **Debug pods are ephemeral** – Automatically cleaned up on exit
5. **Process namespace sharing** – Can see all containers' processes with `ps aux`
6. **Network namespace is shared** – Debug container uses same network as target
7. **Use netshoot for network issues** – `image: nicolaka/netshoot` has all tools

---

## Debug Container Lifecycle

```
1. Run kubectl debug command
       ↓
2. Ephemeral container created in target pod
       ↓
3. Debug container runs with shared namespaces
       ↓
4. User interacts with debug shell
       ↓
5. Exit shell
       ↓
6. Ephemeral container stops but remains in pod spec
```

## Troubleshooting Debug Sessions

**Debug container won't start:**

```bash
# Check pod status
kubectl get pods -n exercise-17
kubectl describe pod broken-app -n exercise-17
```

**Can't see target container processes:**

```bash
# Ensure --target flag is used
kubectl debug -n exercise-17 broken-app --image=busybox:1.36 --target=broken-app

# Check if process namespace is shared
ls -la /proc/1/root/
```

**Node debug pod fails:**

```bash
# Check node taints
kubectl describe node $NODE_NAME | grep -A5 Taints

# Use tolerations if needed
kubectl debug node/$NODE_NAME --image=busybox:1.36 -it -- \
  --overrides='{"spec":{"tolerations":[{"operator":"Exists"}]}}'
```
