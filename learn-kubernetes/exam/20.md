Implement Pod Security Standards (PSS) at the namespace level to enforce security policies. This exercise covers enforcing restricted, baseline, and restricted security contexts on pods.

## Context

Pod Security Standards replaced Pod Security Policies in Kubernetes 1.25+. They enforce security constraints at the namespace level through labels. The CKA tests your ability to:

- Apply PSS labels to namespaces
- Understand the three levels: restricted, baseline, and privileged
- Diagnose when pods violate security policies
- Use audit and warn modes for testing before enforcement

In Kubernetes 1.35, Pod Security Standards are part of the standard admission control process.

## Tasks

1. Create a namespace called `exercise-20`
2. Label it with Pod Security Standards at `restricted` level in `enforce` mode
3. Attempt to run a pod with a privileged container in `exercise-20`—it should be rejected
4. Create a second namespace `exercise-20-baseline` with `baseline` PSS level
5. Run a pod with `runAsNonRoot: true` in the baseline namespace—it should succeed
6. Run a pod with `privileged: true` in the baseline namespace—it should be rejected
7. Create a third namespace `exercise-20-audit` with `restricted` level but in `audit` mode
8. Run a privileged pod in audit mode—it should succeed but be logged as a violation
9. Check the audit annotations on the pod that ran in audit mode

## Understanding PSS Levels

| Level        | Description          | Key Restrictions                                  |
| ------------ | -------------------- | ------------------------------------------------- |
| `privileged` | No restrictions      | All pods allowed                                  |
| `baseline`   | Minimal restrictions | No privileged containers, host namespaces limited |
| `restricted` | Strong security      | `runAsNonRoot: true`, read-only root FS, seccomp  |

## 1. Create namespace exercise-20

```bash
kubectl create namespace exercise-20
```

---

## 2. Label namespace with restricted level in enforce mode

**Apply restricted PSS with enforce mode:**

```bash
kubectl label namespace exercise-20 \
  pod-security.kubernetes.io/enforce=restricted
```

**Verify label was applied:**

```bash
kubectl get namespace exercise-20 --show-labels
```

**Check the namespace's PSS configuration:**

```bash
kubectl describe namespace exercise-20 | grep -A2 "Labels"
```

**Optional – Add warn and audit modes for completeness:**

```bash
kubectl label namespace exercise-20 \
  pod-security.kubernetes.io/enforce=restricted \
  pod-security.kubernetes.io/warn=restricted \
  pod-security.kubernetes.io/audit=restricted
```

## 3. Attempt to run privileged pod – should be rejected

**Try to create a privileged pod:**

```bash
cat <<EOF | kubectl apply -f -
apiVersion: v1
kind: Pod
metadata:
  name: privileged-pod
  namespace: exercise-20
spec:
  containers:
  - name: nginx
    image: nginx:1.28
    securityContext:
      privileged: true
EOF
```

**Expected output:** Error like `FORBIDDEN` or `admission webhook denied`

**Verify pod was not created:**

```bash
kubectl get pods -n exercise-20
```

**Check the event (if any):**

```bash
kubectl get events -n exercise-20
```

**Try a pod without privileged flag (should work):**

```bash
cat <<EOF | kubectl apply -f -
apiVersion: v1
kind: Pod
metadata:
  name: good-pod
  namespace: exercise-20
spec:
  containers:
  - name: nginx
    image: nginx:1.28
EOF
```

**Clean up:**

```bash
kubectl delete pod good-pod -n exercise-20
```

## 5. Run pod with runAsNonRoot:true in baseline namespace – should succeed

```bash

  name: nonroot-pod
  namespace: exercise-20-baseline

  - name: nginx
    image: nginx:1.28

```

**Verify pod was created and is running:**

```bash

kubectl describe pod nonroot-pod -n exercise-20-baseline
```

**Check pod security context:**

```bash
kubectl get pod nonroot-pod -n exercise-20-baseline -o yaml | grep -A5 securityContext
```

## 6. Run privileged pod in baseline namespace – should be rejected

```bash
cat <<EOF | kubectl apply -f -
apiVersion: v1
kind: Pod
metadata:
  name: privileged-baseline
  namespace: exercise-20-baseline
spec:
  containers:
  - name: nginx
    image: nginx:1.28
    securityContext:
      privileged: true
EOF
```

**Expected output:** Rejected (baseline prohibits privileged containers)

**Verify pod was not created:**

```bash
kubectl get pods -n exercise-20-baseline | grep privileged-baseline
```

**Try a pod with allowed baseline settings (should work):**

```bash
cat <<EOF | kubectl apply -f -
apiVersion: v1
kind: Pod
metadata:
  name: baseline-allowed
  namespace: exercise-20-baseline
spec:
  containers:
  - name: nginx
    image: nginx:1.28
    securityContext:
      allowPrivilegeEscalation: false
      capabilities:
        drop: ["ALL"]
EOF
```

## PSS Modes Explained

| Mode      | Behavior                       | Use Case                   |
| --------- | ------------------------------ | -------------------------- |
| `enforce` | Rejects violating pods         | Production enforcement     |
| `audit`   | Logs violations, doesn't block | Testing before enforcement |
| `warn`    | Sends warning message          | Developer feedback         |

**Combining modes:**

```bash
kubectl label namespace my-namespace \
  pod-security.kubernetes.io/enforce=restricted \
  pod-security.kubernetes.io/audit=restricted \
  pod-security.kubernetes.io/warn=restricted
```

## PSS Level Comparison

| Feature                          | Privileged      | Baseline        | Restricted  |
| -------------------------------- | --------------- | --------------- | ----------- |
| `privileged: true`               | ✅ Allowed      | ❌ Blocked      | ❌ Blocked  |
| `hostPID/hostIPC`                | ✅ Allowed      | ❌ Blocked      | ❌ Blocked  |
| `hostNetwork`                    | ✅ Allowed      | ❌ Blocked      | ❌ Blocked  |
| `hostPort`                       | ✅ Allowed      | ⚠️ Limited      | ⚠️ Limited  |
| `allowPrivilegeEscalation: true` | ✅ Allowed      | ❌ Blocked      | ❌ Blocked  |
| `runAsNonRoot: false`            | ✅ Allowed      | ✅ Allowed      | ❌ Blocked  |
| `readOnlyRootFilesystem: false`  | ✅ Allowed      | ✅ Allowed      | ❌ Blocked  |
| `capabilities.drop: ["ALL"]`     | ❌ Not required | ❌ Not required | ✅ Required |

## Pod Security Standards with SecurityContext

### Restricted-compliant pod

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: restricted-compliant
spec:
  securityContext:
    runAsNonRoot: true
    runAsUser: 1000
    seccompProfile:
      type: RuntimeDefault
  containers:
    - name: app
      image: nginx:1.28
      securityContext:
        allowPrivilegeEscalation: false
        capabilities:
          drop: ["ALL"]
        readOnlyRootFilesystem: true
```

### Baseline-compliant pod

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: baseline-compliant
spec:
  containers:
    - name: app
      image: nginx:1.28
      securityContext:
        allowPrivilegeEscalation: false
        capabilities:
          drop: ["ALL"]
```

### Non-compliant pod (will be rejected by restricted)

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: non-compliant
spec:
  containers:
    - name: app
      image: nginx:1.28
      securityContext:
        privileged: true # Violates baseline and restricted
```

## Exam Critical Notes

| Label Key                            | Value Example                          | Effect                      |
| ------------------------------------ | -------------------------------------- | --------------------------- |
| `pod-security.kubernetes.io/enforce` | `restricted`, `baseline`, `privileged` | Blocks violations           |
| `pod-security.kubernetes.io/audit`   | `restricted`, `baseline`, `privileged` | Logs violations             |
| `pod-security.kubernetes.io/warn`    | `restricted`, `baseline`, `privileged` | Shows warnings              |
| Version suffix                       | `-v1.35`                               | Specific version (optional) |

---

## Common Exam Traps

| Trap                                  | Consequence                | Fix                                        |
| ------------------------------------- | -------------------------- | ------------------------------------------ |
| Wrong label key                       | PSS not enforced           | Use `pod-security.kubernetes.io/enforce`   |
| Typo in level name                    | No effect                  | Use `restricted`, `baseline`, `privileged` |
| Forgetting to label namespace         | No enforcement             | Always label after creation                |
| Expecting enforce to block audit mode | Audit only logs            | Audit mode doesn't block                   |
| No securityContext on pod             | Pod may violate restricted | Add required fields                        |

---

## Pro Tips for CKA

1. **Always label namespace first** – Before creating pods
2. **Test with dry-run** – `--dry-run=server -o yaml` shows admission errors
3. **Use audit mode for testing** – Test policies before enforcing
4. **Check pod annotations** – Shows which policies were violated
5. **System namespaces are exempt** – Don't enforce on kube-system
6. **Combine modes for feedback** – enforce + warn + audit
7. **PSS applies to all pods** – Including init containers and ephemeral

## Troubleshooting

**Pod rejected but should be allowed:**

```bash
# Check namespace labels
kubectl get ns <namespace> --show-labels

# Check pod's securityContext
kubectl get pod <pod> -o yaml --dry-run=client | grep -A10 securityContext
```

**No violations being reported:**

```bash
# Check if PSS labels are set
kubectl get ns <namespace> -o yaml | grep pod-security

# Verify pod violates policy
kubectl apply --dry-run=server -f pod.yaml
```

**Audit logs not showing violations:**

```bash
# Check audit mode label
kubectl get ns <namespace> -o yaml | grep audit

# Check pod annotations
kubectl get pod <pod> -o yaml | grep -i audit
```
