Configure Kubernetes Ingress resources for HTTP/HTTPS routing. CKA exam topics include classic Ingress alongside newer Gateway API. This exercise covers path-based routing, TLS termination, and IngressClass configuration.

## Context

Ingress provides external access to services inside a cluster. While Gateway API is the future direction, classic Ingress (networking.k8s.io/v1) appears on most CKA exams. You need to understand:

- How to expose services via Ingress
- Path-based and host-based routing
- TLS certificate setup
- Ingress controller requirements

This differs from Exercise 15 (Gateway API) because it tests the older API that's still in widespread production use.

## Tasks

1. Create a namespace called `exercise-19`
2. Create two Deployments:
   - `web-app` with image `nginx:1.28` and 2 replicas, serving on port 80
   - `api-app` with image `nginx:1.28` and 2 replicas, serving on port 8080
3. Expose `web-app` Deployment with a ClusterIP service named `web-service` on port 80
4. Expose `api-app` Deployment with a ClusterIP service named `api-service` on port 8080
5. Create an Ingress resource named `app-ingress` that routes:
   - `/` traffic to `web-service:80`
   - `/api` traffic to `api-service:8080`
   - Default backend (no matching path) should point to `web-service`
6. Verify the Ingress resource was created and has an address assigned
7. Test path-based routing by describing the Ingress (check rules)

## 2. Create two Deployments

### Create web-app Deployment (nginx:1.28, 2 replicas, port 80)

```bash
cat <<EOF | kubectl apply -f -
apiVersion: apps/v1
kind: Deployment
metadata:
  name: web-app
  namespace: exercise-19
spec:
  replicas: 2
  selector:
    matchLabels:
      app: web-app
  template:
    metadata:
      labels:
        app: web-app
    spec:
      containers:
      - name: nginx
        image: nginx:1.28
        ports:
        - containerPort: 80
EOF
```

## 5. Create Ingress resource with path-based routing

```bash
cat <<EOF | kubectl apply -f -
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: app-ingress
  namespace: exercise-19
  annotations:
    # Add ingress class annotation if needed (depends on controller)
    kubernetes.io/ingress.class: nginx
spec:
  defaultBackend:
    service:
      name: web-service
      port:
        number: 80
  rules:
  - http:
      paths:
      - path: /api
        pathType: Prefix
        backend:
          service:
            name: api-service
            port:
              number: 8080
      - path: /
        pathType: Prefix
        backend:
          service:
            name: web-service
            port:
              number: 80
EOF
```

**Alternative – using spec.ingressClassName (v1.19+):**

```bash
cat <<EOF | kubectl apply -f -
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: app-ingress
  namespace: exercise-19
spec:
  ingressClassName: nginx
  defaultBackend:
    service:
      name: web-service
      port:
        number: 80
  rules:
  - http:
      paths:
      - path: /api
        pathType: Prefix
        backend:
          service:
            name: api-service
            port:
              number: 8080
      - path: /
        pathType: Prefix
        backend:
          service:
            name: web-service
            port:
              number: 80
EOF
```

## 7. Test path-based routing by describing Ingress

**Describe Ingress to see rules:**

```bash
kubectl describe ingress app-ingress -n exercise-19
```

**Look for the rules section:**

```bash
kubectl describe ingress app-ingress -n exercise-19 | grep -A20 "Rules:"
```

**Expected output shows:**

```
Rules:
  Host        Path  Backends
  ----        ----  --------
  *
              /api     api-service:8080 (<IPs>)
              /        web-service:80 (<IPs>)
```

**Get Ingress address for testing:**

```bash
INGRESS_IP=$(kubectl get ingress app-ingress -n exercise-19 -o jsonpath='{.status.loadBalancer.ingress[0].ip}')
echo $INGRESS_IP
```

**If IP is assigned, test endpoints (optional):**

```bash
# Test root path -> web-service
curl -H "Host: example.com" http://$INGRESS_IP/

# Test /api path -> api-service
curl -H "Host: example.com" http://$INGRESS_IP/api
```

## Advanced Ingress Examples for Exam

### Host-based routing

```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: host-ingress
  namespace: exercise-19
spec:
  ingressClassName: nginx
  rules:
    - host: web.example.com
      http:
        paths:
          - path: /
            pathType: Prefix
            backend:
              service:
                name: web-service
                port:
                  number: 80
    - host: api.example.com
      http:
        paths:
          - path: /
            pathType: Prefix
            backend:
              service:
                name: api-service
                port:
                  number: 8080
```

### TLS termination

```bash
# Create TLS secret
kubectl create secret tls tls-secret -n exercise-19 \
  --cert=path/to/tls.crt \
  --key=path/to/tls.key
```

```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: tls-ingress
  namespace: exercise-19
spec:
  ingressClassName: nginx
  tls:
    - hosts:
        - secure.example.com
      secretName: tls-secret
  rules:
    - host: secure.example.com
      http:
        paths:
          - path: /
            pathType: Prefix
            backend:
              service:
                name: web-service
                port:
                  number: 80
```

### Multiple path types

```yaml
rules:
  - http:
      paths:
        - path: /exact-match
          pathType: Exact
          backend:
            service:
              name: exact-service
              port:
                number: 80
        - path: /images/*
          pathType: ImplementationSpecific
          backend:
            service:
              name: image-service
              port:
                number: 80
        - path: /api
          pathType: Prefix
          backend:
            service:
              name: api-service
              port:
                number: 8080
```

### Annotations for custom behavior

```yaml
metadata:
  annotations:
    kubernetes.io/ingress.class: nginx
    nginx.ingress.kubernetes.io/rewrite-target: /
    nginx.ingress.kubernetes.io/ssl-redirect: "true"
    nginx.ingress.kubernetes.io/proxy-body-size: "10m"
    nginx.ingress.kubernetes.io/rate-limit: "10r/s"
```

## PathType Comparison

| PathType                 | Behavior                      | Example                                        |
| ------------------------ | ----------------------------- | ---------------------------------------------- |
| `Exact`                  | Exact match only              | `/exact` matches only `/exact`                 |
| `Prefix`                 | All paths starting with value | `/api` matches `/api`, `/api/v1`, `/api/users` |
| `ImplementationSpecific` | Controller dependent          | Often treated as prefix                        |

## IngressClass Configuration

### View available IngressClasses

```bash
kubectl get ingressclass
```

### Create custom IngressClass

```yaml
apiVersion: networking.k8s.io/v1
kind: IngressClass
metadata:
  name: custom-ingress
spec:
  controller: k8s.io/ingress-nginx
  parameters:
    apiGroup: k8s.example.com
    kind: IngressParameters
    name: custom-params
```

### Reference IngressClass in Ingress

```yaml
spec:
  ingressClassName: custom-ingress
```

## Exam Critical Notes

| Component          | Purpose                 | Key Fields                                  |
| ------------------ | ----------------------- | ------------------------------------------- |
| Ingress Controller | Processes Ingress rules | Must be installed (nginx, traefik, etc.)    |
| Ingress resource   | Routing configuration   | `rules`, `paths`, `backend`                 |
| pathType           | Path matching behavior  | `Prefix`, `Exact`, `ImplementationSpecific` |
| defaultBackend     | Catch-all route         | When no rules match                         |
| IngressClass       | Controller selection    | `ingressClassName` field                    |
| TLS secret         | Certificate storage     | `tls.hosts`, `tls.secretName`               |

---

## Common Exam Traps

| Trap                  | Consequence                    | Fix                                  |
| --------------------- | ------------------------------ | ------------------------------------ |
| No Ingress Controller | Ingress address never assigned | Check kube-system for controller     |
| Wrong service port    | Backend returns 503            | Match service port with targetPort   |
| Missing pathType      | Ingress creation fails         | Always specify `pathType`            |
| Wrong namespace       | Ingress can't find service     | Must be same namespace as service    |
| No defaultBackend     | 404 for unmatched paths        | Set defaultBackend or catch-all rule |
| IngressClass mismatch | Controller ignores Ingress     | Match ingressClassName or annotation |

## Ingress vs Gateway API Comparison

| Feature           | Ingress (Classic) | Gateway API               |
| ----------------- | ----------------- | ------------------------- |
| API stability     | GA, stable        | GA (v1.35+)               |
| Path matching     | Basic             | Advanced (regex, headers) |
| Cross-namespace   | Limited           | Full support              |
| TLS configuration | Simple            | Granular                  |
| Exam frequency    | High              | Medium                    |

## Pro Tips for CKA

1. **Check Ingress Controller first** – No controller = no routing
2. **Use `kubectl describe ingress`** – Shows rules and backends
3. **Wait for address assignment** – May take 30-60 seconds
4. **pathType is required** – Exam will deduct points if missing
5. **Service must be in same namespace** – Ingress can't route across namespaces
6. **Test with `curl -H "Host: ..."`** – For host-based rules
7. **Default backend is optional** – But exam often asks for it

## Troubleshooting

**Ingress address stuck empty:**

```bash
# Check Ingress Controller pods
kubectl get pods -n ingress-nginx

# Check Ingress Controller service type
kubectl get svc -n ingress-nginx
# Should be LoadBalancer or NodePort
```

**Backend returning 503:**

```bash
# Verify service endpoints exist
kubectl get endpoints web-service -n exercise-19
kubectl get endpoints api-service -n exercise-19

# Check pod readiness
kubectl get pods -n exercise-19
```

**Path not matching:**

```bash
# Check pathType configuration
kubectl describe ingress app-ingress -n exercise-19

# Test with exact path
curl http://$INGRESS_IP/api/
curl http://$INGRESS_IP/api/test
```

**IngressClass issues:**

```bash
# Check default IngressClass
kubectl get ingressclass

# Check if annotation works
kubectl get ingress app-ingress -n exercise-19 -o yaml | grep ingress.class
```
