## CKA Practice Exam - Set 1

### Question 1: Pod Creation with Resource Constraints

**Task:**
Create a pod named `resource-checker` in the `default` namespace that:

- Uses the `nginx:alpine` image
- Requests **128Mi** of memory and **250m** CPU
- Limits memory to **256Mi** and CPU to **500m**
- The container should expose port 80

### Question 2: Service Configuration

**Task:**
Expose the pod you created in Question 1 internally within the cluster:

- Create a ClusterIP service named `nginx-service`
- The service should target port 80 on the pod
- The service port should be 8080

### Question 3: ConfigMap and Volume Mount

**Task:**
Create a ConfigMap named `app-config` with the following data:

- `APP_ENV=production`
- `LOG_LEVEL=debug`

Then create a pod named `config-consumer` that:

- Uses the `busybox` image with command: `sleep 3600`
- Mounts the ConfigMap as a volume at `/etc/config`
- Verify the files are accessible within the pod

### Question 4: Multi-Container Pod with Sidecar Pattern

**Task:**
Create a pod named `sidecar-demo` with two containers:

1. **Main container**: `nginx` that serves web content
2. **Sidecar container**: `busybox` that runs `while true; do wget -q -O- http://localhost:80; sleep 5; done` (this continuously requests the nginx page)

- Both containers should share the same network namespace (automatic in pods)
- Add appropriate labels: `app=web` and `component=frontend`

### Question 5: Pod Troubleshooting Scenario

**Task:**
Create a pod named `broken-pod` with the following (intentionally broken) configuration:

- Image: `nginx:alpine`
- Command: `nginx -g "daemon off; bad_command"`
- Add a liveness probe that checks port 80

Then:

1. Create this pod
2. Observe its status
3. **Fix it** by correcting the command
4. Ensure the pod stays in `Running` state

1. **Setup your environment** using Minikube, kind, or Killercoda

3. **Verify your work** by checking pod status, service endpoints, etc.
4. **Document commands** you use - this helps build muscle memory
5. **Time yourself** - aim for 3-5 minutes per question

## Tips for These Questions

1. **Use imperative commands** where possible to save time:

   ```bash
   kubectl run nginx --image=nginx --dry-run=client -o yaml > pod.yaml
   ```

2. **Practice with `kubectl explain`** to understand resource fields:

   ```bash
   kubectl explain pod.spec.containers
   ```

3. **Always verify your work**:

   ```bash
   kubectl get pods -w
   kubectl describe pod <pod-name>
   kubectl logs <pod-name>
   ```

4. **Use the documentation** - practice finding examples quickly on kubernetes.io/docs
