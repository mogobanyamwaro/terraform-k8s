Debug and fix a broken control plane where API server points to wrong etcd endpoint. Tests troubleshooting methodology and static pod modification.

## Tasks

1. Cluster is broken: API server won't start
2. Check kube-apiserver pod logs
3. Find the error: incorrect etcd endpoint IP or port
4. SSH into control plane node
5. Edit `/etc/kubernetes/manifests/kube-apiserver.yaml`
6. Correct the etcd endpoint in `--etcd-servers=` flag
7. Verify IP/port matches `/etc/kubernetes/manifests/etcd.yaml`
8. Save and wait for API server to restart
9. Verify cluster is healthy:
   - `k get nodes` works
   - `k get pods -A` works
   - API server is Running

## Key Learning

- Static pods in `/etc/kubernetes/manifests/` auto-restart on file changes
- API server cannot start without etcd connection
- etcd endpoint must be exact: `https://127.0.0.1:2379` or `https://<etcd-ip>:2379`
- Troubleshooting: check pod logs first, then manifest
- Exam tests understanding of control plane components

## Understanding the Control Plane Issue

| Component      | Static Pod Manifest                             | Typical etcd Endpoint       |
| -------------- | ----------------------------------------------- | --------------------------- |
| kube-apiserver | `/etc/kubernetes/manifests/kube-apiserver.yaml` | `https://127.0.0.1:2379`    |
| etcd           | `/etc/kubernetes/manifests/etcd.yaml`           | Listens on `127.0.0.1:2379` |

**Common errors:**

- Wrong IP address in `--etcd-servers`
- Wrong port number
- HTTP vs HTTPS mismatch
- Missing certificate paths

## 1. Cluster is broken: API server won't start

**First, verify the cluster is unhealthy:**

```bash
kubectl get nodes
```

**Expected:** Error like `Unable to connect to the server`

**Check API server pod status:**

```bash
kubectl get pods -n kube-system | grep kube-apiserver
```

**If kubectl doesn't work, check with crictl on control plane:**

```bash
sudo crictl ps -a | grep apiserver
```

---

## 2. Check kube-apiserver pod logs

**If kubectl works partially:**

```bash
kubectl logs -n kube-system kube-apiserver-<node-name> --tail=50
```

**If kubectl is completely broken, use crictl on control plane node:**

```bash
# SSH to control plane node first
ssh control-plane

# Find the apiserver container ID
sudo crictl ps -a | grep kube-apiserver

# Get logs
sudo crictl logs <container-id> --tail=100
```

**Alternative – check container logs via Docker (if using Docker runtime):**

```bash
sudo docker ps -a | grep apiserver
sudo docker logs <container-id> --tail=100
```

**Look for etcd connection errors:**

```
etcd: connection error: dial tcp 10.0.0.100:2379: i/o timeout
failed to connect to etcd at https://wrong-ip:2379
etcd server refused connection
```

---

## 3. Find the error: incorrect etcd endpoint IP or port

**From the logs, identify the wrong etcd endpoint:**

```bash
sudo crictl logs <apiserver-container-id> 2>&1 | grep -i etcd
```

**Expected error pattern:**

```
--etcd-servers=https://192.168.1.100:2379 (wrong IP)
--etcd-servers=https://127.0.0.1:4001 (wrong port)
```

---

## 4. SSH into control plane node

```bash
ssh <control-plane-node-name>
```

---

## 5. Edit kube-apiserver manifest

**Open the manifest file:**

```bash
sudo vi /etc/kubernetes/manifests/kube-apiserver.yaml
```

**Find the `--etcd-servers` line:**

```bash
sudo grep -n "etcd-servers" /etc/kubernetes/manifests/kube-apiserver.yaml
```

**Example of incorrect configuration:**

```yaml
spec:
  containers:
    - command:
        - kube-apiserver
        - --etcd-servers=https://10.0.0.100:2379 # WRONG IP
```

---

## 6. Correct the etcd endpoint to match etcd.yaml

**First, check the correct etcd endpoint from etcd manifest:**

```bash
sudo grep -A5 "listen-client-urls" /etc/kubernetes/manifests/etcd.yaml
```

**Expected output:**

```yaml
- --listen-client-urls=https://127.0.0.1:2379,https://<node-ip>:2379
- --advertise-client-urls=https://127.0.0.1:2379
```

**The API server should connect to `https://127.0.0.1:2379` (local) or the same IP/port as advertise-client-urls.**

**Edit the API server manifest:**

```bash
sudo vi /etc/kubernetes/manifests/kube-apiserver.yaml
```

**Change the `--etcd-servers` line to:**

```yaml
- --etcd-servers=https://127.0.0.1:2379
```

**If your cluster uses external etcd, use the correct IP:**

```yaml
- --etcd-servers=https://<correct-etcd-ip>:2379
```

**Also verify etcd certificates are correct (if using HTTPS):**

```yaml
- --etcd-cafile=/etc/kubernetes/pki/etcd/ca.crt
- --etcd-certfile=/etc/kubernetes/pki/apiserver-etcd-client.crt
- --etcd-keyfile=/etc/kubernetes/pki/apiserver-etcd-client.key
```

---

## 7. Verify IP/port matches etcd.yaml

**Check etcd listening ports:**

```bash
sudo netstat -tlnp | grep 2379
# or
sudo ss -tlnp | grep 2379
```

**Verify etcd is listening on the correct interface:**

```bash
sudo grep -E "listen-client-urls|advertise-client-urls" /etc/kubernetes/manifests/etcd.yaml
```

**Check etcd container is running:**

```bash
sudo crictl ps | grep etcd
```

**If etcd is not running, check its logs:**

```bash
sudo crictl logs $(sudo crictl ps -a | grep etcd | grep -v apiserver | awk '{print $1}')
```

---

## 8. Save and wait for API server to restart

**The API server static pod will automatically restart** (kubelet watches `/etc/kubernetes/manifests/`).

**Watch the restart:**

```bash
sudo crictl ps -a --watch | grep apiserver
```

**Alternative – check pod status:**

```bash
kubectl get pods -n kube-system --watch 2>/dev/null || echo "Waiting for kubectl to work..."
```

**Wait 30-60 seconds for the API server to come back up.**

---

## 9. Verify cluster is healthy

**Test kubectl commands:**

```bash
kubectl get nodes
```

**Expected:** All nodes show `Ready`

**Get pods across all namespaces:**

```bash
kubectl get pods -A
```

**Check API server pod is Running:**

```bash
kubectl get pods -n kube-system | grep kube-apiserver
```

**Expected:** `kube-apiserver-<node>   1/1   Running`

**Check component statuses:**

```bash
kubectl get componentstatuses
# or
kubectl get cs
```

**Verify etcd endpoint is correct:**

```bash
kubectl get pod -n kube-system kube-apiserver-<node> -o yaml | grep etcd-servers
```

**Check cluster health:**

```bash
kubectl cluster-info
```

## Common Errors and Fixes

| Error in Logs                                     | Cause                          | Fix                        |
| ------------------------------------------------- | ------------------------------ | -------------------------- |
| `dial tcp 10.0.0.100:2379: i/o timeout`           | Wrong IP address               | Change to `127.0.0.1:2379` |
| `connection refused`                              | etcd not running or wrong port | Check etcd pod, fix port   |
| `x509: certificate signed by unknown authority`   | Certificate mismatch           | Verify etcd cert paths     |
| `http: server gave HTTP response to HTTPS client` | Using HTTP instead of HTTPS    | Change to `https://`       |
| `no such host`                                    | Hostname not resolvable        | Use IP address instead     |

## Pro Tips for CKA

1. **Static pods auto-restart** – No need to restart kubelet after editing manifests
2. **Always check etcd first** – If API server can't connect to etcd, check etcd pod
3. **Use localhost for single-node control plane** – `https://127.0.0.1:2379`
4. **Multi-node etcd cluster** – May have multiple endpoints: `--etcd-servers=https://etcd-1:2379,https://etcd-2:2379,https://etcd-3:2379`
5. **Certificate paths matter** – If certs are wrong, API server won't start
6. **kubectl may be broken** – Use `crictl` or `docker` for debugging
7. **Wait 30-60 seconds** – Kubelet doesn't restart static pods instantly

## Complete Fix Script (Exam Reference)

```bash
# On control plane node
ssh control-plane

# Check etcd endpoint from etcd manifest
ETCD_URL=$(sudo grep advertise-client-urls /etc/kubernetes/manifests/etcd.yaml | grep -oP 'https?://[^,]+')
echo "etcd endpoint: $ETCD_URL"

# Backup original manifest
sudo cp /etc/kubernetes/manifests/kube-apiserver.yaml /tmp/kube-apiserver.yaml.backup

# Fix etcd-servers in API server manifest
sudo sed -i 's|--etcd-servers=https://[^ ]*|--etcd-servers=https://127.0.0.1:2379|' /etc/kubernetes/manifests/kube-apiserver.yaml

# Verify the fix
sudo grep etcd-servers /etc/kubernetes/manifests/kube-apiserver.yaml

# Wait for restart
sleep 45

# Test cluster
kubectl get nodes
```
