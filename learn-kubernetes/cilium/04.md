# 04. Datapath Models

**Domain:** Architecture (20%)

## Concept Refresher

Two main ways Cilium moves packets between nodes:

### Tunnel (overlay) — typical default

- Encapsulate pod packets in **VXLAN** (UDP **8472**) or **Geneve** (UDP **6081**)
- Underlay only needs **node-to-node IP connectivity**
- Works even if the physical network cannot route pod CIDRs
- Cost: encapsulation overhead, MTU considerations

### Native routing (direct routing)

- Pod IPs are **routed** on the underlay like any other IP
- Requires the network (or **BGP**, cloud VPC routes) to know pod CIDRs
- Better performance, easier to see pod IPs on the wire
- Used with many cloud ENI setups and BGP-enabled metal

```text
Tunnel:   podA -> VXLAN -> nodeB -> podB
Native:   podA -> route to podCIDR-of-B -> nodeB -> podB
```

### Host routing / extra BPF

Modern Cilium can use **eBPF host routing** so even overlay setups skip iptables in the host namespace. Exam: “datapath is eBPF”; overlay vs native is the *routing model*, not a return to iptables.

### Encryption (datapath-adjacent)

Transparent encryption: **WireGuard** or **IPsec** between nodes (service mesh domain too). You cannot enable both. Encryption is orthogonal to VXLAN vs native, but native + WireGuard is a common “secure without overlay” story.

### IPv4/IPv6

Datapath supports both. Dual-stack needs pools and Kubernetes dual-stack Services.

## Exam tips

- **Cannot route pod CIDRs → tunnel.** **Can route / BGP / ENI → native.**
- VXLAN 8472 UDP, Geneve 6081 UDP — worth memorising.
- Encryption ≠ datapath choice, but both are “how packets look on the wire.”
