# 13. Gateway API vs Ingress

**Domain:** Service Mesh (16%)

## Concept Refresher

**Gateway API** (`gateway.networking.k8s.io`) is the successor model:

| Ingress | Gateway API |
| --- | --- |
| One object mixes lb + routes | **Gateway** (listeners/infra) vs **HTTPRoute/GRPCRoute/TCPRoute** (routing) |
| HTTP(S) focused | Explicit protocol per listener (HTTP, HTTPS, TLS, TCP, UDP) |
| Annotations for advanced stuff | Standard fields + policy attachments |
| Weak multi-tenancy | `allowedRoutes`, ReferenceGrant, roles (infra vs app) |
| `ingressClassName` | `gatewayClassName: cilium` |

Cilium implements Gateway API (`Cilium GatewayClass`). Same Envoy datapath family as Ingress.

### Benefits the exam wants

- **Role separation:** cluster operator owns Gateway; app teams own HTTPRoutes
- **Portability:** fewer nginx-style annotations
- **Richer routing:** header/query matching, weights, timeouts as first-class (implementation-dependent)
- **TLS:** certificate refs on listeners, not only Ingress TLS block
- **Extension** without stuffing annotations

### Cilium-specific

```yaml
spec:
  gatewayClassName: cilium
```

LoadBalancer IP via same mechanisms as Ingress Service.

## Hands-on

Install Gateway API CRDs if needed, enable `gatewayAPI.enabled=true`, apply Gateway + HTTPRoute to httpbin.

## Exam tips

- **Class `cilium`.** **parentRefs** glue routes to gateways.
- Ingress is not deprecated on the exam — know **why Gateway API is better**, not only syntax.
