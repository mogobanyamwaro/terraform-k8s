# 18. Querying and Modifying Cilium Configuration

**Domain:** Installation and Configuration (10%)

## Concept Refresher

Runtime config lives in:

- Helm values / `cilium-config` **ConfigMap** in `kube-system`
- Agent flags derived from that ConfigMap
- Some dynamic settings via CLI

```bash
cilium config view
cilium config get <key>
cilium config set <key> <value>
```

Not every key is hot-reloadable. Many changes **restart agent pods**. Treat `config set` as an install-time sibling, not kubectl edit of random Deployments.

### Common keys (recognise names)

| Key | Meaning |
| --- | --- |
| `kube-proxy-replacement` | eBPF Services |
| `enable-ipv4` / `enable-ipv6` | Families |
| `tunnel-protocol` / routing mode | vxlan/geneve/native |
| `enable-l7-proxy` | Envoy L7 |
| `enable-hubble` | Hubble |
| `cluster-name` / `cluster-id` | Mesh |
| `ipam` | cluster-pool, kubernetes, eni, … |
| `enable-wireguard` / encryption | transit encryption |
| `enable-bgp-control-plane` | BGP |

Exact hyphenation varies by version; exam tests **concept of ConfigMap + cilium config**, not memorising 200 keys.

### kubectl approach

```bash
kubectl -n kube-system get cm cilium-config -o yaml
kubectl -n kube-system exec ds/cilium -- cilium-dbg status
kubectl -n kube-system exec ds/cilium -- cilium-dbg config
```

Inside the agent, `cilium-dbg` is the older `cilium` binary name in recent images.

### Upgrade

CLI/Helm upgrade with the same chart values. Read release notes for kube-proxy replacement and datapath changes. CCA: know upgrade is Helm/CLI, not `kubectl set image` on a random tag without values.

## Hands-on

```bash
cilium config view | head -50
kubectl -n kube-system get cm cilium-config -o yaml | head -80
```

Do not `config set` on a shared lab without knowing the restart impact.

## Exam tips

- ConfigMap **`cilium-config`**. CLI **`cilium config view|set`**.
- **cluster-id** and **ipam** and **kube-proxy-replacement** are the keys worth memorising.
