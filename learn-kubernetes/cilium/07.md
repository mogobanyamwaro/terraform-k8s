# 07. Policy Enforcement Modes

**Domain:** Network Policy (18%)

## Concept Refresher

Cilium has a cluster (or per-endpoint) **enforcement mode**:

| Mode | Behaviour |
| --- | --- |
| **default** | If **no policy selects** the endpoint, **allow all**. If **any** policy selects it, **default deny** for that direction (ingress and/or egress depending on what exists) |
| **always** | Always enforce; endpoints are default-deny even without a selecting policy |
| **never** | Never enforce NetworkPolicy / CNP (audit-only / break-glass). Traffic allowed |

This is the same philosophy as Kubernetes NetworkPolicy: **unselected = unrestricted**; **selected = isolated**.

### Directions

A CNP can have `ingress`, `egress`, or both. Selecting an endpoint with **only ingress** rules does not automatically lock **egress** (in default mode). Isolated in one direction only.

### Default-deny recipe

To lock a workload:

1. Select it with `endpointSelector`
2. Add the allow rules you need
3. Everything else in that direction is denied

Empty `ingress: []` (or ingress present with no from/to that match) isolates ingress.

### Audit / Hubble

Denied packets appear in Hubble with a **dropped** verdict and reason (policy). Enforcement `never` is for testing, not production security.

## Hands-on

Apply a CNP that selects `httpbin` with no ingress from `client`. Curl should fail. Hubble:

```bash
hubble observe --verdict DROPPED --since 2m
```

## Exam tips

- **Unselected = allow** (default mode). That is the #1 policy trick question.
- Ingress policy does not automatically lock egress.
- `never` is not “observe only Hubble”; Hubble can observe in any mode. `never` is about **enforcement**.
