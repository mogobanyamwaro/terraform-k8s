# 24. BGP and Connecting to External Networks

**Domain:** BGP and External Networking (6%)

## Concept Refresher

**BGP** lets Cilium **advertise** routes to ToR switches / routers:

- **Pod CIDRs** (native routing without static routes on every switch)
- **Service LoadBalancer IPs** (LB-IPAM + BGP instead of cloud NLB)

Cilium **BGP Control Plane** uses CRDs such as:

- `CiliumBGPClusterConfig` / `CiliumBGPPeerConfig` / `CiliumBGPAdvertisement` (names evolved; exam: “Cilium speaks BGP to peers”)

Older: MetalLB in BGP mode next to Cilium. Modern: Cilium-native BGP.

### LB-IPAM

Cilium can allocate LoadBalancer IPs from pools (`CiliumLoadBalancerIPPool`) then advertise them via BGP. `service.spec.type: LoadBalancer` gets an IP **without a cloud provider**.

### Maglev + BGP

External clients hit a LB IP anycast/advertised to multiple nodes; Maglev keeps flows consistent.

### Other external options

| Option | Use |
| --- | --- |
| Cloud ENI / VPC routing | Native pod IPs in AWS/Azure/GCP |
| Tunnel + masquerade | Simple, pods not on WAN |
| Ingress / Gateway | HTTP(S) north-south only |
| NodePort | Ugly but works |
| VPN / WireGuard to DC | Encrypted underlay |

### Peering requirements

- ASN, peer IP, hold timers
- Routers must accept the prefixes
- Avoid overlapping advertisements
- `externalTrafficPolicy: Local` vs Cluster — locality / SNAT behaviour for LB

## Hands-on

On kind you will not peer BGP. Skim CRD names:

```bash
kubectl api-resources | grep -i bgp || true
kubectl api-resources | grep -i loadbalancerip || true
```

## Exam tips

- **BGP = advertise pod CIDR / LB VIP to routers.**
- **Masquerade vs advertise** is the whole egress story.
- Metal: **LB-IPAM + BGP**. Cloud: **ENI/VPC**. Overlay: **tunnel + SNAT**.
