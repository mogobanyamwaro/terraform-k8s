# 05. kube-proxy Replacement and Load Balancing

**Domain:** Architecture (20%)

## Concept Refresher

kube-proxy programs **iptables or IPVS** so ClusterIP / NodePort / ExternalIP work. Cilium can **replace kube-proxy** entirely with **eBPF**.

```text
kubeProxyReplacement=true
```

Then:

- ClusterIP is handled by eBPF (socket LB and/or DNAT in kernel)
- NodePort can use **XDP** or TC eBPF for high performance
- Connection tracking in eBPF maps
- **Maglev** consistent hashing for better load spreading and failover

### NodePort / ExternalIP modes

| Mode | Behaviour |
| --- | --- |
| **SNAT** | Reply goes back via the node that received the packet |
| **DSR** (Direct Server Return) | Backend replies **directly** to the client; less node hairpin |
| **Hybrid** | Mix (e.g. DSR for TCP, SNAT for UDP) depending on version/config |

DSR needs the network to accept backends answering with the service IP (or uses IPIP/Geneve DSR variants). Exam: DSR = backend responds to client; SNAT = node NATs.

### Socket-level LB

Cilium can translate ClusterIP at `connect()` in the socket layer so east-west never hits netfilter. Faster, skips conntrack in some paths.

### When you still need kube-proxy

Rare: unsupported kernel, partial feature gaps. CCA expects **replacement is the modern Cilium default recommendation** when the kernel allows it.

### Maglev

Deterministic backend selection from a lookup table. Helps consistent hashing for NodePort/LoadBalancer across nodes.

## Exam tips

- Replacement = **eBPF Services**. Operator does not sit in the packet path.
- **DSR** vs **SNAT** is a favourite comparison.
- XDP = earliest, fastest hook for north-south LB.
