# 16. Hubble CLI, UI, and L7 Visibility

**Domain:** Network Observability (10%)

## Concept Refresher

### CLI

```bash
hubble status
hubble observe
hubble observe --from-pod shop/client --to-pod shop/httpbin
hubble observe --verdict DROPPED
hubble observe --protocol http
hubble observe --http-status 500
hubble observe --fqdn '*.github.com'
hubble observe -o json
```

`cilium hubble port-forward` points the CLI at Relay.

### UI

Service map, namespace filter, flow table. Good for demos; exam still expects CLI verbs: **observe**, filters, verdicts.

### L7 visibility

L3/L4 flows exist whenever Hubble is on. **HTTP method/url** need L7 parsing:

- L7 NetworkPolicy on that port, or
- Extra visibility policy / annotation allowing all L7 but tracing it, or
- Mesh/Ingress Envoy already parsing HTTP

If you only allow TCP/80 in eBPF, Hubble shows TCP, not `/get`.

DNS visibility similar: DNS proxy / DNS policy.
