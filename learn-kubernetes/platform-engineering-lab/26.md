# 26. Security Scanning in the Pipeline

**Domain:** Security (15%) — scan in CD/CI

## Question

Extend Tekton in `cnpe-26`: after build, a Task `scan` that runs `trivy image --exit-code 1 --severity CRITICAL <image>` **or** a Kyverno/conftest step on the rendered manifests. Pipeline must **fail** on critical vulns.

If Trivy is not installed, a Task that runs `echo scan` and exits 1 when ConfigMap `fail-scan=true` is a last resort — the real exam will have the scanner in Quick Reference.

## Answer

```yaml
apiVersion: tekton.dev/v1
kind: Task
metadata: {name: trivy-scan, namespace: cnpe-26}
spec:
  params:
  - name: image
    type: string
  steps:
  - name: scan
    image: aquasec/trivy:latest   # pin in real life; exam may pre-load
    script: |
      #!/bin/sh
      trivy image --exit-code 1 --severity CRITICAL $(params.image)
---
# Pipeline: build then scan with runAfter
```

GitOps: Argo CD / Flux does not scan by itself — scanning is **CI**. A Kyverno policy `verifyImages` / `cosign` is cluster-side if the task asks admission verify.

## Verify

```bash
kubectl -n cnpe-26 get pipelinerun
# failed run if the image is critically vulnerable or the task is wired
```

## Exam tips

- `--exit-code 1` is what **fails the pipeline**.
- Pin scanner image if the cluster has a private copy.
- Cluster verifyImages ≠ Tekton scan; do both if asked.
