# 22. Secure Service Communication

**Domain:** Security (15%)

## Question

In `cnpe-22`, `frontend` must talk to `backend` on 8080. Everyone else denied.

**Path A — NetworkPolicy** (always available): default deny + allow frontend→backend TCP 8080 + DNS.

**Path B — Mesh mTLS** if Istio/Linkerd is in the task: PeerAuthentication `STRICT` in the namespace and AuthorizationPolicy allow `frontend` SA to `backend`.

## Answer (NetworkPolicy)

Same pattern as `01.md` with ports 8080.

**Istio (if asked):**

```yaml
apiVersion: security.istio.io/v1
kind: PeerAuthentication
metadata: {name: default, namespace: cnpe-22}
spec:
  mtls: {mode: STRICT}
---
apiVersion: security.istio.io/v1
kind: AuthorizationPolicy
metadata: {name: backend-allow, namespace: cnpe-22}
spec:
  selector: {matchLabels: {app: backend}}
  action: ALLOW
  rules:
  - from:
    - source:
        principals: ["cluster.local/ns/cnpe-22/sa/frontend"]
    to:
    - operation:
        ports: ["8080"]
```

Use the API version in Quick Reference (`v1` vs `v1beta1`). Linkerd: `linkerd inject` + `Server`/`ServerAuthorization` if those CRs exist.

## Verify

```bash
kubectl -n cnpe-22 get networkpolicy,peerauthentication,authorizationpolicy
```

## Exam tips

- Don’t configure Istio unless the task names it. NetworkPolicy solves “secure comms” on CNI.
- Mesh STRICT without ALLOW policy **blackholes** traffic.
