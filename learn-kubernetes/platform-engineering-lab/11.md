# 11. Design a Platform CRD

**Domain:** Platform APIs (25%)

## Question

Create CRD `workspaces.platform.example.com`:

- Namespaced
- Kind `Workspace`
- Versions: `v1` served and storage
- Schema: spec.owner (string, required), spec.size (string enum `small`|`medium`), status.namespace (string)
- ShortNames: `ws`

Then create Workspace `team-a` in `cnpe-11` with owner `alice@example.com` size `small`.

## Answer

```bash
kubectl create namespace cnpe-11
```

```yaml
apiVersion: apiextensions.k8s.io/v1
kind: CustomResourceDefinition
metadata:
  name: workspaces.platform.example.com
spec:
  group: platform.example.com
  names:
    kind: Workspace
    listKind: WorkspaceList
    plural: workspaces
    singular: workspace
    shortNames: [ws]
  scope: Namespaced
  versions:
  - name: v1
    served: true
    storage: true
    schema:
      openAPIV3Schema:
        type: object
        properties:
          spec:
            type: object
            required: [owner, size]
            properties:
              owner: {type: string}
              size:
                type: string
                enum: [small, medium]
          status:
            type: object
            properties:
              namespace: {type: string}
    subresources:
      status: {}
---
apiVersion: platform.example.com/v1
kind: Workspace
metadata: {name: team-a, namespace: cnpe-11}
spec:
  owner: alice@example.com
  size: small
```

Without a controller, **status.namespace** stays empty. Next task (`12.md`) provisions from this CR.

## Verify

```bash
kubectl get crd workspaces.platform.example.com
kubectl -n cnpe-11 get ws team-a -o yaml
```

## Exam tips

- `kubectl create crd` is gone; apply full CRD YAML. `kubectl explain` does not work until the CRD exists.
- `required` under `spec` properties. Enum typos fail apply.
- Copy CRD skeleton from kubernetes.io *Extend Kubernetes / CRD*.
