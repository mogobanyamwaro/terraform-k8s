# 01. Goals, Objectives, and Approaches

**Domain:** Core Fundamentals (36%)

## Concept Refresher

**Goal of platform engineering:** reduce **cognitive load** and **toil** so many product teams can deliver on a **shared, self-service** substrate — faster, safer, cheaper — without a human in every request.

**Objectives you will see**

- Treat the platform as a **product** (users, UX, roadmap, SLOs)
- Provide **golden paths** (paved roads) with optional **escape hatches**
- Prefer **thinnest viable platform** over a tool museum
- Enable **DevOps** (app teams still own what they run)
- Scale via **APIs and automation**, not headcount on a ticket queue

**Approaches**

| Approach | Idea |
| --- | --- |
| Platform as product | Docs, versioning, feedback, product owner |
| Golden path | Default easy, secure, observable way to ship |
| Self-service | CRDs, templates, portal — no wait |
| Guardrails | Policy as code, quotas, tenancy |
| Canned infrastructure | Compositions (Crossplane), Cluster API, Terraform modules behind an API |

**Not the goal:** replace developers; own every microservice; mandate one language; hide Kubernetes forever if users need it (abstraction level is a product choice).
