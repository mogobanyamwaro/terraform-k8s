# 19. Kubernetes Operator Pattern

**Domain:** Platform APIs and Provisioning (12%)

## Concept Refresher

An **operator** is a controller **plus** domain knowledge: it manages a **CR** representing software/infra (Postgres, certs, apps).

Pattern:

1. CRD defines API  
2. Controller reconciles  
3. Status/conditions  
4. Often: backups, upgrades, failover  

**Operator SDK / kubebuilder / Crossplane / OLM** are implementation paths. CNPA cares about **when** to use one:

- Use an operator when lifecycle is **ongoing** (not a one-shot Job)
- Prefer **mature** operators over each team running Helm install forever
- Operators are **integration**: wrap a vendor/system behind a K8s API

**Anti-pattern:** operator that only shells out once and exits (that is a Job). Anti-pattern: operators for everything including hello-world (overkill).

## Hands-on

`kubectl get crd | head` on a cluster with cert-manager or Crossplane. Those APIs *are* operators.

## Exam tips

- **Operator = CRD + looping domain controller.**
- Productise **approved** operators.
- One-shot ≠ operator.
