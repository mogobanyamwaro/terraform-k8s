# 16. Incident Response in Platform Engineering

**Domain:** Continuous Delivery & Platform Engineering (16%)

## Concept Refresher

Incidents happen on **apps** and on the **platform** (GitOps down, admission blocking all deploys, cluster full).

**Platform IR**

| Phase | Practice |
| --- | --- |
| Detect | Platform SLOs, user reports, synthetic “hello-path” probes |
| Respond | Incident commander; **status page** for internal users |
| Mitigate | Rollback Git, disable bad policy, scale, feature flag, traffic shift |
| Communicate | What users can/cannot do (deploys frozen?) |
| Learn | Blameless review → **path/policy/docs** change |
| Game days | Rehearse GitOps/control-plane failure |

App vs platform: if one microservice is down, **app** on-call. If **all** teams cannot deploy, **platform** incident.

Rollback is a **first-class** platform capability (Git revert, canary abort). MTTR is a DORA key the platform should **improve**.

Do not page the whole company for a single app; do not hide a platform outage.

## Hands-on

## Exam tips

- **Blast radius** decides app vs platform IR.
- **Revert Git** is the default mitigate.
- Reviews change the **path**, not just people.
