# 03. Declarative Resource Management

**Domain:** Core Fundamentals (36%)

## Concept Refresher

**Declarative:** describe **desired state** (YAML, HCL, CUE, compositions). Controllers **reconcile** actual toward it. Opposite: imperative scripts of API calls as the source of truth.

On a platform, declarative management is how you get:

- Repeatable environments
- GitOps
- CRD/operator self-service
- Policy as code (also declarative)

**Layers**

| Layer | Examples |
| --- | --- |
| App runtime | Deployment, Helm, Kustomize |
| Cluster / tenancy | Namespace, vCluster, Project CR |
| Infra | Crossplane XR, Cluster API Cluster, Terraform (if reconciled) |
| Policy | Kyverno ClusterPolicy, OPA Constraint |

**Implications**

- Desired state lives in **Git** (or another versioned store)
- Drift is visible and reconcilable
- ClickOps in a cloud console as truth **fails** this competency
- `:latest` and unversioned modules weaken **immutability**

CNPA will not grade OpenGitOps sentence order like CGOA, but **pull + reconcile** is still the platform default vs CI `kubectl apply`.
