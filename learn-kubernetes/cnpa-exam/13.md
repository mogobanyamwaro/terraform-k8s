# 13. CI Pipelines Overview (Delivery Domain)

**Domain:** Continuous Delivery & Platform Engineering (16%)

## Concept Refresher

Deeper than `06.md`: **how** a platform pipeline is structured and operated.

**Stages (typical golden path)**

1. Lint / unit  
2. Security (SAST, SCA, secret scan)  
3. Build + SBOM + sign  
4. Integration / contract tests  
5. Publish artifact  
6. (Optional) update GitOps config PR — **not** kubectl  

**Platform operations**

- Template versioning (v1 pipelines, deprecation)
- Runner autoscaling and queues as an SLO (wait time is **lead time**)
- Multi-language packs (Java, Go, Node) as products
- Monorepo vs polyrepo: still **one** template family
- Break-glass pipeline with extra approval

Tekton `Pipeline`/`Task`, GitHub reusable workflows, GitLab `include`, Jenkins shared libs, Argo Workflows CI — **examples**. Exam: structure and ownership, not brand YAML.
