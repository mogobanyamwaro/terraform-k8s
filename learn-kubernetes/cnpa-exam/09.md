# 09. Secure Service Communication

**Domain:** Observability, Security, and Conformance (20%)

## Concept Refresher

Services on a platform must **authenticate, encrypt, and authorise** in-cluster traffic — not only at Ingress.

| Control | Idea |
| --- | --- |
| TLS / **mTLS** | Encrypt + identity of both peers |
| Workload identity | SPIFFE/SPIRE, projected SA tokens, mesh identities |
| NetworkPolicy | L3/L4 who can talk |
| Service mesh | Often mTLS + L7 authz + traffic (Istio, Linkerd, Cilium mesh) |
| Gateway / Ingress TLS | North-south; does **not** replace east-west |

**Platform encoding:** secure-by-default (mesh STRICT, default-deny NetworkPolicy + allow templates, cert-manager). App teams should not mint long-lived cluster-wide secrets.

Zero trust flavour: never trust the CNI network alone.

## Exam tips

- **North-south ≠ east-west.**
- Mesh is **an** implementation of mTLS, not the competency name.
- Identity is **short-lived**.
