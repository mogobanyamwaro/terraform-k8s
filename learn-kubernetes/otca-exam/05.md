# 05. Data Model

**Domain:** The OpenTelemetry API and SDK (46%)

## Concept Refresher

OTLP/API share one **data model**.

**Resource** — attributes of the entity (`service.name`, host, k8s).

**Trace** — set of spans with the same `trace_id`.

**Span**

| Field | Meaning |
| --- | --- |
| name | Operation (`GET /users/{id}`) |
| span context | `trace_id`, `span_id`, `trace_flags` (sampled), `trace_state` |
| parent | Parent `span_id` (empty = root) |
| kind | INTERNAL, SERVER, CLIENT, PRODUCER, CONSUMER |
| start/end | Timestamps |
| status | UNSET, OK, ERROR (+ description) |
| attributes | Key/value |
| events | Timed logs on the span |
| links | Causal links to other traces/spans |

**Metric** — identity (name, unit, description) + data points (attributes, timestamps, value / histogram buckets) + aggregation temporality.

**Log record** — timestamp, severity, body, attributes, optional trace context.

**Instrumentation scope** — library name/version that produced the signal (distinct from resource).

## Hands-on

In a console dump, identify trace_id, span_id, parent, kind, resource `service.name`.

## Exam tips

- **Kind ≠ status.** Kind is role; status is success/fail.
- Root span has no parent.
