# 16. Collector Pipelines

**Domain:** The OpenTelemetry Collector (26%)

## Concept Refresher

A **pipeline** is per **signal**: `traces`, `metrics`, `logs` (and `profiles` in newer builds).

```text
receivers → processors (in order) → exporters
```

Fan-in: many receivers. Fan-out: many exporters (each gets a copy).

You can have **multiple pipelines** of the same signal (`traces/2`) with different processors.

**OTLP receiver** feeds all signals you enable. **prometheus** receiver is metrics-only. **jaeger** receiver traces-only. Mixing a traces-only exporter into a metrics pipeline fails.

**Processors are ordered.** `filter` then `transform` ≠ the reverse.

Data does not jump signals unless a **connector** (spanmetrics, forward) converts.
