# 02. Semantic Conventions

**Domain:** Fundamentals of Observability (18%)

## Concept Refresher

**Semantic conventions** are agreed names and meanings for attributes (`http.request.method`, `db.system`, `exception.type`) so backends and Collector processors can treat telemetry uniformly.

**Resource** conventions: `service.name` is **required** for services. Also `service.version`, `service.instance.id`, `host.name`, `k8s.*`.

**Span** conventions depend on **span kind** (HTTP server vs client vs messaging). HTTP spans use request/response attributes, not inventing `url_path_custom`.

Stability: conventions **version**. OTel attaches a **schema URL** so readers know which convention generation produced the data (see domain 4).

Do not put high-cardinality values (`user_id` for every user) on metrics attributes; traces/logs tolerate more.

HTTP conventions have been migrating (`http.method` → `http.request.method`). Exam: **use the documented names**, don’t invent.
