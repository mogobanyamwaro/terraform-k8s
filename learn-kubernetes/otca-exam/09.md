# 09. Metrics Signal

**Domain:** The OpenTelemetry API and SDK (46%)

## Concept Refresher

`Meter` from `MeterProvider`. **Instruments:**

| Instrument | Direction | Typical use |
| --- | --- | --- |
| **Counter** | Monotonic up | Requests, bytes |
| **UpDownCounter** | Up or down | Queue size, in-flight |
| **Histogram** | Distribution | Latency, payload size |
| **Gauge** | Last value (sync; language support varies) | Temperature-like |
| **Observable\*** | Async callback | Used heap, cache size |

**Observable** (asynchronous) instruments are pulled by the SDK on collect — don’t increment them in a hot request path.

**Aggregation:** sum, last-value, histogram (explicit or exponential). Chosen by views / SDK defaults.

**Temporality:**

- **Cumulative** — since start (Prometheus-like)
- **Delta** — since last export (some backends prefer)

`OTEL_EXPORTER_OTLP_METRICS_TEMPORALITY_PREFERENCE` (cumulative/delta/lowmemory).

**Cardinality:** bound attribute values. Use **views** to drop/rename instruments.

Metrics can be produced from traces (spanmetrics connector) — that is Collector, not the Meter API.
