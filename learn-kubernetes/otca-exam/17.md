# 17. Collector Deployment

**Domain:** The OpenTelemetry Collector (26%)

## Concept Refresher

**Agent** — next to the workload:

- Sidecar (one Collector per pod)
- DaemonSet (one per node; host metrics, log files, OTLP from local pods)

Agent jobs: receive OTLP from apps, scrape node, **little** heavy processing, export to **gateway**.

**Gateway** — cluster or regional service (Deployment):

- Tail sampling, heavy OTTL, fan-out to many backends
- Auth, TLS termination
- Scale independently of apps

**No Collector** — app OTLP straight to vendor (simpler, less transform, vendor lock-in risk).

**Kubernetes:** OpenTelemetry Operator can manage Collector CRs (`OpenTelemetryCollector` mode: sidecar, daemonset, deployment, statefulset).

Sidecar: app `localhost:4317`. DaemonSet: often node IP / hostPort / Service.

Don’t run tail sampling on every **sidecar** (incomplete traces).
