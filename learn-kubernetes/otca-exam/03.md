# 03. Instrumentation

**Domain:** Fundamentals of Observability (18%)

## Concept Refresher

**Instrumentation** is code (or an agent) that **creates** telemetry.

| Approach | How | When |
| --- | --- | --- |
| **Automatic / zero-code** | Language **agent** or auto SDK (Java `-javaagent`, .NET profiler, Python auto) | Fast coverage of HTTP, DB, gRPC |
| **Library** | Framework already calls the OTel API | You depend on an instrumented library |
| **Manual** | You start/end spans, add attributes | Business operations, custom queues |

Best practice: **auto for libraries + manual for business spans**. Auto is not a replacement for naming *checkout* vs *http.server*.

Instrumentation should use the **API**, not vendor SDKs, so you can change exporters.

Avoid double-instrumentation (agent *and* manual HTTP wrapper both wrapping the same call) unless you understand span parenting.

Zero-code still needs **SDK/agent config** (`OTEL_*`, endpoint). No config → often **no-op**.
