# 13. Agents (Zero-Code)

**Domain:** The OpenTelemetry API and SDK (46%)

## Concept Refresher

An **agent** is zero-code instrumentation: attach at process start, wrap HTTP/DB/RPC, install an SDK, honour `OTEL_*`.

| Language | Typical attach |
| --- | --- |
| Java | `-javaagent:opentelemetry-javaagent.jar` |
| .NET | Profiler / startup hook |
| Python | `opentelemetry-instrument` wrapper |
| Node | `--require` / loader |
| Go | Weaker classic agent; eBPF/auto evolving — often compile-time or manual |

Agent **suppresses** duplicate lib instrumentation when configured.

K8s: OpenTelemetry Operator `Instrumentation` CR injects agent/env into pods.

Agent is still **in-process SDK**, not the Collector. Data usually goes **OTLP → Collector**.

Limitations: unknown frameworks, custom business spans still need **manual** API; very new libraries may be missing.

`OTEL_JAVAAGENT_DEBUG` / similar for agent diagnostics (not the same as Collector `debug` exporter).
