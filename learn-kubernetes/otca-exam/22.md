# 22. Error Handling and Schema Management

**Domain:** Maintaining and Debugging Observability Pipelines (10%)

## Concept Refresher

**Error handling**

- SDK exporters **retry** transient OTLP failures; then drop.
- Collector exporter `retry_on_failure`, `sending_queue`, `timeout`.
- `memory_limiter` returns backpressure to receivers (OTLP may 429/unavailable).
- Partial success: OTLP can accept some signals and reject others.
- Never crash the **app** because telemetry failed (API/SDK should isolate).

**Drop vs block:** blocking the request path for export is an anti-pattern (use batch + drop).

**Schema management**

Semantic conventions **evolve**. Telemetry may carry **`schema_url`** (e.g. `https://opentelemetry.io/schemas/1.21.0`).

Collector **`transform` / schema processor** (where available) can migrate old attribute names (`http.method` → `http.request.method`).

Pin a schema generation in instrumentation libraries; document it. Mixed versions → dashboards miss fields.

**Compatibility:** keep Collector **newer or equal** to incoming OTLP; pin images.

This domain is 10% — still easy points if you know **retry/queue/drop**, **don’t block users**, and **schema URL / rename via transform**.
