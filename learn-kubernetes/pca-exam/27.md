# 27. Client Libraries

**Domain:** Instrumentation and Exporters

## Concept Refresher

**Direct instrumentation** means adding metrics to your own application code with a client library. The library:

1. Maintains metric objects in process memory.
2. Provides a **registry** collecting them.
3. Exposes an HTTP handler that renders the registry in exposition format at `/metrics`.

### Official client libraries

Maintained by the Prometheus project:

| Language | Package |
| --- | --- |
| **Go** | `github.com/prometheus/client_golang` |
| **Java / JVM** (also Scala, Kotlin, Clojure) | `io.prometheus:simpleclient` / `prometheus-metrics-core` |
| **Python** | `prometheus_client` |
| **Ruby** | `prometheus-client` |
| **Rust** | `prometheus-client` |

### Notable unofficial libraries

.NET/C#, Node.js (`prom-client`), PHP, C++, Elixir, Erlang, Haskell, Lua, Perl, Bash. Dozens exist. The exam only expects you to know the **official five**.

### Go example, end to end

```go
package main

import (
    "net/http"
    "time"

    "github.com/prometheus/client_golang/prometheus"
    "github.com/prometheus/client_golang/prometheus/promauto"
    "github.com/prometheus/client_golang/prometheus/promhttp"
)

var (
    requestsTotal = promauto.NewCounterVec(
        prometheus.CounterOpts{
            Name: "myapp_http_requests_total",
            Help: "Total number of HTTP requests.",
        },
        []string{"method", "path", "status"},
    )

    inFlight = promauto.NewGauge(
        prometheus.GaugeOpts{
            Name: "myapp_http_requests_in_flight",
            Help: "Current number of in-flight HTTP requests.",
        },
    )

    requestDuration = promauto.NewHistogramVec(
        prometheus.HistogramOpts{
            Name:    "myapp_http_request_duration_seconds",
            Help:    "HTTP request latency in seconds.",
            Buckets: []float64{0.005, 0.01, 0.025, 0.05, 0.1, 0.25, 0.5, 1, 2.5, 5, 10},
        },
        []string{"method", "path"},
    )
)

func handler(w http.ResponseWriter, r *http.Request) {
    inFlight.Inc()
    defer inFlight.Dec()

    start := time.Now()
    // ... do the work ...
    status := "200"

    requestDuration.WithLabelValues(r.Method, r.URL.Path).Observe(time.Since(start).Seconds())
    requestsTotal.WithLabelValues(r.Method, r.URL.Path, status).Inc()
}

func main() {
    http.HandleFunc("/", handler)
    http.Handle("/metrics", promhttp.Handler())
    http.ListenAndServe(":8080", nil)
}
```

### Python example

```python
from prometheus_client import Counter, Gauge, Histogram, Summary, start_http_server
import time, random

REQUESTS = Counter(
    "myapp_http_requests_total",
    "Total HTTP requests.",
    ["method", "path", "status"],
)

IN_FLIGHT = Gauge(
    "myapp_http_requests_in_flight",
    "In-flight requests.",
)

LATENCY = Histogram(
    "myapp_http_request_duration_seconds",
    "Request latency.",
    ["method", "path"],
    buckets=(0.005, 0.01, 0.025, 0.05, 0.1, 0.25, 0.5, 1, 2.5, 5, 10),
)

QUEUE_DEPTH = Gauge("myapp_queue_depth", "Items in queue.")

# Decorator form
@LATENCY.labels("GET", "/api").time()
def handle_request():
    with IN_FLIGHT.track_inprogress():
        time.sleep(random.random() / 10)
        REQUESTS.labels("GET", "/api", "200").inc()

if __name__ == "__main__":
    start_http_server(8000)          # exposes /metrics on :8000
    while True:
        handle_request()
```

### Core API surface, common to all libraries

| Type | Methods |
| --- | --- |
| Counter | `.inc()`, `.inc(n)`. **No `dec()` and no `set()`** |
| Gauge | `.inc()`, `.dec()`, `.set(v)`, `.set_to_current_time()`, `.track_inprogress()` |
| Histogram | `.observe(v)`, `.time()` context manager or decorator |
| Summary | `.observe(v)`, `.time()` |

Deliberate design: **a counter has no way to decrease or be set.** The type system enforces monotonicity. Any question implying `counter.dec()` exists is wrong.

### Labels

```python
# Declare label names at construction
REQUESTS = Counter("http_requests_total", "help", ["method", "status"])

# Supply values at observation
REQUESTS.labels("GET", "200").inc()
REQUESTS.labels(method="GET", status="200").inc()
```

- Label **names** are fixed when the metric is created.
- Label **values** are supplied per observation, creating a child series on first use.
- A metric with no labels is a single series and can be used directly.
- Once a label combination is used, its series exists until process restart, even if never touched again. This is why unbounded label values leak memory in the client as well as in Prometheus.

### Registries

```python
from prometheus_client import CollectorRegistry, Counter, generate_latest

registry = CollectorRegistry()
c = Counter("my_metric_total", "help", registry=registry)
c.inc()
print(generate_latest(registry).decode())
```

- Each library has a **default registry**, used implicitly.
- A custom registry is useful for tests, for isolating pushed metrics, and for the multiprocess pattern.
- Registering the same metric name twice on one registry raises an error.

### Built-in metrics you get for free

Every official client library exposes process and runtime metrics automatically:

| Metric | Meaning |
| --- | --- |
| `process_cpu_seconds_total` | CPU time consumed (counter) |
| `process_resident_memory_bytes` | RSS (gauge) |
| `process_virtual_memory_bytes` | VSZ (gauge) |
| `process_open_fds` | Open file descriptors (gauge) |
| `process_max_fds` | FD limit (gauge) |
| `process_start_time_seconds` | Start timestamp (gauge) |
| `go_goroutines` | Goroutine count (Go) |
| `go_gc_duration_seconds` | GC pause summary (Go) |
| `go_memstats_*` | Go heap details |
| `python_gc_*` | Python GC stats |
| `jvm_*` | JVM metrics |
| `promhttp_metric_handler_requests_total` | Scrapes of this endpoint (Go) |

`process_start_time_seconds` is why `time() - process_start_time_seconds` works everywhere.

### Custom collectors

When metrics come from an external source you should **not** cache them in a counter. Instead implement a collector that queries on scrape:

```python
from prometheus_client.core import GaugeMetricFamily, CounterMetricFamily, REGISTRY

class DatabaseCollector:
    def collect(self):
        rows = query_db("SELECT state, count(*) FROM connections GROUP BY state")
        g = GaugeMetricFamily(
            "db_connections",
            "Database connections by state.",
            labels=["state"],
        )
        for state, count in rows:
            g.add_metric([state], count)
        yield g

REGISTRY.register(DatabaseCollector())
```

Custom collectors are the correct pattern for **exporters**, because the underlying system is the source of truth and there is no in-process event to increment.

Important: a custom collector must **not** apply its own timestamps, and it should return the current state at scrape time.

### Concurrency and thread safety

All official client libraries are **thread safe**. Counters and gauges use atomic operations. You do not need your own locks.

### Multiprocess mode (Python)

Python under Gunicorn or uWSGI forks worker processes, each with its own registry. A scrape hits only one worker, so the numbers are wrong.

Solution: multiprocess mode with a shared directory of memory-mapped files.

```bash
export PROMETHEUS_MULTIPROC_DIR=/tmp/prom
```

```python
from prometheus_client import multiprocess, CollectorRegistry, generate_latest

def metrics_app(environ, start_response):
    registry = CollectorRegistry()
    multiprocess.MultiProcessCollector(registry)
    data = generate_latest(registry)
    start_response("200 OK", [("Content-Type", "text/plain")])
    return [data]
```

Caveats: gauges need an explicit aggregation mode (`all`, `liveall`, `min`, `max`, `livesum`), summaries lose quantiles, and dead worker files must be cleaned up with `multiprocess.mark_process_dead(pid)`.

Recognise this problem shape: **"metrics from a forking Python web server are inconsistent between scrapes"** means multiprocess mode is missing.

### When to instrument directly vs use an exporter

| Situation | Approach |
| --- | --- |
| You own the code | **Direct instrumentation** with a client library |
| Third-party software with no Prometheus support | **Exporter** |
| Third-party software with native Prometheus support | Scrape it directly |
| A short-lived batch job | Instrument, push to **Pushgateway** |
| Data from a file or command output | **node_exporter textfile collector** |
| Probing something from the outside | **blackbox_exporter** |

## Answers

**Q1: A.** Go, Java/JVM, Python, Ruby, Rust. Node.js and PHP libraries are excellent but unofficial.

**Q2: C.** Counters cannot decrease.

**Q3: B.** The API deliberately makes monotonicity impossible to violate, because `rate()` interprets any decrease as a reset.

**Q4: B.** Names are declared at construction; values are supplied per observation.

**Q5: B.** A child series is created and lives for the process lifetime. This is why unbounded label values leak memory client-side too.

**Q6: B.** `process_start_time_seconds`.

**Q7: B.** All official libraries are thread safe.

**Q8: B.** Collectors query the source of truth on demand, at scrape time.

**Q9: B.** Query on scrape via a collector. Caching in counters risks staleness and double counting.

**Q10: B.** Forked workers each hold a separate registry, so a scrape samples one arbitrary worker.

**Q11: B.** Multiprocess mode with a shared mmap directory.

**Q12: B.** Summary quantiles are lost and gauges require an aggregation mode such as `livesum` or `max`.

**Q13: B.** `promhttp.Handler()`.

**Q14: B.** `start_http_server(port)`.

**Q15: B.** Duplicate registration is an error, which catches accidental double initialisation.

**Q16: B.** Tests, isolation, and multiprocess collection are the three standard reasons.

**Q17: B.** An exporter translates the third-party system's state into exposition format.

**Q18: C.** `observe(v)`.

**Q19: B.** A gauge, incremented and decremented. A counter cannot decrease, so it cannot represent a current level.

**Q20: B.** Go runtime metrics come for free. `up` and `scrape_duration_seconds` are added by **Prometheus**, not the library.

```python
# app.py
import random
import time
from prometheus_client import (
    Counter, Gauge, Histogram, Summary, Info, Enum,
    start_http_server, CollectorRegistry, generate_latest,
)

REQUESTS = Counter(
    "myapp_http_requests_total",
    "Total HTTP requests.",
    ["method", "path", "status"],
)

IN_FLIGHT = Gauge("myapp_http_requests_in_flight", "In-flight requests.")

LATENCY = Histogram(
    "myapp_http_request_duration_seconds",
    "Request latency in seconds.",
    ["method", "path"],
    buckets=(0.005, 0.01, 0.025, 0.05, 0.1, 0.25, 0.5, 1, 2.5, 5, 10),
)

QUEUE = Gauge("myapp_queue_depth", "Items waiting in the queue.")

RPC_SUMMARY = Summary("myapp_rpc_duration_seconds", "RPC duration.")

BUILD = Info("myapp_build", "Build metadata.")
BUILD.info({"version": "1.4.2", "commit": "deadbeef", "branch": "main"})

STATE = Enum(
    "myapp_state",
    "Current application state.",
    states=["starting", "running", "draining", "stopped"],
)
STATE.state("running")

LAST_SUCCESS = Gauge(
    "myapp_last_success_timestamp_seconds",
    "Unix timestamp of the last successful cycle.",
)

PATHS = ["/api/users", "/api/orders", "/healthz"]
METHODS = ["GET", "POST"]


def handle():
    path = random.choice(PATHS)
    method = random.choice(METHODS)

    IN_FLIGHT.inc()
    start = time.time()
    try:
        # Simulate work with a long tail
        delay = random.random() / 20
        if random.random() < 0.05:
            delay += random.random() * 2
        time.sleep(delay)

        status = "500" if random.random() < 0.03 else "200"
    finally:
        IN_FLIGHT.dec()

    elapsed = time.time() - start
    LATENCY.labels(method, path).observe(elapsed)
    RPC_SUMMARY.observe(elapsed)
    REQUESTS.labels(method, path, status).inc()
    QUEUE.set(random.randint(0, 50))
    if status == "200":
        LAST_SUCCESS.set_to_current_time()


if __name__ == "__main__":
    start_http_server(8000)
    print("metrics on http://0.0.0.0:8000/metrics")
    while True:
        handle()
```

import random
from prometheus_client.core import GaugeMetricFamily, CounterMetricFamily, REGISTRY
from prometheus_client import start_http_server
import time


class FakeDatabaseCollector:
    """Queries the 'database' at scrape time rather than caching values."""

    def collect(self):
        connections = GaugeMetricFamily(
            "fakedb_connections",
            "Connections by state.",
            labels=["state"],
        )
        for state in ["active", "idle", "idle_in_transaction"]:
            connections.add_metric([state], random.randint(0, 100))
        yield connections

        queries = CounterMetricFamily(
            "fakedb_queries_total",
            "Total queries executed.",
            labels=["database"],
        )
        queries.add_metric(["orders"], 148231)
        queries.add_metric(["users"], 92104)
        yield queries

        size = GaugeMetricFamily(
            "fakedb_size_bytes",
            "Database size in bytes.",
            labels=["database"],
        )
        size.add_metric(["orders"], 4.2e9)
        size.add_metric(["users"], 8.1e8)
        yield size


if __name__ == "__main__":
    REGISTRY.register(FakeDatabaseCollector())
    start_http_server(8001)
    print("collector metrics on http://0.0.0.0:8001/metrics")
    while True:

```python
# wsgi_mp.py
import os
from prometheus_client import Counter, CollectorRegistry, multiprocess, generate_latest
from werkzeug.middleware.dispatcher import DispatcherMiddleware

HITS = Counter("wsgi_hits_total", "Hits.")

def app(environ, start_response):
    HITS.inc()
    start_response("200 OK", [("Content-Type", "text/plain")])
    return [b"ok\n"]

def metrics_app(environ, start_response):
    registry = CollectorRegistry()
    multiprocess.MultiProcessCollector(registry)
    data = generate_latest(registry)
    start_response("200 OK", [("Content-Type", "text/plain; version=0.0.4")])
    return [data]

application = DispatcherMiddleware(app, {"/metrics": metrics_app})
```

## Exam tips

- Official client libraries: **Go, Java/JVM, Python, Ruby, Rust**. Everything else is unofficial.
- **Counters have no `dec()` and no `set()`.** Monotonicity is enforced by the API.
- Gauge methods: `inc`, `dec`, `set`, `set_to_current_time`, `track_inprogress`.
- Histogram and Summary: `observe(v)`, plus a `time()` decorator or context manager.
- Label **names** are fixed at construction. Label **values** create child series on first use, which persist for the process lifetime.
- All official libraries are **thread safe**.
- Free metrics: `process_cpu_seconds_total`, `process_resident_memory_bytes`, `process_open_fds`, `process_max_fds`, **`process_start_time_seconds`**, plus language-specific runtime metrics.
- Use a **custom collector** when the data lives in an external system. It queries at scrape time and does not cache.
- Duplicate metric registration on one registry is an **error**.
- Custom registries are for tests, isolation, and multiprocess collection.
- **Forking Python servers need multiprocess mode.** Symptom: inconsistent values between scrapes. Fix: `PROMETHEUS_MULTIPROC_DIR` plus `MultiProcessCollector`. Cost: no summary quantiles, gauges need an aggregation mode.
- You own the code, instrument directly. You do not, use an exporter.
- Go handler: `promhttp.Handler()`. Python server: `start_http_server(port)`.
