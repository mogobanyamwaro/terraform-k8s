# 11. Data Model And Labels

**Domain:** Prometheus Fundamentals

## Concept Refresher

### The data model in one block

```text
A TIME SERIES is uniquely identified by:

     metric name  +  the complete set of label name/value pairs

Internally the metric name is just another label:  __name__

So these are the same thing:

     http_requests_total{method="GET", status="200"}
     {__name__="http_requests_total", method="GET", status="200"}

A SAMPLE is:   (timestamp int64 milliseconds, value float64)

A time series is an ordered stream of samples.
```

Changing **any** label value creates a **different** time series.

### Naming rules

**Metric names** must match:

```text
[a-zA-Z_:][a-zA-Z0-9_:]*
```

- Letters, digits, underscores, and **colons**.
- Cannot start with a digit.
- **Colons are reserved for recording rules by convention.** Never use a colon in a directly instrumented metric name.
- With `--enable-feature=utf8-names` (Prometheus 3.x), arbitrary UTF-8 names are permitted using quoted syntax, but the classic rule is what the exam tests.

**Label names** must match:

```text
[a-zA-Z_][a-zA-Z0-9_]*
```

- No colons in label names.
- Names beginning with `__` are **reserved for internal use**.

**Label values** may be **any UTF-8 string**, including empty.

### The empty label rule

A label with an empty value is **equivalent to that label not existing**.

```text
http_requests_total{method="GET", env=""}
```

is the same series as:

```text
http_requests_total{method="GET"}
```

Consequences:

- `{env=""}` matches series that have no `env` label at all.
- `{env!=""}` matches only series that **do** have a non-empty `env`.
- This is the idiomatic way to select "series that have this label".

### Reserved and internal labels

| Label | Meaning |
| --- | --- |
| `__name__` | The metric name. Survives relabeling |
| `__address__` | Host:port Prometheus will connect to |
| `__scheme__` | `http` or `https` |
| `__metrics_path__` | The URL path |
| `__param_<name>` | A URL query parameter |
| `__scrape_interval__` | Per-target scrape interval override |
| `__scrape_timeout__` | Per-target timeout override |
| `__meta_*` | Service discovery metadata |
| `__tmp_*` | Convention for scratch labels in relabeling, never used by Prometheus |

All labels starting with `__` are dropped after target relabeling, except `__name__`.

### The two labels Prometheus always adds

| Label | Default value |
| --- | --- |
| `job` | The `job_name` of the scrape config |
| `instance` | The post-relabeling `__address__` |

Both can be overridden by relabeling.

### Label matchers

| Matcher | Meaning |
| --- | --- |
| `=` | Exactly equal |
| `!=` | Not equal |
| `=~` | Regex matches (fully anchored) |
| `!~` | Regex does not match (fully anchored) |

**Regexes in matchers are fully anchored.** `status=~"5.."` behaves as `^5..$`. To match a substring you must write `.*foo.*`.

Prometheus uses **RE2**, which means **no backreferences and no lookahead/lookbehind**.

Selecting by metric name using a matcher:

```promql
{__name__="http_requests_total"}
{__name__=~"node_cpu_.*"}
{__name__=~".+"}                    # every series. Expensive
```

A selector must have at least one matcher that does not match the empty string. `{job=~".*"}` alone is rejected.

### Metric types in the data model

Prometheus's TSDB stores **only float64 samples** (plus native histograms). The "type" of a metric is:

- A hint in the exposition (`# TYPE`)
- A convention enforced by client libraries
- **Not** enforced by the server

The server will happily let you call `rate()` on a gauge. It just gives nonsense.

| Type | Exposed series |
| --- | --- |
| Counter | `name_total` (one series) |
| Gauge | `name` (one series) |
| Histogram | `name_bucket{le="..."}` (many), `name_sum`, `name_count` |
| Summary | `name{quantile="..."}` (many), `name_sum`, `name_count` |
| Untyped / Unknown | `name`, no semantics assumed |
| Info (OpenMetrics) | `name_info`, always value 1, carries labels |
| StateSet (OpenMetrics) | One series per state, 0 or 1 |
| GaugeHistogram (OpenMetrics) | Like a histogram but buckets can go down |

### Cardinality arithmetic

```text
series = product of the distinct value counts of every label, per metric name

  method (5) x status (8) x handler (40) x instance (100) = 160,000 series
```

**Never use as label values:** user IDs, session IDs, request IDs, trace IDs, email addresses, full URLs with query strings, IP addresses of clients, timestamps, error messages, stack traces, or unbounded enum-like data.

Safe: HTTP method, status code or status class, handler/route **template**, region, environment, instance, queue name, error **category**.

### Finding cardinality problems

```promql
# Top metric names by series count
topk(10, count by (__name__) ({__name__=~".+"}))

# How many series for one metric
count(http_requests_total)

# Which label is the culprit
count(count by (handler) (http_requests_total))
count(count by (user_id) (http_requests_total))
```

Or the built-in report:

```bash
curl -s http://localhost:9090/api/v1/status/tsdb | jq '.data'
```

That returns `seriesCountByMetricName`, `labelValueCountByLabelName`, `memoryInBytesByLabelName`, and `seriesCountByLabelValuePair`.

### Dropping a bad label after the fact

```yaml
metric_relabel_configs:
  # Drop the offending label entirely
  - regex: "user_id"
    action: labeldrop

  # Or drop the whole metric
  - source_labels: [__name__]
    regex: "my_terrible_metric"
    action: drop
```

Existing series remain until retention expires. Relabeling only affects new samples.

## Answers

**Q1: B.** `__name__`.

**Q2: B.** `[a-zA-Z_:][a-zA-Z0-9_:]*`. Colons are legal but reserved by convention. Prometheus 3.x can be put into UTF-8 name mode with a feature flag, but the classic pattern is the tested answer.

**Q3: B.** Colons signal a recording rule output, following the `level:metric:operations` convention. Direct instrumentation must never use them.

**Q4: B.** Label names exclude colons and reserve the `__` prefix.

**Q5: B.** Label values are arbitrary UTF-8, and empty is allowed (and means absent).

**Q6: C.** An empty label value is indistinguishable from an absent label, so `{env=""}` selects series lacking `env`.

**Q7: B.** `{env!=""}` is the idiom for "has this label".

**Q8: B.** Fully anchored. `status=~"5.."` is effectively `^5..$`. Writing your own `^`/`$` is harmless but redundant.

**Q9: C.** RE2 guarantees linear time by excluding backreferences and lookaround.

**Q10: B.** A selector needs at least one matcher that cannot match the empty string. `{job=~".*"}` matches everything including empty, so it is rejected. `{__name__=~".+"}` is accepted because `.+` requires at least one character.

**Q11: B.** 3 x 12 x 6 x 25 = 5,400.

**Q12: B.** The server does not enforce types. It will compute `rate()` on a gauge and return meaningless numbers. Type discipline is your responsibility.

**Q13: B.** Cumulative `_bucket` series with an `le` label, plus `_sum` and `_count`.

**Q14: B.** Summaries expose a `quantile` label on the base metric name, plus `_sum` and `_count`. There are no buckets.

**Q15: B.** `metric_relabel_configs` runs after the scrape on sample labels, and `labeldrop` removes labels by name regex.

**Q16: B.** Relabeling is applied at ingest. Stored series are untouched and age out with retention, unless you use the admin delete-series API.

**Q17: B.** `/api/v1/status/tsdb` gives `labelValueCountByLabelName`, `seriesCountByMetricName`, and more.

**Q18: C.** Route templates are bounded. URLs with query strings, client IPs, and email addresses are all unbounded.

## Hands-on

Prove the metric name is a label:

```promql
{__name__="up"}
{__name__=~"up|scrape_duration_seconds"}
```

Prove that empty equals absent:

```promql
# Series lacking the env label
up{env=""}

# Series that have env
up{env!=""}

# Both together, should equal count(up)
count(up{env=""}) + count(up{env!=""})
```

Prove regex anchoring:

```promql
# Matches nothing: "demo" is not a full match for "emo"
up{job=~"emo"}

# Matches
up{job=~".*emo.*"}
up{job=~"demo"}
```

Prove the selector restriction:

```bash
curl -sG http://localhost:9090/api/v1/query --data-urlencode 'query={job=~".*"}' | jq '.error'
```

You get "vector selector must contain at least one non-empty matcher".

Explore cardinality:

```promql
topk(10, count by (__name__) ({__name__=~".+"}))
count(node_cpu_seconds_total)
count(count by (cpu) (node_cpu_seconds_total))
count(count by (mode) (node_cpu_seconds_total))
```

Confirm the multiplication:

```promql
count(count by (cpu) (node_cpu_seconds_total)) * count(count by (mode) (node_cpu_seconds_total))
```

That should equal `count(node_cpu_seconds_total)` for a single instance.

Use the TSDB status report:

```bash
curl -s http://localhost:9090/api/v1/status/tsdb | jq '.data.seriesCountByMetricName[:10]'
curl -s http://localhost:9090/api/v1/status/tsdb | jq '.data.labelValueCountByLabelName[:10]'
curl -s http://localhost:9090/api/v1/status/tsdb | jq '.data.memoryInBytesByLabelName[:10]'
```

Create a deliberate cardinality bomb, then fix it:

```bash
for i in $(seq 1 500); do
  echo "bad_metric{request_id=\"req-$i\"} 1"
done | curl --data-binary @- http://localhost:9091/metrics/job/cardinality_bomb
```

```promql
count(bad_metric)
count(count by (request_id) (bad_metric))
```

Now drop the label at ingest:

```yaml
  - job_name: pushgateway
    honor_labels: true
    static_configs:
      - targets: ["pushgateway:9091"]
    metric_relabel_configs:
      - regex: "request_id"
        action: labeldrop
```

```bash
curl -X POST http://localhost:9090/-/reload
```

```promql
count(bad_metric)
```

Now 1 series (they all collapse together, and you will see duplicate-sample warnings, which is itself instructive). Clean up:

```bash
curl -X DELETE http://localhost:9091/metrics/job/cardinality_bomb
```

Look at label API endpoints:

```bash
curl -s http://localhost:9090/api/v1/labels | jq '.data'
curl -s http://localhost:9090/api/v1/label/job/values | jq '.data'
curl -sG http://localhost:9090/api/v1/series --data-urlencode 'match[]=node_cpu_seconds_total{mode="idle"}' | jq '.data | length'
```

## Exam tips

- Series identity = metric name + full label set. Metric name lives in `__name__`.
- Metric names: `[a-zA-Z_:][a-zA-Z0-9_:]*`. Label names: `[a-zA-Z_][a-zA-Z0-9_]*`, no colons. Label values: any UTF-8.
- **Colons are reserved for recording rules.**
- **An empty label value equals an absent label.** `{l=""}` selects series without `l`, `{l!=""}` selects series with it.
- Regex matchers are **fully anchored** and use **RE2**: no backreferences, no lookahead.
- A selector needs at least one matcher that cannot match empty. `{job=~".*"}` is rejected.
- Cardinality multiplies. Compute the product, always.
- The server does **not** enforce metric types. `rate()` on a gauge returns garbage silently.
- Histogram = `_bucket{le}` + `_sum` + `_count`. Summary = `{quantile}` + `_sum` + `_count`.
- `metric_relabel_configs` + `labeldrop` fixes ingest going forward. Old series persist until retention.
- `/api/v1/status/tsdb` is the cardinality report.
