# 28. Metric And Label Naming

**Domain:** Instrumentation and Exporters

## Concept Refresher

"Structuring and naming metrics" is an explicit PCA competency and it is easy marks if you learn the rules.

### The naming formula

```text
[namespace_]<subsystem_>name_<unit>[_total]

  namespace   application or library prefix:  myapp_, http_, node_, prometheus_
  subsystem   optional grouping:              _requests_, _cpu_, _filesystem_
  name        what is measured:               duration, bytes, connections
  unit        BASE unit, always:              _seconds, _bytes, _ratio, _celsius, _volts
  _total      mandatory suffix for counters
```

Examples of well-formed names:

```text
http_requests_total
http_request_duration_seconds
node_filesystem_avail_bytes
node_cpu_seconds_total
process_resident_memory_bytes
myapp_queue_depth
myapp_cache_hit_ratio            (but prefer exposing hits and total separately)
kube_pod_container_restarts_total
prometheus_tsdb_head_series
```

### Rule 1: Always use base units

| Use | Never use |
| --- | --- |
| `seconds` | `milliseconds`, `microseconds`, `minutes`, `hours` |
| `bytes` | `kilobytes`, `megabytes`, `KiB`, `MB` |
| `ratio` (0 to 1) | `percent` (0 to 100) |
| `celsius` | `fahrenheit` |
| `volts`, `amperes`, `joules`, `grams`, `meters` | any prefixed variant |

Rationale: consumers can scale for display; they cannot reliably un-scale ambiguous units. Grafana and Alertmanager templates assume base units.

```text
http_request_duration_seconds     ✓
http_request_duration_ms          ✗
memory_usage_bytes                ✓
memory_usage_mb                   ✗
disk_used_ratio                   ✓  value 0.87
disk_used_percent                 ✗  value 87
```

`promtool check metrics` explicitly warns about non-base units.

### Rule 2: Counters end in `_total`

```text
http_requests_total               ✓
errors_total                      ✓
bytes_sent_total                  ✓
http_requests                     ✗  (counter without _total)
http_requests_count               ✗  (_count is reserved for histogram/summary)
```

`_total` is conventional in the Prometheus text format and **mandatory in OpenMetrics**.

### Rule 3: Reserved suffixes

Do not use these on your own metrics, because they clash with generated series:

| Suffix | Reserved for |
| --- | --- |
| `_total` | Counters |
| `_count` | Histogram and Summary observation count |
| `_sum` | Histogram and Summary value sum |
| `_bucket` | Histogram buckets |
| `_created` | OpenMetrics counter creation time |
| `_info` | OpenMetrics info metrics |

So a gauge named `queue_count` is a mistake; use `queue_depth` or `queue_items`.

### Rule 4: The name must describe the same thing for every label value

All series sharing a metric name must be **semantically identical and summable**.

```text
# WRONG: mixing incomparable measurements under one name
system_metric{type="cpu_seconds"}
system_metric{type="memory_bytes"}
system_metric{type="disk_bytes"}

# RIGHT
system_cpu_seconds_total
system_memory_bytes
system_disk_bytes
```

Test: does `sum(metric_name)` mean anything? If not, the name is doing a label's job.

### Rule 5: Do not put the label name in the metric name

```text
# WRONG
http_requests_get_total
http_requests_post_total
http_responses_500_total

# RIGHT
http_requests_total{method="GET"}
http_requests_total{method="POST", status="500"}
```

Labels exist so you can aggregate. Baking the dimension into the name makes aggregation impossible.

### Rule 6: Do not expose pre-computed ratios, averages, or percentages

```text
# WRONG
cache_hit_ratio 0.95
average_request_duration_seconds 0.12
error_percentage 3.2

# RIGHT
cache_hits_total
cache_lookups_total
http_request_duration_seconds       (histogram: _bucket, _sum, _count)
http_requests_total{status="500"}
http_requests_total
```

Reason: a ratio cannot be re-aggregated. `avg(cache_hit_ratio)` across ten instances is wrong when the instances handle different volumes. Expose numerator and denominator, compute in PromQL.

### Rule 7: Label naming

| Rule | Detail |
| --- | --- |
| Pattern | `[a-zA-Z_][a-zA-Z0-9_]*`. No colons |
| Style | `snake_case`, lower case |
| `__` prefix | Reserved for internal use |
| Bounded values | Label values must come from a small, known set |
| No redundancy | Do not add a label that duplicates the metric name |
| Consistency | Use the same label name across metrics for the same concept: `instance`, `job`, `method`, `status`, `path`, `device` |

Cardinality-safe versus dangerous:

| Safe | Dangerous |
| --- | --- |
| `method="GET"` | `user_id="..."` |
| `status="500"` or `status_class="5xx"` | `request_id="..."` |
| `path="/api/users/:id"` (template) | `path="/api/users/8823"` (actual) |
| `region="eu-west-1"` | `client_ip="..."` |
| `error_type="timeout"` | `error_message="connection refused to 10.2..."` |
| `queue="orders"` | `session_token="..."` |
| `device="sda"` | `timestamp="..."` |

### Rule 8: Do not duplicate the `instance` or `job` labels

Prometheus adds these. An exporter must not expose its own `instance` label, or you get `exported_instance` collisions.

Exception: the Pushgateway pattern, where you deliberately set `job` and `instance` in the push URL and use `honor_labels: true`.

### Rule 9: HELP text is mandatory and should be useful

```text
# HELP http_request_duration_seconds Latency of HTTP requests in seconds, by method and path.
# TYPE http_request_duration_seconds histogram
```

`promtool check metrics` warns about missing HELP. Write a sentence, not the metric name repeated.

### Rule 10: The info-metric pattern for metadata

Do not put slowly-changing metadata on every metric:

```text
# WRONG: version multiplies the cardinality of every series
http_requests_total{method="GET", version="1.4.2", commit="deadbeef"}

# RIGHT: one info metric, joined at query time
myapp_build_info{version="1.4.2", commit="deadbeef", branch="main"} 1
http_requests_total{method="GET"}
```

```promql
rate(http_requests_total[5m]) * on(instance) group_left(version) myapp_build_info
```

### Naming for exporters

An exporter's metrics should be prefixed with the **exported system's** name, not the word "exporter":

```text
mysql_global_status_threads_connected      ✓
node_filesystem_avail_bytes                ✓
redis_connected_clients                    ✓
mysqld_exporter_threads                    ✗
```

Every exporter should also expose its own scrape health:

```text
mysql_up 1
mysql_exporter_last_scrape_error 0
mysql_exporter_scrapes_total 1024
```

### Quick self-review checklist

```text
□ Base units? seconds, bytes, ratio
□ Counter ends in _total?
□ No reserved suffix misuse (_count, _sum, _bucket)?
□ Does sum(metric) mean something?
□ Is any dimension baked into the name instead of a label?
□ Any pre-computed ratio or average? Expose the parts instead
□ Are all label values bounded?
□ No self-supplied instance or job labels?
□ HELP text present and informative?
□ Metadata in an _info metric rather than on every series?
```

## Answers

**Q1: B.** Base unit `seconds`, snake_case.

**Q2: B.** Bytes.

**Q3: B.** A `_ratio` in the range 0 to 1. Multiply by 100 at display time.

**Q4: B.** `_total`. Conventional in the Prometheus text format, mandatory in OpenMetrics.

**Q5: B.** `_count` belongs to histograms and summaries. Use `queue_depth` or `queue_items`.

**Q6: B.** A metric name must denote one comparable quantity. Here the `type` label is doing work that belongs in the name.

**Q7: B.** One metric name, one `method` label. That is what makes `sum by (method) (...)` and `sum(...)` both meaningful.

**Q8: B.** Ratios do not re-aggregate. `avg()` of per-instance ratios ignores volume differences.

**Q9: C.** A route **template** has bounded cardinality. The actual path with an ID does not.

**Q10: B.** `[a-zA-Z_][a-zA-Z0-9_]*`. Colons are allowed in metric **names** but never in label names.

**Q11: B.** Double underscore.

**Q12: B.** Prometheus assigns `instance`, and with the default `honor_labels: false` a colliding exposed label becomes `exported_instance`.

**Q13: B.** The Pushgateway, where the pushed `job` and `instance` are meaningful and `honor_labels: true` preserves them.

**Q14: B.** An `_info` metric with value 1.

**Q15: B.** Metadata as labels on real metrics multiplies cardinality, and every version change orphans the old series.

**Q16: B.** Prefix with the **exported system's** name, describing the source metric.

**Q17: B.** Missing HELP, counters lacking `_total`, non-base units, and histogram consistency problems.

**Q18: B.** If `sum()` is meaningless, you have grouped incomparable things under one name.

**Q19: B.** snake_case, lower case.

**Q20: B.** Celsius is the base unit.

## Hands-on

Write a deliberately bad exposition and let promtool grade it:

```bash
cat > /tmp/bad_names.txt <<'EOF'
# TYPE http_requests counter
http_requests 100
# HELP latency_ms Request latency.
# TYPE latency_ms gauge
latency_ms 250
# HELP disk_percent Disk usage.
# TYPE disk_percent gauge
disk_percent 87
# TYPE queue_count gauge
queue_count 12
# HELP memory_mb Memory.
# TYPE memory_mb gauge
memory_mb 512
# TYPE temperature_fahrenheit gauge
temperature_fahrenheit 98.6
EOF

promtool check metrics < /tmp/bad_names.txt
```

Read every warning. Now write the corrected version:

```bash
cat > /tmp/good_names.txt <<'EOF'
# HELP http_requests_total Total number of HTTP requests handled, by method and status.
# TYPE http_requests_total counter
http_requests_total{method="GET",status="200"} 100
# HELP http_request_duration_seconds Latency of HTTP requests in seconds.
# TYPE http_request_duration_seconds gauge
http_request_duration_seconds 0.25
# HELP node_filesystem_used_ratio Fraction of the filesystem in use, 0 to 1.
# TYPE node_filesystem_used_ratio gauge
node_filesystem_used_ratio{mountpoint="/"} 0.87
# HELP myapp_queue_depth Number of items currently waiting in the queue.
# TYPE myapp_queue_depth gauge
myapp_queue_depth 12
# HELP process_resident_memory_bytes Resident memory size in bytes.
# TYPE process_resident_memory_bytes gauge
process_resident_memory_bytes 536870912
# HELP node_hwmon_temp_celsius Hardware monitor temperature in celsius.
# TYPE node_hwmon_temp_celsius gauge
node_hwmon_temp_celsius{sensor="cpu"} 37.0
EOF

promtool check metrics < /tmp/good_names.txt && echo "CLEAN"
```

Demonstrate why a dimension in the name is bad. Push both shapes:

```bash
cat > /tmp/shape_bad.txt <<'EOF'
# TYPE requests_get_total counter
requests_get_total 500
# TYPE requests_post_total counter
requests_post_total 200
# TYPE requests_delete_total counter
requests_delete_total 30
EOF

cat > /tmp/shape_good.txt <<'EOF'
# TYPE requests_by_method_total counter
requests_by_method_total{method="GET"} 500
requests_by_method_total{method="POST"} 200
requests_by_method_total{method="DELETE"} 30
EOF

curl --data-binary @/tmp/shape_bad.txt  http://localhost:9091/metrics/job/shape_bad
curl --data-binary @/tmp/shape_good.txt http://localhost:9091/metrics/job/shape_good
```

Now try to answer "total requests across all methods" with each:

```promql
# The bad shape forces you to enumerate every metric by hand
requests_get_total + requests_post_total + requests_delete_total

# The good shape aggregates naturally, and keeps working when a new method appears
sum(requests_by_method_total)
sum by (method) (requests_by_method_total)
topk(1, requests_by_method_total)
```

The good shape also survives someone adding `PATCH` without a query change.

Demonstrate why pre-computed ratios break. Two instances with wildly different traffic:

```bash
cat > /tmp/ratio_bad.txt <<'EOF'
# TYPE cache_hit_ratio gauge
cache_hit_ratio{server="busy"} 0.90
cache_hit_ratio{server="idle"} 0.50
EOF

cat > /tmp/ratio_good.txt <<'EOF'
# TYPE cache_hits_total counter
cache_hits_total{server="busy"} 900000
cache_hits_total{server="idle"} 5
# TYPE cache_lookups_total counter
cache_lookups_total{server="busy"} 1000000
cache_lookups_total{server="idle"} 10
EOF

curl --data-binary @/tmp/ratio_bad.txt  http://localhost:9091/metrics/job/ratio_bad
curl --data-binary @/tmp/ratio_good.txt http://localhost:9091/metrics/job/ratio_good
```

```promql
# The naive aggregate of pre-computed ratios
avg(cache_hit_ratio)

# The correct volume-weighted ratio
sum(cache_hits_total) / sum(cache_lookups_total)
```

The first says 0.70. The second says 0.90. The busy server dominates reality, and only the counter form knows that.

Clean up:

```bash
for j in shape_bad shape_good ratio_bad ratio_good; do
  curl -X DELETE http://localhost:9091/metrics/job/$j
done
```

Demonstrate the info-metric join versus label-on-everything:

```bash
cat > /tmp/info_bad.txt <<'EOF'
# TYPE app_requests_total counter
app_requests_total{path="/a",version="1.0.0"} 10
app_requests_total{path="/b",version="1.0.0"} 20
app_requests_total{path="/a",version="1.1.0"} 5
app_requests_total{path="/b",version="1.1.0"} 8
EOF

cat > /tmp/info_good.txt <<'EOF'
# TYPE app2_requests_total counter
app2_requests_total{path="/a"} 15
app2_requests_total{path="/b"} 28
# TYPE app2_build_info gauge
app2_build_info{version="1.1.0",commit="deadbeef"} 1
EOF

curl --data-binary @/tmp/info_bad.txt  http://localhost:9091/metrics/job/info_bad
curl --data-binary @/tmp/info_good.txt http://localhost:9091/metrics/job/info_good
```

```promql
# Series count comparison
count(app_requests_total)
count(app2_requests_total) + count(app2_build_info)

# The join still gives you the version when you need it
app2_requests_total * on(job) group_left(version) app2_build_info
```

Note how every deploy in the first shape orphans the old version's series permanently.

```bash
curl -X DELETE http://localhost:9091/metrics/job/info_bad
curl -X DELETE http://localhost:9091/metrics/job/info_good
```

## Exam tips

- **Base units always: `seconds`, `bytes`, `ratio` (0-1), `celsius`.** Never milliseconds, megabytes, or percent.
- **Counters end in `_total`.** Mandatory in OpenMetrics.
- Reserved suffixes to avoid on your own metrics: **`_count`, `_sum`, `_bucket`, `_total`, `_created`, `_info`**.
- Test the name with: does `sum(metric)` mean anything? If not, you have merged incomparable things.
- Put the dimension in a **label**, never in the metric name. `http_requests_total{method="GET"}`, not `http_requests_get_total`.
- **Never expose pre-computed ratios, averages, or percentages.** Expose numerator and denominator as counters.
- Label names: `[a-zA-Z_][a-zA-Z0-9_]*`, snake_case, no colons, `__` reserved.
- Label **values must be bounded**. Route templates yes, actual paths with IDs no.
- Do not expose your own `instance` or `job` labels. Collisions become `exported_*`. The Pushgateway with `honor_labels: true` is the exception.
- Metadata goes in an **`_info` metric with value 1**, joined via `group_left`.
- Exporters prefix with the **exported system's** name and expose a `<system>_up` health metric.
- `promtool check metrics` catches missing HELP, missing `_total`, and non-base units.
- Style is **snake_case**, lower case. Never camelCase or dots.
