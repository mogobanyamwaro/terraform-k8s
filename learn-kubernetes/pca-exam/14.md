# 14. Relabeling

**Domain:** Prometheus Fundamentals

## Concept Refresher

Relabeling is Prometheus's label rewriting engine. It runs in four places:

| Block | Where | Operates on | Purpose |
| --- | --- | --- | --- |
| `relabel_configs` | In a scrape config, **before** the scrape | Target label set (including `__meta_*`) | Filter targets, set `__address__`, build labels |
| `metric_relabel_configs` | In a scrape config, **after** the scrape | Each sample's label set | Drop metrics, drop labels, rename |
| `write_relabel_configs` | In `remote_write` | Samples going to a remote store | Reduce what you ship |
| `alert_relabel_configs` | In `alerting` | Alerts going to Alertmanager | Strip replica labels, rewrite severity |

Mnemonic: **relabel = targets, metric_relabel = samples, write_relabel = egress, alert_relabel = alerts.**

### Rule anatomy and defaults

```yaml
- source_labels: [label_a, label_b]   # concatenated with separator
  separator: ";"                       # DEFAULT ";"
  regex: "(.*)"                        # DEFAULT "(.*)", fully anchored
  modulus: 0                           # only for hashmod
  target_label: "new_label"            # destination
  replacement: "$1"                    # DEFAULT "$1"
  action: replace                      # DEFAULT replace
```

Every default matters:

- `separator` defaults to `;`
- `regex` defaults to `(.*)` and is **fully anchored**
- `replacement` defaults to `$1`
- `action` defaults to `replace`

Capture groups are referenced as `$1`, `$2`, or `${1}`. Use `${1}` when the reference is followed by other characters, for example `${1}:9100`.

### All relabel actions

| Action | Effect |
| --- | --- |
| `replace` | If `regex` matches the concatenated `source_labels`, set `target_label` to `replacement` with capture groups expanded. If no match, **the rule does nothing** |
| `keep` | Drop the target/sample **unless** `regex` matches |
| `drop` | Drop the target/sample **if** `regex` matches |
| `keepequal` | Keep only if the concatenated `source_labels` equals the value of `target_label` |
| `dropequal` | Drop if the concatenated `source_labels` equals the value of `target_label` |
| `hashmod` | Set `target_label` to `hash(source_labels) % modulus`. Used for sharding |
| `labelmap` | For every **label name** matching `regex`, copy its value to a new label named by `replacement`. Operates on names, not values |
| `labeldrop` | Remove every label whose **name** matches `regex` |
| `labelkeep` | Remove every label whose **name** does **not** match `regex` |
| `lowercase` | Set `target_label` to the lowercased concatenated `source_labels` |
| `uppercase` | Set `target_label` to the uppercased version |

Notes:

- `labelmap`, `labeldrop`, and `labelkeep` operate on **label names** and use `regex` against those names. They do **not** take `source_labels`.
- `labeldrop` and `labelkeep` must not remove `__name__` or produce duplicate series. Prometheus errors if they do.
- Setting `target_label` to an empty `replacement` **deletes** the label.
- Rules run **in order**, top to bottom. Each rule sees the output of the previous one.

### The canonical patterns

**1. Drop targets you do not want**

```yaml
relabel_configs:
  - source_labels: [__meta_kubernetes_pod_annotation_prometheus_io_scrape]
    regex: "true"
    action: keep
```

**2. Rewrite the scrape port**

```yaml
relabel_configs:
  - source_labels: [__meta_kubernetes_pod_ip]
    target_label: __address__
    replacement: "${1}:9100"
```

**3. Custom metrics path from an annotation**

```yaml
relabel_configs:
  - source_labels: [__meta_kubernetes_pod_annotation_prometheus_io_path]
    regex: "(.+)"
    target_label: __metrics_path__
```

Note the `(.+)`: with the default `(.*)` an empty annotation would blank the path. `(.+)` makes the rule a no-op when the annotation is absent.

**4. Combine address and annotation port**

```yaml
relabel_configs:
  - source_labels: [__address__, __meta_kubernetes_pod_annotation_prometheus_io_port]
    regex: "([^:]+)(?::\\d+)?;(\\d+)"
    replacement: "$1:$2"
    target_label: __address__
```

**5. Turn all Kubernetes labels into Prometheus labels**

```yaml
relabel_configs:
  - action: labelmap
    regex: __meta_kubernetes_pod_label_(.+)
```

A pod label `app=frontend` becomes the Prometheus label `app="frontend"`.

**6. Blackbox exporter redirection, the classic**

```yaml
scrape_configs:
  - job_name: blackbox
    metrics_path: /probe
    params:
      module: [http_2xx]
    static_configs:
      - targets:
          - https://example.com
          - https://prometheus.io
    relabel_configs:
      # The "target" we discovered is the URL to probe, not a scrape endpoint
      - source_labels: [__address__]
        target_label: __param_target
      # Keep the URL visible as the instance label
      - source_labels: [__param_target]
        target_label: instance
      # Actually connect to the exporter
      - target_label: __address__
        replacement: blackbox-exporter:9115
```

Read that three-rule block until it is automatic. It is the single most commonly examined relabeling snippet.

**7. Shard targets across Prometheus servers**

```yaml
relabel_configs:
  - source_labels: [__address__]
    modulus: 4
    target_label: __tmp_shard
    action: hashmod
  - source_labels: [__tmp_shard]
    regex: "^0$"
    action: keep
```

**8. Drop noisy metrics after the scrape**

```yaml
metric_relabel_configs:
  - source_labels: [__name__]
    regex: "go_.*|promhttp_.*|process_.*"
    action: drop
```

**9. Drop a high-cardinality label**

```yaml
metric_relabel_configs:
  - regex: "request_id|session_id"
    action: labeldrop
```

**10. Keep only what you need**

```yaml
metric_relabel_configs:
  - source_labels: [__name__]
    regex: "node_cpu_seconds_total|node_memory_.*|up"
    action: keep
```

**11. Rename a metric**

```yaml
metric_relabel_configs:
  - source_labels: [__name__]
    regex: "old_metric_name"
    target_label: __name__
    replacement: "new_metric_name"
```

**12. Strip the replica label from alerts so HA pairs dedupe**

```yaml
alerting:
  alert_relabel_configs:
    - regex: "replica"
      action: labeldrop
```

**13. Reduce remote_write cost**

```yaml
remote_write:
  - url: https://mimir/api/v1/push
    write_relabel_configs:
      - source_labels: [__name__]
        regex: "go_.*|promhttp_.*"
        action: drop
```

**14. Lowercase for consistency**

```yaml
relabel_configs:
  - source_labels: [__meta_ec2_tag_Environment]
    target_label: environment
    action: lowercase
```

### Where relabeling cannot help

- It cannot fix series already stored. Only new samples are affected.
- `metric_relabel_configs` runs **after** the scrape, so it does not reduce network or exporter load. To avoid scraping at all, filter at the SD level or with `relabel_configs`.
- It cannot compute arithmetic. Use recording rules.

### Debugging relabeling

The `/service-discovery` page shows discovered labels next to final labels for every target, including dropped ones. Use it.

```bash
promtool check service-discovery prometheus.yml <job_name>
curl -s 'http://localhost:9090/api/v1/targets?state=dropped' | jq '.data.droppedTargets[].discoveredLabels'
```

## Answers

**Q1: C.** `replace`.

**Q2: B.** `(.*)`, fully anchored, with a capture group so `$1` works by default.

**Q3: B.** A semicolon.

**Q4: C.** `$1`, the first capture group.

**Q5: B.** `drop` removes on match. `keep` removes on non-match.

**Q6: B.** `labeldrop` matches label **names** and removes them.

**Q7: B.** `labelmap` matches label names and copies values to labels named by `replacement`, typically using a capture group.

**Q8: B.** A non-matching `replace` rule does nothing. This is why the `(.+)` idiom matters, and why chained rules are safe.

**Q9: B.** Setting `replacement: ""` on a `target_label` deletes that label, since an empty label value equals an absent label.

**Q10: C.** `write_relabel_configs` inside the `remote_write` block.

**Q11: B.** Only pre-scrape filtering reduces target load. `metric_relabel_configs` runs after the response has already been fetched and parsed.

**Q12: C.** `__address__` must point at the blackbox exporter, because that is what Prometheus connects to.

**Q13: B.** `__param_target` becomes the `?target=` query parameter that tells the exporter what to probe.

**Q14: B.** `hashmod`, followed by a `keep` on the resulting shard label.

**Q15: B.** With the default `(.*)`, an absent annotation still matches (empty string), so `__metrics_path__` would be set to empty. `(.+)` requires at least one character, making the rule skip cleanly.

**Q16: B.** `alert_relabel_configs` with `labeldrop` on `replica`.

**Q17: B.** Sequential, top to bottom. Chaining through `__tmp_*` scratch labels relies on this.

**Q18: B.** Relabeling applies at ingest only. Old series age out with retention (or need the admin delete-series API).

**Q19: B.** `keepequal` compares the concatenated `source_labels` against `target_label`.

**Q20: B.** `/service-discovery` shows before and after label sets, including for dropped targets.

## Hands-on

Add a job that exercises many actions at once:

```yaml
  - job_name: relabel-demo
    static_configs:
      - targets: ["node-exporter:9100"]
        labels:
          Environment: PRODUCTION
          team: platform
          drop_me: yes
    relabel_configs:
      # lowercase
      - source_labels: [Environment]
        target_label: env
        action: lowercase
      # delete the original
      - regex: "Environment"
        action: labeldrop
      # build a composite label
      - source_labels: [env, team]
        separator: "/"
        target_label: owner
      # delete a label with an empty replacement
      - target_label: drop_me
        replacement: ""
      # hashmod for shard visibility
      - source_labels: [__address__]
        modulus: 4
        target_label: shard
        action: hashmod
```

```bash
promtool check config ~/pca-lab/prometheus/prometheus.yml
curl -X POST http://localhost:9090/-/reload
sleep 20
```

```promql
up{job="relabel-demo"}
```

Confirm the labels: `env="production"`, `owner="production/platform"`, no `Environment`, no `drop_me`, `shard` is a number 0-3.

Inspect the before and after in the API:

```bash
curl -s http://localhost:9090/api/v1/targets \
  | jq '.data.activeTargets[] | select(.scrapePool=="relabel-demo") | {discoveredLabels, labels}'
```

## Exam tips

- Defaults: `action: replace`, `regex: (.*)`, `separator: ;`, `replacement: $1`.
- `relabel_configs` = **targets, before** the scrape. `metric_relabel_configs` = **samples, after** the scrape.
- Only pre-scrape filtering reduces load on the target. Post-scrape dropping only saves storage.
- `keep` drops on **non**-match. `drop` drops on match.
- `labelmap`, `labeldrop`, `labelkeep` match label **names** and take no `source_labels`.
- A non-matching `replace` rule is a **no-op**. Prefer `(.+)` for optional inputs.
- `replacement: ""` deletes a label.
- Blackbox pattern, in order: `__address__` → `__param_target`, `__param_target` → `instance`, then `__address__` → exporter address.
- `hashmod` + `keep` = sharding.
- Rules are **sequential**. Use `__tmp_*` scratch labels for intermediate values.
- `alert_relabel_configs` + `labeldrop` on `replica` is how HA alert dedup works.
- `write_relabel_configs` cuts remote_write cost.
- Relabeling never rewrites stored data.
- `/service-discovery` is the debugger, and it shows dropped targets too.
