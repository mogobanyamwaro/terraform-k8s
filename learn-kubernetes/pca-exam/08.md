### Component responsibilities

| Component | Responsibility |
| --- | --- |
| **Retrieval / scrape manager** | Discovers targets, applies `relabel_configs`, performs HTTP GET, applies `metric_relabel_configs`, appends samples |
| **TSDB** | Stores samples. Head block in memory + WAL on disk, compacted into 2h immutable blocks |
| **PromQL engine** | Evaluates queries against the TSDB |
| **Rule manager** | Evaluates recording and alerting rules every `evaluation_interval` |
| **HTTP API + web UI** | `/graph`, `/targets`, `/rules`, `/alerts`, `/config`, `/service-discovery`, `/api/v1/*` |
| **Alertmanager** | Separate binary. Receives fired alerts, then deduplicates, groups, inhibits, silences, routes, notifies |
| **Exporters** | Translate third-party system state into Prometheus exposition format |
| **Pushgateway** | Cache for short-lived batch job metrics, which Prometheus then scrapes |
| **Client libraries** | In-process instrumentation, exposing `/metrics` |

### The critical division of labour

```text
PROMETHEUS decides WHEN an alert fires.       (rule expression + for duration)
ALERTMANAGER decides WHO gets told and HOW.   (routing, grouping, inhibition, silences)
```

Prometheus **pushes** alerts to Alertmanager over HTTP (`POST /api/v2/alerts`). This is the one place where Prometheus pushes. It re-sends firing alerts roughly every `evaluation_interval` while they remain active, so Alertmanager state is continually refreshed.

### Single-binary, single-node

Prometheus is intentionally a **single statically linked Go binary** with **local storage on the node**. There is no built-in clustering, no built-in sharding, no leader election.

High availability is achieved by **running two or more identical Prometheus servers scraping the same targets**. Alertmanager deduplicates the resulting duplicate alerts.

Long-term storage and global query views come from external systems via `remote_write`:

| System | Model |
| --- | --- |
| **Thanos** | Sidecar uploads blocks to object storage, Querier fans out, Store Gateway serves history, Compactor downsamples |
| **Cortex / Grafana Mimir** | Horizontally scalable, receives `remote_write`, microservices architecture |
| **VictoriaMetrics** | Alternative TSDB accepting `remote_write` |
| **Grafana Agent / Alloy** | Collection agent that forwards |

## Answers

**Q1: B.** Prometheus's rule manager evaluates the alerting expression and applies `for`. Alertmanager never decides whether a condition is true.

**Q2: B.** Grouping, inhibition, silencing, deduplication, and routing are all Alertmanager responsibilities.

**Q3: B.** Prometheus pushes to `POST /api/v2/alerts` on Alertmanager. This is the notable exception to "Prometheus always pulls".

**Q4: A.** 9090.

**Q5: C.** 9093 for the web and API. 9094 is the cluster gossip port.

**Q6: B.** Redundant identical scrapers plus Alertmanager deduplication. There is no built-in Prometheus clustering.

**Q7: C.** `/service-discovery` shows pre-relabel discovered labels alongside final target labels.

**Q8: C.** `/-/reload` and `/-/quit` need `--web.enable-lifecycle`. Health and readiness endpoints are always available.

**Q9: B.** `remote_write` streams samples out to systems like Thanos Receive, Mimir, Cortex, or VictoriaMetrics.

**Q10: B.** Local storage, no clustering. This is a deliberate design decision documented as a limitation.

**Q11: B.** The Sidecar runs next to Prometheus and ships blocks to object storage. The Compactor downsamples and compacts them there, the Querier fans out queries.

**Q12: B.** `relabel_configs` operates on the target's label set before the request is made. `metric_relabel_configs` operates on the labels of the samples returned.

**Q13: B.** `/config` shows the effective, currently loaded configuration.

**Q14: C.** Alertmanager is a separate binary and separate process.

**Q15: B.** Alerts are re-sent on each evaluation while firing. Delivery is not guaranteed, and failures surface in `prometheus_notifications_errors_total` and `prometheus_notifications_dropped_total`.

## Hands-on

Walk every UI page and note what it tells you:

```bash
for path in /targets /service-discovery /rules /alerts /config /flags /tsdb-status; do
  echo "=== $path ==="
  curl -s "http://localhost:9090${path}" -o /dev/null -w '%{http_code}\n'
done
```

Query Prometheus about itself:

```promql
# Build and version
prometheus_build_info

# Is the config load healthy? 1 = last reload succeeded
prometheus_config_last_reload_successful

# When was the config last reloaded?
prometheus_config_last_reload_success_timestamp_seconds

# Rule evaluation health
prometheus_rule_group_last_duration_seconds
prometheus_rule_evaluation_failures_total

# Notification pipeline to Alertmanager
prometheus_notifications_sent_total
prometheus_notifications_errors_total
prometheus_notifications_dropped_total
prometheus_notifications_queue_length

# Discovered Alertmanagers
count(prometheus_notifications_alertmanagers_discovered)
```

Prove Prometheus pushes to Alertmanager. Stop Alertmanager and watch errors climb:

```bash
docker stop alertmanager
sleep 60
```

```promql
increase(prometheus_notifications_errors_total[5m])
```

Restart it:

```bash
docker start alertmanager
```

Test reload behaviour:

```bash
# Without the flag this returns 405
curl -i -X POST http://localhost:9090/-/reload

# Break the config, then try to reload
echo "  bogus_key: true" >> ~/pca-lab/prometheus/prometheus.yml
curl -X POST http://localhost:9090/-/reload
```

```promql
prometheus_config_last_reload_successful
```

That returns 0. Prometheus keeps running the **old good config**. Fix the file and reload again.

Inspect the runtime:

```bash
curl -s http://localhost:9090/api/v1/status/runtimeinfo | jq
curl -s http://localhost:9090/api/v1/status/buildinfo | jq
curl -s http://localhost:9090/api/v1/status/flags | jq
curl -s http://localhost:9090/api/v1/status/config | jq -r '.data.yaml' | head -30
```

## Exam tips

- **Prometheus decides when. Alertmanager decides who and how.** This single sentence answers a surprising number of questions.
- Prometheus **pushes** alerts to Alertmanager. Everything else it does is pull.
- Ports: 9090 Prometheus, 9091 Pushgateway, 9093 Alertmanager, 9094 Alertmanager cluster, 9100 node_exporter, 9115 blackbox, 3000 Grafana.
- Prometheus is a single binary with local storage and **no clustering**. HA = run duplicates and let Alertmanager dedupe.
- `relabel_configs` = before the scrape, on target labels. `metric_relabel_configs` = after the scrape, on sample labels.
- `/-/reload` and `/-/quit` need `--web.enable-lifecycle`.
- A failed reload leaves the previous config running and sets `prometheus_config_last_reload_successful` to 0.
- Thanos: Sidecar uploads, Store Gateway serves history, Querier fans out, Compactor compacts and downsamples, Ruler evaluates rules globally.
- Alertmanager is **not** part of the Prometheus binary.
