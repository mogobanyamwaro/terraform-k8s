## Answers

**Q1: B.** `rate(up[5m])` reduces a range vector to an instant vector. A is a range vector, C is a type error, D is a string.

**Q2: B.** Fully anchored, so `web` matches only `web`. You need `.*web.*` or `web.*`.

**Q3: C.** `{instance=~".*"}` has no matcher that excludes the empty string. Adding a metric name would make it valid.

**Q4: B.** Rate first, then aggregate. Counters on different instances reset at different times, and summing raw values destroys the information needed for reset correction.

**Q5: C.** At least 4x the interval, so `2m`.

**Q6: B.** Extrapolation to the window boundaries produces fractional results. Expected and documented.

**Q7: B.** `irate()`. It is deliberately spiky and can miss activity between the last two samples.

**Q8: A.** `delta()` is for gauges and applies no reset correction, so it can be negative.

**Q9: B.** Simple linear regression across every sample in the window, yielding a per-second slope.

**Q10: B.** Fit the last hour, project one hour ahead, alert if it crosses zero.

**Q11: C.** The count-of-count idiom.

**Q12: B.** `by` is a keep-list, `without` is a drop-list.

**Q13: B.** `topk`, `bottomk`, `quantile`, `count_values`.

**Q14: B.** It preserves labels, which is why you can see which series is the outlier.

**Q15: B.** `@ end()` fixes the series set for the whole graph.

**Q16: C.** 3600 / 15 = 240.

**Q17: B.** `up` is 1 or 0, so its mean is the fraction of successful scrapes.

**Q18: B.** `expr[range:resolution]`, with the colon mandatory.

**Q19: B.** Cost. Recording rules pre-compute the inner expression once per evaluation interval.

**Q20: B.** No `bool` means filter. With `bool` means map to 1/0 and keep all series.

**Q21: B.** Filter with `> 2`, then `count()`. Note `sum(x > bool 2)` also works.

**Q22: B.** It sums the **load values**, not the count. This is the trap that Q21 sets up.

**Q23: B.** Label set mismatch. Diagnose by running each side alone and comparing labels.

**Q24: B.** `on()`. `by()` is for aggregation, not matching.

**Q25: B.** The arrow points at the many side.

**Q26: B.** Info metrics are always 1, so multiplication preserves the value while the join brings the label across.

**Q27: B.** Set difference.

**Q28: B.** `vector(0)` has no match on the left, so `or` includes it exactly when the left is empty.

**Q29: B.** Dropped.

**Q30: B.** Filtering comparisons return the original series unchanged, name included.

**Q31: B.** Quantile first, as a fraction.

**Q32: B.** `le` is required and plain `sum` removes it.

**Q33: B.** Aggregate buckets keeping `le`, then take the quantile once.

**Q34: B.** The estimate saturates at the highest finite boundary, giving a falsely optimistic reading.

**Q35: B.** `rate(_sum) / rate(_count)`.

**Q36: B.** Read the pre-computed quantile directly. A fails (no `le`), C is mathematically invalid, D has no `le` to group by.

**Q37: B.** A scalar equal to the evaluation step's timestamp.

**Q38: B.** 0. Saturday is 6.

**Q39: B.** Destination second, source second-to-last.

**Q40: B.** `absent()` only produces output when its argument is empty.

## Exam tips

- **Type discipline** first. Scan any candidate answer for `rate()` on an instant vector or an aggregator on a range vector.
- **`histogram_quantile(0.95, sum by (le) (rate(x_bucket[5m])))`** is the single most important query shape in the exam. Write it out from memory ten times.
- **Rate before aggregate.** Never the reverse.
- `bool` on a comparison keeps all series and returns 1/0. Without it, comparison filters.
- `on`/`ignoring` for matching, `by`/`without` for aggregation.
- `group_left` = many on the left.
- Empty result from a binary op = label mismatch, 90% of the time.
- Subquery colon is mandatory: `[1h:1m]`.
- `offset` goes inside: `rate(x[5m] offset 1h)`.
- `@ end()` stabilises `topk` in graphs.
- Range ≥ 4x scrape interval.
