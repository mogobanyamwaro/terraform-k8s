# Kyverno Certified Associate (KCA) Practice

This folder mirrors `prometheus`, `backstage`, and `opentelemetry`: **closed-book multiple choice**, not a live cluster like CKA or CKS.

Outline checked against the Linux Foundation [KCA page](https://training.linuxfoundation.org/certification/kyverno-certified-associate-kca/), [CNCF KCA](https://www.cncf.io/training/certification/kca/), and [kyverno.io](https://kyverno.io/docs/) on 2026-08-19.

KCA is **the Kyverno product exam**: YAML policies, admission, CLI, reports. It is not CKS (broader cluster security, live terminal) and not “OPA/Gatekeeper Rego.”

A minimally qualified candidate can read a `ClusterPolicy`, tell **validate / mutate / generate / verifyImages** apart, run `kyverno apply` / `kyverno test`, and know Audit vs Enforce.

## Universal KCA Reasoning Flow

```text
1. Is it Policy or ClusterPolicy?
     Namespaced vs cluster-wide
2. Which rule type?
     validate | mutate | generate | verifyImages | cleanup CR
3. When does it run?
     Admission (CREATE/UPDATE) vs background scan vs generate/sync
4. Fail the request or only report?
     Enforce vs Audit; webhook failurePolicy is a different knob
5. Shift-left?
     kyverno apply / kyverno test / jp  — not kubectl first
```
