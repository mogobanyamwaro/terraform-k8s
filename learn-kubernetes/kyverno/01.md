# 01. Policies and Rules

**Domain:** Fundamentals of Kyverno (18%)

## Concept Refresher

Kyverno is a **Kubernetes-native policy engine**: policies are YAML CRs, not Rego.

| Kind | Scope |
| --- | --- |
| **Policy** | Namespaced — applies to resources **in that namespace** (plus some cluster-scoped caveats) |
| **ClusterPolicy** | Cluster-wide |

A policy contains **rules**. Each rule has a name and typically **one** type:

| Rule | Effect |
| --- | --- |
| **validate** | Allow or deny (or audit) the request |
| **mutate** | Patch the resource |
| **generate** | Create other resources |
| **verifyImages** | Check signatures/attestations |

**Cleanup** is a separate CR (`CleanupPolicy` / `ClusterCleanupPolicy`), not a `spec.rules[].validate` sibling in classic v1.

Match/exclude select **which** objects. Preconditions further filter.

Kyverno sits on **admission webhooks** plus **background** controllers.

## Hands-on

`kubectl get clusterpolicies,policies -A`. Read one policy and name its rule types.

## Exam tips

- **ClusterPolicy ≠ Policy.**
- Four verbs: validate, mutate, generate, verifyImages.
