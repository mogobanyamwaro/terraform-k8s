# 10. `kyverno test`

**Domain:** Kyverno CLI (12%)

## Concept Refresher

**`kyverno test`** runs **fixtures**: policies + resources + expected results.

Typical layout:

```text
test.yaml          # or kyverno-test.yaml
policy.yaml
resource-pass.yaml
resource-fail.yaml
```

```yaml
name: require-labels
policies:
  - policy.yaml
resources:
  - pod-ok.yaml
  - pod-bad.yaml
results:
  - policy: require-labels
    rule: check-team
    resource: good
    kind: Pod
    result: pass
  - policy: require-labels
    rule: check-team
    resource: bad
    kind: Pod
    result: fail
```

```bash
kyverno test .
```

CI should fail the pipeline on test failure. This is **stronger** than ad-hoc `apply` because expectations are encoded.

`result` values: pass, fail, skip, warn (as documented for the version).

Mutate tests can compare **patched** resources. Generate tests can check cloned objects.
