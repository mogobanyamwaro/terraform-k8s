# 06. Kyverno CRDs

**Domain:** Installation, Configuration, and Upgrades (18%)

## Concept Refresher

Helm installs **CRDs** in `kyverno.io` (and reports APIs). Without CRDs, `kubectl apply -f clusterpolicy.yaml` fails.

High-yield kinds:

| Kind | Role |
| --- | --- |
| ClusterPolicy, Policy | Rules |
| PolicyException | Break-glass / allowlist |
| CleanupPolicy, ClusterCleanupPolicy | Scheduled delete |
| PolicyReport, ClusterPolicyReport | Results (OpenReports / policy report CRDs) |
| UpdateRequest | Generate/mutate-existing work queue |
| AdmissionReport / BackgroundScanReport | Internal report sources |

`kubectl get crds | grep kyverno` is the sanity check.

CRDs must be upgraded **with** Kyverno (Helm usually handles). Old CRD + new controller = version skew.

Users writing policies need RBAC to create ClusterPolicy (cluster-admin or a dedicated role) — next file.
