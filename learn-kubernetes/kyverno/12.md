# 12. Applying Policies in Cluster

**Domain:** Applying Policies (10%)

## Concept Refresher

Install policy CRs with `kubectl apply` / GitOps. They must exist **in-cluster** to affect admission.

**`validationFailureAction`**

| Value | Admission | Reports |
| --- | --- | --- |
| **Audit** | Allow violating requests | Fail recorded |
| **Enforce** | **Deny** violating requests | Fail recorded |

Default has historically been Audit — **do not assume Enforce**. Roll out Audit → watch reports → Enforce.

`validationFailureActionOverrides` per namespace.

**`failurePolicy`** on the policy (Ignore/Fail) relates to **errors evaluating** the policy, distinct from Audit/Enforce.

**`webhookTimeoutSeconds`**. **`schemaValidation`**. **`applyRules: One/All`**.

GitOps: treat policies as code; `kyverno test` in CI then apply.

Deleting a ClusterPolicy stops new enforcement; existing mutated fields remain.
