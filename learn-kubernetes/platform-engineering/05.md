# 05. Platform Architecture and Capabilities

**Domain:** Core Fundamentals (36%)

## Concept Refresher

A cloud native platform is a **stack of capabilities** with a **user-facing API/UX**, not a single binary.

**Typical capability map**

```text
Developer experience (portal, templates, docs)
        |
 Golden paths (CI, GitOps, app chart)
        |
 Policy, identity, tenancy
        |
 Observability, secrets, service comms
        |
 Runtime (Kubernetes) + infra APIs (Crossplane, CAPI)
        |
 Cloud / datacenter
```

**Architecture principles**

- **Modular:** swap Prometheus vs vendor metrics without rewriting the portal
- **API-first:** everything a human can click, a CR/API can do
- **Secure/observable by default**
- **Least privilege** between layers
- **Multi-cluster** as a product (fleet) when you outgrow one API server
- **Control plane vs data plane:** platform control (Argo, Crossplane, portal) may sit in a management cluster

**Capabilities vs tools:** “we need service identity” not “we must buy Istio.” Service mesh is **one** way to do mTLS.
