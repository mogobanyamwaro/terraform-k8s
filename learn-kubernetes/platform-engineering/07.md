# 07. Continuous Delivery and GitOps (Core)

**Domain:** Core Fundamentals (36%)

## Concept Refresher

**CD:** automatically take a **proven artifact** to an environment (often with progressive delivery). Humans review **Git**, not SSH.

**GitOps** (platform capability): desired state in Git; an **agent pulls** and **reconciles** (Argo CD, Flux, Config Sync). See `gitops` for pillar wording; CNPA asks **why the platform offers it**.

Why platforms standardise GitOps:

- Same path for 50 teams
- Audit (Git history) and rollback (revert commit)
- Cluster credentials stay with the agent
- Env promotion = PR to `prod/` overlay

**CD without GitOps** (push from CI) can exist; CNPA still prefers pull for Kubernetes estates.

Progressive delivery (canary) may sit **on** GitOps (Rollout object in Git) — capability combo, not a single tool religion.

This file is **core**. Domain 3 (`13–16`) goes deeper on pipelines, incidents, and env GitOps.
