# 06. Continuous Integration Fundamentals

**Domain:** Core Fundamentals (36%)

## Concept Refresher

**CI:** on every change, **automatically** build, test, and produce **immutable artifacts** (image digest, SBOM). Fast feedback to the author.

Platform CI **product**:

- Reusable pipeline templates (GitHub Actions reusable workflows, GitLab includes, Tekton/Argo Workflows)
- Shared runners with caching
- Required checks on the **app** repo (unit, lint, SAST, image scan)
- Output: **digest** + provenance, not `:latest`
- CI does **not** need cluster-admin to prod (that is CD/GitOps)

**Fundamentals**

| Idea | Platform encoding |
| --- | --- |
| Every commit is a candidate | PR pipelines |
| Fail fast | Short unit stage before heavy e2e |
| Hermetic / repeatable | Pinned actions/images, lockfiles |
| Trunk-based / small batches | Enables DORA frequency |
| Artifact promotion | Build once |

CI vs CD: CI **proves** a revision; CD **deploys** a proven revision. Mixing `kubectl apply` into CI is the classic anti-pattern (also CGOA).
