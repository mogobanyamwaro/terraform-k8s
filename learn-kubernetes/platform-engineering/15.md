# 15. GitOps Workflows and Application Environments

**Domain:** Continuous Delivery & Platform Engineering (16%)

## Concept Refresher

**Workflows** (here) = how teams **promote** across envs with Git, not Argo Workflows DAGs.

Patterns:

| Pattern | How prod changes |
| --- | --- |
| Directory overlays | PR copies digest into `prod/` |
| Kustomize / Helm values | Same |
| Environment branches | Merge `staging` → `prod` (review) |
| App-of-Apps / ApplicationSet | Platform composes many apps |
| PR previews | Temporary env; TTL |

**Per-env GitOps**

- Separate sync windows, policies, approval (CODEOWNERS on `prod/`)
- Same engine, different **destinations**
- Secrets: SOPS/Sealed per env, not copied plaintext

**Multi-cluster:** `destination` per env cluster; still one desired-state repo family.

Break-glass: kubectl then **commit** (or Git will fight).

Deeper GitOps theory: `gitops`. Here: **env product**.
