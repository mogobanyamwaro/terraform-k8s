# 04. Application Environments and Infrastructure

**Domain:** Core Fundamentals (36%)

## Concept Refresher

**Environment:** a slice of the platform where an app revision runs (dev, test, staging, prod) with **isolation**, **data**, **policy**, and **promotion** rules.

Platform choices:

| Pattern | Notes |
| --- | --- |
| Namespaces on a shared cluster | Cheap; need NetworkPolicy, quotas, PSS |
| Separate clusters per env/team | Strong isolation; more cost/ops |
| vClusters / projects | Middle ground |
| Ephemeral PR previews | Fast feedback; ApplicationSet/PRs, TTL |

**Promotion** should be **Git/config** (same artifact, new overlay), not “rebuild for prod.”

**Infrastructure concepts** the platform hides or products:

- Compute (nodes, Karpenter, Cluster API)
- Networking (CNI, Ingress/Gateway, mesh optional)
- Identity (OIDC, workload identity, RBAC)
- Data (operators for Postgres, object storage classes)
- Tenancy and chargeback

**Dev/prod parity:** same golden path, smaller size, fake secrets, not a totally different assembler.

Snowflake “prod is special snowflake terraform” is a maturity smell.

## Exam tips

- **Promote artifacts, not rebuilds.**
- Isolation is a **choice**, always with guardrails.
- Platform owns the **boring infra**; apps own **app config**.
