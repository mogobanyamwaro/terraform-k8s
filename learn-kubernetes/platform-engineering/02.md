# 02. DevOps Practices in Platform Engineering

**Domain:** Core Fundamentals (36%)

## Concept Refresher

**DevOps** (culture): share responsibility for **build, run, and feedback**. Silos (throw over wall to Ops) are the anti-pattern.

**Platform engineering** encodes DevOps into **paved paths**: CI, CD/GitOps, observability, security defaults so *every* team can practise DevOps without each inventing a toolchain.

Practices the platform should **productise**

| Practice | Platform shape |
| --- | --- |
| CI | Shared pipeline templates, caches, runners |
| CD / GitOps | Env promotion via Git, not laptop kubectl |
| IaC / CaC | Modules, compositions, Git as desired state |
| Feedback | OTel, SLOs, error budgets on apps **and** platform |
| You build it, you run it | App team on-call for *their* service; platform on-call for *the path* |
| Blameless learning | Incident reviews; platform fixes classes of failure |

**Team topologies:** stream-aligned app teams; platform team provides an internal product; enabling team coaches. Avoid the platform team becoming the **only** people who can deploy.

CALMS (Culture, Automation, Lean, Measurement, Sharing) still applies — automation and measurement are how platforms scale Culture.
