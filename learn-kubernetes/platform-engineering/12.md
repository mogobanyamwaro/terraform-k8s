# 12. Security in CI/CD Pipelines

**Domain:** Observability, Security, and Conformance (20%)

## Concept Refresher

The pipeline is part of the **trusted computing base**. Compromise CI ⇒ compromise prod.

**Practices**

| Control | Idea |
| --- | --- |
| Least privilege runners | No prod kubeconfig; OIDC to cloud |
| Isolated / ephemeral runners | Untrusted PRs cannot steal secrets |
| Pin actions/images | Supply chain of the pipeline itself |
| SAST / SCA / image scan | Default template stages |
| SBOM + signing (Sigstore) | Provenance |
| SLSA-ish | Build attested, isolated |
| Secrets | Vault/OIDC, not long-lived PATs in logs |
| Branch protection | Required reviews + checks |
| CD identity | GitOps agent SA, not CI |

Fork PR pipelines must not expose **write** secrets (classic GitHub Actions trap).
