# 22. Apply ResourceQuota And LimitRange

**Domain:** Minimize Microservice Vulnerabilities

## Question

In namespace `cks-22`, prevent resource exhaustion by setting default container requests/limits and a namespace ResourceQuota.

## Answer

Create namespace:

```bash
kubectl create namespace cks-22
```

Create a LimitRange:

```yaml
apiVersion: v1
kind: LimitRange
metadata:
  name: default-container-limits
  namespace: cks-22
spec:
  limits:
  - type: Container
    defaultRequest:
      cpu: 100m
      memory: 128Mi
    default:
      cpu: 500m
      memory: 512Mi
```

Create a ResourceQuota:

```yaml
apiVersion: v1
kind: ResourceQuota
metadata:
  name: namespace-quota
  namespace: cks-22
spec:
  hard:
    pods: "10"
    requests.cpu: "1"
    requests.memory: 1Gi
    limits.cpu: "2"
    limits.memory: 2Gi
```

Apply:

```bash
kubectl apply -f limitrange.yaml
kubectl apply -f quota.yaml
```

Create a pod without resources:

```bash
kubectl run app -n cks-22 --image=nginx:1.27
```

## Verify

```bash
kubectl describe limitrange default-container-limits -n cks-22
kubectl describe resourcequota namespace-quota -n cks-22
kubectl get pod app -n cks-22 -o yaml | grep -A8 resources
```

Expected: Kubernetes defaults should be added from the LimitRange.

## Exam tips

- Resource limits reduce denial-of-service risk from noisy workloads.
- A LimitRange can default missing requests/limits.
- A ResourceQuota caps total namespace consumption.
