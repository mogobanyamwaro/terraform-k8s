# 03. Admission Controllers

**Domain:** Fundamentals of Kyverno (18%)

## Concept Refresher

```text
kubectl apply
  → kube-apiserver authentication/authorization
  → MutatingAdmissionWebhooks  (Kyverno mutate)
  → object schema defaults
  → ValidatingAdmissionWebhooks (Kyverno validate / verifyImages)
  → persist etcd
```

Kyverno registers **mutating** and **validating** webhook configurations. If the webhook is **down** and `failurePolicy=Fail`, **admission can block** cluster-wide (fail closed). `Ignore` fails open (requests proceed; policies not evaluated).

Do not confuse:

| Knob | Meaning |
| --- | --- |
| Webhook `failurePolicy` | What if **Kyverno is unreachable** |
| `validationFailureAction` | Audit vs **Enforce** when a **policy** fails |

**background** scans do not go through that same user request path; the background controller lists objects and writes reports (and can mutate/generate existing when configured).

Timeouts: `webhookTimeoutSeconds` on the policy / webhook. Too low → webhook errors.
