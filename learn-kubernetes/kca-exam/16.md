# 16. Mutation and JSON Patches

**Domain:** Writing Policies (32%)

## Concept Refresher

**patchStrategicMerge** (K8s-style overlay):

```yaml
mutate:
  patchStrategicMerge:
    metadata:
      labels:
        +(env): prod          # add if not present (+ / ^ style per version)
    spec:
      containers:
        - (name): "*"
          imagePullPolicy: IfNotPresent
```

**patchesJson6902** (RFC 6902):

```yaml
mutate:
  patchesJson6902: |-
    - op: add
      path: /metadata/annotations/foo
      value: bar
```

JSON patch paths use `/` and must escape `~` and `/` in keys (`~1`, `~0`).

**targets** + **mutateExisting** — patch objects other than the triggering resource.

Mutate runs in the **mutating webhook**. Order: Kyverno among other mutators (reinvocation policy).

Don’t mutate immutable fields after creation (Pod most spec). Prefer CREATE.

Strategic merge vs JSON patch: maps/lists (merge keys like `name` on containers) vs explicit ops.
