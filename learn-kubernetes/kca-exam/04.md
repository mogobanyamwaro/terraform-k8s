# 04. OCI Images (Policies as Artifacts)

**Domain:** Fundamentals of Kyverno (18%)

## Concept Refresher

Kyverno treats **OCI** in two ways:

1. **Workload images** — `verifyImages` (signatures, attestations, digests). That is writing-policies domain; here: *images exist in registries*.
2. **Policy-as-OCI** — store policy YAML as an **OCI artifact**, pull/apply without a Git clone.

CLI can apply from a registry reference (`oci://…` / documented `kyverno apply` OCI forms). Cosign can **sign** policy artifacts like images.

Cluster install still uses Helm/YAML; OCI is a **distribution** channel (GitOps, air-gap, signed policies).

`imageRegistry` context in policies looks up tags/digests at admission (API call to registry) — related but not “policy stored in OCI.”

Don’t confuse: verifying **app** images vs fetching **policy** YAML from OCI.
