# 07. Controllers, Flags, and RBAC

**Domain:** Installation, Configuration, and Upgrades (18%)

## Concept Refresher

Four controller roles (names vary by chart):

| Controller | Job |
| --- | --- |
| **admission-controller** | Webhooks: mutate/validate/verifyImages |
| **background-controller** | Background scans, generate/sync, mutate existing |
| **reports-controller** | PolicyReports |
| **cleanup-controller** | CleanupPolicy schedules |

**Flags / args** (Helm `extraArgs` / container args): enable/disable reports, webhook names, logging, `backgroundScan`, feature gates. Exam: **admission vs background vs reports vs cleanup** — not every flag.

**RBAC**

- Controllers need get/list/watch on matched resources, plus create/patch for generate/mutate, plus report CRDs.
- **Too little** RBAC → generate fails, background skips.
- **Users** creating ClusterPolicy need `create` on `clusterpolicies.kyverno.io`.
- Don’t give Kyverno `cluster-admin` without a reason; chart ships Roles/ClusterRoles.

ServiceAccount in `kyverno` namespace. Webhook certs via cert manager or Kyverno’s certs.
