# 20. Cleanup Policies and CEL

**Domain:** Writing Policies (32%)

## Concept Refresher

**CleanupPolicy / ClusterCleanupPolicy** (`kyverno.io/v2`) — **cron** delete of matched resources.

```yaml
apiVersion: kyverno.io/v2
kind: ClusterCleanupPolicy
metadata:
  name: delete-temp
spec:
  schedule: "0 * * * *"
  match:
    any:
      - resources:
          kinds: [Pod]
          namespaces: [scratch]
          selector:
            matchLabels: { ephemeral: "true" }
  conditions:
    all:
      - key: "{{ time_since('', '{{ object.metadata.creationTimestamp }}', '') }}"
        operator: GreaterThan
        value: 24h
```

This is **not** `validationFailureAction`. Cleanup **deletes**. Needs cleanup-controller + RBAC.

**CEL** (Common Expression Language) — Kubernetes-native expressions (same family as ValidatingAdmissionPolicy):

```yaml
validate:
  cel:
    expressions:
      - expression: "object.spec.containers.all(c, has(c.resources.limits))"
        message: "limits required"
```

Kyverno can also generate Kubernetes **ValidatingAdmissionPolicy** from CEL in some versions. Exam: CEL is an official writing competency alongside overlay/deny.

CEL vs JMESPath: different syntax; both appear on KCA.
