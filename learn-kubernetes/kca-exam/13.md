# 13. Resource Selection and Common Settings

**Domain:** Applying Policies (10%)

## Concept Refresher

**Selection**

```yaml
match:
  any:
    - resources:
        kinds: [Pod, Deployment]
        namespaces: [prod, staging]
        names: ["web-*"]
        selector:
          matchLabels: { team: platform }
        annotations:
          foo: bar
        operations: [CREATE, UPDATE]
```

`operations`: CREATE, UPDATE, DELETE, CONNECT. Default CREATE/UPDATE for most validate.

User matching: `subjects`, `clusterRoles`, `roles` under match (who made the request).

**Common settings**

| Field | Meaning |
| --- | --- |
| `background` | Scan existing objects |
| `skipBackgroundRequests` | Don’t evaluate Kyverno’s own SA |
| `failurePolicy` | Ignore/Fail on **engine errors** |
| `admission` | Enable/disable admission for the policy |
| `emitWarning` | Warnings on allow |
| `webhookTimeoutSeconds` | Per policy |

`exclude` for kube-system / Kyverno namespace is a common pattern so you don’t lock yourself out.

`preconditions` (writing domain) further narrow after match.
