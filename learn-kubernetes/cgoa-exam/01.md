# 01. Declarative Description and Desired State

**Domain:** GitOps Terminology (20%)

## Concept Refresher

**Declarative description** (OpenGitOps): configuration that describes the **desired operating state** without specifying **procedures** (commands, API calls, scripts) for how to get there. *What*, not *how*.

**Desired state**: the aggregate of all configuration data **sufficient to recreate the system** so instances are behaviourally indistinguishable. It usually **does not** include database contents; it often **does** include credentials *references* or backup-tool config.

**Actual state**: what the runtime really is right now (live cluster, VMs, cloud resources).

GitOps stores desired state in the **state store**. The reconciler makes actual ≈ desired.

Kubernetes YAML, Terraform (mostly), Helm values, Crossplane composites are declarative. `kubectl run`, bash `aws ec2 run-instances` loops, Ansible *imperative* shell tasks as the *source of truth* are not.

## Hands-on

Compare `kubectl create deployment --image=nginx` (imperative) vs a YAML file in Git (declarative).

## Exam tips

- Glossary wording: **without specifying procedures**.
- Desired state **recreates the system**; it is not the live cluster.
