# 18. Reconciliation Engines (Argo CD, Flux, Alternatives)

**Domain:** Tooling (14%)

## Concept Refresher

A **reconciliation engine** is the software agent: pull desired state, compare actual, apply.

**Argo CD** (CNCF): Application CR, UI, SSO, sync policies (automated, self-heal, prune), multi-cluster destinations, App-of-Apps / ApplicationSets. Opinionated GitOps **app** delivery.

**Flux** (CNCF GitOps Toolkit): composable controllers — Source (Git/OCI/Helm), Kustomize, Helm, Notification, Image automation. Kubernetes-native, GitOps for **more than apps** (also platform addons). No required UI (there are UIs).

**Jenkins X:** GitOps-ish Kubernetes CD (know it exists; less detail).

**Alternatives:** Rancher Fleet, Config Sync (Anthos), Pulp/others, home-grown operators, Terraform controllers (tf-controller / Atlantis — map carefully: Atlantis is PR-plan/apply, not always a continuous cluster loop).

Exam is **vendor-neutral**: engines must **adhere to and extend** the four principles. A fancy UI that only click-syncs without Git is not an engine.

**Self-heal / prune / interval** = continuous reconciliation knobs.
