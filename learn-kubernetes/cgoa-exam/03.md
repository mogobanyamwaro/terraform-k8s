# 03. State Store, Managed System, Feedback Loop

**Domain:** GitOps Terminology (20%)

## Concept Refresher

**State store**: stores **immutable versions** of desired-state declarations. Must provide **access control** and **auditing**. Git is the **canonical** example. Other systems may be used **if** they meet the principles (versioned, immutable, history, ACL, audit). OCI registries (Flux OCIRepository), some artifact stores — with precautions.

**GitOps managed software system** includes:

1. One or more **runtime environments** (resources under management)
2. **Management agents** in each runtime
3. **Policies** controlling access to repos, deployments, runtimes

**Feedback** (closed loop, control theory): how previous apply attempts affected actual state. Examples: not enough quota → retry, alert humans, or auto-rollback. Feedback is **not** only a Slack notification, but notifications are a common implementation.

## Hands-on

Look at Git history of a config repo (`git log`). That history *is* the state store property the exam wants.

## Exam tips

- Store = **desired** declarations, not etcd.
- System = **runtimes + agents + policies**.
- Feedback = **control loop**, not only ChatOps.
