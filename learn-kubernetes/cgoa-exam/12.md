# 12. Deployment and Release Patterns

**Domain:** GitOps Patterns (20%)

## Concept Refresher

**Deploy** = bits on a cluster. **Release** = traffic/users see them. GitOps can declare both (Deployments + Service/Ingress weights, feature flags).

| Pattern | Idea |
| --- | --- |
| Recreate | Down then up (downtime) |
| Rolling | Surge new pods, drain old |
| Blue/green | Two stacks; flip Service/Ingress |
| Canary | Small % traffic to new |
| Shadow | Copy traffic, don’t serve users (mirroring) |

In GitOps, the **switch** is a Git change (Service selector, Istio/Cilium weights, Argo Rollouts spec, Flagger). The agent applies it.

Kubernetes default Deployment is **rolling**. Blue/green is two Deployments + Service selector in Git.

**Environment promotion:** same artifact, new desired state: `dev/` → `staging/` → `prod/` folders, or PRs between branches. Prefer **same image digest** promoted, not rebuild.

## Hands-on

Declare a Deployment and a Service, then a second Service or flag that “releases” traffic. Deploy and release are different Git objects.

## Exam tips

- **Promotion = Git change of the same artifact.**
- Patterns live **in** desired state; GitOps **applies** them.
