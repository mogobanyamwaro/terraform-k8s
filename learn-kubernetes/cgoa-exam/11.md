# 11. CI, CD, and Mapping to GitOps

**Domain:** Related Practices (16%)

## Concept Refresher

**CI (Continuous Integration):** build, test, scan on every change. Output: **artifact** (container image, chart) + test evidence.

**CD (Continuous Delivery/Deployment):** get that artifact into environments. GitOps is a **CD style**, not a CI replacement.

Healthy split:

```text
App git push
  -> CI: test, build image, push registry, optionally PR/commit new tag into CONFIG repo
  -> GitOps agent: pull CONFIG repo, reconcile cluster
```

Anti-pattern:

```text
CI: kubectl apply -f k8s/ --context prod
```

**Continuous Delivery** vs **Continuous Deployment**: delivery = always *able* to release (maybe manual prod button). Deployment = every change that passes goes out. GitOps supports both: **automated sync** vs **manual sync** on prod Application.

GitOps does not remove CI. Without CI you have untested YAML.

## Exam tips

- **CI builds. GitOps reconciles.**
- Updating Git from CI is OK. Applying to the cluster from CI is the trap.
