# 16. Manifest Format and Packaging

**Domain:** Tooling (14%)

## Concept Refresher

Desired state must be **renderable to a declarative API**. Common packaging:

| Format | Notes |
| --- | --- |
| Plain YAML/JSON | Simplest, verbose |
| **Kustomize** | Overlay patches, no templates; native `kubectl -k` |
| **Helm** | Templated charts, values per env; versioned charts |
| Jsonnet / CUE / cdk8s | Generate YAML |
| Kustomize + Helm | Helm inflator / post-render |
| OCI Helm charts | Chart as artifact, not only git tree |

**Precautions** (exam wording):

- Templates must still produce **deterministic**, **versioned** output (`:latest` in values is bad)
- Helm `latest` chart version floating
- Secrets in templates
- Overlays that silently differ from base
- Binary/unreadable generated files without source
- Server-side vs client-side render (who renders: CI or in-cluster Helm)

GitOps engines: Argo CD supports Helm/Kustomize/directory; Flux has HelmRelease + Kustomization.

Prefer **pin chart version + image digest**.
