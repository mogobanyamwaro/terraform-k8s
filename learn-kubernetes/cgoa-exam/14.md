# 14. Pull vs Event-Driven

**Domain:** GitOps Patterns (20%)

## Concept Refresher

**Pull-based:** agent periodically (and/or on webhook) **fetches** Git. This **is** GitOps principle 3.

**Event-driven:** a webhook/event bus **notifies** the agent immediately on git push, image push, or alert. Faster. Must not **replace** the pull loop.

**Push-based:** pipeline **pushes** manifests into the cluster. Events trigger the pipeline. Classic Jenkins/GitHub Actions `kubectl`. **Not** GitOps even if “event-driven”.

Exam trap: “event-driven GitOps” = **events accelerate pull**, not “CI pushes YAML”.

Image events: Flux image automation / Argo Image Updater **open a Git commit** (desired state change), then pull/reconcile. The cluster is still not receiving `kubectl` from the registry webhook.

## Exam tips

- **Event ≠ push.** Event + pull = GitOps. Event + kubectl = not.
- Polling is the safety net.
