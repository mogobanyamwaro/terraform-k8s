# Certified GitOps Associate (CGOA) Practice

This folder mirrors `pca-exam` and `cca-exam`: **closed-book multiple choice**, not a live cluster like CKA or ICA.

Outline checked against the Linux Foundation [CGOA page](https://training.linuxfoundation.org/certification/certified-gitops-associate-cgoa/), CNCF CGOA, OpenGitOps Principles/Glossary v1.0.0, and the CD Foundation exam notes on 2026-08-19.

The exam is **vendor-neutral**. Argo CD and Flux appear as **reconciliation engines**, not as a product certification. If a question can be answered from OpenGitOps without naming a tool, that is the intended answer.

## The Four Principles (memorise the official sentences)

1. **Declarative** — A system managed by GitOps must have its desired state expressed declaratively.
2. **Versioned and Immutable** — Desired state is stored in a way that enforces immutability, versioning and retains a complete version history.
3. **Pulled Automatically** — Software agents automatically pull the desired state declarations from the source.
4. **Continuously Reconciled** — Software agents continuously observe actual system state and attempt to apply the desired state.

## Universal CGOA Reasoning Flow

```text
1. Is the desired state in an immutable, versioned store (usually Git)?
   No  -> not GitOps (wiki, kubectl, chatops apply)
   Yes -> continue

2. Did a cluster (or management) AGENT PULL it, or did CI PUSH kubectl/helm?
   Push-only pipeline -> CI/CD, not GitOps
   Pull (webhook optional as accelerator) -> GitOps-shaped

3. Does something keep comparing actual vs desired and reconciling drift?
   One-shot apply -> not continuously reconciled
   Loop / controller -> GitOps

4. Is the description declarative (what) not imperative (how)?
   bash that calls APIs as the source of truth -> fails Declarative
```

## GitOps Truths

- Git is the **canonical** state store, not the only possible one. Alternatives must still be versioned, immutable, access-controlled, and auditable.
- **Continuous** means reconciliation keeps happening, **not** that it is instantaneous.
- Rollback in GitOps is a **new desired state** (revert/commit), not a hidden cluster mutation that Git will fight.
- `:latest` and floating tags violate **versioned and immutable**.
- Webhooks **speed up** pull; they must not be the **only** way the agent learns desired state.
- CI **builds artifacts** and may **commit image tags** to the config repo. CD **reconciles the cluster**. Mixing them into `kubectl apply` from the CI runner is the classic anti-pattern.
