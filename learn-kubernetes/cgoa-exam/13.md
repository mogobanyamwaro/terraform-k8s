# 13. Progressive Delivery Patterns

**Domain:** GitOps Patterns (20%)

## Concept Refresher

**Progressive delivery**: release gradually, measure, decide (promote or rollback). Includes canary, A/B, feature flags, blue/green with analysis.

Tools you should **recognise** (not master): **Argo Rollouts**, **Flagger** (often with Flux/Istio/Contour), **Keptn**, some mesh traffic splits.

Analysis: Prometheus/metrics, success rate, latency. Failed analysis → **rollback desired state** (ReplicaSet/weight in Git or Rollout object).

GitOps fit: Rollout CR is **declarative** in Git; the Rollout controller is another reconciler. Still pull-based if Git is source.

Progressive delivery is **not** a fifth OpenGitOps principle; it is a **pattern** on top.
