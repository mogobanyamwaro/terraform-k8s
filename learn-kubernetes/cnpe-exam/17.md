# 17. Prometheus ServiceMonitor and Alert

**Domain:** Observability (20%)

## Question

Namespace `cnpe-17` has Deployment `api` with Prometheus annotations **or** you add a `ServiceMonitor`.

1. Service `api` port `http` **8080**, label `app=api`.
2. `ServiceMonitor` `api` in `cnpe-17` selecting that Service, interval **30s**, path `/metrics`.
3. `PrometheusRule` `api-alerts`: alert `ApiDown` when `up{job="api"} == 0` for **1m**, severity `critical`.

Label the namespace `prometheus=monitor` if the operator uses that selector (check existing Prometheus CR `serviceMonitorNamespaceSelector`).

## Answer

```yaml
apiVersion: monitoring.coreos.com/v1
kind: ServiceMonitor
metadata:
  name: api
  namespace: cnpe-17
  labels:
    release: kube-prometheus-stack   # MATCH the Prometheus selector
spec:
  selector:
    matchLabels: {app: api}
  endpoints:
  - port: http
    interval: 30s
    path: /metrics
---
apiVersion: monitoring.coreos.com/v1
kind: PrometheusRule
metadata:
  name: api-alerts
  namespace: cnpe-17
  labels:
    release: kube-prometheus-stack
spec:
  groups:
  - name: api
    rules:
    - alert: ApiDown
      expr: up{job="api"} == 0
      for: 1m
      labels: {severity: critical}
      annotations:
        summary: API scrape is down
```

If the task uses raw Prometheus (no operator), edit `prometheus.yml` ConfigMap — only if asked.

## Verify

```bash
kubectl -n cnpe-17 get servicemonitor,prometheusrule
# Prometheus UI /targets if Grafana/Prometheus is in the exam browser
```

## Exam tips

- **Label mismatch** is the #1 miss. Copy labels from a working ServiceMonitor in `monitoring`.
- `port:` is the **Service port name**, not the number.
