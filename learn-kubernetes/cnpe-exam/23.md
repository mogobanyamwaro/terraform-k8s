# 23. RBAC on Platform Resources

**Domain:** Security (15%)

## Question

Group `platform-devs` may manage Workspace CRs in `cnpe-23` but **not** delete the CRD. Create Role `workspace-editor` with verbs get/list/watch/create/update/patch/delete on `workspaces` in API group `platform.example.com`. Bind the group. They must **not** have `cluster-admin`.

Also: ServiceAccount `workspace-controller` in `cnpe-23` needs ClusterRole to create Namespaces and ResourceQuotas for the provisioning workflow.

## Answer

```yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata: {name: workspace-editor, namespace: cnpe-23}
rules:
- apiGroups: [platform.example.com]
  resources: [workspaces]
  verbs: [get, list, watch, create, update, patch, delete]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata: {name: platform-devs-ws, namespace: cnpe-23}
subjects:
- kind: Group
  name: platform-devs
  apiGroup: rbac.authorization.k8s.io
roleRef:
  apiGroup: rbac.authorization.k8s.io
  kind: Role
  name: workspace-editor
---
apiVersion: v1
kind: ServiceAccount
metadata: {name: workspace-controller, namespace: cnpe-23}
---
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRole
metadata: {name: workspace-controller}
rules:
- apiGroups: [""]
  resources: [namespaces, resourcequotas]
  verbs: [get, list, watch, create, update, patch]
- apiGroups: [platform.example.com]
  resources: [workspaces, workspaces/status]
  verbs: [get, list, watch, update, patch]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRoleBinding
metadata: {name: workspace-controller}
subjects:
- kind: ServiceAccount
  name: workspace-controller
  namespace: cnpe-23
roleRef:
  apiGroup: rbac.authorization.k8s.io
  kind: ClusterRole
  name: workspace-controller
```

## Verify

```bash
kubectl auth can-i delete crd --as-group=platform-devs --as=u
kubectl auth can-i create workspaces.platform.example.com -n cnpe-23 --as-group=platform-devs --as=u
```

## Exam tips

- Users get **Role** on CRs. Controller gets **ClusterRole** for Namespace create.
- `workspaces/status` is a separate resource for status updates.
