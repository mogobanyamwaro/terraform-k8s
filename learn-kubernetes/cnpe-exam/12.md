# 12. Self-Service Provisioning Workflow

**Domain:** Platform APIs (25%)

## Question

When Workspace `team-a` exists (from `11.md` or the exam CR), provision:

- Namespace `ws-team-a`
- ResourceQuota `compute` in that namespace: requests.cpu `1`, requests.memory `1Gi` for size `small` (medium: cpu `2`, memory `2Gi`)
- RoleBinding: give `alice@example.com` (`User`) `admin` in that namespace

If a controller is **not** installed, a Job `provision-team-a` in `cnpe-11` that uses a service account with permission to create those objects is acceptable **if the task allows an automation Job**. Prefer a real operator/Crossplane if present.

## Answer

Manual (exam sometimes wants you to *be* the controller once):

```bash
kubectl create namespace ws-team-a
kubectl -n ws-team-a apply -f - <<'EOF'
apiVersion: v1
kind: ResourceQuota
metadata: {name: compute}
spec:
  hard: {requests.cpu: "1", requests.memory: 1Gi}
EOF
kubectl create rolebinding alice-admin -n ws-team-a \
  --clusterrole=admin --user=alice@example.com
```

Patch status if you have permission:

```bash
kubectl -n cnpe-11 patch ws team-a --subresource=status --type=merge \
  -p '{"status":{"namespace":"ws-team-a"}}'
```

**Crossplane** path: Claim `kind: Workspace` that binds to an XRD — see `Crossplane.md`. That is the intended “platform API” if Crossplane is in the environment.

## Verify

```bash
kubectl get ns ws-team-a
kubectl -n ws-team-a get quota,rolebinding
```

## Exam tips

- Size → quota mapping is the **product**. Don’t leak AWS.
- GitOps: commit the Workspace CR; the operator creates the namespace (you may only apply the CR).
- RBAC for the **controller SA** is a common second half of the task (`20.md`).
