# 18. Logging and Tracing

**Domain:** Observability (20%)

## Question

1. Ensure app `web` in `cnpe-18` logs to stdout (nginx default). Add annotation `platform.example.com/scrape-logs: "true"` if the task’s collector uses it.
2. Deploy or patch an OpenTelemetry Collector ConfigMap to add a **OTLP** receiver and export to the Jaeger endpoint named in the task (often `jaeger-collector.observability:4317`).
3. Annotate the Deployment with `sidecar.opentelemetry.io/inject: "true"` **or** set `OTEL_EXPORTER_OTLP_ENDPOINT` if that is the exam’s injection method.

## Answer

Keep this generic — copy Collector YAML from Quick Reference.

```yaml
# Deployment env (no sidecar)
env:
- name: OTEL_EXPORTER_OTLP_ENDPOINT
  value: http://otel-collector.observability:4317
- name: OTEL_SERVICE_NAME
  value: web
```

Jaeger: `kubectl -n observability port-forward svc/jaeger-query 16686:16686` and confirm traces **if the UI is allowed**. Graders usually check env/annotations and Collector config, not a live trace.

## Verify

```bash
kubectl -n cnpe-18 get deploy web -o yaml | grep -i otel
kubectl -n observability get deploy,svc | grep -E 'otel|jaeger'
```

## Exam tips

- OTel Collector is the **platform** piece; apps get env/SDK.
- Don’t rewrite Jaeger; point the exporter at it.
- Grafana dashboards: if asked to import, use the ConfigMap/sidecar pattern in Quick Reference.
