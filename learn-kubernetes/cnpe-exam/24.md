# 24. Audit and SBOM Compliance

**Domain:** Security (15%)

## Question

1. Ensure API audit is on (exam cluster usually already logs). If tasked to add an audit policy file, use kubernetes.io audit policy example: log `RequestResponse` for `secrets` and `tokenreviews`.
2. In CI namespace `cnpe-24`, ConfigMap `sbom-policy` requiring `spdx` format (or create a Kyverno policy that annotations `spdx.example.com/sbom: required` must exist on images — follow the task).
3. Job `sbom-gen` using `anchore/syft` or `bitnami/kubectl` that writes `/sbom/sbom.json` to an emptyDir (if those images are allowed). Simpler exam: annotate Deployment `inventory: "true"` and apply a provided CronJob.

Pragmatic exam answer when no syft image: create the ConfigMap and a Kyverno policy that **requires** annotation `org.opencontainers.image.sbom` on Deployments in `cnpe-24`.

## Answer

```yaml
apiVersion: kyverno.io/v1
kind: ClusterPolicy
metadata: {name: require-sbom-annotation}
spec:
  validationFailureAction: Enforce
  rules:
  - name: sbom-ann
    match:
      any:
      - resources:
          kinds: [Deployment]
          namespaces: [cnpe-24]
    validate:
      message: sbom annotation required
      pattern:
        metadata:
          annotations:
            org.opencontainers.image.sbom: "?*"
```

If the task says “generate an SBOM file at `/opt/sbom.json` on the host”, use the host’s documented CLI (`syft`, `trivy image --format spdx`).

## Verify

```bash
kubectl get clusterpolicy require-sbom-annotation
# deploy without annotation should be denied
```

## Exam tips

- Compliance items are **policy + artifact**, not a PDF.
- Quick Reference will name `trivy`/`syft` if they are on the PATH.
