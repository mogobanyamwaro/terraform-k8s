# 13. Crossplane Claim (or Composition)

**Domain:** Platform APIs (25%) — automation frameworks

## Question

Crossplane is installed. An XRD `xworkspaces.platform.example.com` and Composition already exist (exam provides them). Create a **Claim** `Workspace` named `shop` in `cnpe-13` with `spec.parameters.size: small` (field names from `kubectl explain workspace.spec` / XRD).

Wait until the Claim is **Ready** / Synced. Confirm a composed Namespace or Object exists.

If only the Kubernetes provider is available, the composition likely creates a Namespace + RoleBinding.

## Answer

```bash
kubectl get xrd,composition
kubectl explain workspace.spec   # or the claim GVK from the task
```

```yaml
apiVersion: platform.example.com/v1alpha1   # MATCH the XRD claimNames
kind: Workspace
metadata:
  name: shop
  namespace: cnpe-13
spec:
  compositionRef:
    name: xworkspaces.platform.example.com   # or compositionSelector
  parameters:
    size: small
```

```bash
kubectl wait --for=condition=Ready workspace/shop -n cnpe-13 --timeout=180s
kubectl describe workspace shop -n cnpe-13
```

Fix common failures: ProviderConfig missing, composition `ready: False`, RBAC, wrong `apiVersion`.

## Verify

```bash
kubectl get claim,composite,ns | head
kubectl get providerconfig
```

## Exam tips

- **Claim** is namespaced UX. **XR** is cluster composite. Users apply Claims.
- `kubectl get xrd -o yaml` shows `claimNames`.
- Do not edit the Composition unless asked; fill the Claim.
