# 10. GitOps for Infrastructure YAML

**Domain:** GitOps and CD (25%) — app **and** infra

## Question

A Git repo (or a local directory already cloned at `/work/infra`) contains a Namespace `cnpe-10` and a ResourceQuota. Point Flux **or** Argo CD at that path so the quota exists in the cluster. Enable prune.

If no Git remote exists in the exam, use a `GitRepository` to the URL in the task, or Argo CD `spec.source.path`.

## Answer

**Flux**

```yaml
apiVersion: source.toolkit.fluxcd.io/v1
kind: GitRepository
metadata: {name: platform-infra, namespace: flux-system}
spec:
  interval: 1m
  url: https://git.example.internal/platform/infra   # TASK URL
  ref: {branch: main}
---
apiVersion: kustomize.toolkit.fluxcd.io/v1
kind: Kustomization
metadata: {name: platform-infra, namespace: flux-system}
spec:
  interval: 2m
  prune: true
  path: ./tenants/payments
  sourceRef: {kind: GitRepository, name: platform-infra}
```

**Argo CD** — Application `platform-infra`, destination `https://kubernetes.default.svc`, namespace as in the YAML (cluster-scoped Namespace objects use `destination.namespace` still but the object’s metadata.namespace wins / cluster resources need AppProject allow).

If the quota is cluster-scoped-adjacent (Namespace), AppProject may need `clusterResourceWhitelist`. Copy from Argo CD project docs.

## Verify

```bash
kubectl get ns cnpe-10
kubectl -n cnpe-10 get quota
```

## Exam tips

- Infra GitOps is the **same engine** as apps. Path + prune.
- Cluster-scoped objects: Argo **project** whitelist. Flux Kustomization needs RBAC on the SA.
- Do not kubectl-apply the quota if the task says GitOps — the grader watches the engine objects.
