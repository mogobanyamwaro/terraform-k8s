# 08. Canary with Argo Rollouts

**Domain:** GitOps and CD (25%) — Progressive delivery

## Question

In `cnpe-08`, replace a Deployment with a Rollout `shop`:

- image `argoproj/rollouts-demo:blue`, port 8080, replicas 5
- Services `shop-stable` and `shop-canary` (same selector `app=shop`)
- Canary steps: **20%** weight, pause **30s**, **50%**, pause **30s**, then 100%
- Traffic routing: **replica** canary (no mesh) is fine unless the task names Istio

## Answer

Install Rollouts if needed. Then:

```yaml
apiVersion: v1
kind: Service
metadata: {name: shop-stable, namespace: cnpe-08}
spec:
  selector: {app: shop}
  ports: [{port: 80, targetPort: 8080}]
---
apiVersion: v1
kind: Service
metadata: {name: shop-canary, namespace: cnpe-08}
spec:
  selector: {app: shop}
  ports: [{port: 80, targetPort: 8080}]
---
apiVersion: argoproj.io/v1alpha1
kind: Rollout
metadata: {name: shop, namespace: cnpe-08}
spec:
  replicas: 5
  selector: {matchLabels: {app: shop}}
  template:
    metadata: {labels: {app: shop}}
    spec:
      containers:
      - name: demo
        image: argoproj/rollouts-demo:blue
        ports: [{containerPort: 8080}]
  strategy:
    canary:
      canaryService: shop-canary
      stableService: shop-stable
      steps:
      - setWeight: 20
      - pause: {duration: 30s}
      - setWeight: 50
      - pause: {duration: 30s}
```

Change image to `:yellow` to start a canary. `kubectl argo rollouts get rollout shop -n cnpe-08 --watch`

Flagger variant: `Canary` CR + `targetRef` Deployment — use Quick Reference if the cluster has Flagger not Rollouts.

## Verify

```bash
kubectl -n cnpe-08 get rollout shop
kubectl argo rollouts status shop -n cnpe-08
```

## Exam tips

- Delete the old Deployment **or** scale it to 0 so Services do not split randomly.
- Empty `pause: {}` waits for **promote** — only if the task wants a manual gate.
