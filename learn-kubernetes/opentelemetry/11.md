# 11. SDK Pipelines

**Domain:** The OpenTelemetry API and SDK (46%)

## Concept Refresher

In-process path:

```text
API call → SDK processor/reader → exporter → (network) Collector or backend
```

**Traces**

- **SimpleSpanProcessor** — export on each `end()` (dev; slow).
- **BatchSpanProcessor** — queue + batch (production default).

Then **SpanExporter**: OTLP, console, Zipkin, etc.

**Sampler** runs at span **start** (head). Unsampled → non-recording, still propagates context if ParentBased says so.

**Metrics**

- Instrument → SDK aggregation → **PeriodicExportingMetricReader** (or Prometheus pull reader) → **MetricExporter**.

**Logs**

- Processor (batch/simple) → LogRecordExporter.

Multiple exporters: `OTEL_TRACES_EXPORTER=otlp,console` (comma) or several processors.

Backpressure: batch queue full → drop (SDK) or later Collector `memory_limiter`.
