# 06. API vs SDK (Composability)

**Domain:** The OpenTelemetry API and SDK (46%)

## Concept Refresher

**Split:**

| Piece | Role |
| --- | --- |
| **API** | What instrumentation calls (`tracer.span(...)`). Default **no-op**. |
| **SDK** | Real providers, processors, exporters, samplers. |
| **Collector** | Separate process; not the in-process SDK. |

Libraries depend on **API only** so they stay vendor-neutral. The **application** (or agent) registers an SDK.

**Providers:** `TracerProvider`, `MeterProvider`, `LoggerProvider` — global or explicit.

**Composability:** swap exporters (OTLP, console, Jaeger) without changing span calls. Register **span processors**, **metric readers**, **propagators**.

**Extension:** custom Sampler, custom exporter, custom propagator — still implementing SDK interfaces. OTCA: know *that* you plug in, not write one in the exam.

`OTEL_SDK_DISABLED=true` forces no-op even if SDK is on the classpath.

Agent **is** an SDK + auto instrumentation bundled.
