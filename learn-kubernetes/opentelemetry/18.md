# 18. Collector Scaling

**Domain:** The OpenTelemetry Collector (26%)

## Concept Refresher

**Stateless** pipelines (batch, attributes, filter, OTLP export) scale by adding gateway **replicas** behind a Service.

**Stateful** processors:

- **tail_sampling**, some grouping, spanmetrics with flush windows
- Need **all spans of a trace on the same Collector** → load-balance by **trace ID** (Collector load balancing exporter, service mesh hash, or a single-writer pattern)

**memory_limiter** + GOMEMLIMIT (Go) prevent OOM. When limited, Collector **refuses/drops** rather than unbounded RAM.

**batch** reduces export QPS; tune `send_batch_size`, `timeout`.

**Horizontal vs vertical:** more replicas vs more CPU/RAM. Exporters to slow backends cause queue growth (`sending_queue`).

**Scraping:** Prometheus receiver is often sharded (hashmod) like Prometheus itself.

Health: `health_check` extension for probes. Don’t use zpages as the only prod signal.
