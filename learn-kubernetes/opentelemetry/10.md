# 10. Logs Signal

**Domain:** The OpenTelemetry API and SDK (46%)

## Concept Refresher

Logs in OTel: **Logs Bridge API** + SDK `LoggerProvider`. Existing loggers (Logback, log4j, slog) are **bridged** so records pick up context.

**LogRecord:** timestamp, observed timestamp, severity (number + text), body, attributes, resource, instrumentation scope, optional **trace_id / span_id / flags**.

If a span is current, bridges should **inject trace context** so logs correlate.

Logs are **not** traces. Do not emit one span per log line. Use log bodies for payload; spans for operations.

Export: OTLP logs, or Collector `filelog` receiver (that is Collector ingest of *files*, not the SDK).

Severity numbers follow a conventional scale (TRACE/DEBUG/INFO/WARN/ERROR/FATAL ranges).
