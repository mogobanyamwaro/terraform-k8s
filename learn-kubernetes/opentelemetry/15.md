# 15. Collector Configuration

**Domain:** The OpenTelemetry Collector (26%)

## Concept Refresher

The Collector is a **vendor-neutral pipeline**. Config is YAML:

```yaml
receivers:    # how data enters
processors:   # mutate/filter/batch
exporters:    # where data goes
connectors:   # exporter of one pipeline → receiver of another (e.g. spanmetrics)
extensions:   # zpages, health, pprof, auth — not in the data path unless used
service:
  extensions: [health_check, zpages]
  pipelines:
    traces:
      receivers: [otlp]
      processors: [memory_limiter, batch]
      exporters: [otlp]
  telemetry:    # Collector's own logs/metrics
```

A component **declared** but not listed under `service.pipelines` / `extensions` does **nothing**.

**Distributions:** `otelcol` (core) vs `otelcol-contrib` (many receivers). Missing component → start error.

**memory_limiter** should be **first** processor. **batch** usually **last** before export.
