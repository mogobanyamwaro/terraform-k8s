# 17. Load Balancing and Session Affinity

## Concept Refresher

Once a VirtualService has chosen a `host` and optional `subset`, **DestinationRule `trafficPolicy.loadBalancer`** picks the endpoint.

```yaml
apiVersion: networking.istio.io/v1
kind: DestinationRule
metadata:
  name: reviews
  namespace: bookinfo
spec:
  host: reviews
  trafficPolicy:
    loadBalancer:
      simple: LEAST_REQUEST
```

### Simple algorithms

| `simple` | Behaviour |
| --- | --- |
| `LEAST_REQUEST` | Fewest outstanding requests. **Istio default** |
| `ROUND_ROBIN` | Next endpoint in the list |
| `RANDOM` | Uniform random |
| `PASSTHROUGH` | Send to the IP the caller already resolved. Used with `resolution: NONE` |

There is no `LEAST_CONN` in this API. That is the Envoy name; Istio's is `LEAST_REQUEST`.

### Consistent hash (session affinity)

Pin a caller to the same pod using a hash key:

```yaml
  trafficPolicy:
    loadBalancer:
      consistentHash:
        httpCookie:
          name: user
          ttl: 0s
```

Other hash keys (exactly one):

| Field | Hashes on |
| --- | --- |
| `httpHeaderName` | Named request header |
| `httpCookie` | Cookie; Envoy **sets** it if missing when `ttl` is set |
| `useSourceIp: true` | Client IP |
| `httpQueryParameterName` | Query string key |
| `ringHash` / `maglev` | Tune the hash implementation (optional) |

`ttl: 0s` on a cookie means session cookie. A positive ttl makes Envoy issue `Set-Cookie`.

Affinity is **best-effort**. Pods come and go; the hash ring changes; a client can move. It is not a sticky session guarantee for stateful apps that cannot tolerate that.

### Locality-aware LB (preview of `21.md`)

```yaml
        localityLbSetting:
          enabled: true
          distribute:
            - from: "us-west/us-west-1a/*"
              to:
                "us-west/us-west-1a/*": 80
                "us-west/us-west-1b/*": 20
```

Without this, Istio still prefers the local locality when endpoints exist there. Failover to other zones needs **outlier detection** (`19.md`, `21.md`).

## Tasks

`httpbin` in `demo` has at least two replicas.

1. Set load balancing for `httpbin` to `ROUND_ROBIN`.
2. Pin clients of `httpbin` by header `x-user`.
3. Pin by cookie `session`.
4. Pin by source IP.
5. Use `ROUND_ROBIN` globally but `RANDOM` on subset `v2` only.

## Solutions

### 1. ROUND_ROBIN

```yaml
apiVersion: networking.istio.io/v1
kind: DestinationRule
metadata:
  name: httpbin
  namespace: demo
spec:
  host: httpbin
  trafficPolicy:
    loadBalancer:
      simple: ROUND_ROBIN
```

### 2. Header hash

```yaml
  trafficPolicy:
    loadBalancer:
      consistentHash:
        httpHeaderName: x-user
```

```bash
kubectl -n demo exec deploy/sleep -c sleep -- \
  curl -sS -H 'x-user: alice' http://httpbin:8000/get
```

### 3. Cookie

```yaml
        consistentHash:
          httpCookie:
            name: session
            ttl: 0s
```

### 4. Source IP

```yaml
        consistentHash:
          useSourceIp: true
```

Useful for TCP or when you cannot set headers. Behind a gateway, this is the **sidecar-to-service** source (often the gateway pod), not the real client, unless you hop at the edge with care.

### 5. Per-subset override

```yaml
spec:
  host: httpbin
  trafficPolicy:
    loadBalancer:
      simple: ROUND_ROBIN
  subsets:
    - name: v1
      labels:
        version: v1
    - name: v2
      labels:
        version: v2
      trafficPolicy:
        loadBalancer:
          simple: RANDOM
```

Remember: a subset `trafficPolicy` **replaces** the parent for that subset (`11.md`). v2 does not inherit connection pool settings from the parent if you only set `loadBalancer` here.

## Verify

```bash
istioctl proxy-config cluster deploy/sleep.demo --fqdn httpbin.demo.svc.cluster.local -o json \
  | jq '.[0].lbPolicy // .[0].loadAssignment.policy'

# Hit many times and count upstream pod IPs from access logs or /headers
kubectl -n demo scale deploy/httpbin --replicas=3
kubectl -n demo exec deploy/sleep -c sleep -- \
  sh -c 'for i in $(seq 1 30); do curl -s http://httpbin:8000/hostname; echo; done' | sort | uniq -c
```

For header hash, same `x-user` should land on one replica far more often than 1/N.

## Exam Tips

- Load balancing is **DestinationRule**, not VirtualService. Weights on VS pick subsets; LB picks pods inside the subset.
- `LEAST_REQUEST` is default; you only set `simple` when the task names another algorithm.
- `consistentHash` and `simple` are mutually exclusive in one `loadBalancer` block.
- Docs: DestinationRule reference, `spec.trafficPolicy.loadBalancer`.
