# 19. Circuit Breaking, Connection Pools, Outlier Detection

## Concept Refresher

Circuit breaking in Istio is **not** a VirtualService field. It is DestinationRule `trafficPolicy`:

- **Connection pool** - hard limits. Excess requests fail immediately (`UO`, overflow).
- **Outlier detection** - eject unhealthy endpoints from the load-balancing pool for a time.

```yaml
apiVersion: networking.istio.io/v1
kind: DestinationRule
metadata:
  name: httpbin
  namespace: demo
spec:
  host: httpbin
  trafficPolicy:
    connectionPool:
      tcp:
        maxConnections: 1
        connectTimeout: 30ms
      http:
        http1MaxPendingRequests: 1
        http2MaxRequests: 1
        maxRequestsPerConnection: 1
        maxRetries: 3
        idleTimeout: 60s
    outlierDetection:
      consecutive5xxErrors: 1
      interval: 1s
      baseEjectionTime: 30s
      maxEjectionPercent: 100
      minHealthPercent: 0
```

### Connection pool knobs

| Field | What it limits |
| --- | --- |
| `tcp.maxConnections` | Concurrent TCP connections to the host |
| `tcp.connectTimeout` | TCP connect timeout |
| `http.http1MaxPendingRequests` | HTTP/1.1 requests queued waiting for a connection |
| `http.http2MaxRequests` | Concurrent HTTP/2 requests |
| `http.maxRequestsPerConnection` | Force connection churn; `1` disables keep-alive reuse |
| `http.maxRetries` | Retries outstanding at once **to this cluster** (not VS attempts) |
| `http.h2UpgradePolicy` | `UPGRADE` / `DO_NOT_UPGRADE` |

When a limit is hit, Envoy increments overflow stats and the caller sees **`503`** with response flag **`UO`** (upstream overflow).

### Outlier detection knobs

| Field | Meaning |
| --- | --- |
| `consecutive5xxErrors` | Eject after this many 5xx in a row (default **5**) |
| `consecutiveGatewayErrors` | 502/503/504 specifically |
| `consecutiveLocalOriginFailures` | Local origin failures, when split is enabled |
| `interval` | Sweep interval (default **10s**) |
| `baseEjectionTime` | First ejection length; doubles each time (default **30s**) |
| `maxEjectionPercent` | Cap on how much of the pool may be ejected (default **10%**) |
| `minHealthPercent` | If healthy % drops below this, outlier detection is disabled |
| `splitExternalLocalOriginErrors` | Treat local vs upstream errors separately |

**Failover (`21.md`) requires outlier detection.** Locality failover will not move traffic off a dying zone without it.

### Circuit breaker vs retry vs timeout

```text
Timeout     : this request waited too long          -> VirtualService
Retry       : try another endpoint                  -> VirtualService
Pool limit  : too many in-flight to this host       -> DestinationRule (fail fast, UO)
Outlier     : this POD is sick, skip it for a while -> DestinationRule
```

## Solutions

### 1. Tiny pool

```yaml
apiVersion: networking.istio.io/v1
kind: DestinationRule
metadata:
  name: httpbin
  namespace: demo
spec:
  host: httpbin
  trafficPolicy:
    connectionPool:
      tcp:
        maxConnections: 1
      http:
        http1MaxPendingRequests: 1
        maxRequestsPerConnection: 1
```

```bash
# Two delayed requests at once
kubectl -n demo exec deploy/sleep -c sleep -- \
  sh -c 'curl -s -o /dev/null -w "%{http_code}\n" http://httpbin:8000/delay/3 &
         curl -s -o /dev/null -w "%{http_code}\n" http://httpbin:8000/delay/3 &
         wait'
```

One `200`, one `503`. Sidecar access log flag `UO`.

### 2. Aggressive outlier

```yaml
  trafficPolicy:
    outlierDetection:
      consecutive5xxErrors: 1
      interval: 1s
      baseEjectionTime: 15s
      maxEjectionPercent: 100
      minHealthPercent: 0
```

`minHealthPercent: 0` is required if you have few pods. Default `minHealthPercent` can disable ejection on a 1-replica service (ejecting the only pod would drop below the floor).

Generate 5xx:

```bash
kubectl -n demo exec deploy/sleep -c sleep -- curl -s -o /dev/null -w "%{http_code}\n" http://httpbin:8000/status/500
```

Then watch endpoints:

```bash
istioctl proxy-config endpoint deploy/sleep.demo --cluster "outbound|8000||httpbin.demo.svc.cluster.local"
```

Ejected hosts show unhealthy / not in active set.

### 3. Production-shaped

```yaml
  trafficPolicy:
    connectionPool:
      tcp:
        maxConnections: 10
      http:
        http1MaxPendingRequests: 10
        http2MaxRequests: 10
    outlierDetection:
      consecutive5xxErrors: 5
      interval: 10s
      baseEjectionTime: 30s
      maxEjectionPercent: 50
```

### 4. Two retry limits

- VirtualService `retries.attempts` = how many times **this request** may be retried.
- DestinationRule `connectionPool.http.maxRetries` = how many retries may be **in flight to this cluster** across requests.

The pool `maxRetries` can starve VS retries under load. For ICA, set them consistently. If a task only mentions circuit breaking, do **not** put retries on the VirtualService.

## Verify

```bash
istioctl proxy-config cluster deploy/sleep.demo --fqdn httpbin.demo.svc.cluster.local -o json \
  | jq '.[0] | {
      maxConnections: .circuitBreakers.thresholds[0].maxConnections,
      maxPending: .circuitBreakers.thresholds[0].maxPendingRequests,
      maxRequests: .circuitBreakers.thresholds[0].maxRequests,
      maxRetries: .circuitBreakers.thresholds[0].maxRetries,
      outlier: .outlierDetection
    }'

# Envoy stats
kubectl -n demo exec deploy/sleep -c istio-proxy -- \
  curl -s http://127.0.0.1:15000/stats | grep -E 'httpbin.*overflow|eject'
```

## Exam Tips

- **`maxEjectionPercent` default is 10.** On a 2-pod service you cannot eject even one pod (would be 50%). Exam tasks that say "eject unhealthy instances" on small services need `maxEjectionPercent: 100` and usually `minHealthPercent: 0`.
- `consecutive5xxErrors: 0` **disables** that detector, it does not mean "eject immediately".
- Circuit breaking does not "open a circuit" in Hystrix language for the whole service; it limits pools and ejects **endpoints**.
- Docs: [Circuit breaking](https://istio.io/docs/tasks/traffic-management/traffic-management-concepts/circuit-breaking/) and DestinationRule `connectionPool` / `outlierDetection`.
