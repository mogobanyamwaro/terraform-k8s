# 14. Egress: ServiceEntry and External Services

## Concept Refresher

Kubernetes Services cover in-cluster DNS. Anything **outside** the mesh (public APIs, a VM, a database hostname) is invisible to Istio until you register it with a **ServiceEntry**.

Until then, two things are true:

1. With the default `outboundTrafficPolicy.mode: ALLOW_ANY`, sidecars **will still send** the traffic, as passthrough, with almost no Istio features.
2. With `REGISTRY_ONLY`, sidecars **drop** unknown destinations (`502` / `BlackHoleCluster`).

A ServiceEntry adds the host to Istio's service registry so you can attach VirtualServices, DestinationRules, mTLS, telemetry, and egress gateways.

```yaml
apiVersion: networking.istio.io/v1
kind: ServiceEntry
metadata:
  name: httpbin-ext
  namespace: demo
spec:
  hosts:
    - httpbin.org
  ports:
    - number: 80
      name: http
      protocol: HTTP
    - number: 443
      name: https
      protocol: HTTPS
  location: MESH_EXTERNAL
  resolution: DNS
```

### Fields you must know

| Field | Meaning |
| --- | --- |
| `hosts` | How callers address it (`curl http://httpbin.org`). Also the key VirtualServices match on |
| `location` | `MESH_EXTERNAL` (outside, no mTLS by default) or `MESH_INTERNAL` (treat as mesh service) |
| `resolution` | How Envoy finds endpoints: `NONE`, `STATIC`, `DNS`, `DNS_ROUND_ROBIN` |
| `addresses` | CIDR/VIP, used with `NONE` or as an additional match |
| `endpoints` | Static IPs or unix sockets, used with `STATIC` |
| `exportTo` | Who can see this ServiceEntry. `"."` = this namespace, `"*"` = all |
| `workloadSelector` | Bind to WorkloadEntries / pods for mesh expansion |
| `subjectAltNames` | Expected SAN when originating TLS |

### Resolution

| Mode | Envoy cluster type | Use when |
| --- | --- | --- |
| `NONE` | Original destination (passthrough) | You already have the IP (CONNECT, opaque TCP) |
| `STATIC` | Static endpoints you listed | VMs, known IPs |
| `DNS` | Strict DNS, all returned IPs become endpoints | Hostnames, most exam tasks |
| `DNS_ROUND_ROBIN` | Logical DNS, one IP at a time | Very large DNS answers |

**HTTP to an external HTTPS site** needs a DestinationRule `tls.mode: SIMPLE` (or the app already speaks TLS and you use protocol `TLS`/`HTTPS` with `resolution: DNS`). Double TLS (app TLS + Envoy TLS) breaks the handshake. See task 4.

### WorkloadEntry (mesh expansion)

A WorkloadEntry is a non-Kubernetes endpoint that can join the mesh:

```yaml
apiVersion: networking.istio.io/v1
kind: WorkloadEntry
metadata:
  name: vm-1
  namespace: vm
spec:
  address: 10.20.30.40
  labels:
    app: legacy
    class: vm
  serviceAccount: legacy
```

Pair it with a ServiceEntry `workloadSelector: { matchLabels: { app: legacy } }` so mesh services can call `legacy.vm.svc.cluster.local`. ICA will at most ask you to register an external IP this way, not to bootstrap a VM agent.

## Tasks

From `sleep` in namespace `demo` (meshed). Control plane is default `ALLOW_ANY` unless a task says otherwise.

1. Allow and observe HTTP calls to `httpbin.org:80` as a first-class mesh service. Add a 3s timeout on those calls.
2. Register `api.github.com:443` so you can apply a DestinationRule that originates TLS (`SIMPLE`).
3. Register a static TCP database at `10.0.9.12:5432` named `payments-db.external`.
4. Switch the mesh to `REGISTRY_ONLY` (or a Sidecar that does the same for `demo`) and show that `curl http://never-registered.example` fails, then whitelist it.
5. Export a ServiceEntry from `istio-system` so **only** namespace `demo` can use `httpbin.org`.

## Solutions

### 1. HTTP external + timeout

```bash
kubectl apply -f - <<'EOF'
apiVersion: networking.istio.io/v1
kind: ServiceEntry
metadata:
  name: httpbin-ext
  namespace: demo
spec:
  hosts:
    - httpbin.org
  ports:
    - number: 80
      name: http
      protocol: HTTP
  location: MESH_EXTERNAL
  resolution: DNS
---
apiVersion: networking.istio.io/v1
kind: VirtualService
metadata:
  name: httpbin-ext
  namespace: demo
spec:
  hosts:
    - httpbin.org
  http:
    - timeout: 3s
      route:
        - destination:
            host: httpbin.org
            port:
              number: 80
EOF
```

```bash
kubectl -n demo exec deploy/sleep -c sleep -- curl -sS -o /dev/null -w "%{http_code}\n" http://httpbin.org/get
```

### 2. HTTPS origin

```yaml
apiVersion: networking.istio.io/v1
kind: ServiceEntry
metadata:
  name: github
  namespace: demo
spec:
  hosts:
    - api.github.com
  ports:
    - number: 443
      name: https
      protocol: HTTPS
  location: MESH_EXTERNAL
  resolution: DNS
---
apiVersion: networking.istio.io/v1
kind: DestinationRule
metadata:
  name: github
  namespace: demo
spec:
  host: api.github.com
  trafficPolicy:
    tls:
      mode: SIMPLE
      sni: api.github.com
```

If the **application** already dials TLS (`curl https://api.github.com`), set protocol `TLS` and do **not** add `SIMPLE` or Envoy will wrap TLS in TLS.

### 3. Static TCP

```yaml
apiVersion: networking.istio.io/v1
kind: ServiceEntry
metadata:
  name: payments-db
  namespace: demo
spec:
  hosts:
    - payments-db.external
  addresses:
    - 10.0.9.12
  ports:
    - number: 5432
      name: tcp
      protocol: TCP
  location: MESH_EXTERNAL
  resolution: STATIC
  endpoints:
    - address: 10.0.9.12
```

### 4. REGISTRY_ONLY

Mesh-wide (needs an IstioOperator / MeshConfig change, see `06.md`):

```yaml
meshConfig:
  outboundTrafficPolicy:
    mode: REGISTRY_ONLY
```

Namespace-scoped, preferred on the exam if a Sidecar is allowed:

```yaml
apiVersion: networking.istio.io/v1
kind: Sidecar
metadata:
  name: default
  namespace: demo
spec:
  outboundTrafficPolicy:
    mode: REGISTRY_ONLY
  egress:
    - hosts:
        - "./*"
        - "istio-system/*"
```

Then add a ServiceEntry for every external host you need.

### 5. Visibility

```yaml
apiVersion: networking.istio.io/v1
kind: ServiceEntry
metadata:
  name: httpbin-ext
  namespace: istio-system
spec:
  hosts:
    - httpbin.org
  exportTo:
    - demo
  ports:
    - number: 80
      name: http
      protocol: HTTP
  location: MESH_EXTERNAL
  resolution: DNS
```

`exportTo: ["."]` keeps it in `istio-system` only. `exportTo: ["*"]` is the default (everyone).

## Verify

```bash
istioctl proxy-config cluster deploy/sleep.demo | grep httpbin.org
istioctl proxy-config cluster deploy/sleep.demo | grep BlackHoleCluster

kubectl -n demo exec deploy/sleep -c sleep -- curl -sv http://httpbin.org/get 2>&1 | grep -E 'HTTP/|Connected'

istioctl analyze -n demo
```

Under `REGISTRY_ONLY`, unknown hosts hit `BlackHoleCluster` and `curl` fails. After the ServiceEntry, a real cluster named for that host appears.

## Exam Tips

- **VirtualService `hosts` must equal the ServiceEntry `hosts`.** `httpbin.org` and `www.httpbin.org` are different services.
- Protocol `HTTP` on port 443 is usually wrong. Match protocol to what Envoy should parse.
- `ALLOW_ANY` hides missing ServiceEntries. If a task says "only registered external services", you must set `REGISTRY_ONLY`.
- Docs: [ServiceEntry](https://istio.io/docs/reference/config/networking/service-entry/) and [Egress TLS origination](https://istio.io/docs/tasks/traffic-management/egress/egress-tls-origination/).
