# 36. Ambient-Specific Troubleshooting

## Concept Refresher

Ambient failures look like "Istio is installed but nothing happens" because **L4 and L7 are separate**.

```text
Namespace labelled istio.io/dataplane-mode=ambient
        |
        v
   ztunnel does mTLS + L4 authz + TCP metrics
        |
        |  still NO retries, timeouts, HTTP authz, fault, HTTP VS routing
        v
   waypoint (GatewayClass istio-waypoint) + use-waypoint label
        |
        v
   L7 features work
```

### Tooling differences

| Sidecar | Ambient |
| --- | --- |
| `istioctl proxy-status` | `istioctl ztunnel-config` / waypoint `proxy-config` |
| `istio-proxy` logs | `kubectl -n istio-system logs ds/ztunnel` |
| `pc cluster` on app pod | app pod has **no** Envoy |
| HBONE 15008 | see this port in NetworkPolicy / ss |

```bash
kubectl -n istio-system get ds ztunnel
kubectl get ns -L istio.io/dataplane-mode
istioctl ztunnel-config all
istioctl ztunnel-config workload
istioctl ztunnel-config certificate
istioctl waypoint list
```

### Enrolment bugs

| Symptom | Cause |
| --- | --- |
| Pods not in mesh, no mTLS | Missing `istio.io/dataplane-mode=ambient`, or `istio-injection=enabled` fighting it |
| CNI not ready | Ambient **requires** CNI. `profile=ambient` |
| Traffic bypasses ztunnel | HostNetwork pods, or redirection failure (`istio-cni` logs) |
| Mixed mode in one ns | Pod override `istio.io/dataplane-mode=none` |

Do not set `istio-injection=enabled` on an ambient namespace.

### L7 policy ignored

```bash
kubectl get gateway -A
kubectl get svc -n shop --show-labels
# expect istio.io/use-waypoint=<waypoint-name>
```

VirtualService/AuthorizationPolicy HTTP fields need the waypoint **in path**. For a Service:

```bash
istioctl waypoint apply -n shop
kubectl label svc reviews -n shop istio.io/use-waypoint=waypoint
```

Namespace-wide waypoint: label the namespace `istio.io/use-waypoint=waypoint`.

### ztunnel crash / mTLS fail

```bash
kubectl -n istio-system describe ds ztunnel
kubectl -n istio-system logs -l app=ztunnel --tail=100
istioctl proxy-status   # waypoints still show here
```

Root CA issues (`28.md`) break ztunnel the same as sidecars.

### Waypoint not programmed

Waypoints are Envoys. Use:

```bash
istioctl pc route deploy/waypoint.shop
istioctl analyze -n shop
```

`gatewayClassName` must be `istio-waypoint`. Wrong class = idle Deployment.

## Tasks

Use cluster `kind-ambient-lab` from Lab-Setup.

1. Enrol `shop` in ambient. Show ztunnel sees the workloads. Confirm app pods are **1/1**.
2. Apply a 1s timeout VirtualService to `httpbin`. Show it does **not** apply. Add a waypoint and show `/delay/3` now 504.
3. Apply an AuthorizationPolicy ALLOW GET only (paths). Show it is ineffective before waypoint, effective after.
4. Diagnose `istio-injection=enabled` plus ambient label together.

## Solutions

### 1. Enrol

```bash
kubectl create ns shop
kubectl label ns shop istio.io/dataplane-mode=ambient
kubectl -n shop apply -f samples/httpbin/httpbin.yaml
kubectl -n shop apply -f samples/sleep/sleep.yaml
kubectl -n shop get po   # 1/1
istioctl ztunnel-config workload | grep shop
```

### 2. Timeout needs waypoint

```yaml
apiVersion: networking.istio.io/v1
kind: VirtualService
metadata:
  name: httpbin
  namespace: shop
spec:
  hosts: [httpbin]
  http:
    - timeout: 1s
      route:
        - destination:
            host: httpbin
            port: { number: 8000 }
```

```bash
istioctl waypoint apply -n shop
kubectl label ns shop istio.io/use-waypoint=waypoint --overwrite
# or label the Service
kubectl -n shop exec deploy/sleep -- curl -sS -o /dev/null -w "%{http_code}\n" http://httpbin:8000/delay/3
```

### 3. L7 authz

Same waypoint requirement. Before: POST works. After: POST 403.

### 4. Conflicting labels

```bash
kubectl label ns shop istio-injection=enabled --overwrite
# new pods may get sidecars AND ambient labels — undefined/wrong
kubectl label ns shop istio-injection-
kubectl label ns shop istio.io/dataplane-mode=ambient --overwrite
kubectl -n shop rollout restart deploy
```

## Verify

```bash
kubectl get ns shop --show-labels
kubectl -n istio-system get po -l app=ztunnel
istioctl waypoint list
istioctl analyze -n shop
```

## Exam Tips

- **1/1 pods in ambient is success**, not a missing sidecar.
- HTTP VirtualService + ambient = waypoint or the task is not done.
- `istioctl pc` on an app pod in ambient **fails** (no istio-proxy). Use ztunnel-config or the waypoint Deployment.
- Docs: [Ambient](https://istio.io/docs/ambient/) and [Troubleshooting ambient](https://istio.io/docs/ambient/usage/troubleshoot/).
