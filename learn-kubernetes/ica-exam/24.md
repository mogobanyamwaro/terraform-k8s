# 24. RequestAuthentication and JWT Validation

## Concept Refresher

**RequestAuthentication** tells Envoy how to **validate** a JWT. It does **not** require a token and it does **not** authorize. Unauthenticated requests still pass unless an **AuthorizationPolicy** rejects them.

This two-resource split is the single most important JWT exam fact.

```yaml
apiVersion: security.istio.io/v1
kind: RequestAuthentication
metadata:
  name: httpbin
  namespace: demo
spec:
  selector:
    matchLabels:
      app: httpbin
  jwtRules:
    - issuer: "https://auth.example.com"
      jwksUri: "https://auth.example.com/.well-known/jwks.json"
      audiences:
        - httpbin
      forwardOriginalToken: true
```

### What Envoy does with a request

```text
No JWT                    -> JWT filter allows, no requestPrincipal
Valid JWT for this issuer -> requestPrincipal = "issuer/subject"
JWT present but invalid   -> 401  (even without AuthorizationPolicy)
JWT for unknown issuer    -> treated as no JWT unless another rule matches
```

So: **bad tokens always 401.** Missing tokens are allowed until you add AuthorizationPolicy.

### Pairing with AuthorizationPolicy

Require a valid token (any issuer you listed):

```yaml
apiVersion: security.istio.io/v1
kind: AuthorizationPolicy
metadata:
  name: httpbin-require-jwt
  namespace: demo
spec:
  selector:
    matchLabels:
      app: httpbin
  action: ALLOW
  rules:
    - from:
        - source:
            requestPrincipals: ["*"]
```

Require a specific issuer and subject:

```yaml
            requestPrincipals:
              - "https://auth.example.com/sleep-user"
```

`requestPrincipals` format is **`iss/sub`**. Claims in `when`:

```yaml
    - when:
        - key: request.auth.claims[groups]
          values: ["admin"]
```

### jwtRules fields worth knowing

| Field | Purpose |
| --- | --- |
| `issuer` | Must match JWT `iss` |
| `jwksUri` | Where to fetch public keys |
| `jwks` | Inline JWKS, useful when the exam gives you a key and no URL |
| `audiences` | JWT `aud` must match. If omitted, Envoy accepts any aud **or** uses the request host depending on version; **set it when the task names an audience** |
| `fromHeaders` | Default `Authorization: Bearer`. Override for `x-jwt` |
| `fromParams` | JWT in a query parameter |
| `outputPayloadToHeader` | Put JSON claims in a header for the app |
| `forwardOriginalToken` | Keep `Authorization` when talking to the app |
| `outputClaimToHeaders` | Map individual claims to headers |

### Selector vs targetRef

`selector` matches workload labels. Gateway JWT uses `targetRef` to a Gateway or the ingress gateway labels. For ingress, apply RequestAuthentication in the **gateway namespace** with the gateway selector, or JWT never runs.

## Tasks

You will need a JWT. For the lab, use Istio's sample at `samples/security/jwt` or https://raw.githubusercontent.com/istio/istio/release-1.26/security/tools/jwt/samples/demo.jwt

The sample token's issuer is typically `testing@secure.istio.io` with jwks from the same samples folder.

1. Validate JWTs on `httpbin` using issuer `testing@secure.istio.io` and the sample `jwksUri`.
2. Reject requests **without** a token. Accept requests with a valid token.
3. Allow only if claim `groups` contains `group1`.
4. Read the token from header `x-token` instead of `Authorization`.
5. Apply JWT validation at the **ingress gateway** for host `httpbin.example.com`.

### 1. Validate only

```yaml
apiVersion: security.istio.io/v1
kind: RequestAuthentication
metadata:
  name: httpbin
  namespace: demo
spec:
  selector:
    matchLabels:
      app: httpbin
  jwtRules:
    - issuer: "testing@secure.istio.io"
      jwksUri: "https://raw.githubusercontent.com/istio/istio/release-1.26/security/tools/jwt/samples/jwks.json"
```

```bash
TOKEN=$(curl -s https://raw.githubusercontent.com/istio/istio/release-1.26/security/tools/jwt/samples/demo.jwt)

# no token: 200 (authn only)
kubectl -n demo exec deploy/sleep -c sleep -- curl -sS -o /dev/null -w "%{http_code}\n" http://httpbin:8000/get

# bad token: 401
kubectl -n demo exec deploy/sleep -c sleep -- \
  curl -sS -o /dev/null -w "%{http_code}\n" -H "Authorization: Bearer nope" http://httpbin:8000/get

# good token: 200
kubectl -n demo exec deploy/sleep -c sleep -- \
  curl -sS -o /dev/null -w "%{http_code}\n" -H "Authorization: Bearer $TOKEN" http://httpbin:8000/get
```

### 2. Require a token

Keep the RequestAuthentication. Add:

```yaml
apiVersion: security.istio.io/v1
kind: AuthorizationPolicy
metadata:
  name: httpbin-jwt
  namespace: demo
spec:
  selector:
    matchLabels:
      app: httpbin
  action: ALLOW
  rules:
    - from:
        - source:
            requestPrincipals: ["*"]
```

No token now returns **403** (authorization), not 401. Invalid token remains **401**.

### 3. Claim group1

```yaml
  rules:
    - when:
        - key: request.auth.claims[groups]
          values: ["group1"]
```

The demo token may not have `groups`. The exam will tell you the claim name and value. Nested claims: `request.auth.claims[foo][bar]` in newer Istio; prefer the docs example if unsure.

### 4. Custom header

```yaml
  jwtRules:
    - issuer: "testing@secure.istio.io"
      jwksUri: "https://raw.githubusercontent.com/istio/istio/release-1.26/security/tools/jwt/samples/jwks.json"
      fromHeaders:
        - name: x-token
          prefix: "Bearer "
```

If the header is the raw JWT with no prefix, omit `prefix`.

### 5. Gateway JWT

```yaml
apiVersion: security.istio.io/v1
kind: RequestAuthentication
metadata:
  name: ingress-jwt
  namespace: istio-system
spec:
  selector:
    matchLabels:
      istio: ingressgateway
  jwtRules:
    - issuer: "testing@secure.istio.io"
      jwksUri: "https://raw.githubusercontent.com/istio/istio/release-1.26/security/tools/jwt/samples/jwks.json"
---
apiVersion: security.istio.io/v1
kind: AuthorizationPolicy
metadata:
  name: ingress-jwt
  namespace: istio-system
spec:
  selector:
    matchLabels:
      istio: ingressgateway
  action: ALLOW
  rules:
    - from:
        - source:
            requestPrincipals: ["*"]
```

Host-restrict with `to.operation.hosts` if the gateway serves many apps.

## Verify

```bash
kubectl get requestauthentication,authorizationpolicy -n demo -n istio-system
istioctl analyze -n demo -n istio-system
```

Decode a token without verifying: `echo $TOKEN | cut -d. -f2 | base64 -d 2>/dev/null; echo` to see `iss` and `sub`.

## Exam Tips

- **RequestAuthentication alone never "requires login".** You need ALLOW `requestPrincipals`.
- Invalid JWT = **401**. Missing JWT with ALLOW requestPrincipals = **403**. Mix-ups fail the verify step.
- `jwks` inline vs `jwksUri`: if the cluster cannot reach the internet, you must paste JWKS.
- Issuer string must match **exactly**, including `https://` if that is what `iss` is.
- Docs: [JWT](https://istio.io/docs/tasks/security/authorization/authz-jwt/) and RequestAuthentication reference.
