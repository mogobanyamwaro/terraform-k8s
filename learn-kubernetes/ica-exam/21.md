# 21. Locality Load Balancing and Failover

## Concept Refresher

Istio reads locality from node labels:

```text
region  = topology.kubernetes.io/region
zone    = topology.kubernetes.io/zone
subzone = topology.istio.io/subzone   (optional, Istio-specific)
```

The tuple is `region/zone/subzone`. Lab-Setup stamps these on kind nodes so this file is runnable.

**Default behaviour:** Envoy prefers endpoints in the **same locality** as the **source proxy**. If the local zone has healthy endpoints, remote zones get little or no traffic.

### Explicit distribution

```yaml
apiVersion: networking.istio.io/v1
kind: DestinationRule
metadata:
  name: httpbin
  namespace: demo
spec:
  host: httpbin
  trafficPolicy:
    loadBalancer:
      localityLbSetting:
        enabled: true
        distribute:
          - from: "us-west/us-west-1a/*"
            to:
              "us-west/us-west-1a/*": 80
              "us-west/us-west-1b/*": 20
          - from: "us-east/*"
            to:
              "us-east/*": 100
    outlierDetection:
      consecutive5xxErrors: 1
      interval: 1s
      baseEjectionTime: 30s
      maxEjectionPercent: 100
```

`from` is the **client** locality. `to` weights must sum to 100.

### Failover

When the local locality is **unhealthy**, send to a backup locality instead of spilling everywhere:

```yaml
        localityLbSetting:
          enabled: true
          failover:
            - from: us-west
              to: us-east
            - from: us-east
              to: us-west
```

**Outlier detection is mandatory for failover.** Without it Istio cannot mark a locality unhealthy, so failover never triggers. This pairing is directly examinable.

`failover` and `distribute` cannot both be set on the same `localityLbSetting`.

### failoverPriority (Istio 1.15+)

An ordered list of labels used to rank endpoints when the caller and endpoint share those labels:

```yaml
        localityLbSetting:
          failoverPriority:
            - "topology.istio.io/network"
            - "topology.kubernetes.io/region"
            - "topology.kubernetes.io/zone"
```

### Mesh-wide vs per DestinationRule

You can set locality settings in MeshConfig `localityLbSetting` as the default, then override per host on a DestinationRule. Exam tasks usually want the DestinationRule.

## Tasks

Kind cluster from Lab-Setup: control-plane `us-west/us-west-1a`, workers in `us-west-1b` and `us-east-1a`. Spread `httpbin` across zones.

1. Enable locality LB on `httpbin` so west-1a clients send 80% local, 20% west-1b.
2. Configure region failover: `us-west` fails over to `us-east`. Include the required outlier detection.
3. Prove that without outlier detection, failover is a no-op even if you set `failover`.

## Solutions

Spread pods (example):

```bash
kubectl -n demo patch deploy httpbin --type merge -p '{
  "spec": {
    "replicas": 3,
    "template": {
      "spec": {
        "topologySpreadConstraints": [{
          "maxSkew": 1,
          "topologyKey": "topology.kubernetes.io/zone",
          "whenUnsatisfiable": "ScheduleAnyway",
          "labelSelector": {"matchLabels": {"app": "httpbin"}}
        }]
      }
    }
  }
}'
kubectl -n demo get pod -o wide -L topology.kubernetes.io/zone
```

If the cluster has no zone labels, the rest of this file will not show locality behaviour. Fix the nodes first (`Lab-Setup.md`).

### 1. Distribute

```yaml
apiVersion: networking.istio.io/v1
kind: DestinationRule
metadata:
  name: httpbin
  namespace: demo
spec:
  host: httpbin
  trafficPolicy:
    loadBalancer:
      localityLbSetting:
        enabled: true
        distribute:
          - from: "us-west/us-west-1a/*"
            to:
              "us-west/us-west-1a/*": 80
              "us-west/us-west-1b/*": 20
    outlierDetection:
      consecutive5xxErrors: 5
      interval: 10s
      baseEjectionTime: 30s
```

Even for distribute-only, outlier detection is good practice so dead local pods do not eat the 80%.

### 2. Failover

```yaml
  trafficPolicy:
    loadBalancer:
      localityLbSetting:
        enabled: true
        failover:
          - from: us-west
            to: us-east
    outlierDetection:
      consecutive5xxErrors: 1
      interval: 1s
      baseEjectionTime: 15s
      maxEjectionPercent: 100
      minHealthPercent: 0
```

`from` / `to` here are **region** names, not `region/zone`.

### 3. The trap

Apply failover **without** `outlierDetection`, scale west pods to return 500 (or delete them after a pause). Traffic will still try west endpoints (or spill unpredictably) instead of a clean region failover. Add outlier detection, repeat, watch east endpoints take over in `proxy-config endpoint`.

## Verify

```bash
# Locality on endpoints
istioctl proxy-config endpoint deploy/sleep.demo -o json \
  | jq -r '.[] | select(.name|test("httpbin")) | "\(.locality // "none") \(.healthStatus) \(.address)"'

# Which node is sleep on?
kubectl -n demo get pod -o wide -l app=sleep

# After injecting 500s in west, healthStatus should flip
istioctl proxy-config cluster deploy/sleep.demo --fqdn httpbin.demo.svc.cluster.local -o json \
  | jq '.[0].loadAssignment.policy'
```

## Exam Tips

- **Failover without outlier detection does not work.** If a task mentions "failover to another region", write both stanzas.
- `distribute` weights must sum to 100. `80` and `10` is invalid.
- Wildcard: `us-west/*` is all zones in that region. `*` is everything.
- Kind nodes need the labels **before** pods are scheduled; labelling later does not move existing pods' locality until restart.
- Docs: [Locality load balancing](https://istio.io/docs/tasks/traffic-management/locality-load-balancing/).
