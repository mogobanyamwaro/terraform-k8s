# 20. Fault Injection: Delay and Abort

## Concept Refresher

Fault injection is Istio's chaos switch. It lives on the VirtualService HTTP route, next to timeout and retries, and is evaluated on the **client** sidecar (or waypoint).

```yaml
apiVersion: networking.istio.io/v1
kind: VirtualService
metadata:
  name: ratings
  namespace: bookinfo
spec:
  hosts:
    - ratings
  http:
    - fault:
        delay:
          percentage:
            value: 100.0
          fixedDelay: 5s
        abort:
          percentage:
            value: 10.0
          httpStatus: 500
      route:
        - destination:
            host: ratings
            subset: v1
```

Two fault types:

| Fault | Effect |
| --- | --- |
| `delay` | Wait `fixedDelay` (or `exponentialDelay`) then continue. Tests timeouts |
| `abort` | Return `httpStatus` / `grpcStatus` immediately (after delay, if both set). Tests retries and error handling |

### Rules

- **If both delay and abort are set, delay runs first, then abort.** A 5s delay plus abort 500 means the client waits 5s and then gets 500.
- `percentage.value` is 0-100 **float**. `percent: 100` is the old integer field. Use `percentage.value`.
- Faults apply only to requests that **matched this route**. Put them on a header match to break one user.
- Faults do **not** require DestinationRule subsets, but if you route to a subset, the subset must exist.
- TCP/TLS routes have **no** fault injection.
- Ambient: needs a waypoint. Otherwise the VS is valid and ignored.

### Interaction with retries and timeouts (exam favourite)

```text
abort 500% 500 + retries attempts 3 retryOn 5xx
  -> client still gets 500 after retries exhaust, but you see 4 upstream aborts

delay 5s + timeout 2s
  -> client gets 504, upstream may never be called (delay is injected before the request)
```

Delay is injected by Envoy **before** calling upstream. A delay longer than the route timeout never hits the destination.

## Tasks

1. Delay **all** `ratings` traffic by **7 seconds**.
2. Abort **50%** of `httpbin` requests with HTTP **500**.
3. For header `end-user: jason` only, abort `reviews` with **418**. Everyone else is clean.
4. Delay `/delay-me` on `httpbin` by 3s and abort 100% of `/fail-me` with 503. Other paths normal.
5. Combine: 100% abort 500 on `ratings`, and configure retries so productpage retries twice on 5xx.

## Solutions

### 1. Delay ratings

```yaml
apiVersion: networking.istio.io/v1
kind: VirtualService
metadata:
  name: ratings
  namespace: bookinfo
spec:
  hosts:
    - ratings
  http:
    - fault:
        delay:
          percentage:
            value: 100.0
          fixedDelay: 7s
      route:
        - destination:
            host: ratings
            subset: v1
```

Bookinfo productpage will feel slow / timeout on stars.

### 2. Fifty percent 500

```yaml
apiVersion: networking.istio.io/v1
kind: VirtualService
metadata:
  name: httpbin
  namespace: demo
spec:
  hosts:
    - httpbin
  http:
    - fault:
        abort:
          percentage:
            value: 50.0
          httpStatus: 500
      route:
        - destination:
            host: httpbin
            port:
              number: 8000
```

### 3. User-scoped abort

```yaml
apiVersion: networking.istio.io/v1
kind: VirtualService
metadata:
  name: reviews
  namespace: bookinfo
spec:
  hosts:
    - reviews
  http:
    - match:
        - headers:
            end-user:
              exact: jason
      fault:
        abort:
          percentage:
            value: 100.0
          httpStatus: 418
      route:
        - destination:
            host: reviews
            subset: v1
    - route:
        - destination:
            host: reviews
            subset: v1
```

### 4. Two paths

```yaml
  http:
    - match:
        - uri:
            exact: /delay-me
      fault:
        delay:
          percentage:
            value: 100.0
          fixedDelay: 3s
      route:
        - destination:
            host: httpbin
            port: { number: 8000 }
    - match:
        - uri:
            exact: /fail-me
      fault:
        abort:
          percentage:
            value: 100.0
          httpStatus: 503
      route:
        - destination:
            host: httpbin
            port: { number: 8000 }
    - route:
        - destination:
            host: httpbin
            port: { number: 8000 }
```

### 5. Abort plus retries

Same abort VS on `ratings`, plus:

```yaml
      retries:
        attempts: 2
        retryOn: 5xx
```

on that route. Productpage still fails after 3 tries (1 + 2). Access logs show the repeats.

## Exam Tips

- **`percentage.value` is a float.** `value: 100` is fine (integer JSON), `value: "100%"` is not.
- Forgetting `route` and only setting `fault` is invalid. A rule still needs a destination even if you abort 100%.
- `httpStatus` is an integer, not `"500"`.
- gRPC abort uses `grpcStatus: DEADLINE_EXCEEDED` (string enum), not an HTTP code.
- Docs: [Fault injection](https://istio.io/docs/tasks/traffic-management/fault-injection/).
