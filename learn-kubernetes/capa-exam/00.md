# Certified Argo Project Associate (CAPA) Practice

This folder mirrors `pca-exam`, `cca-exam`, and `cgoa-exam`: **closed-book multiple choice**, not a live cluster like CKA or ICA.

Outline checked against the Linux Foundation [CAPA page](https://training.linuxfoundation.org/certification/certified-argo-project-associate-capa/) and [CNCF CAPA](https://www.cncf.io/training/certification/capa/) on 2026-08-19.

CAPA is **the Argo product exam**. It is not CGOA (vendor-neutral GitOps) and not “Argo CD only”. Workflows is the largest domain. The core skill is **which Argo tool, when, and how the four tools integrate**.

## The Four Tools (memorise in one line each)

1. **Argo Workflows** — Kubernetes-native **workflow engine** (container steps, DAGs, artifacts, CronWorkflow).
2. **Argo CD** — Declarative **GitOps continuous delivery** (Git desired state ↔ live cluster).
3. **Argo Rollouts** — **Progressive delivery** controller (blue-green, canary, analysis) replacing a plain Deployment strategy.
4. **Argo Events** — **Event-driven** automation (EventSource → EventBus → Sensor → Trigger).

## Universal CAPA Reasoning Flow

```text
1. What is the job?
   Git keep cluster = Git     -> Argo CD
   Batch/ML/CI steps on k8s   -> Workflows
   Canary / blue-green / analysis -> Rollouts
   Webhook / S3 / Kafka / cron event -> Events
   Two of the above           -> integrate (do not mash into one tool)

2. If Workflows: is it a template definition or an invocator?
   Does work (container/script/resource/...) vs calls others (steps/DAG)

3. If CD: is the question sync, health, source type, or project constraint?

4. If Rollouts: blue-green (two stacks + switch) vs canary (weights + pauses)?
   AnalysisTemplate = reusable spec; AnalysisRun = one execution.

5. If Events: which of the four components?
   EventSource captures, EventBus transports, Sensor decides, Trigger acts.
```
