## Question 3: ConfigMap, Secret, and Sidecar Container

### Scenario

You're deploying an application that needs:

1. Configuration data (non-sensitive) - stored in a ConfigMap
2. A database password (sensitive) - stored as a Secret
3. A sidecar container that logs application output

### Tasks

1. Create a ConfigMap named `app-config` with:
   - Key: `app.properties` with value: `environment=production\nlog_level=info`
   - Key: `features.json` with value: `{"darkmode": true, "analytics": false}`

2. Create a Secret named `db-secret` with:
   - Key: `password` with value: `SuperSecret123!`
   - Key: `username` with value: `appuser`

3. Create a multi-container pod named `web-app` with:
   - Main container: `nginx:alpine` mounting the ConfigMap as a file at `/etc/config`
   - Sidecar container: `busybox` that runs `tail -f /var/log/access.log` to monitor logs
   - Both containers should share the same volume for logs

4. Mount the Secret as an environment variable `DB_PASSWORD` in the main container only

## Let's Build This Step by Step

### Step 1: Create the ConfigMap

**Try these commands:**

```bash
# Method 1: From literal values
kubectl create configmap app-config \
  --from-literal=app.properties="environment=production\nlog_level=info" \
  --from-literal=features.json='{"darkmode": true, "analytics": false}'

# Method 2: From files (more realistic)
echo -e "environment=production\nlog_level=info" > app.properties
echo '{"darkmode": true, "analytics": false}' > features.json
kubectl create configmap app-config --from-file=app.properties --from-file=features.json

# Verify
kubectl get configmap app-config -o yaml
```

### Step 2: Create the Secret

```bash
# Create secret from literals
kubectl create secret generic db-secret \
  --from-literal=password='SuperSecret123!' \
  --from-literal=username='appuser'

# Verify (the data will be base64 encoded)
kubectl get secret db-secret -o yaml

# Decode to verify
kubectl get secret db-secret -o jsonpath='{.data.password}' | base64 -d
```

### Step 3: Create the Multi-Container Pod

**This is the challenging part.** Create a file named `web-app.yaml`:

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: web-app
spec:
  volumes:
    - name: config-volume
      configMap:
        name: app-config
    - name: log-volume
      emptyDir: {}

  containers:
    # Main container
    - name: nginx
      image: nginx:alpine
      volumeMounts:
        - name: config-volume
          mountPath: /etc/config
        - name: log-volume
          mountPath: /var/log/nginx
      env:
        - name: DB_PASSWORD
          valueFrom:
            secretKeyRef:
              name: db-secret
              key: password
        - name: DB_USERNAME
          valueFrom:
            secretKeyRef:
              name: db-secret
              key: username

    # Sidecar container
    - name: log-watcher
      image: busybox
      command: ["/bin/sh"]
      args: ["-c", "tail -f /var/log/nginx/access.log"]
      volumeMounts:
        - name: log-volume
          mountPath: /var/log/nginx
```

Apply the pod:

```bash
kubectl apply -f web-app.yaml
```

### Step 4: Verify Everything Works

```bash
# Check pod status
kubectl get pods -w

# Check both containers are running
kubectl get pod web-app -o jsonpath='{.status.containerStatuses[*].name}'

# View ConfigMap files in the main container
kubectl exec web-app -c nginx -- cat /etc/config/app.properties
kubectl exec web-app -c nginx -- cat /etc/config/features.json

# Check environment variables in main container
kubectl exec web-app -c nginx -- env | grep DB_

# Generate some access logs
kubectl exec web-app -c nginx -- sh -c "echo 'test' > /var/log/nginx/access.log"
kubectl exec web-app -c nginx -- sh -c "wget -O- http://localhost 2>&1 > /dev/null"

# View logs from sidecar container
kubectl logs web-app -c log-watcher
```

## Common Issues & Solutions

**Issue 1:** Pod won't start - ConfigMap or Secret not found

```bash
# Verify they exist
kubectl get configmap app-config
kubectl get secret db-secret
```

**Issue 2:** Sidecar container exits

```bash
# Check sidecar logs
kubectl logs web-app -c log-watcher

# The tail command should keep running, not exit
```

**Issue 3:** ConfigMap files not showing

```bash
# Check mount path
kubectl exec web-app -c nginx -- ls -la /etc/config/
```

## CKA Exam Tips

- **Multi-container pods** often use sidecars for logging, monitoring, or proxying
- **ConfigMaps can be mounted as files** or environment variables
- **Secrets are base64 encoded only** (not encrypted by default)
- **EmptyDir volumes** share data between containers in the same pod
- **ConfigMap updates eventually sync** to pods (but not to environment variables)
