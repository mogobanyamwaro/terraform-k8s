### Question 1: Troubleshooting & RBAC (Weight: ~30% & ~25%)

This question simulates a real-world scenario combining troubleshooting (exam domain with highest weight) and security/RBAC.

**Scenario:**
You are the cluster administrator. A developer named `john` created a pod, but it is stuck in the `CrashLoopBackOff` state. Additionally, another developer named `jane` needs access to list pods in the `production` namespace, but she keeps getting a `forbidden` error.

**Tasks:**

1.  Identify why the pod `crashing-pod` in the `default` namespace is failing.
2.  Fix the pod so it runs successfully.
3.  Create a Role and RoleBinding so user `jane` can only `get` and `list` pods in the `production` namespace.

### How to Approach This in the Exam

The CKA exam is about methodical troubleshooting. Don't just guess. Follow this flow:

1.  **Assess the Situation:** First, see what's wrong.

    ```bash
    # See all resources and their status
    kubectl get all

    # Focus on the problematic pod
    kubectl get pods
    ```

2.  **Deep Dive into the Problem Pod:** You see a pod named `crashing-pod` with status `CrashLoopBackOff`. This usually means the container starts and then exits immediately.

    ```bash
    # 1. Describe the pod for events (timeouts, image pull errors, etc.)
    kubectl describe pod crashing-pod

    # 2. Check the logs (the most direct way to see the error)
    kubectl logs crashing-pod

    # 3. If it's crashing, check logs from the previous attempt
    kubectl logs crashing-pod --previous
    ```

3.  **Fix the Pod:** The logs show an error: `exec /usr/local/bin/start.sh: exec format error` or `permission denied`. This is a common issue where the container entrypoint is misconfigured. To fix this for the exam, you would edit the pod's configuration. However, **pods are immutable for their `spec`**, so you cannot edit the container command on a running pod. You must save the YAML, delete the pod, and recreate it.

    ```bash
    # Save the current (broken) pod definition to a file
    kubectl get pod crashing-pod -o yaml > fixed-pod.yaml

    # Edit the file (e.g., fix the 'command:' or 'args:' section, or add a simple 'sleep' command to keep it alive)
    # For example, change the command to: ["sleep", "3600"]
    vi fixed-pod.yaml

    # Delete the old pod
    kubectl delete pod crashing-pod

    # Create the new, fixed pod from the edited YAML
    kubectl apply -f fixed-pod.yaml

    # Verify it's running
    kubectl get pods
    ```

4.  **Solve the RBAC Issue:** Now, for `jane`'s permission problem. You need to create a Role (rules for a namespace) and a RoleBinding (assigns the Role to a user). You can generate the YAML using `--dry-run`.

    ```bash
    # Create the Role YAML
    kubectl create role pod-reader --verb=get,list --resource=pods --dry-run=client -o yaml -n production > jane-role.yaml

    # Create the RoleBinding YAML
    kubectl create rolebinding jane-pod-binding --role=pod-reader --user=jane --dry-run=client -o yaml -n production > jane-binding.yaml

    # Apply both files
    kubectl apply -f jane-role.yaml
    kubectl apply -f jane-binding.yaml

    # Verify (optional, but good practice)
    kubectl auth can-i get pods --as=jane -n production
    ```

### Key Exam Tips from this Example

- **Memorize `--dry-run`**: This is your most powerful tool. It generates YAML so you don't have to type it from scratch. `kubectl create deployment --image=nginx nginx --dry-run=client -o yaml > deploy.yaml`
- **Logs are gold**: Always run `kubectl logs <pod-name>` first when troubleshooting a failing application.
- **Read, Don't Skim**: The `kubectl describe pod` command gives you events and reasons (e.g., `FailedPull`, `CrashLoopBackOff`) which tell you exactly where to look.
- **Namespace is key**: Many exam questions are set in specific namespaces. Always check your context or use the `-n` flag. `kubectl config set-context --current --namespace=production`

## Step 1: Create the Problematic Pod

First, let's create the crashing pod that we'll troubleshoot. Run this command in your terminal:

```bash
cat <<EOF | kubectl apply -f -
apiVersion: v1
kind: Pod
metadata:
  name: crashing-pod
spec:
  containers:
  - name: my-app
    image: busybox
    command: ["/bin/sh"]
    args: ["-c", "exit 1"]
EOF
```

This pod is designed to fail immediately - it runs the `exit 1` command which causes the container to crash right after starting.

## Step 2: Verify It's Crashing

Check the pod status:

```bash
kubectl get pods
```

You should see something like `CrashLoopBackOff` or `Error`. Watch it for a few seconds:

```bash
kubectl get pods -w
```

(Press Ctrl+C to stop watching)

## Step 3: Your Turn to Troubleshoot

Now it's your turn to investigate. Try these commands in order and note what you find:


Look at the "Events" section at the bottom - what does it say?

2. **Check the logs:**

**Question for you:** Based on what you see in the logs, why is the pod crashing?

## Step 4: Fix the Pod

Now let's fix it. Since we can't edit a running pod's spec, we need to:

1. **Save the pod configuration:**

```bash
kubectl get pod crashing-pod -o yaml > crashing-pod.yaml
```

2. **Edit the file** (open it in VS Code):

```bash
code crashing-pod.yaml
# or use: vi crashing-pod.yaml
```

3. **Find the `command` and `args` section** - it looks like:

```yaml
command:
  - /bin/sh
args:
  - -c
  - exit 1
```

4. **Change it to something that keeps running**, for example:

```yaml
command:
  - /bin/sh
args:
  - -c
  - sleep 3600
```

5. **Delete the old pod and create the fixed one:**

```bash
kubectl delete pod crashing-pod
kubectl apply -f crashing-pod.yaml
```

6. **Verify it's running:**

```bash
kubectl get pods
```

## Common Issues & Solutions

**If the pod still crashes:**

- Check if you edited the YAML correctly
- Make sure `sleep 3600` is in the args, not as a separate command
- Try: `command: ["sleep", "3600"]` (simpler format)

**If RBAC isn't working:**

- Verify namespace: `kubectl get role -n production`
- Verify binding: `kubectl get rolebinding -n production`
- Check if user is spelled correctly: `jane` (lowercase)
