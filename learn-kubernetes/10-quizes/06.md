## Question 6: Persistent Storage for Stateful Applications

### Scenario

You need to deploy a database application that requires persistent storage. The application must:

1. Retain data even if the pod restarts
2. Have stable network identity (hostname)
3. Scale to multiple replicas with each having its own storage
4. Support ordered deployment and scaling

### Tasks

1. Create a **PersistentVolume** (PV) using hostPath with 1Gi capacity
2. Create a **PersistentVolumeClaim** (PVC) that binds to the PV
3. Create a single pod that uses the PVC to store data
4. Convert the pod to a **StatefulSet** with 3 replicas
5. Test that each pod has its own persistent storage
6. Test ordered startup and deletion

## Let's Build This Step by Step

### Step 1: Create a PersistentVolume

Create a file named `pv.yaml`:

```yaml
apiVersion: v1
kind: PersistentVolume
metadata:
  name: my-pv
  labels:
    type: local
spec:
  capacity:
    storage: 1Gi
  volumeMode: Filesystem
  accessModes:
    - ReadWriteOnce
  persistentVolumeReclaimPolicy: Retain
  hostPath:
    path: /mnt/data
```

**Note:** For Multipass (single node), hostPath works fine. For multi-node clusters, you'd use network storage.

Apply it:

```bash
kubectl apply -f pv.yaml

# Verify PV created
kubectl get pv
```

### Step 2: Create a PersistentVolumeClaim

Create `pvc.yaml`:

```yaml
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: my-pvc
spec:
  accessModes:
    - ReadWriteOnce
  volumeMode: Filesystem
  resources:
    requests:
      storage: 500Mi
  # Optional: bind to specific PV
  # volumeName: my-pv
```

Apply and verify binding:

```bash
kubectl apply -f pvc.yaml

# Check PVC status (should be Bound)
kubectl get pvc

# Check PV status (should be Bound)
kubectl get pv

# See binding details
kubectl describe pvc my-pvc
```

### Step 3: Create a Pod That Uses the PVC

Create `pod-with-pvc.yaml`:

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: data-pod
spec:
  volumes:
    - name: data-storage
      persistentVolumeClaim:
        claimName: my-pvc
  containers:
    - name: app
      image: busybox
      command: ["/bin/sh"]
      args:
        ["-c", "while true; do echo $(date) >> /data/test.txt; sleep 10; done"]
      volumeMounts:
        - name: data-storage
          mountPath: /data
```

Apply and test:

```bash
kubectl apply -f pod-with-pvc.yaml

# Wait for pod to run
kubectl wait --for=condition=ready pod/data-pod --timeout=30s

# Verify data persistence
kubectl exec data-pod -- cat /data/test.txt

# Delete pod
kubectl delete pod data-pod

# Recreate pod
kubectl apply -f pod-with-pvc.yaml

# Verify data is still there
kubectl exec data-pod -- cat /data/test.txt
```

### Step 4: Create StatefulSet with Headless Service

StatefulSets require a **headless service** (clusterIP: None) for stable network identities.

Create `statefulset.yaml`:

```yaml
# Headless Service for StatefulSet
apiVersion: v1
kind: Service
metadata:
  name: webapp-service
  labels:
    app: webapp
spec:
  clusterIP: None
  selector:
    app: webapp
  ports:
    - port: 80
      name: web
---
# StatefulSet
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: webapp-statefulset
spec:
  serviceName: webapp-service
  replicas: 3
  selector:
    matchLabels:
      app: webapp
  template:
    metadata:
      labels:
        app: webapp
    spec:
      containers:
        - name: nginx
          image: nginx:alpine
          ports:
            - containerPort: 80
          volumeMounts:
            - name: data
              mountPath: /usr/share/nginx/html
  volumeClaimTemplates:
    - metadata:
        name: data
      spec:
        accessModes: ["ReadWriteOnce"]
        resources:
          requests:
            storage: 1Gi
```

Apply and watch:

```bash
kubectl apply -f statefulset.yaml

# Watch pods start in order
kubectl get pods -w

# Check StatefulSet status
kubectl get statefulset

# Check PVCs created for each pod
kubectl get pvc
```

### Step 5: Test Stable Network Identity

```bash
# Check DNS names (StatefulSet pods have predictable names)
kubectl run -it --rm debug-pod --image=busybox --restart=Never -- sh

# Inside the pod, test DNS resolution:
nslookup webapp-statefulset-0.webapp-service
nslookup webapp-statefulset-1.webapp-service
nslookup webapp-statefulset-2.webapp-service

# Exit the pod
exit
```

### Step 6: Test Persistent Storage per Pod

Write unique data to each pod:

```bash
# Write to pod-0
kubectl exec webapp-statefulset-0 -- sh -c "echo 'Pod 0 Data' > /usr/share/nginx/html/index.html"

# Write to pod-1
kubectl exec webapp-statefulset-1 -- sh -c "echo 'Pod 1 Data' > /usr/share/nginx/html/index.html"

# Write to pod-2
kubectl exec webapp-statefulset-2 -- sh -c "echo 'Pod 2 Data' > /usr/share/nginx/html/index.html"

# Verify each pod has its own data
kubectl exec webapp-statefulset-0 -- cat /usr/share/nginx/html/index.html
kubectl exec webapp-statefulset-1 -- cat /usr/share/nginx/html/index.html
kubectl exec webapp-statefulset-2 -- cat /usr/share/nginx/html/index.html
```

### Step 7: Test Ordered Operations

**Test ordered deletion (reverse order):**

```bash
# Delete the StatefulSet
kubectl delete statefulset webapp-statefulset

# Watch deletion order (pods terminate from highest ordinal)
kubectl get pods -w
```

**Test ordered creation:**

```bash
# Recreate the StatefulSet
kubectl apply -f statefulset.yaml

# Watch pods start in order (0, then 1, then 2)
kubectl get pods -w
```

### Step 8: Test Scaling StatefulSet

```bash
# Scale up to 5 replicas
kubectl scale statefulset webapp-statefulset --replicas=5

# Watch pods created in order
kubectl get pods -w

# Check new PVCs created
kubectl get pvc

# Scale down to 2 replicas (removes 4,3 in reverse order)
kubectl scale statefulset webapp-statefulset --replicas=2

# Watch deletion (removes 4, then 3)
kubectl get pods -w

# PVCs remain after scale down (for data retention)
kubectl get pvc
```

### Step 9: Test Rolling Update for StatefulSet

```bash
# Update the image
kubectl patch statefulset webapp-statefulset --type='json' \
  -p='[{"op": "replace", "path": "/spec/template/spec/containers/0/image", "value": "nginx:1.20"}]'

# Watch rolling update (reverse order)
kubectl get pods -w

# Check rollout status
kubectl rollout status statefulset webapp-statefulset
```

## PV Access Modes

| Access Mode             | Description            | Use Case       |
| ----------------------- | ---------------------- | -------------- |
| **ReadWriteOnce (RWO)** | Single node read/write | Databases      |
| **ReadOnlyMany (ROX)**  | Many nodes read-only   | Config data    |
| **ReadWriteMany (RWX)** | Many nodes read/write  | Shared storage |

## PV Reclaim Policies

| Policy      | Behavior                                         |
| ----------- | ------------------------------------------------ |
| **Retain**  | Keep PV and data after PVC deletion              |
| **Delete**  | Delete PV and data after PVC deletion            |
| **Recycle** | Scrub data and make available again (deprecated) |

## CKA Exam Tips

- **StatefulSet pods are NOT interchangeable** - each has unique identity
- **StatefulSets require headless service** (clusterIP: None)
- **PVC templates** create unique PVC for each replica
- **Ordinal indexing starts at 0** - pods are podname-0, podname-1, etc.
- **Termination is reverse order** - highest ordinal first
- **Rolling updates go reverse order** - highest ordinal first
- **PVCs persist** even after StatefulSet deletion
