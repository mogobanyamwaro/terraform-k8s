## Question 7: Network Policies for Pod Isolation

### Scenario

You have a microservices application with:

- A **frontend** pod that should only receive traffic from ingress controller
- An **API** pod that should only accept traffic from the frontend
- A **database** pod that should only accept traffic from the API
- All other traffic should be blocked

### Tasks

1. Create three namespaces: `frontend`, `api`, `database`
2. Deploy an nginx pod in each namespace with appropriate labels
3. Create NetworkPolicies to enforce:
   - **Default deny all ingress** for all namespaces
   - **Allow frontend** to only receive traffic from outside (ingress)
   - **Allow API** to only receive traffic from frontend namespace
   - **Allow database** to only receive traffic from API namespace
4. Test connectivity between pods (should only work as defined)

## Let's Build This Step by Step

### Step 1: Create Namespaces and Pods

```bash
# Create namespaces
kubectl create namespace frontend
kubectl create namespace api
kubectl create namespace database

# Deploy frontend pod (nginx serving website)
kubectl run frontend-pod --image=nginx --namespace=frontend --labels="app=frontend,role=web"

# Deploy API pod (nginx acting as API)
kubectl run api-pod --image=nginx --namespace=api --labels="app=api,role=processor"

# Deploy database pod (redis for this example)
kubectl run db-pod --image=redis --namespace=database --labels="app=database,role=storage"

# Verify all pods are running
kubectl get pods --all-namespaces -l "app in (frontend,api,database)"
```

### Step 2: Test Default Connectivity (All Pods Can Talk)

First, let's see that without NetworkPolicies, all pods can communicate:

```bash
# Test frontend -> API (should work)
kubectl exec -n frontend frontend-pod -- wget -qO- --timeout=2 http://api-pod.api.svc.cluster.local

# Test API -> Database (should work)
kubectl exec -n api api-pod -- wget -qO- --timeout=2 http://db-pod.database.svc.cluster.local:6379

# Test Database -> Frontend (should work - but shouldn't!)
kubectl exec -n database db-pod -- wget -qO- --timeout=2 http://frontend-pod.frontend.svc.cluster.local
```

### Step 3: Create Default Deny Policies

Create `default-deny-frontend.yaml`:

```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: default-deny-ingress
  namespace: frontend
spec:
  podSelector: {}
  policyTypes:
    - Ingress
```

Apply for all namespaces:

```bash
# Apply default deny to all namespaces
kubectl apply -f - <<EOF
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: default-deny-ingress
  namespace: frontend
spec:
  podSelector: {}
  policyTypes:
  - Ingress
---
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: default-deny-ingress
  namespace: api
spec:
  podSelector: {}
  policyTypes:
  - Ingress
---
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: default-deny-ingress
  namespace: database
spec:
  podSelector: {}
  policyTypes:
  - Ingress
EOF

# Verify policies created
kubectl get networkpolicies --all-namespaces
```

### Step 4: Test After Default Deny (All Traffic Blocked)

```bash
# All these should FAIL now
kubectl exec -n frontend frontend-pod -- wget -qO- --timeout=2 http://api-pod.api.svc.cluster.local 2>&1 | grep -i "connection refused\|timed out"

kubectl exec -n api api-pod -- wget -qO- --timeout=2 http://db-pod.database.svc.cluster.local:6379 2>&1 | grep -i "connection refused\|timed out"

kubectl exec -n database db-pod -- wget -qO- --timeout=2 http://frontend-pod.frontend.svc.cluster.local 2>&1 | grep -i "connection refused\|timed out"
```

### Step 5: Allow Frontend to Receive Traffic

Create `allow-frontend-ingress.yaml`:

```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: allow-frontend-ingress
  namespace: frontend
spec:
  podSelector:
    matchLabels:
      app: frontend
  policyTypes:
    - Ingress
  ingress:
    - from:
        - ipBlock:
            cidr: 0.0.0.0/0 # Allow from anywhere (simulating ingress controller)
      ports:
        - protocol: TCP
          port: 80
```

Apply:

```bash
kubectl apply -f allow-frontend-ingress.yaml
```

### Step 6: Allow API to Only Receive from Frontend

Create `allow-api-from-frontend.yaml`:

```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: allow-api-from-frontend
  namespace: api
spec:
  podSelector:
    matchLabels:
      app: api
  policyTypes:
    - Ingress
  ingress:
    - from:
        - namespaceSelector:
            matchLabels:
              kubernetes.io/metadata.name: frontend
      ports:
        - protocol: TCP
          port: 80
```

Apply:

```bash
kubectl apply -f allow-api-from-frontend.yaml
```

### Step 7: Allow Database to Only Receive from API

Create `allow-db-from-api.yaml`:

```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: allow-db-from-api
  namespace: database
spec:
  podSelector:
    matchLabels:
      app: database
  policyTypes:
    - Ingress
  ingress:
    - from:
        - namespaceSelector:
            matchLabels:
              kubernetes.io/metadata.name: api
      ports:
        - protocol: TCP
          port: 6379 # Redis port
```

Apply:

```bash
kubectl apply -f allow-db-from-api.yaml
```

### Step 8: Test Network Policies

Now test the connectivity again:

```bash
echo "=== Test 1: Frontend -> API (Should work) ==="
kubectl exec -n frontend frontend-pod -- wget -qO- --timeout=2 http://api-pod.api.svc.cluster.local | head -1

echo -e "\n=== Test 2: API -> Database (Should work) ==="
kubectl exec -n api api-pod -- wget -qO- --timeout=2 http://db-pod.database.svc.cluster.local:6379 2>&1 | head -1

echo -e "\n=== Test 3: Database -> Frontend (Should FAIL) ==="
kubectl exec -n database db-pod -- wget -qO- --timeout=2 http://frontend-pod.frontend.svc.cluster.local 2>&1 | grep -i "connection refused\|timed out"

echo -e "\n=== Test 4: Frontend -> Database (Should FAIL - no policy) ==="
kubectl exec -n frontend frontend-pod -- wget -qO- --timeout=2 http://db-pod.database.svc.cluster.local:6379 2>&1 | grep -i "connection refused\|timed out"

echo -e "\n=== Test 5: API -> Frontend (Should FAIL - no egress policy) ==="
kubectl exec -n api api-pod -- wget -qO- --timeout=2 http://frontend-pod.frontend.svc.cluster.local 2>&1 | grep -i "connection refused\|timed out"
```

## Advanced Scenarios

### Scenario A: Allow Egress Traffic as Well

Create egress policy for API to only talk to database:

```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: api-egress-to-db
  namespace: api
spec:
  podSelector:
    matchLabels:
      app: api
  policyTypes:
    - Egress
  egress:
    - to:
        - namespaceSelector:
            matchLabels:
              kubernetes.io/metadata.name: database
      ports:
        - protocol: TCP
          port: 6379
```

### Scenario B: Allow Within Same Namespace

Allow frontend pods to talk to each other:

```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: allow-same-namespace
  namespace: frontend
spec:
  podSelector: {}
  policyTypes:
    - Ingress
  ingress:
    - from:
        - podSelector: {}
```

### Scenario C: Combine Namespace and Pod Selectors

Allow API to only receive from frontend pods with specific label:

```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: api-from-frontend-specific
  namespace: api
spec:
  podSelector:
    matchLabels:
      app: api
  ingress:
    - from:
        - namespaceSelector:
            matchLabels:
              kubernetes.io/metadata.name: frontend
          podSelector:
            matchLabels:
              role: web
      ports:
        - port: 80
```

## Network Policy Rules Summary

| Rule Type                                        | Selector              | Effect                  |
| ------------------------------------------------ | --------------------- | ----------------------- |
| `podSelector: {}`                                | All pods in namespace | Applies to everything   |
| `podSelector: {matchLabels: {app: web}}`         | Specific pods         | Applies to labeled pods |
| `namespaceSelector: {matchLabels: {name: prod}}` | All pods in namespace | Cross-namespace         |
| `ipBlock: {cidr: 10.0.0.0/24}`                   | External IPs          | Allow external traffic  |

## CKA Exam Tips

- **Default deny is critical** - Always create default-deny first
- **NetworkPolicy is namespace-scoped** - Each namespace needs its own policies
- **Empty podSelector (`{}`)** means all pods in namespace
- **Policies are additive** - If ANY policy allows traffic, it's allowed
- **Default deny + specific allow** is the recommended pattern
- **Namespace labels** - Use `kubernetes.io/metadata.name` for namespace selection
- **Egress is often forgotten** - Remember to consider both directions
