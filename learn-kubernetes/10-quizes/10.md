## Question 10: Advanced Scheduling and Node Management

### Scenario

You have a cluster with different types of nodes:

- **2 general-purpose nodes** for most workloads
- **1 high-memory node** for memory-intensive apps (4GB RAM)
- **1 GPU node** for ML workloads (label: `accelerator=nvidia-tesla`)

### Tasks

1. Taint the GPU node so only specific pods can run there
2. Create a pod that tolerates the GPU taint
3. Use node affinity to schedule a memory-intensive pod on the high-memory node
4. Use pod affinity to schedule two related pods together
5. Use pod anti-affinity to spread pods across different nodes
6. Cordon and drain a node for maintenance

## Let's Build This Step by Step

### Step 1: Label and Taint Nodes

First, let's see what nodes you have:

```bash

# If you have only one node, add multiple labels to simulate different node types
```

### Step 2: Pod with Toleration (GPU Workload)

```yaml
      command: ["sleep", "3600"]
```


### Step 4: Node Affinity - Memory-Intensive Pod

Create `memory-pod.yaml`:

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: memory-intensive
spec:
  containers:
    - name: app
      image: nginx
      resources:
        requests:
          memory: "2Gi"
        limits:
          memory: "3Gi"
  affinity:
    nodeAffinity:
      requiredDuringSchedulingIgnoredDuringExecution:
        nodeSelectorTerms:
          - matchExpressions:
              - key: memory
                operator: In
                values:
                  - high
      preferredDuringSchedulingIgnoredDuringExecution:
        - weight: 100
          preference:
            matchExpressions:
              - key: node-type
                operator: In
                values:
                  - general
```

Apply:

```bash
kubectl apply -f memory-pod.yaml

# Check where it scheduled
kubectl get pods -o wide

# Verify node affinity
kubectl describe pod memory-intensive | grep -A15 "Node Affinity"
```

### Step 5: Pod Affinity - Schedule Related Pods Together

Create `frontend-backend-affinity.yaml`:

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: frontend
  labels:
    app: web
    tier: frontend
spec:
  containers:
    - name: nginx
      image: nginx
---
apiVersion: v1
kind: Pod
metadata:
  name: backend
  labels:
    app: web
    tier: backend
spec:
  containers:
    - name: redis
      image: redis
  affinity:
    podAffinity:
      requiredDuringSchedulingIgnoredDuringExecution:
        - labelSelector:
            matchExpressions:
              - key: tier
                operator: In
                values:
                  - frontend
          topologyKey: kubernetes.io/hostname
```

Apply and verify:

```bash
kubectl apply -f frontend-backend-affinity.yaml

# Check both pods scheduled on same node
kubectl get pods -o wide

# Verify pod affinity
kubectl describe pod backend | grep -A15 "Pod Affinity"
```

### Step 6: Pod Anti-Affinity - Spread Pods Across Nodes

Create `anti-affinity.yaml`:

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: webapp
spec:
  replicas: 3
  selector:
    matchLabels:
      app: webapp
  template:
    metadata:
      labels:
        app: webapp
    spec:
      affinity:
        podAntiAffinity:
          requiredDuringSchedulingIgnoredDuringExecution:
            - labelSelector:
                matchExpressions:
                  - key: app
                    operator: In
                    values:
                      - webapp
              topologyKey: kubernetes.io/hostname
      containers:
        - name: nginx
          image: nginx
```

Apply and observe:

```bash
kubectl apply -f anti-affinity.yaml

# Watch pods schedule (each on different node if possible)
kubectl get pods -o wide -w

# Verify anti-affinity
kubectl describe pod webapp-<pod-id> | grep -A15 "Pod Anti-Affinity"
```

### Step 7: Node Maintenance - Cordon and Drain

```bash
# Cordon a node (mark as unschedulable)
kubectl cordon <your-node-name>

# Verify node is cordoned
kubectl get nodes

# Try to schedule new pod (will remain pending)
kubectl run test-pod --image=nginx

# Check pod status
kubectl get pods

# Drain a node (evict all pods)
kubectl drain <your-node-name> --ignore-daemonsets --delete-emptydir-data

kubectl uncordon <your-node-name>

# Verify node is schedulable again
kubectl get nodes
```

### Step 8: Advanced - Multiple Taints and Tolerations

Add multiple taints to a node:

```bash
# Add multiple taints

  - key: "disktype"
    operator: "Equal"
    value: "ssd"
    effect: "NoSchedule"
```

### Step 9: Node Affinity with Multiple Expressions

Create `complex-affinity.yaml`:

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: complex-affinity-pod
spec:
  containers:
    - name: app
      image: nginx
  affinity:
    nodeAffinity:
      requiredDuringSchedulingIgnoredDuringExecution:
        nodeSelectorTerms:
          - matchExpressions:
              - key: node-type
                operator: In
                values:
                  - general
                  - high-memory
              - key: kubernetes.io/os
                operator: In
                values:
                  - linux
      preferredDuringSchedulingIgnoredDuringExecution:
        - weight: 80
          preference:
            matchExpressions:
              - key: zone
                operator: In
                values:
                  - us-east-1
        - weight: 20
          preference:
            matchExpressions:
              - key: ssd
                operator: Exists
```

### Step 10: Topology Spread Constraints

Spread pods evenly across zones:

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: spread-deployment
spec:
  replicas: 6
  selector:
    matchLabels:
      app: spread-app
  template:
    metadata:
      labels:
        app: spread-app
    spec:
      topologySpreadConstraints:
        - maxSkew: 1
          topologyKey: kubernetes.io/hostname
          whenUnsatisfiable: DoNotSchedule
          labelSelector:
            matchLabels:
              app: spread-app
      containers:
        - name: nginx
          image: nginx
```

## Taint/Toleration Effects

| Effect               | Behavior                                     |
| -------------------- | -------------------------------------------- |
| **NoSchedule**       | New pods without toleration won't schedule   |
| **PreferNoSchedule** | Scheduler tries to avoid, but not guaranteed |
| **NoExecute**        | Evict existing pods without toleration       |

## Affinity Types Summary

| Type                | Purpose                         |
| ------------------- | ------------------------------- |
| **nodeAffinity**    | Schedule pods on specific nodes |
| **podAffinity**     | Schedule pods together          |
| **podAntiAffinity** | Spread pods apart               |

## CKA Exam Tips

- **Taints are applied to nodes**, tolerations are in pod spec
- **Taints and tolerations do NOT guarantee placement** - only prevent
- **Node affinity is more flexible** than nodeSelector
- **`requiredDuringScheduling`** is hard requirement (pod won't schedule)
- **`preferredDuringScheduling`** is soft requirement (scheduler tries)
- **`IgnoredDuringExecution`** means node changes don't affect running pods
- **`topologyKey`** is usually `kubernetes.io/hostname` or failure-domain labels
- **Cordon** = mark unschedulable, **Drain** = evict pods
