## Question 4: Deployment Strategy and Rollback

### Scenario

You have a web application that needs to be deployed with zero downtime. The initial version (v1) is running, but you need to update to v2. Something goes wrong with v2, and you must rollback quickly.

### Tasks

1. Create a Deployment named `webapp` with:
   - 3 replicas
   - Image: `nginx:1.20`
   - Labels: `app=webapp, version=v1`
   - Resource limits: memory 128Mi, CPU 100m

2. Expose the Deployment as a ClusterIP service on port 80

3. Perform a rolling update to `nginx:1.21` (v2)

4. During the update, check the rollout status

5. Something is wrong with v2 - perform an immediate rollback to v1

6. Verify the rollback was successful

## Let's Build This Step by Step

### Step 1: Create the Initial Deployment

**Try this first:**

```bash
# Create deployment with specific image
kubectl create deployment webapp --image=nginx:1.20 --replicas=3

# Add labels (or create with YAML for more control)
kubectl label deployment webapp app=webapp version=v1 --overwrite

# Set resource limits
kubectl set resources deployment webapp --limits=memory=128Mi,cpu=100m

# Verify
kubectl get deployment webapp
kubectl get pods -l app=webapp
```

**Better approach - create a YAML file `webapp-deploy.yaml`:**

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: webapp
  labels:
    app: webapp
    version: v1
spec:
  replicas: 3
  selector:
    matchLabels:
      app: webapp
  template:
    metadata:
      labels:
        app: webapp
        version: v1
    spec:
      containers:
        - name: nginx
          image: nginx:1.20
          resources:
            limits:
              memory: "128Mi"
              cpu: "100m"
          ports:
            - containerPort: 80
```

Apply it:

```bash
kubectl apply -f webapp-deploy.yaml
```

### Step 2: Expose the Deployment

```bash
# Create service
kubectl expose deployment webapp --port=80 --target-port=80 --type=ClusterIP

# Verify service
kubectl get svc webapp
kubectl get endpoints webapp
```

### Step 3: Test v1 is Working

```bash
# Get service IP
kubectl get svc webapp

# Test access (from within cluster)
kubectl run test-pod --image=busybox -it --rm --restart=Never -- sh -c "wget -qO- webapp:80 | head -5"

# Check current image version
kubectl get pods -l app=webapp -o jsonpath='{.items[0].spec.containers[0].image}'
```

### Step 4: Perform Rolling Update to v2

```bash
# Update the image
kubectl set image deployment/webapp nginx=nginx:1.21

# Watch the rollout
kubectl rollout status deployment/webapp

# Check rollout history
kubectl rollout history deployment/webapp

# Verify new version
kubectl get pods -l app=webapp
kubectl describe deployment webapp | grep Image
```

### Step 5: Monitor During Update (in another terminal)

While the update is happening, run this to see the rolling update in action:

```bash
# Watch pods being created and destroyed
kubectl get pods -l app=webapp -w

# In another terminal, check service endpoints
kubectl get endpoints webapp -w
```

### Step 6: Something Went Wrong - Rollback!

```bash
# Check rollout history to see revisions
kubectl rollout history deployment/webapp

# Perform rollback to previous version
kubectl rollout undo deployment/webapp

# Watch the rollback
kubectl rollout status deployment/webapp

# Verify v1 is back
kubectl get pods -l app=webapp
kubectl describe deployment webapp | grep Image
```

### Step 7: Verify Complete Success

```bash
# Check deployment status
kubectl get deployment webapp

# Check replica sets (old and new)
kubectl get rs -l app=webapp

# Check pod images
kubectl get pods -l app=webapp -o jsonpath='{range .items[*]}{.spec.containers[0].image}{"\n"}{end}'

# Test service again
kubectl run test-pod --image=busybox -it --rm --restart=Never -- sh -c "wget -qO- webapp:80 | head -1"
```

## Advanced Scenarios to Try

### Scenario A: Pause and Resume Rollout

```bash
# Update to v2 but pause immediately
kubectl set image deployment/webapp nginx=nginx:1.22
kubectl rollout pause deployment/webapp

# Check status - only some pods updated
kubectl get pods -l app=webapp

# Resume rollout
kubectl rollout resume deployment/webapp
```

### Scenario B: Rollout with Custom Strategy

Edit the deployment to use a different strategy:

```bash
kubectl edit deployment webapp
```

Add this under `spec`:

```yaml
strategy:
  rollingUpdate:
    maxSurge: 1
    maxUnavailable: 0
  type: RollingUpdate
```

This ensures zero downtime (maxUnavailable=0).

### Scenario C: Scale During Rollout

```bash
# While updating, scale up
kubectl scale deployment webapp --replicas=5

# Check how scale affects rollout
kubectl get pods -l app=webapp -w
```

## Common Issues & Solutions

**Issue 1:** Rollout stuck

```bash
# Check events
kubectl describe deployment webapp

# Check pod status
kubectl get pods -l app=webapp

# Check if image pull fails
kubectl get events --sort-by='.lastTimestamp' | grep -i error
```

**Issue 2:** Too many revisions

```bash
# Clean up old replica sets
kubectl delete rs <old-replicaset-name>

# Or set revision history limit
kubectl edit deployment webapp
# Add: revisionHistoryLimit: 2
```

**Issue 3:** Service not working after rollback

```bash
# Check endpoints again
kubectl get endpoints webapp

# Check selector matches
kubectl get svc webapp -o yaml | grep -A3 selector
kubectl get pods --show-labels | grep webapp
```

## CKA Exam Tips

- **Rollout commands are critical:** `kubectl rollout status`, `history`, `undo`, `pause`, `resume`
- **`--record` is deprecated** - changes are automatically recorded now
- **Check ReplicaSets** to see old versions - they remain for rollback
- **Rolling update default:** maxSurge=25%, maxUnavailable=25%
- **Zero downtime:** Set `maxUnavailable=0` and `maxSurge=1`
- **Rollback keeps history** - you can rollback to any revision

## Quick Reference Card

```bash
# Common rollout commands for CKA
kubectl rollout status deployment/<name>           # Check progress
kubectl rollout history deployment/<name>          # See revisions
kubectl rollout undo deployment/<name>             # Rollback to previous
kubectl rollout undo deployment/<name> --to-revision=2  # Rollback to specific revision
kubectl rollout pause deployment/<name>            # Pause update
kubectl rollout resume deployment/<name>           # Resume update
```
