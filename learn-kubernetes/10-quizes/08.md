## Question 8: Batch Processing with Jobs and CronJobs

### Scenario

You need to run batch processing tasks in your Kubernetes cluster:

1. A one-time data migration job that must run to completion
2. A parallel processing job that processes 10 work items
3. A scheduled backup job that runs every night at 2 AM
4. A cleanup job that runs every hour but only keeps successful pods

### Tasks

1. Create a Job that runs a simple calculation and exits
2. Create a parallel Job that processes 5 work items with 2 parallel pods
3. Create a CronJob that runs a backup script every minute (for testing)
4. Test job failure and retry behavior
5. View job history and clean up completed jobs

## Let's Build This Step by Step

### Step 1: Basic Job (One-time Task)

Create a file named `basic-job.yaml`:

```yaml
apiVersion: batch/v1
kind: Job
metadata:
  name: pi-calculator
spec:
  template:
    spec:
      containers:
        - name: pi
          image: perl
          command: ["perl", "-Mbignum=bpi", "-wle", "print bpi(100)"]
      restartPolicy: Never
  backoffLimit: 4
```

Apply and monitor:

```bash
# Create the job
kubectl apply -f basic-job.yaml

# Watch job status
kubectl get jobs -w

# Check pods created by job
kubectl get pods -l job-name=pi-calculator

# View job output
kubectl logs job/pi-calculator

# Check job details
kubectl describe job pi-calculator
```

### Step 2: Parallel Processing Job

Create `parallel-job.yaml`:

```yaml
apiVersion: batch/v1
kind: Job
metadata:
  name: parallel-processor
spec:
  completions: 5 # Total number of successful pods needed
  parallelism: 2 # How many pods to run in parallel
  template:
    spec:
      containers:
        - name: worker
          image: busybox
          command: ["/bin/sh", "-c"]
          args:
            - |
              echo "Processing item $ITEM"
              sleep 5
              echo "Item $ITEM completed"
          env:
            - name: ITEM
              valueFrom:
                fieldRef:
                  fieldPath: metadata.name
      restartPolicy: Never
  backoffLimit: 2
```

Apply and watch:

```bash
kubectl apply -f parallel-job.yaml

# Watch pods spin up (2 at a time)
kubectl get pods -w

# See job completion status
kubectl get jobs -w

# Check all pod outputs
kubectl logs -l job-name=parallel-processor
```

### Step 3: Create a CronJob

Create `backup-cronjob.yaml`:

```yaml
apiVersion: batch/v1
kind: CronJob
metadata:
  name: database-backup
spec:
  schedule: "*/1 * * * *" # Every minute (for testing)
  jobTemplate:
    spec:
      template:
        spec:
          containers:
            - name: backup
              image: busybox
              args:
                - /bin/sh
                - -c
                - |
                  echo "Starting backup at $(date)"
                  echo "Backing up database..."
                  sleep 10
                  echo "Backup completed at $(date)"
          restartPolicy: Never
  successfulJobsHistoryLimit: 3
  failedJobsHistoryLimit: 1
```

Apply and monitor:

```bash
kubectl apply -f backup-cronjob.yaml

# Check CronJob status
kubectl get cronjob

# Watch jobs being created every minute
kubectl get jobs -w

# See pods created by CronJob
kubectl get pods --watch

# View CronJob details
kubectl describe cronjob database-backup
```

### Step 4: Job with Failure Handling

Create `failing-job.yaml`:

```yaml
apiVersion: batch/v1
kind: Job
metadata:
  name: retry-job
spec:
  backoffLimit: 3
  template:
    spec:
      containers:
        - name: retry-container
          image: busybox
          command: ["/bin/sh", "-c"]
          args:
            - |
              # Simulate random failure
              if [ $((RANDOM % 3)) -eq 0 ]; then
                echo "Success!"
                exit 0
              else
                echo "Failed! Will retry..."
                exit 1
              fi
      restartPolicy: Never
```

Test failure handling:

```bash
kubectl apply -f failing-job.yaml

# Watch retry attempts
kubectl get pods -w

# Check failed pods
kubectl get pods --field-selector=status.phase=Failed

# View job status
kubectl get jobs

# See job history
kubectl describe job retry-job
```

### Step 5: Job with Completion Timeout

Create `timeout-job.yaml`:

```yaml
apiVersion: batch/v1
kind: Job
metadata:
  name: timeout-job
spec:
  activeDeadlineSeconds: 30 # Job must complete in 30 seconds
  template:
    spec:
      containers:
        - name: slow-task
          image: busybox
          command: ["/bin/sh", "-c"]
          args:
            - |
              echo "Starting slow task..."
              sleep 60
              echo "Task completed"
      restartPolicy: Never
```

Test timeout:

```bash
kubectl apply -f timeout-job.yaml

# Watch job fail after 30 seconds
kubectl get jobs -w

# Check why it failed
kubectl describe job timeout-job
```

### Step 6: Indexed Job (Parallel with Unique Index)

Create `indexed-job.yaml`:

```yaml
apiVersion: batch/v1
kind: Job
metadata:
  name: indexed-processor
spec:
  completions: 5
  parallelism: 5
  completionMode: Indexed
  template:
    spec:
      containers:
        - name: processor
          image: busybox
          command: ["/bin/sh", "-c"]
          args:
            - |
              echo "Processing index $JOB_COMPLETION_INDEX"
              # Each pod gets a unique index
              echo "Data for shard $JOB_COMPLETION_INDEX" > /tmp/data-$JOB_COMPLETION_INDEX
              cat /tmp/data-$JOB_COMPLETION_INDEX
              sleep 2
      restartPolicy: Never
```

Apply and test:

```bash
kubectl apply -f indexed-job.yaml

# See all pods running with different indexes
kubectl get pods -l job-name=indexed-processor -o wide

# Check each pod's output
for i in 0 1 2 3 4; do
  echo "Pod $i output:"
  kubectl logs indexed-processor-$i 2>/dev/null | head -2
done
```

### Step 7: Clean Up Old Jobs

Create a job that cleans up automatically:

```yaml
apiVersion: batch/v1
kind: CronJob
metadata:
  name: cleanup-job
spec:
  schedule: "0 */6 * * *" # Every 6 hours
  successfulJobsHistoryLimit: 2
  failedJobsHistoryLimit: 1
  jobTemplate:
    spec:
      ttlSecondsAfterFinished: 300 # Delete job 5 minutes after completion
      template:
        spec:
          containers:
            - name: cleaner
              image: busybox
              command: ["/bin/sh", "-c"]
              args:
                - |
                  echo "Cleaning up old resources..."
                  # kubectl delete old jobs (would need RBAC)
                  echo "Cleanup complete"
          restartPolicy: Never
```

## CronJob Schedule Syntax

```
┌───────────── minute (0 - 59)
│ ┌───────────── hour (0 - 23)
│ │ ┌───────────── day of month (1 - 31)
│ │ │ ┌───────────── month (1 - 12)
│ │ │ │ ┌───────────── day of week (0 - 6) (Sunday=0)
│ │ │ │ │
* * * * *
```

Common schedules:

- `*/5 * * * *` - Every 5 minutes
- `0 * * * *` - Every hour
- `0 2 * * *` - Every day at 2 AM
- `0 2 * * 0` - Every Sunday at 2 AM
- `0 2 1 * *` - Every month on the 1st at 2 AM

## Job Types Summary

| Job Type     | Use Case                | Key Parameters                   |
| ------------ | ----------------------- | -------------------------------- |
| **Single**   | One-time task           | `completions: 1` (default)       |
| **Parallel** | Multiple items          | `completions: N, parallelism: M` |
| **Indexed**  | Each pod gets unique ID | `completionMode: Indexed`        |
| **CronJob**  | Scheduled recurring     | `schedule: "* * * * *"`          |

## CKA Exam Tips

- **`restartPolicy: Never`** for jobs - pods won't restart automatically
- **`backoffLimit`** controls how many retries
- **`activeDeadlineSeconds`** - job timeout
- **`ttlSecondsAfterFinished`** - auto-cleanup completed jobs
- **CronJob schedules are UTC** - consider timezone differences
- **Job pods are NOT automatically deleted** - manage history limits
- **`successfulJobsHistoryLimit`** and **`failedJobsHistoryLimit`** prevent unlimited pods
