# 16. Automated Ingestion

**Domain:** Catalog (22%)

## Concept Refresher

**Manual:** you point at a file/URL. **Automated:** Backstage **discovers** entities.

**Entity providers** (ingest): GitHub org discovery, GitLab, Bitbucket, LDAP/MS Graph users, custom providers. They **emit** entities on a schedule without a static location per repo.

**Catalog processors** (transform): run on entities already being ingested — validate schema, add annotations, resolve relations, generate entities from `$text` / OpenAPI, apply policy. Processors do **not** crawl GitHub orgs by themselves.

```text
Provider  -->  raw entities / locations
Processor -->  validate, mutate, stitch relations
Database  -->  catalog API --> UI
```

Example: `GithubEntityProvider` finds `catalog-info.yaml` in an org. `BuiltinKindsEntityProcessor` validates Component/API/….

**Life of an entity:** provider/location → processors → upsert in DB → refresh → optional orphan deletion.

Config lives under `catalog.providers` (and processor modules registered in `packages/backend`). Installing a discovery plugin is **backend** work plus YAML; not a frontend route.

CBA: **providers ingest, processors transform.** Do not swap the words.
