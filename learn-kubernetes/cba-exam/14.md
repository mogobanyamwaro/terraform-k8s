# 14. Manual Entity Locations

**Domain:** Catalog (22%)

## Concept Refresher

A **Location** is a pointer the catalog **reads**: a file path or URL to YAML (one or more entities).

**Static locations** in `app-config.yaml`:

```yaml
catalog:
  locations:
    - type: file
      target: ../../examples/entities.yaml
    - type: url
      target: https://github.com/org/repo/blob/main/catalog-info.yaml
    - type: url
      target: https://github.com/org/repo/blob/main/template.yaml
      rules:
        - allow: [Template]
```

**UI:** Catalog → Create → **Register existing component** — pastes a URL. That creates a Location entity (persisted in the DB), not only a config file.

`type: file` is for paths the **backend process** can read (local/dev). Production prefers `url` (GitHub/GitLab) plus SCM integration token.

`rules.allow` limits which kinds that location may emit (security: don’t let a random URL inject Users).

Unregistering: remove from config **or** delete the Location in the catalog UI (for registered ones).

## Exam tips

- **Config locations vs UI-registered locations** — both are Locations.
- Private URL + no token = fetch failure, not a YAML kind error.
