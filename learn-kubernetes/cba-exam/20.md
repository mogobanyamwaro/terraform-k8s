# 20. React in the Backstage App

**Domain:** Customizing Backstage (32%)

## Concept Refresher

The create-app frontend is a **React** SPA in `packages/app`.

Important files:

| File | Role |
| --- | --- |
| `src/App.tsx` | `createApp`, plugins, `<FlatRoutes>` / routes, sign-in |
| `src/components/Root/Root.tsx` | App shell, **Sidebar** |
| `src/components/catalog/EntityPage.tsx` | Entity tabs/cards |
| `src/index.tsx` | Mount |

```tsx
import { createApp } from '@backstage/app-defaults';
import { FlatRoutes } from '@backstage/core-app-api';
import { CatalogIndexPage, CatalogEntityPage } from '@backstage/plugin-catalog';

const app = createApp({ apis, plugins: [...], components: { ... } });
const AppProvider = app.getProvider();
const AppRouter = app.getRouter();

<AppProvider>
  <AppRouter>
    <Root>
      <FlatRoutes>
        <Route path="/catalog" element={<CatalogIndexPage />} />
        <Route path="/catalog/:namespace/:kind/:name" element={<CatalogEntityPage />} />
      </FlatRoutes>
    </Root>
  </AppRouter>
</AppProvider>
```

You can add a **plain React page** (`<Route path="/ops" element={<MyPage />} />`) without a full plugin package — still “changes to React code in the app.”

Hooks from `@backstage/core-plugin-api`: `useApi`, `useEntity`, `configApiRef`. Exam: you **change** these files; you do not memorise every API.
