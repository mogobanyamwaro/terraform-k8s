# 11. Why the Software Catalog

**Domain:** Catalog (22%)

## Concept Refresher

The Software Catalog is Backstage’s **inventory of software**: who owns it, how it relates, where the source is, and which plugins attach (CI, k8s, docs).

**Why:** discoverability, ownership, golden-path metadata, one place for “what do we run?”. Not a replacement for Git; Git stays source. The catalog **indexes** YAML (and providers).

**System model** (software catalog model):

```text
Domain
  └── System
        ├── Component  (service, website, library)
        ├── API
        └── Resource   (db, bucket, queue)
User / Group  (ownership)
Template      (Scaffolder)
Location      (where YAML was loaded from)
```

Entity **ref**: `kind:namespace/name` (default namespace `default`). Example: `component:default/demo-service`.

Relations (`spec.owner`, `spec.system`, `dependsOn`, `providesApis`, …) power the graph and owner pages.
