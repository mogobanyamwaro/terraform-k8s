# 06. Identity-Based Network Security

**Domain:** Network Policy (18%)

## Concept Refresher

iptables firewalls match **IPs**. Cilium maps **labels → numeric security identity** and stores that in eBPF maps. Policy rules say “identity 1234 may talk to identity 5678 on TCP/80”, not “10.0.1.5 may talk to 10.0.2.9”.

When a pod restarts and gets a new IP, **identity stays the same** if labels stay the same. That is the point.

### What forms an identity

Typically:

- `k8s:io.kubernetes.pod.namespace`
- `k8s:io.cilium.k8s.policy.cluster`
- selected Kubernetes labels (`app`, `version`, …) as configured
- Special reserved identities

### Reserved identities (memorise)

| Name | Meaning |
| --- | --- |
| `host` | Local node (host namespace) |
| `remote-node` | Other nodes |
| `world` | Outside the cluster (and not identified as remote-node) |
| `health` | cilium-health endpoints |
| `init` | Pod during initialization |
| `unmanaged` | Not managed by Cilium |
| `kube-apiserver` | API server identity (when distinguished) |
| `ingress` | Cilium Ingress |

Policies use these as **entities**: `fromEntities: [world]`.

### Label source prefixes

- `k8s:` Kubernetes labels
- `any:` 
- CIDR identities for `fromCIDR`

### Policy always references identities

`endpointSelector` picks **who is being locked down**. `fromEndpoints` / `toEndpoints` pick **peers by labels**, which become identities.

## Hands-on

```bash
kubectl -n kube-system exec ds/cilium -- cilium-dbg identity list | head
kubectl -n shop exec ds/cilium -n kube-system -- cilium-dbg endpoint list
```

(From a node agent, `endpoint list` shows identity IDs per pod.)

## Exam tips

- **Identity = labels, not IP.**
- Memorise **world, host, remote-node, health, init**.
- Entities are how policies talk about those reserved identities.
