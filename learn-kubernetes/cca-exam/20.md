# 20. Global Services and Cross-Cluster Load Balancing

**Domain:** Cluster Mesh (10%)

## Concept Refresher

A normal Service only load-balances **local** cluster endpoints. In Cluster Mesh, annotate:

```yaml
metadata:
  annotations:
    service.cilium.io/global: "true"
```

Same Service **name + namespace** in each cluster become one **global** VIP/service. Backends from all clusters join the eBPF LB map (subject to affinity).

### Other annotations (recognise)

| Annotation | Role |
| --- | --- |
| `service.cilium.io/global: "true"` | Join the mesh service |
| `service.cilium.io/shared: "true"` | Share (related to global) |
| `service.cilium.io/affinity: "local"` | Prefer local backends, fail over remote |
| `service.cilium.io/affinity: "remote"` | Prefer remote |
| `service.cilium.io/affinity: "none"` | Any |

Exact affinity strings: **local** is the exam favourite (topology-aware / locality).

### Headless / ClusterIP

Global ClusterIP: callers use the Service DNS **in their cluster**; Cilium datapath may send packets to remote pods (native or tunnel as configured).

### Policy

Remote cluster identities carry a **cluster** label. Policies can allow `k8s:io.cilium.k8s.policy.cluster: other`.

### Connect procedure (high level)

```bash
cilium clustermesh enable
cilium clustermesh status
cilium clustermesh connect --destination-context <ctx>
```

Certificates and API server endpoints are exchanged. Both sides must enable mesh.

## Hands-on

Read annotation docs; in one cluster:

```bash
kubectl explain service.metadata.annotations
# remember the cilium global annotation string
```

## Exam tips

- Annotation **`service.cilium.io/global: "true"`** — memorise it.
- **Same ns/name.** **affinity local.**
- Mesh enable **both sides**, unique IDs, no CIDR overlap.
