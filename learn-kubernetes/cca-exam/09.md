# 09. L7 and DNS Policies

**Domain:** Network Policy (18%)

## Concept Refresher

L3/L4: identities + ports. **L7**: inspect HTTP/gRPC/Kafka (via **Envoy**) or DNS (via Cilium DNS proxy).

```yaml
      toPorts:
        - ports:
            - port: "80"
              protocol: TCP
          rules:
            http:
              - method: GET
                path: "/get"
```

Effects:

- Only GET `/get` is allowed; POST `/post` dropped
- Hubble can show HTTP method/path when L7 is on the path
- Adds latency vs pure eBPF L3/L4 (proxy hop)

### DNS / FQDN

```yaml
  egress:
    - toFQDNs:
        - matchName: "httpbin.org"
        - matchPattern: "*.github.com"
      toPorts:
        - ports:
            - port: "443"
              protocol: TCP
    - toEndpoints:
        - matchLabels:
            k8s:io.kubernetes.pod.namespace: kube-system
            k8s-app: kube-dns
      toPorts:
        - ports:
            - port: "53"
              protocol: ANY
          rules:
            dns:
              - matchPattern: "*"
```

Cilium snoops DNS answers and **only then** allows the resolved IPs (with TTL). Without allowing DNS to CoreDNS, FQDN rules cannot work.

`matchName` exact. `matchPattern` wildcards.

### Visibility without enforce

You can enable L7 **visibility** (Hubble HTTP fields) with a policy that allows all HTTP or with extra visibility annotations/CR — exam: **L7 fields in Hubble require L7 parsing**, not just `hubble observe`.

## Hands-on

Add HTTP GET-only on httpbin:80. `curl /get` works, `curl -X POST /post` fails. `hubble observe --protocol http`.

## Exam tips

- **L7 = proxy.** **FQDN = DNS proxy + allow kube-dns.**
- Visibility vs enforcement: both can populate Hubble L7; enforcement also drops.
- `toFQDNs` is egress, not a replacement for Ingress host rules.
