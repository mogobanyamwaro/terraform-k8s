# 14. Encrypting Traffic in Transit

**Domain:** Service Mesh (16%)

## Concept Refresher

Cilium **transparent encryption** encrypts **pod-to-pod traffic between nodes** without app TLS.

| Mode | Notes |
| --- | --- |
| **WireGuard** | Modern default recommendation. Simple, fast, kernel WG. Enable `encryption.enabled=true` `encryption.type=wireguard` |
| **IPsec** | Older, more moving parts (keys in Secrets, algorithms). `encryption.type=ipsec` |

**Do not enable both.**

### What is encrypted

- Typically **overlay or native traffic leaving the node** toward another node
- Host-to-host WireGuard overlay
- **Not** a replacement for NetworkPolicy
- **Not** automatically “mTLS identities in HTTP headers” like Istio PeerAuthentication — it is **network-layer** encryption

Local pod-to-pod **on the same node** may not need encryption on the wire (no NIC hop).

### Keys

WireGuard: Cilium manages node keys. IPsec: you manage/rotate secrets more carefully.

### When to use

Compliance “encryption in transit”, untrusted underlay, multi-tenant metal. Combine with policy: encryption ≠ authorization.

## Hands-on

```bash
kubectl -n kube-system exec ds/cilium -- cilium-dbg status | grep -i encrypt
```

Enabling WG on a running cluster is a datapath change — lab rebuild is safer.

## Exam tips

- **WG or IPsec, not both.**
- Confidentiality ≠ NetworkPolicy.
- Sidecar mTLS (Istio) vs node WireGuard (Cilium) is a comparison question waiting to happen.
