# 08. Policy Rule Structure

**Domain:** Network Policy (18%)

## Concept Refresher

```yaml
apiVersion: cilium.io/v2
kind: CiliumNetworkPolicy
metadata:
  name: httpbin-ingress
  namespace: shop
spec:
  endpointSelector:
    matchLabels:
      app: httpbin
  ingress:
    - fromEndpoints:
        - matchLabels:
            app: client
      toPorts:
        - ports:
            - port: "80"
              protocol: TCP
```

### Building blocks

| Field | Meaning |
| --- | --- |
| `endpointSelector` | Which endpoints **this policy applies to** (the subject) |
| `ingress` | Who may **call them** |
| `egress` | Who they may **call** |
| `fromEndpoints` / `toEndpoints` | Peer pods by labels (same namespace unless using extra selectors) |
| `fromEntities` / `toEntities` | world, host, remote-node, cluster, … |
| `fromCIDR` / `toCIDR` | IP blocks |
| `fromNodes` / `toNodes` | Node labels (host-level) |
| `toFQDNs` | DNS names (egress) |
| `toServices` | Kubernetes Services |
| `toPorts` | L4 ports + optional L7 `rules.http` |
| `deny` (ingressDeny/egressDeny) | Explicit deny, evaluated with deny-priority |

### Namespace matching

`fromEndpoints` matches in the **policy’s namespace** by default. To allow another namespace, add:

```yaml
        matchLabels:
          app: client
          k8s:io.kubernetes.pod.namespace: other
```

or `fromEntities: [cluster]` (broad).

### CiliumClusterwideNetworkPolicy (CCNP)

Same spec idea, **cluster-scoped**, no namespace. Used for host policies, whole-cluster defaults, node selectors.

### L4 is strings

`"80"` as string is conventional in CNP (IntOrString). Protocol TCP/UDP/ANY.

## Hands-on

Apply the YAML in the refresher, then:

```bash
kubectl -n shop exec client -- curl -sS -o /dev/null -w "%{http_code}\n" http://httpbin
```

Add a second client without `app=client` and show it fails.

## Exam tips

- Subject = `endpointSelector`. Peers = `from*` / `to*`.
- Cross-namespace needs an explicit namespace label (or entity `cluster`).
- FQDN is **egress**. Ingress cannot match client FQDNs the same way.
