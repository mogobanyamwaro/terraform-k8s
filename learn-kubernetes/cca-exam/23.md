# 23. Egress Connectivity Requirements

**Domain:** BGP and External Networking (6%)

## Concept Refresher

Pods have **cluster-internal IPs**. The internet and corporate networks do not route those CIDRs unless you advertise them (BGP/native) or **masquerade**.

### Masquerade / SNAT (default story)

- Pod → external IP: node **SNATs** to the **node IP** (or designated egress IP)
- Replies come back to the node, conntrack undoes NAT
- Requirement: node has a working default route; firewall allows the node IP out

Cilium implements masquerade in **eBPF** when replacement is on (`enable-ipv4-masquerade`).

### When you must not masquerade

- External systems must see the **real pod IP** (some firewalls, audit)
- Then you need **native routing + BGP (or cloud routes)** so return path exists

### Egress Gateway

**CiliumEgressGatewayPolicy**: pin namespace/pod egress to **specific gateway nodes** with a defined SNAT IP. Used so enterprise firewalls allow one egress IP, not every node.

```text
client pods  ->  designated egress node  ->  SNAT  ->  internet
```

Requirements: gateway nodes, policy selecting source pods, destination CIDRs.

### DNS

External HTTP needs DNS (CoreDNS → upstream). NetworkPolicy must allow DNS or egress breaks even if SNAT is fine.

### ICMP / firewalls

Do not forget underlay: nodes need to reach 8.8.8.8 if that is the test; NetworkPolicy `toEntities: world` on egress.

## Exam tips

- **Cannot route pod CIDR → SNAT.** **Can route → optional no-masquerade.**
- Egress Gateway = **stable corporate egress IP**.
- Policy + DNS are part of “egress requirements.”
