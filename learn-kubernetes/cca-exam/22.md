# 22. eBPF Platforms vs iptables Platforms

**Domain:** eBPF (10%)

## Concept Refresher

Traditional kube-proxy + many CNIs: **iptables** (or IPVS).

iptables:

- **List of rules**, evaluated **in order**
- Cost grows with **number of Services and rules** (can be O(n))
- conntrack in netfilter
- Hard to attach rich **identity** (labels) — matches IPs/ports
- `iptables-restore` storms on every Service change (historically)

eBPF (Cilium kube-proxy replacement + policy):

- **Hash maps**: backend lookup ~ **O(1)**
- Incremental map updates, not full table rewrite
- Identity keys, not only IPs
- XDP can drop/load-balance **before** iptables
- Hubble from the same path

IPVS is a middle ground (hashed LB) but still not Cilium’s identity-aware policy datapath.

Calico can use eBPF too; exam contrast is **generic iptables kube-proxy CNI vs Cilium eBPF**, not a vendor war.

### When iptables still appears

- kube-proxy not replaced
- Host firewall leftovers
- Some L7 still userspace Envoy (not iptables)

## Exam tips

- **O(n) chains vs O(1) maps.**
- **IPs vs identities.**
- **Full table rewrite vs map patch.**
- XDP = earlier than iptables.
