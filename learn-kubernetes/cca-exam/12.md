# 12. Ingress with Cilium

**Domain:** Service Mesh (16%)

## Concept Refresher

Cilium can run an **Ingress controller** that programs **Envoy** (not nginx). Enable:

```text
ingressController.enabled=true
```

Then a standard Kubernetes `Ingress` with:

```yaml
  ingressClassName: cilium
```

is implemented by Cilium: listener on the Ingress Service, L7 routes to backend Services, optional TLS via Secrets.

### How it fits the mesh

North-south L7 enters node Envoy, then east-west can stay eBPF. Same identity/policy story as the rest of the cluster.

### vs other ingresses

You should **not** run two default ingress classes fighting for the same Ingress objects. `ingressClassName: cilium` is explicit.

LoadBalancer IP for the Ingress Service can come from cloud LB, **LB-IPAM**, BGP, or NodePort in labs.

## Hands-on

Enable ingress in Helm/CLI, apply a tiny Ingress to httpbin, curl the Ingress LB/NodePort with `Host` header.

## Exam tips

- Class name **`cilium`**.
- Ingress = north-south HTTP. Gateway API is the evolution (`13.md`).
- Cilium Ingress is **not** kube-proxy.
