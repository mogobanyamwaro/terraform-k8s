# 22. Timestamp Metrics And Time Functions

**Domain:** PromQL

## Concept Refresher

"Timestamp Metrics" is an explicit PCA competency. It covers the time-related functions and the pattern of exposing timestamps as gauges.

### time() vs timestamp()

These are constantly confused. Learn the difference precisely.

| Function | Takes | Returns |
| --- | --- | --- |
| `time()` | Nothing | A **scalar**: the Unix timestamp of the current **evaluation** step |
| `timestamp(v)` | An instant vector | An **instant vector** whose values are each **sample's own timestamp** |

```promql
time()                                # e.g. 1755518400
timestamp(up)                          # per series, the timestamp of its latest sample
time() - timestamp(up)                 # per series, seconds since its last sample
```

`time()` is **not** "now" in the wall-clock sense during a range query. It is the timestamp of the current step being evaluated. In a range query over yesterday, `time()` returns yesterday's timestamps step by step. This is exactly what makes it usable in recording rules and range graphs.

### The timestamp-gauge pattern

Batch jobs and periodic processes should expose a **timestamp gauge**, not a counter:

```text
# TYPE backup_last_success_timestamp_seconds gauge
backup_last_success_timestamp_seconds 1755518400
```

Then measure freshness in PromQL:

```promql
# Seconds since the last success
time() - backup_last_success_timestamp_seconds

# Alert if it has not succeeded in 25 hours
time() - backup_last_success_timestamp_seconds > 25 * 3600

# In hours, for a readable annotation
(time() - backup_last_success_timestamp_seconds) / 3600
```

This is **the** standard pattern for monitoring anything that runs periodically, and it is the correct answer for "how do I alert that a nightly batch job did not run", since a Pushgateway job has no `up` metric.

Always use **seconds since the Unix epoch** and suffix the metric `_timestamp_seconds`.

### Process and target uptime

```promql
# How long has the process been running
time() - process_start_time_seconds

# In days
(time() - process_start_time_seconds) / 86400

# Recently restarted (within 10 minutes)
time() - process_start_time_seconds < 600

# node_exporter equivalent for machine uptime
time() - node_boot_time_seconds
```

`process_start_time_seconds` is exposed by every Prometheus client library, which makes it a reliable restart detector.

### Detecting stale data

```promql
# Seconds since each series was last written
time() - timestamp(up)

# A target whose data is more than 5 minutes old
time() - timestamp(up) > 300

# Better, using absent_over_time
absent_over_time(up{job="critical"}[10m])
```

Note that because of staleness markers and the 5 minute lookback delta, a truly gone series does not appear at all, so `timestamp()` cannot see it. Use `absent_over_time` for missing series and `timestamp()` for stale-but-present ones (typically Pushgateway data).

### Calendar functions

All of these take an optional instant vector. If omitted, they operate on `time()` at the current step. All are computed in **UTC**.

| Function | Returns |
| --- | --- |
| `year(v)` | Year, e.g. 2026 |
| `month(v)` | Month, 1 to 12 |
| `day_of_month(v)` | 1 to 31 |
| `day_of_week(v)` | **0 = Sunday** through 6 = Saturday |
| `day_of_year(v)` | 1 to 365 or 366 |
| `days_in_month(v)` | 28 to 31 |
| `hour(v)` | 0 to 23 |
| `minute(v)` | 0 to 59 |

**`day_of_week()` returns 0 for Sunday.** That is the detail the exam asks about.

Business-hours gating:

```promql
# Only alert Monday to Friday, 09:00 to 17:00 UTC
some_condition
  and on() (day_of_week() >= 1 and day_of_week() <= 5)
  and on() (hour() >= 9 and hour() < 17)

# Only alert outside business hours
some_condition
  unless on() (hour() >= 9 and hour() < 17)
```

The `on()` with an empty label list is required so the label-less calendar vector matches every series.

### vector() and scalar()

```promql
vector(0)              # a label-less instant vector with value 0
vector(time())         # turn a scalar into a vector
scalar(sum(up))        # turn a single-element vector into a scalar
```

`vector(s)` is essential for the "default to zero" idiom:

```promql
sum(rate(errors_total[5m])) or vector(0)
```

`scalar(v)` returns `NaN` unless `v` has exactly one element.

### Other value-shaping functions worth knowing

| Function | Effect |
| --- | --- |
| `abs(v)` | Absolute value |
| `ceil(v)` | Round up to the nearest integer |
| `floor(v)` | Round down |
| `round(v, to_nearest)` | Round to the nearest multiple, default 1 |
| `clamp(v, min, max)` | Constrain to a range |
| `clamp_max(v, max)` | Upper bound |
| `clamp_min(v, min)` | Lower bound |
| `exp(v)`, `ln(v)`, `log2(v)`, `log10(v)`, `sqrt(v)` | Maths |
| `sgn(v)` | -1, 0, or 1 |
| `pi()` | π |
| `deg(v)`, `rad(v)` | Degrees and radians |
| `sort(v)` | Ascending by value |
| `sort_desc(v)` | Descending by value |
| `sort_by_label(v, label...)` | Sort by label value |
| `sort_by_label_desc(v, label...)` | Reverse label sort |

`sort()` and `sort_desc()` only affect the display order of an **instant query**. They are meaningless in a range query.

`clamp_min(x, 1)` is the standard guard against division by zero.

### absent() and absent_over_time()

```promql
absent(up{job="api"})                    # 1 if the instant vector is EMPTY
absent_over_time(up{job="api"}[10m])     # 1 if there were NO samples in the window
```

`absent()` behaviour with labels: it copies **equality matchers** from the selector into the output labels, which makes the alert annotation useful.

```promql
absent(up{job="api", env="prod"})
# => {job="api", env="prod"} 1
```

Regex matchers are **not** copied, so `absent(up{job=~"api.*"})` returns a label-less series.

Use `absent()` to detect "a target that was never discovered", which `up == 0` cannot catch.

```yaml
- alert: TargetMissing
  expr: absent(up{job="critical-api"})
  for: 5m
  annotations:
    summary: "No targets discovered for job {{ $labels.job }}"
```

### changes() and resets() revisited

```promql
changes(up[1h])                          # transitions of a gauge, flapping detector
resets(http_requests_total[1h])          # counter decreases, restart detector
changes(process_start_time_seconds[1h])  # also a restart detector
```

### Practical timestamp patterns

```promql
# Certificate expiry in days
(probe_ssl_earliest_cert_expiry - time()) / 86400

# Alert on a cert expiring within 14 days
probe_ssl_earliest_cert_expiry - time() < 14 * 86400

# Time until a Kubernetes cronjob's next schedule
kube_cronjob_next_schedule_time - time()

# Days since last successful backup
(time() - backup_last_success_timestamp_seconds) / 86400

# Node uptime in days
(time() - node_boot_time_seconds) / 86400

# Prometheus config age
time() - prometheus_config_last_reload_success_timestamp_seconds

# Detect a Pushgateway group that has gone stale
time() - push_time_seconds > 3600
```

`push_time_seconds` is exposed automatically by the Pushgateway for every group, which makes freshness alerting on pushed metrics straightforward.

## Answers

**Q1: B.** A scalar equal to the evaluation step's timestamp.

**Q2: B.** An instant vector of per-series sample timestamps.

**Q3: B.** `time()` minus the stored timestamp.

**Q4: B.** Gauge. It is a point-in-time value, and it can stay flat or jump. Counters accumulate; timestamps do not.

**Q5: B.** The freshness comparison. Option A fails because a Pushgateway-based job has no `up` metric.

**Q6: B.** `time() - process_start_time_seconds`.

**Q7: B.** 0. Sunday is 0, Saturday is 6.

**Q8: B.** UTC always. If your business hours are local, you must offset manually.

**Q9: A.** Weekdays are 1 through 5, so `> 0 and < 6`. The `on()` is required for the vector match.

**Q10: B.** Calendar functions with no argument return a vector with no labels. Without `on()`, the default matcher requires identical label sets and nothing matches.

**Q11: B.** A single label-less series with the given value.

**Q12: B.** `vector(0)` has no match on the left, so `or` includes it precisely when the left side is empty.

**Q13: B.** `NaN`. `scalar()` needs exactly one element.

**Q14: B.** Empty. `absent()` only returns a value when its argument is empty.

**Q15: B.** Equality matchers are copied so the resulting alert has useful labels.

**Q16: B.** Only equality matchers. Regex matchers cannot be reduced to a single label value.

**Q17: B.** A never-discovered target has no `up` series, so a comparison cannot match. `absent()` is the tool for that case.

**Q18: B.** Subtract `time()` and convert to days.

**Q19: B.** `clamp_min(b, 1)` guarantees a non-zero denominator.

**Q20: B.** Sorting is a display concern for instant queries only. In a range query it is discarded.

**Q21: B.** `push_time_seconds`, which is why freshness alerting on pushed metrics works even without `up`.

**Q22: B.** `time()` is the evaluation-step timestamp, not wall-clock now. That is what makes it valid in graphs and recording rules.

**Q23: B.** `changes()` on the start-time gauge. `resets()` is for counters, and `rate()` on a gauge is meaningless.

**Q24: B.** The optional second argument of `round` is the multiple to round to.

## Exam tips

- `time()` = **scalar**, the current **evaluation step** timestamp. `timestamp(v)` = **vector**, each sample's own timestamp.
- `time()` walks the range during a range query. It is not wall-clock now.
- Batch job pattern: expose `*_last_success_timestamp_seconds` as a **gauge**, alert on `time() - metric > threshold`. This is the answer whenever `up` is unavailable.
- Uptime = `time() - process_start_time_seconds`. Machine uptime = `time() - node_boot_time_seconds`.
- **`day_of_week()` returns 0 for Sunday**, 6 for Saturday. Weekdays are 1 to 5.
- All calendar functions are **UTC** and take an optional vector, defaulting to `time()`.
- Combining a metric with a calendar function needs **`on()`** because the calendar vector has no labels.
- `vector(s)` makes a label-less vector. `x or vector(0)` is the default-to-zero idiom.
- `scalar(v)` returns `NaN` unless `v` has exactly one element.
- `absent(v)` returns 1 only when `v` is **empty**, and copies **equality matchers** into the output labels. Regex matchers are not copied.
- `absent()` catches never-discovered targets. `up == 0` cannot.
- `absent_over_time(v[d])` tolerates brief gaps and is the better "metric stopped arriving" alert.
- `clamp_min(x, 1)` guards divisions.
- `sort()` and `sort_desc()` only matter for instant queries.
- Pushgateway exposes `push_time_seconds` per group for freshness checks.
- Cert expiry: `(probe_ssl_earliest_cert_expiry - time()) / 86400` gives days.
