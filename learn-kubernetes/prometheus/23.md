# 23. Label Manipulation And The Query API

**Domain:** PromQL

## Concept Refresher

### label_replace

```promql
label_replace(v, dst_label, replacement, src_label, regex)
```

Five arguments, in that order. It applies `regex` to the value of `src_label`; if it matches, `dst_label` is set to `replacement` with `$1`, `$2` capture group expansion. **If the regex does not match, the series is returned unchanged.**

```promql
# Extract the host from instance="demo-a:8080" into a new `host` label
label_replace(up, "host", "$1", "instance", "(.*):.*")

# Extract the port
label_replace(up, "port", "$1", "instance", ".*:(.*)")

# Copy a label wholesale
label_replace(up, "service", "$1", "job", "(.*)")

# Delete a label by setting it empty
label_replace(up, "job", "", "", "")

# Rename a metric via __name__
label_replace(up, "__name__", "target_up", "__name__", "up")
```

The regex is **fully anchored**, as everywhere in Prometheus.

To *delete* a label the idiom is `label_replace(v, "the_label", "", "", "")`: an empty `src_label` with an empty regex always matches, and the empty replacement removes the label.

### label_join

```promql
label_join(v, dst_label, separator, src_label_1, src_label_2, ...)
```

Concatenates the values of the listed source labels using the separator.

```promql
label_join(up, "target", "/", "job", "instance")
# => up{job="demo", instance="demo-a:8080", target="demo/demo-a:8080"}

label_join(up, "id", "-", "job", "instance", "env")
```

### Which to use

| Need | Function |
| --- | --- |
| Extract part of a label value | `label_replace` |
| Rename a label | `label_replace` |
| Rename a metric | `label_replace` on `__name__` |
| Delete a label | `label_replace(v, "l", "", "", "")` |
| Combine several labels into one | `label_join` |

These operate at **query time** and do not change stored data. To change what is stored, use `metric_relabel_configs` or a recording rule.

### The `info` function (experimental)

Prometheus 3.x adds `info(v, {label_matchers})` which automates the info-metric join:

```promql
info(rate(http_requests_total[5m]), {version=~".+"})
```

It is the shorthand for `* on(instance) group_left(version) target_info`. Recognise the name; the manual `group_left` form is what the exam expects.

### Response shapes

```json
{
  "status": "success",
  "data": {
    "resultType": "vector",
    "result": [
      {
        "metric": { "__name__": "up", "job": "demo", "instance": "demo-a:8080" },
        "value": [ 1755518400.123, "1" ]
      }
    ]
  }
}
```

`resultType` is one of:

| resultType | Produced by |
| --- | --- |
| `vector` | An instant query returning an instant vector |
| `matrix` | A range query, or an instant query whose expression is a range vector |
| `scalar` | An instant query returning a scalar |
| `string` | An instant query returning a string |

Note that **sample values are JSON strings**, not numbers. That preserves float precision and allows `"NaN"`, `"+Inf"`, `"-Inf"`.

Errors:

```json
{ "status": "error", "errorType": "bad_data", "error": "invalid parameter \"query\"..." }
```

`errorType` values include `timeout`, `canceled`, `execution`, `bad_data`, `internal`, `unavailable`, `not_found`.

A response may also carry `warnings` (for example, "quantile value is not in a bucket range") while still reporting success.

### step and resolution in range queries

```bash
curl -sG http://localhost:9090/api/v1/query_range \
  --data-urlencode 'query=rate(node_cpu_seconds_total[5m])' \
  --data-urlencode "start=$(date -d '-1 hour' +%s)" \
  --data-urlencode "end=$(date +%s)" \
  --data-urlencode 'step=60'
```

Points returned per series = `(end - start) / step + 1`. Prometheus enforces a maximum of **11,000 points per series** per range query. Exceeding it gives "exceeded maximum resolution of 11,000 points per timeseries".

Grafana computes `step` automatically from the panel width, which is why the same query looks different at different zoom levels.

### promtool for querying

```bash
promtool query instant http://localhost:9090 'up'
promtool query range http://localhost:9090 'rate(node_cpu_seconds_total[5m])' \
  --start=$(date -d '-10 min' +%s) --end=$(date +%s) --step=1m
promtool query labels http://localhost:9090 job
promtool query series http://localhost:9090 --match='up{job="demo"}'
promtool query analyze --server=http://localhost:9090 --type=histogram
```

### Query performance and limits

| Flag | Default | Effect |
| --- | --- | --- |
| `--query.max-samples` | 50,000,000 | Total samples loadable into memory for one query |
| `--query.timeout` | `2m` | Maximum query duration |
| `--query.max-concurrency` | 20 | Concurrent queries |
| `--query.lookback-delta` | `5m` | How far back an instant query looks for a sample |

```yaml

  query_log_file: /prometheus/query.log
```


## Answers

**Q1: B.** `label_replace(v, dst_label, replacement, src_label, regex)`. Destination first, source second to last.

**Q2: B.** Unchanged pass-through. This makes `label_replace` safe to apply to a mixed set of series.

**Q3: B.** Destination `host`, replacement `$1`, source `instance`, regex `(.*):.*`.

**Q4: A.** Empty `src_label` with an empty regex always matches, and the empty replacement removes the destination label.

**Q5: B.** It concatenates source label values into the new label.

**Q6: B.** `__name__` is an ordinary label as far as `label_replace` is concerned.

**Q7: B.** Query time only. Nothing on disk changes.

**Q8: B.** `/api/v1/query`.

**Q9: B.** `query`, `start`, `end`, `step`.

**Q10: B.** `matrix`.

**Q11: B.** `matrix` as well. An instant query whose expression is a range vector returns a matrix of raw samples, which is how the Table view shows `up[5m]`.

**Q12: B.** Strings avoid JSON float precision loss and can represent the special values.

**Q13: B.** 11,000 points per timeseries.

**Q14: C.** 3600 / 60 = 60 intervals, which is 61 points including both endpoints.

**Q15: B.** `/api/v1/label/job/values`.

**Q16: B.** `/api/v1/metadata`, with `/api/v1/targets/metadata` for the per-target view.

**Q17: B.** `/api/v1/write` needs the remote write receiver flag.

**Q18: B.** `match[]`. Without it, federation returns nothing.

**Q19: C.** `2m`.

**Q20: B.** `global.query_log_file`.

**Q21: B.** Warnings accompany successful results when correctness may be affected. Histogram quantile warnings are the common case.

**Q22: B.** `promtool query instant`.

**Q23: B.** `bad_data`.

**Q24: B.** Grafana picks `step` based on pixel width. A 30 day view with a 1 hour step hides spikes that a 1 hour view with a 15 second step reveals.

## Hands-on

`label_replace`:

```promql
up
label_replace(up, "host", "$1", "instance", "(.*):.*")
label_replace(up, "port", "$1", "instance", ".*:(.*)")
label_replace(up, "service", "$1", "job", "(.*)")

# Non-matching regex leaves it alone
label_replace(up, "host", "$1", "instance", "^nomatch(.*)$")

# Delete a label
label_replace(up, "job", "", "", "")

# Rename the metric
label_replace(up, "__name__", "target_up", "__name__", "up")

# Chain two replacements
label_replace(
  label_replace(up, "host", "$1", "instance", "(.*):.*"),
  "port", "$1", "instance", ".*:(.*)"
)
```

`label_join`:

```promql
label_join(up, "target", "/", "job", "instance")
label_join(up, "id", "-", "job", "instance")
label_join(up, "full", ":", "job", "instance", "env")
```

Practical extraction on node_exporter data:

```promql

label_replace(node_filesystem_avail_bytes, "disk", "$1", "device", "/dev/(.*)")
```

The API, end to end:

```bash
# Instant
curl -sG http://localhost:9090/api/v1/query --data-urlencode 'query=up' | jq

# Instant at a past time
curl -sG http://localhost:9090/api/v1/query \
  --data-urlencode 'query=up' \
  --data-urlencode "time=$(( $(date +%s) - 1800 ))" | jq '.data.result | length'

# resultType comparison
for q in 'up' 'up[5m]' 'scalar(sum(up))' 'time()'; do
  printf '%-20s -> ' "$q"
  curl -sG http://localhost:9090/api/v1/query --data-urlencode "query=$q" | jq -r '.data.resultType'
done
```

Range query and point counting:

```bash
START=$(( $(date +%s) - 3600 ))
END=$(date +%s)

curl -sG http://localhost:9090/api/v1/query_range \
  --data-urlencode 'query=up{job="node"}' \
  --data-urlencode "start=$START" \
  --data-urlencode "end=$END" \
  --data-urlencode 'step=60' | jq '.data.result[0].values | length'
```

That returns 61. Change `step` to 30 and it becomes 121.

```bash

  --data-urlencode "end=$(date +%s)" \
```

## Exam tips

- **`label_replace(v, dst, replacement, src, regex)`.** Destination comes **second**, right after the vector. Memorise the order.
- A non-matching `label_replace` regex leaves the series **untouched**.
- `label_replace(v, "l", "", "", "")` **deletes** label `l`.
- Rename a metric with `label_replace` on `__name__`.
- `label_join(v, dst, separator, src...)` concatenates.
- Both are **query-time only**. Persistent changes need `metric_relabel_configs` or recording rules.
- `/api/v1/query` = instant (`query`, `time`). `/api/v1/query_range` = range (`query`, `start`, `end`, `step`).
- `resultType`: `vector` for an instant vector, **`matrix`** for a range query **and** for an instant query on a range vector, plus `scalar` and `string`.
- Sample values are **JSON strings** to preserve precision and allow `NaN`/`Inf`.
- Range query cap = **11,000 points per series**. Points = `(end - start) / step + 1`.
- `/federate` requires `match[]`.
- `/api/v1/write` needs `--web.enable-remote-write-receiver`. Admin endpoints need `--web.enable-admin-api`. `/-/reload` needs `--web.enable-lifecycle`.
- Defaults: `--query.timeout 2m`, `--query.max-samples 50,000,000`, `--query.max-concurrency 20`, `--query.lookback-delta 5m`.
- `global.query_log_file` logs slow queries.
- `warnings` can accompany a successful response, most often from `histogram_quantile`.
