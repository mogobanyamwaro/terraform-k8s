# 13. Exposition Format And OpenMetrics

**Domain:** Prometheus Fundamentals

## Concept Refresher

### The Prometheus text exposition format

Content type:

```text
Content-Type: text/plain; version=0.0.4; charset=utf-8
```

Structure, one sample per line:

```text
# HELP http_requests_total The total number of HTTP requests.
# TYPE http_requests_total counter
http_requests_total{method="post",code="200"} 1027 1395066363000
http_requests_total{method="post",code="400"}    3 1395066363000

# Minimalistic line
metric_without_timestamp_and_labels 12.47

# Escaping in label values
msdos_file_access_time_seconds{path="C:\\DIR\\FILE.TXT",error="Cannot find file:\n\"FILE.TXT\""} 1.458255915e9

# Special float values
something_weird{problem="division by zero"} +Inf
another_metric NaN
```

Grammar, precisely:

```text
metric_name [ "{" label_name "=" `"` label_value `"` { "," ... } [ "," ] "}" ] value [ timestamp ]
```

Rules you must know:

| Rule | Detail |
| --- | --- |
| Line ending | `\n` only. `\r\n` is **not** allowed |
| Encoding | UTF-8 |
| Comments | Lines starting with `#`. `# HELP` and `# TYPE` are special, everything else is ignored |
| `# HELP` | `# HELP <metric_name> <docstring>`. At most one per metric name. `\` and `\n` are escaped in the docstring |
| `# TYPE` | `# TYPE <metric_name> <counter\|gauge\|histogram\|summary\|untyped>`. At most one per metric name. Must come **before** the first sample of that metric |
| Value | A Go-parsable float. Accepts `Nan`, `NaN`, `+Inf`, `-Inf`, `1.5e3`, `0x1p-3` |
| Timestamp | Optional int64 **milliseconds** since epoch. Usually omitted so Prometheus uses scrape time |
| Grouping | All lines for one metric name should be contiguous. Duplicates within a scrape are an error |
| Label value escaping | `\\` for backslash, `\n` for newline, `\"` for double quote. **`\t` is not defined** |
| Label ordering | Irrelevant. `{a="1",b="2"}` equals `{b="2",a="1"}` |
| Trailing comma | Allowed inside the label braces |
| Whitespace | Blank lines are ignored. Whitespace around tokens is tolerated |
| Empty label value | Equivalent to the label being absent |
| Compression | Prometheus sends `Accept-Encoding: gzip`. Exporters should support it |

The format is **line-oriented and stateless**, deliberately trivial to generate. A shell script can produce it.

### OpenMetrics

Content type:

```text
Content-Type: application/openmetrics-text; version=1.0.0; charset=utf-8
```

OpenMetrics is a CNCF standard derived from the Prometheus format. Differences that matter:

| Aspect | Prometheus text 0.0.4 | OpenMetrics 1.0.0 |
| --- | --- | --- |
| Terminator | None | **`# EOF` is mandatory** as the last line |
| Counter naming | `_total` conventional | `_total` **required**, and the `# TYPE` declares the name without the suffix |
| Timestamps | int64 milliseconds | **Float seconds** |
| Exemplars | Not supported | Supported, after `#` on `_bucket` and counter lines |
| Extra types | No | `info`, `stateset`, `gaugehistogram` |
| `_created` series | No | Optional `<name>_created` giving counter creation time |
| `# UNIT` | No | Optional `# UNIT <name> <unit>`, the unit must be a suffix of the name |
| Untyped name | `untyped` | `unknown` |
| `NaN`/`Inf` | Allowed | Allowed |

Example OpenMetrics payload:

```text
# TYPE http_requests counter
# UNIT http_requests requests
# HELP http_requests Total requests.
http_requests_total{method="get"} 1027.0
http_requests_created{method="get"} 1687000000.0
# TYPE request_duration_seconds histogram
# UNIT request_duration_seconds seconds
# HELP request_duration_seconds Request duration.
request_duration_seconds_bucket{le="0.1"} 5.0
request_duration_seconds_bucket{le="0.5"} 12.0 # {trace_id="a1b2c3"} 0.42 1687000000.0
request_duration_seconds_bucket{le="+Inf"} 15.0
request_duration_seconds_sum 3.4
request_duration_seconds_count 15.0
# TYPE build info
# HELP build Build metadata.
build_info{version="1.4.2",commit="deadbeef"} 1
# TYPE process_state stateset
process_state{process_state="starting"} 0
process_state{process_state="running"} 1
process_state{process_state="stopping"} 0
# EOF
```

Forgetting `# EOF` makes the payload invalid OpenMetrics. That is a favourite exam detail.

### Content negotiation

Prometheus sends:

```text
Accept: application/openmetrics-text;version=1.0.0;q=0.6,
        application/openmetrics-text;version=0.0.1;q=0.5,
        text/plain;version=0.0.4;q=0.4,
        */*;q=0.2
```

The exporter picks the best format it supports and states it in `Content-Type`. Override the preference order in the scrape config:

```yaml
scrape_protocols:
  - OpenMetricsText1.0.0
  - OpenMetricsText0.0.1
  - PrometheusText0.0.4
  - PrometheusProto        # required for native histograms
```

### Protobuf exposition

Used for **native histograms**. It is not human readable and is negotiated via `Accept: application/vnd.google.protobuf`. You will not need to write it, only to know that native histograms require it.

### Writing a valid exposition endpoint by hand

The simplest possible valid exporter:

```bash
cat > /tmp/serve_metrics.sh <<'SH'
#!/usr/bin/env bash
while true; do
  BODY=$(cat <<EOF
# HELP shell_random_value A random number.
# TYPE shell_random_value gauge
shell_random_value ${RANDOM}
# HELP shell_scrapes_total Times scraped.
# TYPE shell_scrapes_total counter
shell_scrapes_total ${SCRAPES:-0}
EOF
)
  LEN=${#BODY}
  printf 'HTTP/1.1 200 OK\r\nContent-Type: text/plain; version=0.0.4\r\nContent-Length: %d\r\n\r\n%s' "$LEN" "$BODY" | nc -l -p 9999 -q 1
  SCRAPES=$(( ${SCRAPES:-0} + 1 ))
done
SH
chmod +x /tmp/serve_metrics.sh
```

The point: exposition is just text over HTTP.

### Validation

```bash
promtool check metrics < metrics.txt
curl -s http://localhost:9100/metrics | promtool check metrics
```

`promtool check metrics` catches:

- Missing `# HELP` or `# TYPE`
- Counters not ending in `_total`
- Metric and label naming violations
- Non-cumulative histogram buckets
- `+Inf` bucket mismatched with `_count`
- Units not in base units (it warns about `_milliseconds` etc.)
- Duplicate metric declarations

### Common exposition errors and their scrape-side symptoms

| Mistake | Symptom |
| --- | --- |
| `\r\n` line endings | Parse error, `up = 0` |
| Duplicate series in one payload | "duplicate sample for timestamp", scrape fails |
| `# TYPE` after the samples | Parse error |
| Two `# HELP` lines for one metric | Parse error |
| Unescaped `"` in a label value | Parse error |
| Missing `# EOF` in OpenMetrics | Parse error |
| Non-numeric value | "expected float as value" |
| `le` bucket values out of order | Accepted by the parser, but `histogram_quantile` returns nonsense |
| Missing `+Inf` bucket | `histogram_quantile` cannot compute upper quantiles |

## Answers

**Q1: B.** `text/plain; version=0.0.4; charset=utf-8`.

**Q2: B.** Line feed only. `\r\n` is explicitly disallowed and is a real-world cause of `up == 0` when someone generates metrics on Windows.

**Q3: B.** `# HELP` and `# TYPE`. Any other `#` line is an ignored comment.

**Q4: B.** int64 milliseconds since the Unix epoch.

**Q5: B.** OpenMetrics switched to float seconds. Knowing that the two formats differ here is the point of the question.

**Q6: B.** `# EOF`. Its absence makes the payload invalid.

**Q7: A.** Only `\\`, `\n`, and `\"` are defined for label values. `\t` is notably **not** defined.

**Q8: B.** Label sets are unordered maps. Prometheus normalises them.

**Q9: B.** Go-parsable floats plus the special values `NaN`, `+Inf`, `-Inf`. Strings are never sample values.

**Q10: B.** `# TYPE` must precede the metric's first sample.

**Q11: B.** Duplicate series in one payload is an error: "duplicate sample for timestamp". The whole scrape fails.

**Q12: B.** OpenMetrics. Plus `--enable-feature=exemplar-storage` on the Prometheus side to persist them.

**Q13: C.** Protobuf. (OpenMetrics 2.0 adds support, but protobuf is the answer for current Prometheus.)

**Q14: B.** The `# UNIT` value must be a suffix of the metric name. `# UNIT foo_seconds bytes` is invalid.

**Q15: B.** In OpenMetrics the `# TYPE` declares the base name and the exposed counter series carries the mandatory `_total` suffix.

**Q16: B.** `unknown`.

**Q17: B.** `promtool check metrics`, fed the exposition text on stdin.

**Q18: B.** Prometheus convention is base units, so seconds not milliseconds and bytes not kilobytes. `promtool` warns.

**Q19: B.** Cumulative buckets must be non-decreasing as `le` increases.

**Q20: B.** Simplicity of generation was an explicit design goal. Any language, or even `echo`, can produce it.

## Hands-on

Look at real exposition output and identify every element:

```bash
curl -s http://localhost:9100/metrics | head -30
```

Request OpenMetrics explicitly and find the `# EOF`:

```bash
curl -s -H 'Accept: application/openmetrics-text; version=1.0.0' http://localhost:9100/metrics | tail -3
```

Check the negotiated content type:

```bash
curl -sI -H 'Accept: application/openmetrics-text; version=1.0.0' http://localhost:9100/metrics | grep -i content-type
curl -sI http://localhost:9100/metrics | grep -i content-type
```

Validate a good payload:

```bash
cat > /tmp/good.txt <<'EOF'
# HELP app_requests_total Total requests handled.
# TYPE app_requests_total counter
app_requests_total{method="get",code="200"} 1027
app_requests_total{method="post",code="500"} 3
# HELP app_queue_depth Items waiting.
# TYPE app_queue_depth gauge
app_queue_depth 12
# HELP app_latency_seconds Request latency.
# TYPE app_latency_seconds histogram
app_latency_seconds_bucket{le="0.1"} 4
app_latency_seconds_bucket{le="0.5"} 9
app_latency_seconds_bucket{le="1"} 11
app_latency_seconds_bucket{le="+Inf"} 12
app_latency_seconds_sum 2.85
app_latency_seconds_count 12
EOF
promtool check metrics < /tmp/good.txt && echo "VALID"
```

Now break it, one rule at a time, and read the error each time.

Missing `_total` suffix on a counter:

```bash
cat > /tmp/bad1.txt <<'EOF'
# HELP app_requests Total requests.
# TYPE app_requests counter
app_requests 5
EOF
promtool check metrics < /tmp/bad1.txt
```

Non-base unit:

```bash
cat > /tmp/bad2.txt <<'EOF'
# HELP app_latency_milliseconds Latency.
# TYPE app_latency_milliseconds gauge
app_latency_milliseconds 250
EOF
promtool check metrics < /tmp/bad2.txt
```

Non-cumulative buckets:

```bash
cat > /tmp/bad3.txt <<'EOF'
# TYPE app_latency_seconds histogram
app_latency_seconds_bucket{le="0.5"} 12
app_latency_seconds_bucket{le="1"} 8
app_latency_seconds_bucket{le="+Inf"} 15
app_latency_seconds_sum 3.4
app_latency_seconds_count 15
EOF
promtool check metrics < /tmp/bad3.txt
```

`# TYPE` after the sample:

```bash
printf 'app_thing 1\n# TYPE app_thing gauge\n' | promtool check metrics
```

Duplicate series:

```bash
printf '# TYPE app_dup gauge\napp_dup{a="1"} 1\napp_dup{a="1"} 2\n' > /tmp/bad4.txt
curl --data-binary @/tmp/bad4.txt http://localhost:9091/metrics/job/duptest
```

Prove `\r\n` breaks parsing. Serve a CRLF payload:

```bash
mkdir -p /tmp/crlf && cd /tmp/crlf
printf '# TYPE crlf_metric gauge\r\ncrlf_metric 1\r\n' > metrics
python3 -m http.server 8098 &
```

Point a scrape job at it and watch `up` go to 0 with a parse error on `/targets`.

Special float values:

```bash
cat > /tmp/floats.txt <<'EOF'
# TYPE special_values gauge
special_values{kind="positive_inf"} +Inf
special_values{kind="negative_inf"} -Inf
special_values{kind="not_a_number"} NaN
special_values{kind="scientific"} 1.4582e9
EOF
promtool check metrics < /tmp/floats.txt
curl --data-binary @/tmp/floats.txt http://localhost:9091/metrics/job/floattest
```

```promql
special_values
```

Note how `NaN` and `Inf` render.

Escaping:

```bash
cat > /tmp/escape.txt <<'EOF'
# TYPE file_access_seconds gauge
file_access_seconds{path="C:\\DIR\\FILE.TXT",error="Cannot find:\n\"FILE.TXT\""} 1.458255915e9
EOF
promtool check metrics < /tmp/escape.txt
```

Write a minimal exporter in three lines of Python:

```bash
mkdir -p /tmp/tiny && cd /tmp/tiny
cat > metrics <<'EOF'
# HELP tiny_exporter_up Always one.
# TYPE tiny_exporter_up gauge
tiny_exporter_up 1
EOF
python3 -m http.server 8097
```

Scrape it. That is all an exporter fundamentally is.

## Exam tips

- Prometheus text: `text/plain; version=0.0.4`, `\n` endings, **int64 millisecond** timestamps.
- OpenMetrics: `application/openmetrics-text; version=1.0.0`, **`# EOF` mandatory**, **float second** timestamps, `_total` required, supports exemplars, `info`, `stateset`, `gaugehistogram`, `_created`, `# UNIT`.
- Only `# HELP` and `# TYPE` are parsed. `# TYPE` must come before the samples.
- Escapes in label values: `\\`, `\n`, `\"`. **Not `\t`.**
- Label order does not matter. Duplicate series in one scrape is a hard error.
- Values are floats plus `NaN`, `+Inf`, `-Inf`. Never strings.
- Exemplars need **OpenMetrics**. Native histograms need **protobuf**.
- `# UNIT` value must be a suffix of the metric name.
- `untyped` in Prometheus text = `unknown` in OpenMetrics.
- `promtool check metrics` is the validator. It flags missing `_total`, non-base units, and broken histograms.
- Base units always: **seconds, bytes, ratios**. Never milliseconds, kilobytes, or percentages.
