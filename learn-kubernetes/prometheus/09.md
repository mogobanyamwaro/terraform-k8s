# 09. Configuration File Structure

**Domain:** Prometheus Fundamentals

## Concept Refresher

`prometheus.yml` has exactly these top-level keys:

```yaml
global:                 # defaults inherited by all scrape and rule configs
rule_files:             # list of glob paths to rule files
scrape_configs:         # list of scrape jobs
alerting:               # where to send alerts
remote_write:           # push samples out
remote_read:            # read samples from a remote store
storage:                # TSDB / exemplar tuning (limited)
tracing:                # OTLP tracing of Prometheus itself
scrape_config_files:    # glob paths to files containing extra scrape_configs
runtime:                # runtime tuning, e.g. gogc
```

You will not be tested on `tracing` or `runtime`. You **will** be tested on `global`, `rule_files`, `scrape_configs`, and `alerting`.

### global

```yaml
global:
  scrape_interval: 15s          # default 1m
  scrape_timeout: 10s           # default 10s, must be <= scrape_interval
  evaluation_interval: 15s      # default 1m
  query_log_file: /var/log/prometheus/query.log
  body_size_limit: 10MB         # 0 = unlimited
  sample_limit: 0               # 0 = unlimited
  target_limit: 0
  label_limit: 0
  label_name_length_limit: 0
  label_value_length_limit: 0
  keep_dropped_targets: 0
  external_labels:
    cluster: production
    region: eu-west-1
    replica: A
```

**`external_labels` are critical.** They are attached to metrics **only when they leave Prometheus**: on `remote_write`, on federation, and on alerts sent to Alertmanager. They are **not** stored locally and are **not** visible in local queries. That is exactly why Alertmanager can deduplicate two HA replicas: give each replica a different `replica` external label, and configure Alertmanager to ignore it.

### scrape_configs

```yaml
scrape_configs:
  - job_name: api                       # REQUIRED, must be unique. Becomes the `job` label
    scrape_interval: 10s                # overrides global
    scrape_timeout: 5s
    metrics_path: /metrics              # default /metrics
    scheme: http                        # http (default) or https
    honor_labels: false                 # default false
    honor_timestamps: true              # default true
    track_timestamps_staleness: false
    sample_limit: 5000                  # drop the whole scrape if exceeded
    label_limit: 30
    follow_redirects: true
    enable_http2: true
    scrape_protocols:                   # negotiation order
      - OpenMetricsText1.0.0
      - OpenMetricsText0.0.1
      - PrometheusText0.0.4

    params:                             # appended as URL query parameters
      module: [http_2xx]
      format: [prometheus]

    basic_auth:
      username: prom
      password_file: /etc/prometheus/pw
    # or
    authorization:
      type: Bearer
      credentials_file: /var/run/secrets/token
    # or
    oauth2:
      client_id: x
      client_secret_file: /etc/prometheus/secret
      token_url: https://idp/token

    tls_config:
      ca_file: /etc/prometheus/ca.crt
      cert_file: /etc/prometheus/client.crt
      key_file: /etc/prometheus/client.key
      server_name: api.internal
      insecure_skip_verify: false

    proxy_url: http://proxy:3128

    static_configs:
      - targets: ["api-1:8080", "api-2:8080"]
        labels:
          env: production

    relabel_configs: []                 # before scrape, on target labels
    metric_relabel_configs: []          # after scrape, on sample labels
```

Key facts:

- `job_name` is the only mandatory field and must be unique across the file.
- `scrape_timeout` must be less than or equal to `scrape_interval`. Prometheus refuses to start otherwise.
- `honor_labels: false` (default) means labels exposed by the target that collide with target labels get prefixed with `exported_`. With `honor_labels: true`, the target's own labels win.
- `honor_timestamps: true` (default) means Prometheus uses timestamps present in the exposition. Set to `false` to force Prometheus's own scrape time. Set `false` for the Pushgateway if you want push time ignored.
- `sample_limit` exceeded means the **entire scrape fails**, not a partial ingest.

### alerting

```yaml
alerting:
  alert_relabel_configs:            # rewrite or drop alerts before sending
    - source_labels: [replica]
      action: labeldrop
  alertmanagers:
    - timeout: 10s
      api_version: v2               # v2 is the default and the one to use
      path_prefix: /
      scheme: http
      static_configs:
        - targets:
            - alertmanager-1:9093
            - alertmanager-2:9093
      # or discover them
      kubernetes_sd_configs:
        - role: endpoints
          namespaces:
            names: [monitoring]
```

`alert_relabel_configs` is the mechanism for stripping the `replica` external label so HA replicas produce identical alerts, which lets Alertmanager dedupe them.

### rule_files

```yaml
rule_files:
  - /etc/prometheus/rules/*.yml
  - /etc/prometheus/rules/*.yaml
  - rules/single-file.yml
```

Globs are supported. Paths are relative to the working directory, so absolute paths are safer.

Changing a rule **file's content** still requires a reload. Only `file_sd` target files are watched automatically.

### remote_write and remote_read

```yaml
remote_write:
  - url: https://mimir.example.com/api/v1/push
    name: mimir
    remote_timeout: 30s
    headers:
      X-Scope-OrgID: tenant-a
    write_relabel_configs:
      - source_labels: [__name__]
        regex: "go_.*|process_.*"
        action: drop
    queue_config:
      capacity: 10000
      max_shards: 200
      min_shards: 1
      max_samples_per_send: 2000
      batch_send_deadline: 5s
      min_backoff: 30ms
      max_backoff: 5s
    metadata_config:
      send: true
      send_interval: 1m

remote_read:
  - url: https://mimir.example.com/api/v1/read
    read_recent: false
    required_matchers:
      cluster: production
```

`write_relabel_configs` is how you filter what gets shipped, saving cost.

### Command line flags (not in the YAML)

These are flags, not config file entries. Confusing the two is a classic exam trap.

| Flag | Purpose |
| --- | --- |
| `--config.file` | Path to `prometheus.yml` |
| `--storage.tsdb.path` | Data directory, default `data/` |
| `--storage.tsdb.retention.time` | Default `15d` |
| `--storage.tsdb.retention.size` | e.g. `50GB`, default `0` (off) |
| `--storage.tsdb.min-block-duration` | Default `2h` |
| `--storage.tsdb.max-block-duration` | Default 10% of retention |
| `--storage.tsdb.wal-compression` | Enabled by default in recent versions |
| `--web.listen-address` | Default `0.0.0.0:9090` |
| `--web.external-url` | Public URL, used in alert links |
| `--web.route-prefix` | Path prefix |
| `--web.enable-lifecycle` | Enables `/-/reload` and `/-/quit` |
| `--web.enable-admin-api` | Enables delete series, snapshot, clean tombstones |
| `--web.config.file` | TLS and basic auth for the Prometheus web endpoint itself |
| `--query.max-samples` | Default 50,000,000 |
| `--query.timeout` | Default `2m` |
| `--query.max-concurrency` | Default 20 |
| `--query.lookback-delta` | Default `5m` |
| `--rules.alert.for-outage-tolerance` | Default `1h` |
| `--rules.alert.for-grace-period` | Default `10m` |
| `--rules.alert.resend-delay` | Default `1m` |
| `--enable-feature=...` | Feature flags, e.g. `exemplar-storage`, `native-histograms`, `agent` |
| `--log.level` | `debug`, `info`, `warn`, `error` |

**Retention is a flag, not a YAML key.** Remember that.

### Validation and reload

```bash
promtool check config prometheus.yml
promtool check rules rules/*.yml
promtool check web-config web-config.yml

curl -X POST http://localhost:9090/-/reload
kill -HUP $(pidof prometheus)
```

## Answers

**Q1: B.** `job_name` only, and it must be unique. Everything else has a default or is optional.

**Q2: C.** Retention is a command line flag: `--storage.tsdb.retention.time`. There is no YAML key for it. This is one of the most reliably tested facts.

**Q3: D.** `1m`. Most people configure `15s` or `30s`, but the **default** is one minute.

**Q4: B.** `10s`.

**Q5: B.** Prometheus refuses to load the config. `scrape_timeout` must be less than or equal to `scrape_interval`.

**Q6: B.** External labels are added on egress only: remote_write, `/federate`, and alerts. They are not stored locally, so local queries do not see them.

**Q7: B.** Different `replica` values make the two servers distinguishable in remote storage, and `alert_relabel_configs` with `labeldrop` removes the label from alerts so Alertmanager sees identical alerts and dedupes them.

**Q8: B.** The colliding exposed label is prefixed with `exported_`. This preserves both values.

**Q9: C.** `sample_limit`. Exceeding it fails the whole scrape. `target_limit` caps the number of targets in the job, `label_limit` caps labels per series.

**Q10: B.** Rule file content changes need a reload. Only `file_sd` target files are hot-watched.

**Q11: B.** `write_relabel_configs` inside a `remote_write` block.

**Q12: B.** `--web.enable-lifecycle`.

**Q13: B.** The `params` map. `params: { module: [http_2xx] }` yields `?module=http_2xx`. You can also build them via relabeling with `__param_<name>`.

**Q14: C.** `1m`.

**Q15: B.** The old config stays live and the reload-success gauge drops to 0. Always alert on `prometheus_config_last_reload_successful == 0`.

**Q16: C.** `--query.lookback-delta` is a flag. The others are YAML.

**Q17: B.** Prometheus uses its own scrape timestamp, ignoring any timestamp in the exposition text.

## Hands-on

Validate your config and deliberately break it:

```bash
promtool check config ~/pca-lab/prometheus/prometheus.yml
```

Try an invalid timeout relationship:

```yaml
global:
  scrape_interval: 10s
  scrape_timeout: 30s
```

```bash
promtool check config ~/pca-lab/prometheus/prometheus.yml
# FAILED: scrape timeout greater than scrape interval
```

Prove `external_labels` are invisible locally:

```yaml
global:
  external_labels:
    cluster: pca-lab
    replica: A
```

```bash
curl -X POST http://localhost:9090/-/reload
```

```promql
up
```

No `cluster` label appears. Now check federation, which is an egress path:

```bash
curl -sG 'http://localhost:9090/federate' --data-urlencode 'match[]=up' | head -5
```

The `cluster` and `replica` labels are present there.

Demonstrate `honor_labels`. Push a metric with a `job` label to Pushgateway:

```bash
echo 'weird_metric{job="i-set-this-myself"} 1' \
  | curl --data-binary @- http://localhost:9091/metrics/job/pgw_group
```

With `honor_labels: true` on the Pushgateway job you see `job="i-set-this-myself"`. Flip it to `false`, reload, and you get `exported_job="i-set-this-myself"` with `job="pushgateway"`.

Test `sample_limit`:

```yaml
  - job_name: node
    sample_limit: 10
    static_configs:
      - targets: ["node-exporter:9100"]
```

```bash
curl -X POST http://localhost:9090/-/reload
```

```promql
up{job="node"}
```

It becomes 0. Check the error on `/targets`: "sample limit exceeded". Note that **no** samples are ingested, not a truncated subset.

Inspect the effective config and flags:

```bash
curl -s http://localhost:9090/api/v1/status/config | jq -r '.data.yaml'
curl -s http://localhost:9090/api/v1/status/flags | jq '.data | {"storage.tsdb.retention.time","query.lookback-delta","web.enable-lifecycle"}'
```

Watch reload health:

```promql
prometheus_config_last_reload_successful
time() - prometheus_config_last_reload_success_timestamp_seconds
```

## Exam tips

- `job_name` is the only required scrape config field, and it must be unique.
- Defaults: `scrape_interval 1m`, `scrape_timeout 10s`, `evaluation_interval 1m`, `metrics_path /metrics`, `scheme http`.
- `scrape_timeout <= scrape_interval`, enforced at load time.
- **Retention is a CLI flag**, `--storage.tsdb.retention.time`, default `15d`. Not YAML.
- `external_labels` attach on egress only: remote_write, federation, alerts. Invisible to local queries.
- `honor_labels: false` prefixes colliding exposed labels with `exported_`. `true` lets the target's labels win. Use `true` for Pushgateway.
- `sample_limit` exceeded discards the **whole** scrape.
- Rule file content changes need a reload. `file_sd` target files do not.
- `write_relabel_configs` filters remote_write. `alert_relabel_configs` rewrites alerts. `relabel_configs` shapes targets. `metric_relabel_configs` shapes samples.
- Failed reload keeps the old config and sets `prometheus_config_last_reload_successful` to 0.
- `params` builds query strings, which is how blackbox exporter modules are selected.
