# 29. Exporters

**Domain:** Instrumentation and Exporters

## Concept Refresher

An **exporter** is a process that translates a third-party system's state into Prometheus exposition format. You use one when you cannot instrument the software yourself.

```text
┌──────────────┐    native protocol    ┌──────────────┐   /metrics    ┌────────────┐
│  MySQL       │◄──────────────────────│  mysqld_     │◄──────────────│ Prometheus │
│  (no Prom    │  SHOW GLOBAL STATUS   │  exporter    │  exposition   │            │
│   support)   │                       │  :9104       │               │            │
└──────────────┘                       └──────────────┘               └────────────┘
```

Two deployment topologies:

| Topology | When |
| --- | --- |
| **Sidecar / local**: exporter runs next to the thing it monitors, one per instance | node_exporter, mysqld_exporter, redis_exporter |
| **Central / multi-target**: one exporter serves many targets, selected by a URL parameter | blackbox_exporter, snmp_exporter |

The multi-target pattern always requires the relabeling trick with `__param_target`.

### node_exporter

Exposes host-level metrics from `/proc` and `/sys`.

```bash
node_exporter \
  --collector.systemd \
  --collector.processes \
  --no-collector.hwmon \
  --collector.textfile.directory=/var/lib/node_exporter/textfile \
  --web.listen-address=:9100
```

Key metric families:

| Metric | Type | Notes |
| --- | --- | --- |
| `node_cpu_seconds_total{cpu, mode}` | counter | One series per core per mode. Modes: user, system, idle, iowait, nice, irq, softirq, steal |
| `node_memory_MemTotal_bytes`, `node_memory_MemAvailable_bytes` | gauge | Prefer `MemAvailable` over `MemFree` |
| `node_filesystem_size_bytes`, `node_filesystem_avail_bytes`, `node_filesystem_files_free` | gauge | Labels: `device`, `fstype`, `mountpoint`. Filter out `tmpfs`/`overlay` |
| `node_disk_read_bytes_total`, `node_disk_written_bytes_total`, `node_disk_io_time_seconds_total` | counter | Per `device` |
| `node_network_receive_bytes_total`, `node_network_transmit_bytes_total`, `node_network_receive_errs_total` | counter | Per `device` |
| `node_load1`, `node_load5`, `node_load15` | gauge | Load averages |
| `node_boot_time_seconds` | gauge | For uptime |
| `node_time_seconds` | gauge | For clock skew |
| `node_systemd_unit_state{name, state}` | gauge | Needs the systemd collector |
| `node_textfile_scrape_error` | gauge | 1 if a textfile failed to parse |

Running it in a container needs host mounts:

```bash
docker run -d --name node-exporter \
  --pid=host \
  -v /:/host:ro,rslave \
  -p 9100:9100 \
  prom/node-exporter:v1.9.1 \
  --path.rootfs=/host
```

### The textfile collector

This is the standard way to get **arbitrary custom metrics from a script** into Prometheus without writing an exporter.

```bash
# Write to a .prom file in the configured directory, ATOMICALLY
cat > /var/lib/node_exporter/textfile/backup.prom.$$ <<EOF
# HELP backup_last_success_timestamp_seconds Unix time of the last successful backup.
# TYPE backup_last_success_timestamp_seconds gauge
backup_last_success_timestamp_seconds $(date +%s)
# HELP backup_size_bytes Size of the last backup.
# TYPE backup_size_bytes gauge
backup_size_bytes 4823910
EOF
mv /var/lib/node_exporter/textfile/backup.prom.$$ /var/lib/node_exporter/textfile/backup.prom
```

Rules:

- Files must end in `.prom`.
- **Write to a temp file and `mv` into place.** A partially written file causes parse errors, and `mv` is atomic on the same filesystem.
- node_exporter reads the files **on each scrape**, so values persist between script runs.
- `node_textfile_mtime_seconds` gives each file's age, so you can alert on staleness.
- Errors surface as `node_textfile_scrape_error 1`.

Textfile collector versus Pushgateway:

| | Textfile collector | Pushgateway |
| --- | --- | --- |
| Data location | A file on the host | A central service |
| Discovery | Comes with the host's existing target | A separate scrape job |
| Best for | **Machine-level** cron jobs | **Service-level** batch jobs |
| Staleness | `node_textfile_mtime_seconds` | `push_time_seconds` |
| Requires | node_exporter on that host | Network reachability |

### blackbox_exporter

Probes endpoints **from the outside**, without any cooperation from the target.

`blackbox.yml`:

```yaml
modules:
  http_2xx:
    prober: http
    timeout: 5s
    http:
      valid_status_codes: []          # empty means 2xx
      valid_http_versions: ["HTTP/1.1", "HTTP/2.0"]
      method: GET
      follow_redirects: true
      preferred_ip_protocol: ip4
      fail_if_body_not_matches_regexp:
        - "healthy"

  http_post_2xx:
    prober: http
    http:
      method: POST
      body: '{"probe":"true"}'
      headers:
        Content-Type: application/json

  tcp_connect:
    prober: tcp
    timeout: 5s

  icmp:
    prober: icmp
    timeout: 5s
    icmp:
      preferred_ip_protocol: ip4

  dns_soa:
    prober: dns
    dns:
      query_name: example.com
      query_type: SOA
```

The scrape config, which you must be able to recognise instantly:

```yaml
scrape_configs:
  - job_name: blackbox
    metrics_path: /probe
    params:
      module: [http_2xx]
    static_configs:
      - targets:
          - https://example.com
          - https://prometheus.io
    relabel_configs:
      - source_labels: [__address__]
        target_label: __param_target
      - source_labels: [__param_target]
        target_label: instance
      - target_label: __address__
        replacement: blackbox-exporter:9115
```

Metrics produced:

| Metric | Meaning |
| --- | --- |
| `probe_success` | 1 if the probe succeeded |
| `probe_duration_seconds` | Total probe time |
| `probe_http_status_code` | HTTP status returned |
| `probe_http_duration_seconds{phase}` | Phases: resolve, connect, tls, processing, transfer |
| `probe_ssl_earliest_cert_expiry` | Certificate expiry as a Unix timestamp |
| `probe_http_ssl` | 1 if TLS was used |
| `probe_dns_lookup_time_seconds` | DNS resolution time |
| `probe_ip_protocol` | 4 or 6 |
| `probe_failed_due_to_regex` | 1 if the body regex check failed |

Note the distinction: **`up` reflects whether Prometheus could scrape the blackbox exporter. `probe_success` reflects whether the probed endpoint is healthy.** Alert on `probe_success == 0`, not `up == 0`.

### snmp_exporter

Same multi-target pattern as blackbox:

```yaml
  - job_name: snmp
    metrics_path: /snmp
    params:
      module: [if_mib]
    static_configs:
      - targets: ["switch-1", "switch-2"]
    relabel_configs:
      - source_labels: [__address__]
        target_label: __param_target
      - source_labels: [__param_target]
        target_label: instance
      - target_label: __address__
        replacement: snmp-exporter:9116
```

`snmp.yml` is generated from MIBs by the `generator` tool. You will not be asked to write it.

### statsd_exporter

Bridges push-based StatsD traffic into pull-based Prometheus. Applications keep sending UDP StatsD, and Prometheus scrapes the exporter.

```text
App ──UDP StatsD──► statsd_exporter :9125 ──► /metrics :9102 ◄──scrape── Prometheus
```

Mapping config turns dotted StatsD names into labelled Prometheus metrics:

```yaml
mappings:
  - match: "myapp.request.*.*"
    name: "myapp_requests_total"
    labels:
      method: "$1"
      status: "$2"
```

This is the standard migration path from StatsD or Graphite.

### kube-state-metrics vs cAdvisor vs node_exporter

A frequently confused trio.

| | kube-state-metrics | cAdvisor | node_exporter |
| --- | --- | --- | --- |
| Source | Kubernetes API server | Container runtime / cgroups | Host `/proc` and `/sys` |
| Answers | "What does the cluster **declare**?" | "What are containers **using**?" | "What is the **machine** doing?" |
| Examples | `kube_deployment_spec_replicas`, `kube_pod_status_phase`, `kube_node_status_condition` | `container_cpu_usage_seconds_total`, `container_memory_working_set_bytes` | `node_cpu_seconds_total`, `node_filesystem_avail_bytes` |
| Deployment | A Deployment, one replica | Built into the kubelet, at `/metrics/cadvisor` | A DaemonSet |
| Nature | Object **state**, not resource usage | Resource **usage** | Host resources |

kube-state-metrics does **not** export resource usage, and cAdvisor does **not** know about Deployments or Ingresses. Questions often test exactly this boundary.

### Writing your own exporter

Guidelines from the Prometheus docs:

1. Query the target system **when scraped**, using a custom collector. Do not poll on a timer into cached counters.
2. Expose a `<system>_up` gauge indicating whether the underlying system could be reached.
3. Expose scrape health: `<system>_exporter_last_scrape_error`, `<system>_exporter_scrape_duration_seconds`.
4. Prefix metrics with the **exported system's** name.
5. Do **not** set your own timestamps.
6. Do **not** set `instance` or `job` labels.
7. Preserve the source system's units where sensible, but convert to base units.
8. Never let a slow backend hang the scrape indefinitely; honour a timeout, using the `X-Prometheus-Scrape-Timeout-Seconds` header if you can.

### Exporter health monitoring

```promql
# Prometheus could scrape the exporter
up{job="mysql"} == 0

# The exporter could reach MySQL
mysql_up == 0

# The exporter's own last scrape failed
mysql_exporter_last_scrape_error == 1

# Blackbox: the probed endpoint is unhealthy
probe_success == 0

# Textfile collector parse failure
node_textfile_scrape_error == 1

# Textfile data has gone stale
time() - node_textfile_mtime_seconds > 3600
```

The two-level pattern (`up` for the exporter, `<system>_up` for the backend) is important. `up == 1` with `mysql_up == 0` means the exporter is fine but the database is unreachable.

## Answers

**Q1: B.** Translation of a third-party system's state into exposition format. Note that exporters are **scraped**, not pushed to.

**Q2: C.** 9100.

**Q3: B.** 9115.

**Q4: B.** The blackbox exporter's address, because that is what Prometheus connects to.

**Q5: B.** `__param_target` becomes `?target=...` in the request.

**Q6: B.** `probe_success`.

**Q7: B.** Two-level health. `up` covers Prometheus to exporter; `probe_success` covers exporter to endpoint.

**Q8: B.** snmp_exporter.

**Q9: B.** It is a push-to-pull bridge, the standard StatsD migration path.

**Q10: B.** `.prom` files in the configured directory, re-read on each scrape.

**Q11: B.** Atomicity. A partially written file yields parse errors and `node_textfile_scrape_error 1`.

**Q12: B.** `node_textfile_mtime_seconds`.

**Q13: B.** Textfile collector, because the metric belongs to that machine and node_exporter is already a target there.

**Q14: B.** `MemAvailable` accounts for reclaimable cache, so it reflects genuinely usable memory. `MemFree` understates it badly on Linux.

**Q15: C.** 8 x 8 = 64. Cardinality multiplies.

**Q16: B.** Object state from the API server. It does **not** expose resource usage.

**Q17: B.** cAdvisor, embedded in the kubelet and served at `/metrics/cadvisor`.

**Q18: B.** kube-state-metrics gives `kube_deployment_spec_replicas` and `kube_deployment_status_replicas_available`.

**Q19: B.** On scrape, so the values are current and there is no cache-staleness problem.

**Q20: B.** `<system>_up`, distinct from Prometheus's synthetic `up`.

**Q21: B.** No. Self-supplied timestamps interfere with staleness handling.

**Q22: B.** No. Prometheus owns those labels.

**Q23: B.** blackbox_exporter, which is why it is used for external endpoints and third-party services.

**Q24: B.** `probe_ssl_earliest_cert_expiry`, a Unix timestamp, so `(x - time()) / 86400` gives days.

**Q25: B.** They are virtual or container-layer filesystems. Alerting on them produces noise.

That becomes 1. Note that valid files still work. Remove the broken one:

```bash

```

Write a realistic cron-style script:

```bash
cat > ~/pca-lab/textfile-writer.sh <<'SH'
#!/usr/bin/env bash
set -euo pipefail
DIR=/home/$USER/pca-lab/textfile
TMP="$DIR/.custom.prom.$$"

USERS=$(who | wc -l)
PROCS=$(ps ax | wc -l)
UPDAYS=$(awk '{printf "%.2f", $1/86400}' /proc/uptime)

cat > "$TMP" <<EOF
# HELP custom_logged_in_users Number of logged-in users.
# TYPE custom_logged_in_users gauge
custom_logged_in_users ${USERS}
# HELP custom_process_count Number of processes.
# TYPE custom_process_count gauge
custom_process_count ${PROCS}
# HELP custom_uptime_days Host uptime in days.
# TYPE custom_uptime_days gauge
custom_uptime_days ${UPDAYS}
# HELP custom_script_last_run_timestamp_seconds Last successful run.
# TYPE custom_script_last_run_timestamp_seconds gauge
custom_script_last_run_timestamp_seconds $(date +%s)
EOF

mv "$TMP" "$DIR/custom.prom"
SH
chmod +x ~/pca-lab/textfile-writer.sh
~/pca-lab/textfile-writer.sh
```

```bash
promtool check metrics < ~/pca-lab/textfile/custom.prom
curl -s http://localhost:9100/metrics | grep '^custom_'
```

## Exam tips

- An exporter **translates** a third-party system into exposition format and is **scraped**, never pushed to.
- Ports: **node_exporter 9100, blackbox 9115, snmp 9116, pushgateway 9091, statsd 9102 (9125/udp in), mysqld 9104, postgres 9187, redis 9121, kube-state-metrics 8080, cAdvisor 8080**.
- Multi-target exporters (blackbox, snmp) need the three-rule relabel: `__address__` → `__param_target`, `__param_target` → `instance`, then `__address__` → the exporter.
- **`up` = can Prometheus reach the exporter. `probe_success` / `<system>_up` = can the exporter reach the thing.** Alert on the right one.
- `probe_ssl_earliest_cert_expiry` is a Unix timestamp. Days left = `(x - time()) / 86400`.
- Textfile collector: `.prom` files, re-read **every scrape**, write via temp file plus `mv`. Health: `node_textfile_scrape_error` and `node_textfile_mtime_seconds`.
- Textfile collector = **machine-level** jobs. Pushgateway = **service-level** jobs.
- Prefer `node_memory_MemAvailable_bytes` over `MemFree`.
- Always filter `fstype!~"tmpfs|overlay"` on filesystem metrics.
- `node_cpu_seconds_total` cardinality = cores x modes.
- **kube-state-metrics = object state from the API. cAdvisor = container resource usage. node_exporter = host resources.** Know the boundaries.
- Writing an exporter: query **on scrape** with a custom collector, expose `<system>_up`, prefix with the exported system's name, set **no** timestamps, set **no** `instance` or `job` labels.
- statsd_exporter and graphite_exporter are **push-to-pull bridges**, the standard migration path.
