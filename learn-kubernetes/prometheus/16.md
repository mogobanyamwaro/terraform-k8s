# 16. Selecting Data: Instant Vectors And Matchers

**Domain:** PromQL

## Concept Refresher

### The four PromQL expression types

```text
┌──────────────────┬────────────────────────────────────────────────────────┐
│ Instant vector   │ ONE sample per series, all at the same timestamp       │
│                  │   up                                                  │
│                  │   node_cpu_seconds_total{mode="idle"}                  │
├──────────────────┼────────────────────────────────────────────────────────┤
│ Range vector     │ A RANGE of samples per series over a time window       │
│                  │   up[5m]                                              │
│                  │   node_cpu_seconds_total{mode="idle"}[1h]              │
│                  │   NOT directly graphable. Must be reduced by a function│
├──────────────────┼────────────────────────────────────────────────────────┤
│ Scalar           │ A single numeric value with no labels                  │
│                  │   42                                                  │
│                  │   time()                                              │
│                  │   scalar(up{instance="a"})                             │
├──────────────────┼────────────────────────────────────────────────────────┤
│ String           │ A string literal. Only usable as a function argument   │
│                  │   "hello"                                             │
└──────────────────┴────────────────────────────────────────────────────────┘
```

Type discipline is the number one source of PromQL errors:

- `rate()` requires a **range vector**. `rate(up)` is an error.
- `sum()` requires an **instant vector**. `sum(up[5m])` is an error.
- Range vectors cannot be graphed. Grafana will refuse.

### Instant vector selectors

```promql
up                                          # all series named up
up{job="demo"}                              # equality
up{job!="demo"}                             # inequality
up{job=~"demo|node"}                        # regex match, FULLY ANCHORED
up{job!~"demo.*"}                           # regex non-match
up{job="demo", instance="demo-a:8080"}      # multiple matchers are AND'd
{__name__="up"}                             # metric name via matcher
{__name__=~"node_cpu_.*", mode="idle"}      # regex on the name
{job="demo"}                                # all metrics from that job
```

### The four matchers

| Matcher | Meaning |
| --- | --- |
| `=` | Equal |
| `!=` | Not equal |
| `=~` | Regex matches |
| `!~` | Regex does not match |

Regex facts:

- **Fully anchored.** `job=~"demo"` is `^demo$`. To match a substring use `.*demo.*`.
- **RE2 engine.** No backreferences, no lookahead, no lookbehind.
- Case-insensitive matching uses the inline flag: `job=~"(?i)DEMO"`.
- Alternation: `status=~"200|301|404"`.
- Anchors you write are allowed but redundant.

### The empty-matcher rules

```promql
up{env=""}       # series with NO env label (empty == absent)
up{env!=""}      # series that HAVE a non-empty env label
```

A selector must contain **at least one matcher that does not match the empty string**:

```promql
{job=~".*"}          # ERROR: vector selector must contain at least one non-empty matcher
{job=~".+"}          # OK
{__name__=~".+"}     # OK, selects everything. Very expensive
up{job=~".*"}        # OK, because __name__="up" is a non-empty matcher
```

### Offset modifier

Look at data from the past:

```promql
up offset 5m                                  # value 5 minutes ago
rate(http_requests_total[5m] offset 1w)       # rate as of one week ago
sum(rate(x[5m])) - sum(rate(x[5m] offset 1h)) # change vs an hour ago
```

- `offset` goes **immediately after** the selector or range vector, before any function wrapping.
- Negative offsets look into the future. They require `--enable-feature=promql-negative-offset` on older versions and are useful only in recording-rule backfill scenarios.

Wrong placement:

```promql
rate(http_requests_total[5m]) offset 1h    # ERROR
rate(http_requests_total[5m] offset 1h)    # correct
```

### The @ modifier

Pin evaluation to a fixed timestamp:

```promql
up @ 1687000000                     # value at that Unix timestamp
up @ start()                        # value at the query range start
up @ end()                          # value at the query range end
rate(x[5m] @ end())
topk(5, sum by (job) (rate(x[5m]))) # top 5 changes over the graph
topk(5, sum by (job) (rate(x[5m] @ end())))  # top 5 as of the END, stable series set
```

`@ end()` is the idiomatic fix for "topk keeps changing which series it shows across the graph".

You may combine `offset` and `@` in either order:

```promql
up @ 1687000000 offset 5m
up offset 5m @ 1687000000
```

### Duration syntax

```text
ms  milliseconds
s   seconds
m   minutes
h   hours
d   days      (always 24h, no DST awareness)
w   weeks     (always 7d)
y   years     (always 365d, no leap years)
```

Units must be ordered **largest to smallest** and can be combined without separators:

```promql
up[1h30m]        # valid
up[1d12h]        # valid
up[90s]          # valid
up[1m30s]        # valid
up[30s1m]        # INVALID, wrong order
up[1.5h]         # INVALID, no fractions
```

Since Prometheus 2.x, negative and float durations are not allowed in range selectors.

### Selecting metric names as data

```promql
count by (__name__) ({__name__=~".+"})     # series count per metric name
{__name__=~"node_(cpu|memory)_.*"}          # regex family selection
```

### Query cost awareness

These are slow and can hit `--query.max-samples` (default 50 million):

```promql
{__name__=~".+"}                    # every series in the TSDB
{__name__=~".+"}[30d]               # every series, 30 days of samples
count({job=~".+"})                  # broad selector
```

Prefer narrow selectors and short ranges. Error you will see: "query processing would load too many samples into memory".

### Instant query vs range query

| | Instant query | Range query |
| --- | --- | --- |
| API | `/api/v1/query` | `/api/v1/query_range` |
| Params | `query`, `time` | `query`, `start`, `end`, `step` |
| Result | One value per series | One series of values per series |
| UI tab | Table | Graph |
| Range vector allowed as final result | Yes, shown as a matrix | No |

## Answers

**Q1: B.** `up[5m]`. The bracketed duration is what makes it a range vector.

**Q2: B.** Type mismatch. `rate()` takes a range vector.

**Q3: B.** The reverse mismatch. Aggregation operators take instant vectors. To aggregate over a window you need a `*_over_time` function or a subquery.

**Q4: B.** Fully anchored, so `demo` matches only `demo` exactly.

**Q5: B.** Wrap with `.*` on both sides.

**Q6: C.** RE2 excludes backreferences and lookaround to guarantee linear-time matching.

**Q7: C.** `{env!=""}`. Because empty equals absent, `!=""` means "has the label".

**Q8: B.** `{job=~".*"}` has no matcher that excludes the empty string. Adding a metric name, as in option C, makes it legal.

**Q9: B.** `offset` goes **inside**, attached to the range vector.

**Q10: B.** It pins the selector's evaluation timestamp to the query range end.

**Q11: B.** Without `@ end()`, `topk` is recomputed at every step, so the series membership flickers. Pinning it produces a stable, readable graph.

**Q12: C.** Fractional durations are not allowed. Write `[90m]`.

**Q13: B.** Exactly 24 hours. PromQL durations are fixed-length, with no calendar or DST awareness. Likewise `1w` = 7d and `1y` = 365d.

**Q14: B.** `/api/v1/query_range`.

**Q15: C.** `scalar()` converts a single-element instant vector to a scalar. `sum(up)` is still an instant vector with no labels, not a scalar.

**Q16: B.** Range vectors must be reduced. Grafana errors otherwise.

**Q17: A.** The RE2 inline flag `(?i)`.

**Q18: B.** 50,000,000.

**Q19: B.** AND. All matchers must be satisfied.

**Q20: B.** `{job="demo"}` with no metric name selects all metrics carrying that label. Option C returns only the `up` metric.

## Hands-on

Work through the type system deliberately:

```promql
# Instant vector
up

# Range vector. In the UI, switch to the Table tab to see the raw samples
up[5m]

# This errors. Read the message carefully
rate(up)

# This errors too
sum(up[5m])

# Correct
rate(node_cpu_seconds_total[5m])
sum(up)
avg_over_time(up[5m])
```

Explore matchers:

```promql
up{job="demo"}
up{job!="demo"}
up{job=~"demo|node"}
up{job!~"demo"}
up{job=~".*emo.*"}
up{job=~"emo"}                 # returns nothing, proving anchoring
up{job=~"(?i)DEMO"}            # case-insensitive
{__name__="up"}
{__name__=~"node_cpu_.*"}
{job="demo"}                   # every metric from that job
```

Prove the non-empty matcher rule:

```bash
curl -sG http://localhost:9090/api/v1/query --data-urlencode 'query={job=~".*"}' | jq -r '.error'
curl -sG http://localhost:9090/api/v1/query --data-urlencode 'query={job=~".+"}' | jq -r '.status'
```

Prove empty equals absent:

```promql
count(up)
count(up{env=""})
count(up{env!=""})
```

The last two must sum to the first.

Practise offset:

```promql
up
up offset 5m
node_load1
node_load1 offset 10m
node_load1 - node_load1 offset 10m

rate(node_cpu_seconds_total{mode="idle"}[5m])
rate(node_cpu_seconds_total{mode="idle"}[5m] offset 30m)

# Week over week comparison
sum(rate(demo_api_request_duration_seconds_count[5m]))
  - sum(rate(demo_api_request_duration_seconds_count[5m] offset 1d))
```

Try the wrong placement and read the error:

```bash
curl -sG http://localhost:9090/api/v1/query \
  --data-urlencode 'query=rate(node_cpu_seconds_total[5m]) offset 1h' | jq -r '.error'
```

Practise `@`:

```promql
up @ start()
up @ end()
node_load1 @ 1687000000

# Unstable topk across a graph
topk(3, sum by (instance) (rate(node_cpu_seconds_total[5m])))

# Stable topk
topk(3, sum by (instance) (rate(node_cpu_seconds_total[5m] @ end())))
```

Run both as range queries in the Graph tab over 6 hours and compare the legends.

Test duration validity:

```bash
for d in 1h30m 90s 1d12h 1.5h 30s1m 5m 1y; do
  printf '%-8s -> ' "$d"
  curl -sG http://localhost:9090/api/v1/query \
    --data-urlencode "query=avg_over_time(up[$d])" | jq -r '.status + " " + (.error // "")'
done
```

Compare instant and range API results:

```bash
# Instant
curl -sG http://localhost:9090/api/v1/query \
  --data-urlencode 'query=up' | jq '.data.resultType'

# Range
curl -sG http://localhost:9090/api/v1/query_range \
  --data-urlencode 'query=up' \
  --data-urlencode "start=$(( $(date +%s) - 600 ))" \
  --data-urlencode "end=$(date +%s)" \
  --data-urlencode 'step=60' | jq '.data.resultType'

# Range vector as an instant query returns a matrix
curl -sG http://localhost:9090/api/v1/query \
  --data-urlencode 'query=up[5m]' | jq '.data.resultType'

# Range vector in a range query is an error
curl -sG http://localhost:9090/api/v1/query_range \
  --data-urlencode 'query=up[5m]' \
  --data-urlencode "start=$(( $(date +%s) - 600 ))" \
  --data-urlencode "end=$(date +%s)" \
  --data-urlencode 'step=60' | jq -r '.error'
```

Hit the sample limit deliberately:

```bash
curl -sG http://localhost:9090/api/v1/query \
  --data-urlencode 'query=count_over_time({__name__=~".+"}[30d])' | jq -r '.error // .status'
```

```bash

curl -s http://localhost:9090/api/v1/label/job/values | jq '.data'
```

## Exam tips

- Four types: **instant vector, range vector, scalar, string**. Most PromQL errors are type errors.
- `rate()` and every `*_over_time()` need a **range vector**. Aggregation operators need an **instant vector**.
- A range vector cannot be graphed.
- Matchers: `=`, `!=`, `=~`, `!~`. Regexes are **fully anchored** and use **RE2** (no backreferences or lookahead).
- Substring match requires `.*foo.*`. Case-insensitive uses `(?i)`.
- `{l=""}` = series without label `l`. `{l!=""}` = series with it.
- A selector needs **at least one matcher that cannot match empty**. `{job=~".*"}` is rejected.
- `offset` goes **inside**, right after the selector or range: `rate(x[5m] offset 1h)`.
- `@ end()` pins evaluation time. It stabilises `topk` across a graph.
- Durations: `ms s m h d w y`, ordered largest to smallest, **no fractions**. `1d` = 24h exactly, `1y` = 365d.
- Multiple matchers are AND'd.
- `{job="demo"}` with no metric name returns every metric from that job.
- `/api/v1/query` is instant, `/api/v1/query_range` is a graph. Default `--query.max-samples` is 50,000,000.
