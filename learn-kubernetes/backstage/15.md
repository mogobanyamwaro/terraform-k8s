# 15. Troubleshooting Entity Ingestion

**Domain:** Catalog (22%)

## Concept Refresher

Ingestion loop: **Location/provider → fetch → parse YAML → processors (validate, mutate, relations) → database**. Failures show on the entity, Location page, or backend logs.

**Typical failures**

| Symptom | Likely cause |
| --- | --- |
| Location error / 404 | Bad URL, branch, or path |
| 401/403 on fetch | Missing SCM token / GitHub App |
| YAML parse error | Tabs, missing `:`, bad indent |
| Missing required field | Component without `spec.type` / `owner` / `lifecycle` |
| Unknown kind | Typo (`Componet`) or processor not installed |
| Duplicate entity | Same `kind`+`namespace`+`name` from two locations |
| Entity stale | Refresh interval; location not polling; provider crash |
| Relations missing | Wrong ref (`component:foo` vs name only); not ingested yet |
| Processor error | Policy / orphan rules / schema |

**Where to look:** Catalog → the **Location** entity’s status; backend logs (`yarn start`); entity page “about” / warnings. `analyze-location` / catalog unprocessed entities APIs exist; exam: **logs + Location status + YAML**.

Orphan cleanup: entities whose location vanished may linger until `orphanStrategy` / deletion.

Do not debug ingestion by changing React `App.tsx`.

## Exam tips

- **Fetch vs parse vs validate** — three different errors.
- Frontend is the wrong place to fix ingestion.
