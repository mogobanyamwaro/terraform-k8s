# 13. Annotations

**Domain:** Catalog (22%)

## Concept Refresher

`metadata.annotations` are **string key/value** hooks. Plugins read them to bind an entity to GitHub, Kubernetes, TechDocs, Sonar, etc.

They are **not** labels (labels are for filtering; annotations are opaque plugin config).

**Well-known examples**

| Annotation | Used by |
| --- | --- |
| `backstage.io/techdocs-ref` | TechDocs (`dir:.` or URL) |
| `backstage.io/source-location` | View source |
| `backstage.io/view-url` / `edit-url` | SCM links |
| `backstage.io/managed-by-location` | How this entity was ingested (system) |
| `github.com/project-slug` | GitHub plugins (`org/repo`) |
| `backstage.io/kubernetes-id` | Kubernetes plugin (label match) |
| `backstage.io/kubernetes-label-selector` | Alternate k8s binding |
| `sonarqube.org/project-key` | Sonar plugin |
| `backstage.io/code-coverage` | Coverage plugin |

```yaml
metadata:
  name: demo
  annotations:
    backstage.io/techdocs-ref: dir:.
    github.com/project-slug: acme/demo
    backstage.io/kubernetes-id: demo
```

Wrong or missing annotation → plugin tab empty, **not** a catalog parse failure (unless a processor requires it).

`managed-by-location` is usually **set by Backstage**, not hand-edited.
