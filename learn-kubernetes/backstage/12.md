# 12. Populate the Catalog (Kinds and YAML)

**Domain:** Catalog (22%)

## Concept Refresher

Entities are YAML documents:

```yaml
apiVersion: backstage.io/v1alpha1
kind: Component
metadata:
  name: artist-web
  description: Artist web app
  tags: [java]
  links:
    - url: https://example.com
      title: Admin
spec:
  type: website
  lifecycle: production
  owner: team-a
  system: artist-engagement
  providesApis: [artist-api]
  dependsOn:
    - resource:default/artists-db
```

**Kinds you must recognise**

| Kind | Typical `spec` |
| --- | --- |
| **Component** | `type`, `lifecycle`, `owner` |
| **API** | `type` (openapi/grpc/…), `lifecycle`, `owner`, `definition` |
| **Resource** | `type` (database, s3, …), `owner` |
| **System** | `owner`, optional `domain` |
| **Domain** | `owner` |
| **Template** | Scaffolder `parameters` + `steps` |
| **User** | `profile`, `memberOf` |
| **Group** | `type`, `children` / `parent` |
| **Location** | `targets` (rarely hand-written) |

`metadata.name` is the unique name in the namespace. `spec.type` is free-ish but conventional (`service`, `website`, `library`).

Populate by: static `catalog.locations`, UI **Register existing component**, or **entity providers** (next files).
