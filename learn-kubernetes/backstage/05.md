# 05. Docker Image of Backstage

**Domain:** Development Workflow (24%)

## Concept Refresher

Production image is usually **the backend** serving the **built frontend** (or a split deploy). create-app ships `packages/backend/Dockerfile`.

Typical flow:

```bash
yarn install --immutable
yarn tsc
yarn build:backend
yarn build-image
# docker run -p 7007:7007 -e POSTGRES_HOST=... <image>
```

Multi-stage Docker: Node build → slim runtime. **Do not** run `yarn start` in production (dev servers, SQLite by default).

Config at runtime: env vars / mounted `app-config.production.yaml`. `baseUrl` must match the public URL.

Frontend-only nginx image is a possible split; exam default is the **backend Dockerfile**.
