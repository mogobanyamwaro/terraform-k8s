# 19. Customizing Plugins

**Domain:** Customizing Backstage (32%)

## Concept Refresher

You rarely fork plugin source. You **compose** them in the app:

| Customization | Where |
| --- | --- |
| Which tabs/cards on an entity | `EntityPage.tsx` (`EntityLayout`, `EntitySwitch`) |
| Which pages exist | `App.tsx` `<Route>` |
| Sidebar entries | `Root.tsx` (`SidebarItem`) |
| Plugin config | `app-config.yaml` |
| Hide a plugin | Don’t mount the route / card |
| Wrap / extend | Pass props; `if` on `isKind('api')`; feature flags |

```tsx
<EntityLayout>
  <EntityLayout.Route path="/" title="Overview">
    <Grid container>
      <EntityAboutCard />
      <EntityCatalogGraphCard />
    </Grid>
  </EntityLayout.Route>
  <EntityLayout.Route path="/ci" title="CI">
    <EntityGithubActionsContent />
  </EntityLayout.Route>
</EntityLayout>
```

`EntitySwitch` / `isKind('component')` / annotation existence checks show a tab only when relevant.

Patching `node_modules` is not the CBA way. **App-level composition** is.
