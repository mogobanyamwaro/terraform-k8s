# THE 18-FOLDER INCIDENT: _"The Midnight Certificate Apocalypse"_

## One Scenario That Forces You To Touch EVERY Folder

**The Story:** It's 2 AM. Your company's main e-commerce site is down. The SSL certificate expired, but when you try to renew, EVERYTHING breaks. You have 1 hour before the CEO wakes up.

**Your Mission:** Fix the certificate renewal system. But each fix breaks something else. You'll traverse ALL 18 folders by the end.

# PHASE 1: THE INITIAL BREAK (First 15 min)

## Step 1: `/bin` - The First Command Fails

```bash
# You try to check the certificate
openssl x509 -in /etc/ssl/certs/server.crt -text -noout

# ERROR: "openssl: command not found"
```

**What's happening:** Someone cleaned `/bin` and removed openssl symlink.

**Your action:**

```bash
# Find where openssl really lives
ls -la /usr/bin/openssl
# -> /usr/bin/openssl (binary exists!)

# Create symlink in /bin
sudo ln -s /usr/bin/openssl /bin/openssl

# Test
openssl version
# -> OpenSSL 1.1.1f  (SUCCESS - YOU HAVE ACHIEVED: /bin fix)
```

**What you learned:** `/bin` is essential PATH, but binaries can live in `/usr/bin`. Symlinks connect them.

## Step 2: `/etc` - The Config Is Corrupt

```bash
# Check nginx config
sudo nginx -t

# ERROR: "unknown directive 'ssl_certificate' in /etc/nginx/sites-enabled/default:42"
```

**Your action:**

```bash
# Backup corrupt config
sudo cp /etc/nginx/sites-enabled/default /etc/nginx/sites-enabled/default.corrupt

# Check what's wrong
cat /etc/nginx/sites-enabled/default | grep -A2 -B2 ssl_certificate

# Someone commented out the SSL module!
# Fix: Uncomment
sudo sed -i 's/#ssl_certificate/ssl_certificate/' /etc/nginx/sites-enabled/default

# Test again
sudo nginx -t
# -> syntax is ok (SUCCESS - YOU HAVE ACHIEVED: /etc fix)
```

**What you learned:** `/etc/nginx/` controls web servers. Always backup before editing.

# PHASE 2: THE ESCALATION (Next 20 min)

## Step 4: `/dev` and `/proc` - Generate New Key

```bash
# Generate new private key
sudo openssl genrsa -out /etc/ssl/private/server.key 2048

# ERROR: "Can't open /etc/ssl/private/server.key for writing: No such file or directory"
```

**What's happening:** `/etc/ssl/private` directory might be missing.

**Your action:**

```bash
# Check if directory exists
ls -la /etc/ssl/ | grep private
# -> Nothing!

# Create it
sudo mkdir -p /etc/ssl/private

# Set correct permissions (600 for private keys)
sudo chmod 700 /etc/ssl/private

# Generate key again
sudo openssl genrsa -out /etc/ssl/private/server.key 2048
# -> Generating RSA private key... (SUCCESS)

# Check random device used (openssl reads from /dev/urandom)
cat /proc/sys/kernel/random/entropy_avail
# -> 3456 (enough entropy!)
```

**What you learned:** `/dev/urandom` provides randomness for crypto. `/proc/sys/kernel/random/entropy_avail` shows available entropy.

## Step 5: `/tmp` and `/run` - Certificate Signing Request

```bash
# Create CSR in temp location
cd /tmp
sudo openssl req -new -key /etc/ssl/private/server.key -out server.csr

# Enter details (CN=yourdomain.com, etc.)

# Check CSR created
ls -la /tmp/server.csr
# -> -rw-r--r-- 1 root root 1234 Dec 9 02:30 server.csr

# Now sign it (self-signed for demo)
sudo openssl x509 -req -days 365 -in /tmp/server.csr -signkey /etc/ssl/private/server.key -out /tmp/server.crt

# Move to proper location
sudo mv /tmp/server.crt /etc/ssl/certs/
sudo mv /tmp/server.csr /run/ (keep running process info)

# Verify
ls -la /run/server.csr
# -> File exists (SUCCESS - temp files managed)
```

**What you learned:** `/tmp` for temporary files, `/run` for runtime state (cleared on reboot).

## Step 6: `/lib` and `/usr` - The Library Nightmare

```bash
# Try to restart nginx
sudo systemctl restart nginx

# ERROR: "nginx: error while loading shared libraries: libssl.so.1.1: cannot open shared object file"

# Your heart sinks. OpenSSL library is missing!
```

**Your action:**

```bash
# Check where libssl should be
ldd /usr/sbin/nginx | grep ssl
# -> libssl.so.1.1 => not found

# Find libssl on system
sudo find / -name "libssl.so*" 2>/dev/null
# -> /usr/lib/x86_64-linux-gnu/libssl.so.3 (version mismatch!)

# Check what package provides it
dpkg -S /usr/lib/x86_64-linux-gnu/libssl.so.3
# -> libssl3: /usr/lib/x86_64-linux-gnu/libssl.so.3

# You need version 1.1. Install older package
sudo apt update
sudo apt install libssl1.1

# Verify
ls -la /lib/x86_64-linux-gnu/libssl.so.1.1
# -> lrwxrwxrwx 1 root root ... (SUCCESS)

# Now nginx can find it
ldd /usr/sbin/nginx | grep ssl
# -> libssl.so.1.1 => /lib/x86_64-linux-gnu/libssl.so.1.1
```

**What you learned:** `/lib` and `/usr/lib` hold shared libraries. Version mismatches break binaries.

```bash

**Your action:**

```

**What you learned:** `/sbin` contains admin tools (sysctl, fdisk, mkfs). `/boot` holds kernels. Sometimes SSL needs kernel update.

## Step 8: `/home` and `/root` - Permission Denied

```bash
# After reboot, nginx won't start
sudo systemctl start nginx

# ERROR: "Permission denied" for /etc/ssl/private/server.key

# Check permissions
ls -la /etc/ssl/private/server.key
# -> -rw------- 1 alice alice 1704 Dec 9 02:30 server.key
#    ^ alice owns it, but nginx runs as www-data!
```

**Your action:**

```bash
# Fix ownership
sudo chown root:www-data /etc/ssl/private/server.key
sudo chmod 640 /etc/ssl/private/server.key

# But why was user alice in /home?
cat /etc/passwd | grep alice
# -> alice:x:1001:1001:Alice,,,:/home/alice:/bin/bash

# Alice is a regular user. She shouldn't generate system certs!
# Move to root's home for security
sudo mv /etc/ssl/private/server.key /root/backup_keys/
sudo cp /root/backup_keys/server.key /etc/ssl/private/

# Set correct ownership
sudo chown root:www-data /etc/ssl/private/server.key
```

**What you learned:** `/home` for users, `/root` for admin. System certs owned by root, not users.

## Step 9: `/media` and `/mnt` - Backup Recovery

```bash
# You realize the old certificate was backed up on USB
# Find USB device
lsblk
# -> sdb1 8:17 0 32G 0 part /media/admin/BACKUP

# Check if mounted
mount | grep media
# -> /dev/sdb1 on /media/admin/BACKUP type vfat (rw,nosuid,nodev)

# Copy old key from backup
sudo cp /media/admin/BACKUP/ssl/server.key.old /etc/ssl/private/

# But /mnt is empty - you could mount here for permanence
sudo umount /media/admin/BACKUP
sudo mount /dev/sdb1 /mnt/recovery
ls -la /mnt/recovery/ssl/
# -> server.key.old exists!

# Restore original
sudo cp /mnt/recovery/ssl/server.key.old /etc/ssl/private/server.key
```

**What you learned:** `/media` for auto-mounted removable drives. `/mnt` for manual permanent mounts.

# PHASE 4: THE FINAL BATTLE (Last 10 min)

## Step 10: `/proc` and `/sys` - Live Debug

```bash
# Nginx still has SSL errors
sudo tail -f /var/log/nginx/error.log
# -> "SSL_read() failed (SSL: error:14094412:SSL routines:ssl3_read_bytes:sslv3 alert bad certificate)"

# Check nginx process memory map
ps aux | grep nginx
# -> root 12345 0.0 1.2 100000 12000 ? Ss 02:45 0:00 nginx: master process
# -> www-data 12346 0.0 0.8 100000 8000 ? S 02:45 0:00 nginx: worker

# Look at /proc for worker process
cat /proc/12346/status | grep -E "^(Uid|Gid)"
# -> Uid: 33 33 33 33 (www-data)
# -> Gid: 33 33 33 33

# Check open files
lsof -p 12346 | grep ssl
# -> nginx 12346 www-data mem REG 8,1 123456 789 /etc/ssl/certs/server.crt

# Check kernel SSL parameters
cat /proc/sys/net/core/somaxconn
# -> 128 (too low for high traffic!)

# Increase
sudo sysctl -w net.core.somaxconn=1024
echo "net.core.somaxconn=1024" | sudo tee -a /etc/sysctl.conf

# Also check sysfs for network tuning
cat /sys/class/net/eth0/speed
# -> 1000 (Gigabit - good)

# Set TCP keepalive
echo 600 > /proc/sys/net/ipv4/tcp_keepalive_time
```

**What you learned:** `/proc/PID/*` shows process details. `/sys/class/net/*` shows network stats. Tune in real-time.
