# Module 2: User Administration & System Security

## 2.1 User Account Architecture

Before managing users, understand what happens when a user is created:

```bash
# When you create a user, these files are modified:
/etc/passwd     # User account information
/etc/shadow     # Encrypted passwords (root access only)
/etc/group      # Group definitions
/etc/gshadow    # Group passwords (root access only)
/home/username/ # User's home directory
/var/mail/username  # User's mail spool
```

### The /etc/passwd File Format

```bash
# View the file
cat /etc/passwd | head -3

# Format: username:password:UID:GID:GECOS:home:shell
# Example: root:x:0:0:root:/root:/bin/bash
#          ^  ^ ^ ^   ^     ^       ^
#          |  | | |   |     |       +-- Login shell
#          |  | | |   |     +---------- Home directory
#          |  | | |   +---------------- Full name (GECOS)
#          |  | | +-------------------- Group ID
#          |  | +---------------------- User ID
#          |  +------------------------ Password placeholder (x means in /etc/shadow)
#          +--------------------------- Username
```

### The /etc/shadow File Format

```bash
# View shadow file (requires root)
sudo cat /etc/shadow | grep $USER

# Format: username:encrypted_password:last_change:min:max:warn:inactive:expire
# Example: user:$6$salt$hash:19245:0:99999:7:::
```

**📝 Hands-On Practice:**

```bash
# Create a user and examine the changes
sudo useradd -m -s /bin/bash -c "John Doe" john
sudo tail -1 /etc/passwd
sudo tail -1 /etc/shadow
sudo tail -1 /etc/group
ls -la /home/john

# Set a password
sudo passwd john
# Enter password when prompted

# Examine shadow entry after password
sudo tail -1 /etc/shadow
# Notice the encrypted password is now present

# User account aging
sudo chage -l john
sudo chage -M 90 john  # Set max days to 90
sudo chage -W 7 john   # Warn 7 days before expiry
```

## 2.2 Advanced User Management

### User Templates and Defaults

```bash
# View default user settings
cat /etc/default/useradd
cat /etc/login.defs | grep -v "^#" | grep -v "^$"

# Custom skeleton directory for new users
ls -la /etc/skel/
# Files here are copied to every new user's home directory

# Create a custom welcome message for new users
echo "Welcome to the system. Contact admin@company.com for help." | \
sudo tee /etc/skel/README.txt

# Create a new user to test
sudo useradd -m testuser
ls -la /home/testuser/
sudo userdel -r testuser
```

### Primary vs Supplementary Groups

```bash
# Create groups for organization
sudo groupadd developers
sudo groupadd operations
sudo groupadd sales

# Create users with specific primary groups
sudo useradd -m -g developers -G operations,users dev1
# Home directory: /home/dev1 (from -m)
# Primary group: developers (from -g)
# Also in groups: operations and users (from -G)
sudo useradd -m -g sales sales1

# Examine group memberships
id dev1
groups dev1

# Modify existing users
sudo usermod -g developers dev1  # Change primary group
sudo usermod -aG sales dev1      # Add supplementary group
sudo usermod -G "" dev1          # Remove all supplementary groups

# List members of a group
getent group developers
```

### User Quotas (Disk Space Limits)

```bash
# Install quota tools
sudo apt install -y quota quotatool

# Edit fstab to enable quotas
sudo cp /etc/fstab /etc/fstab.backup
# Add 'usrquota,grpquota' to the root mount options
# Example: UUID=xxx / ext4 defaults,usrquota,grpquota 0 1

# Remount and initialize
sudo mount -o remount /
sudo quotacheck -cum /  # Create quota files
sudo quotaon /

# Set quotas for a user
sudo edquota -u john
# Set soft limit (grace period) and hard limit (absolute)
# Example: 100M soft, 150M hard

# Check quotas
sudo quota -u john
sudo repquota -a
```

## 2.3 Sudo: Delegating Administrative Access

Sudo allows users to run commands with elevated privileges. This is more secure than giving out the root password.

### Understanding Sudoers

```bash
# View sudoers file syntax
sudo visudo  # Always use visudo to edit (prevents syntax errors)

# Common sudoers entries:
# User specification:
john ALL=(ALL:ALL) ALL
# Format: user host=(run_as_user:run_as_group) commands

# Allow specific commands only:
webadmin ALL=(ALL) /usr/bin/systemctl restart nginx, /usr/bin/systemctl status nginx

# Allow without password:
deploy ALL=(ALL) NOPASSWD: /usr/bin/systemctl

# Group specification (using % prefix):
%developers ALL=(ALL) /usr/bin/apt, /usr/bin/dnf

# Command aliases:
Cmnd_Alias WEB = /usr/bin/systemctl restart nginx, /usr/bin/systemctl status nginx
webteam ALL=(ALL) WEB
```

**📝 Hands-On Practice:**

```bash
# Create a dedicated admin user
sudo useradd -m -s /bin/bash -G sudo admin_john
sudo passwd admin_john

# Create a limited admin for web services
sudo useradd -m -s /bin/bash webadmin
sudo passwd webadmin

# Configure sudo for webadmin
sudo visudo
# Add this line:
webadmin ALL=(ALL) /usr/bin/systemctl restart nginx, /usr/bin/systemctl status nginx

# Test sudo access
sudo -i -u webadmin
sudo -l  # List allowed commands
sudo systemctl status nginx  # Should work
sudo systemctl restart ssh  # Should fail
exit

# Create sudoers.d file (cleaner than editing main file)
echo "webadmin ALL=(ALL) NOPASSWD: /usr/bin/systemctl status nginx" | \
sudo tee /etc/sudoers.d/webadmin
sudo chmod 440 /etc/sudoers.d/webadmin

# Verify sudo configuration
sudo visudo -c  # Check syntax
```

**🔴 RHEL Note:** On RHEL, the sudo group is typically `wheel`, not `sudo`. Also, sudoers syntax is identical.

## 2.4 SSH Security & Configuration

SSH is the primary way you'll access Linux servers. Secure configuration is critical.

### SSH Architecture

```
Client                                Server
┌─────────────┐                      ┌─────────────┐
│ ssh client  │ ─── SSH Handshake ──▶│ sshd daemon │
│ ~/.ssh/     │                      │ /etc/ssh/   │
│ - id_rsa    │                      │ sshd_config │
│ - id_rsa.pub│ ◀─── Authentication ─│             │
│ - config    │                      │             │
│ - known_hosts                     │             │
└─────────────┘                      └─────────────┘
```

### SSH Key-Based Authentication (Essential for Admin)

```bash
# Generate SSH key pair
ssh-keygen -t rsa -b 4096 -C "your_email@example.com"
# Or for modern security:
ssh-keygen -t ed25519 -C "your_email@example.com"

# View keys
ls -la ~/.ssh/
# id_rsa      - PRIVATE key (NEVER share this)
# id_rsa.pub  - PUBLIC key (share this)

# Copy public key to a remote server (or local for testing)
ssh-copy-id localhost
# Or manually:
cat ~/.ssh/id_rsa.pub >> ~/.ssh/authorized_keys
chmod 700 ~/.ssh
chmod 600 ~/.ssh/authorized_keys

# Test passwordless login
ssh localhost
```

### SSH Client Configuration

```bash
# Create SSH config file for shortcuts
cat > ~/.ssh/config << 'EOF'
# Default settings
Host *
    ServerAliveInterval 60
    StrictHostKeyChecking accept-new

# Lab server
Host lab
    HostName 192.168.1.100
    User admin
    Port 2222
    IdentityFile ~/.ssh/lab_rsa

# Production server
Host prod
    HostName prod.example.com
    User deploy
    ForwardAgent yes
    Compression yes
EOF

chmod 600 ~/.ssh/config
```

### Securing SSH Daemon

```bash
# Backup original config
sudo cp /etc/ssh/sshd_config /etc/ssh/sshd_config.backup

# Edit SSH server configuration
sudo nano /etc/ssh/sshd_config

# Key security settings to modify:
# Port 2222                         # Change from default 22
# PermitRootLogin no                # Never allow root login
# PasswordAuthentication no         # Force key-based auth
# PubkeyAuthentication yes
# MaxAuthTries 3                    # Limit attempts
# ClientAliveInterval 300           # Disconnect idle sessions
# ClientAliveCountMax 2
# AllowUsers admin_john webadmin    # Whitelist users
# DenyUsers baduser                 # Blacklist users
# AllowGroups developers sudo       # Whitelist groups

# Test configuration before restarting
sudo sshd -t

# Restart SSH service
sudo systemctl restart sshd

# Keep a second session open while testing new config!
```

**🔴 RHEL Note:** On RHEL, the SSH service is called `sshd` (same as Ubuntu), but the config file location is identical.

## 2.5 PAM (Pluggable Authentication Modules)

PAM provides flexible authentication mechanisms.

```bash
# View PAM configuration
ls -la /etc/pam.d/
cat /etc/pam.d/common-auth

# Common PAM modules:
# pam_unix.so    - Standard UNIX authentication
# pam_tally2.so  - Account lockout on failed attempts
# pam_limits.so  - Resource limits
# pam_time.so    - Time-based access controls

sudo nano /etc/pam.d/common-auth
# Add:
# auth required pam_tally2.so deny=5 unlock_time=300

# View failed attempts
sudo pam_tally2
sudo pam_tally2 --reset -u username
```

## 2.6 Package Management: APT Deep Dive

Now let's understand Ubuntu's package management thoroughly.

### Understanding APT Architecture

```
Repositories (sources.list)
    ↓
Package Index (apt update)
    ↓
Package Database (/var/lib/apt/lists/)
    ↓
Download Packages (.deb files)
    ↓
Install/Dependencies (apt install)
    ↓
Configuration (/etc/)
    ↓
Service Start
```

### Repository Management

```bash
# View repository configuration
cat /etc/apt/sources.list
ls /etc/apt/sources.list.d/

# Understanding repository line format:
# deb http://archive.ubuntu.com/ubuntu jammy main restricted
# |   |                          |      |     |    |
# |   |                          |      |     |    +-- Component
# |   |                          |      |     +------ Distribution codename
# |   |                          |      +------------ Distribution
# |   +--------------------------+------------------- Repository URL
# +-------------------------------------------------- Type (deb or deb-src)

# Add a repository
sudo add-apt-repository ppa:ondrej/php
sudo apt update

# Remove a repository
sudo add-apt-repository --remove ppa:ondrej/php

# Manually add repository
echo "deb http://archive.ubuntu.com/ubuntu jammy-backports main restricted" | \
sudo tee /etc/apt/sources.list.d/backports.list
```

### Advanced APT Commands

```bash
# Search with more detail
apt search nginx | grep -E "(nginx|^  )"
apt-cache show nginx  # Detailed package info
apt-cache depends nginx  # List dependencies
apt-cache rdepends nginx  # Reverse dependencies (what depends on nginx)

# Version management
apt-cache policy nginx  # Show available versions
sudo apt install nginx=1.18.0-0ubuntu1  # Install specific version

# Download package without installing
apt download nginx
ls -la *.deb

# Extract .deb to inspect
dpkg -x nginx*.deb ./nginx-extracted
ls -la ./nginx-extracted/

# List files installed by a package
dpkg -L nginx

# Find which package owns a file
dpkg -S /etc/nginx/nginx.conf

# Reconfigure a package
sudo dpkg-reconfigure tzdata

# Hold packages to prevent updates
echo "nginx hold" | sudo dpkg --set-selections
dpkg --get-selections | grep nginx

# Unhold
echo "nginx install" | sudo dpkg --set-selections
```

### Building from Source (When packages aren't enough)

```bash
# Install build dependencies
sudo apt install -y build-essential checkinstall

# Download source
wget https://nginx.org/download/nginx-1.24.0.tar.gz
tar xzf nginx-1.24.0.tar.gz
cd nginx-1.24.0

# Configure (custom paths, modules)
./configure \
    --prefix=/usr/local/nginx \
    --with-http_ssl_module \
    --with-http_v2_module

# Compile (takes time)
make -j$(nproc)

# Create package and install
sudo checkinstall
```

**🔴 RHEL Note:** This entire section is different on RHEL. Instead of APT, you'll use DNF/YUM. We'll cover that in a separate RHEL-specific module.

## 2.7 Firewall: UFW (Uncomplicated Firewall)

Ubuntu's default firewall tool is UFW.

```bash
# Check status
sudo ufw status verbose

# Default policies (deny all incoming, allow all outgoing)
sudo ufw default deny incoming
sudo ufw default allow outgoing

# Allow services by name
sudo ufw allow ssh
sudo ufw allow http
sudo ufw allow https

# Allow by port/protocol
sudo ufw allow 2222/tcp
sudo ufw allow 3306/tcp

# Allow specific IP
sudo ufw allow from 192.168.1.100
sudo ufw allow from 192.168.1.0/24 to any port 22 proto tcp

# Advanced rules
sudo ufw deny from 203.0.113.0/24
sudo ufw limit ssh/tcp  # Rate limiting

# View numbered rules
sudo ufw status numbered

# Delete by number
sudo ufw delete 3

# Enable firewall
sudo ufw enable

# Reset to defaults
sudo ufw reset
```

**🔴 RHEL Note:** RHEL uses `firewalld` with a completely different syntax and concept of zones. We'll cover this in detail later.

## Module 2 Practice Assessment

### Real-World Scenario: Onboarding a New Employee

You need to set up a new developer, Sarah, who needs:

- A user account with proper permissions
- SSH access with key-based authentication
- Sudo access for specific web services
- Limited disk space
- Firewall access to development servers

```bash
# Complete solution
#!/bin/bash

# 1. Create user with proper settings
sudo useradd -m -s /bin/bash -c "Sarah Developer" sarah

# 2. Create her groups
sudo groupadd developers
sudo usermod -aG developers sarah

# 3. Set password (prompt)
sudo passwd sarah

# 4. Create .ssh directory and add her public key
sudo mkdir -p /home/sarah/.ssh
echo "ssh-ed25519 AAAAC3... sarah@developer" | sudo tee /home/sarah/.ssh/authorized_keys
sudo chown -R sarah:developers /home/sarah/.ssh
sudo chmod 700 /home/sarah/.ssh
sudo chmod 600 /home/sarah/.ssh/authorized_keys

# 5. Set disk quota
sudo setquota -u sarah 100M 150M 0 0 /

# 6. Configure sudo for web server management
echo "sarah ALL=(ALL) /usr/bin/systemctl restart nginx, /usr/bin/systemctl status nginx" | \
sudo tee /etc/sudoers.d/sarah
sudo chmod 440 /etc/sudoers.d/sarah

# 7. Firewall access (if connecting from specific IP)
sudo ufw allow from 10.0.0.50 to any port 22 proto tcp

# 8. Create welcome message with access info
sudo tee /home/sarah/README.txt << 'EOF'
Welcome Sarah!
- Your account is ready
- SSH access is configured
- You can restart nginx with: sudo systemctl restart nginx
- Your home directory has 100MB soft limit, 150MB hard limit
- Contact IT for any issues
EOF

# 9. Verify all settings
sudo chage -l sarah
sudo quota -u sarah
sudo -l -U sarah
groups sarah
```
