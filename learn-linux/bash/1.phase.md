Excellent. Let's dive deep into **Phase 1: The Foundation (Daily Interactive Use)** . These are the commands you'll use hundreds of times per day as a Linux admin.

## Phase 1: Master the Interactive Shell

### 1. Filesystem Navigation

**`pwd`** - Print Working Directory (where am I?)

```bash
[peter@linux ~]$ pwd
/home/peter

[peter@linux ~]$ cd /var/log
[peter@linux log]$ pwd
/var/log
```

**`ls`** - List directory contents (your eyes on the filesystem)

```bash
# Basic listing
ls                    # Bare minimum (just names)
ls -l                 # Long format (permissions, owner, size, date)
ls -a                 # Show ALL files (including hidden .files)
ls -la                # Combine: long format + hidden files
ls -lh                # Human-readable sizes (1K, 2M, 3G)
ls -ltr               # Sort by time, reversed (newest files at bottom - VERY useful)
ls -l /var/log        # List specific directory

# Real admin example - find the most recent log file
[peter@linux log]$ ls -lt /var/log | head -5
-rw-r--r-- 1 root root 1.2M May 14 08:30 syslog
-rw-r--r-- 1 root root 45K May 14 08:25 auth.log
-rw-r--r-- 1 root root 12K May 14 08:15 dpkg.log
```

**`cd`** - Change Directory

```bash
cd /etc/nginx        # Absolute path (from root)
cd ../var            # Relative path (up one level, then into var)
cd ~                 # Go to your home directory
cd ~peter            # Go to peter's home directory (if you have permission)
cd -                 # Go to previous directory (like a back button!)
cd ..                # Up one level
cd ../..             # Up two levels

# Admin pattern - toggle between config and log directory
[peter@linux ~]$ cd /etc/nginx
[peter@linux nginx]$ cd -
/home/peter
[peter@linux ~]$ cd -
/etc/nginx
```

**`pushd` / `popd`** - Directory stack (for power users)

```bash
pushd /var/log      # Go to /var/log and remember where you were
pushd /etc          # Go to /etc and remember both previous locations
dirs -v             # View stack: 0:/etc 1:/var/log 2:/home/peter
popd                # Go back to /var/log
popd                # Go back to /home/peter
```

### 2. Viewing & Manipulating Files

**`cat`** - Concatenate files (best for small files only!)

```bash
cat file.txt              # Dump entire file to screen
cat file1.txt file2.txt   # Combine multiple files
cat > newfile.txt         # Create file from keyboard input (Ctrl+D to save)
cat >> existing.txt       # Append to existing file

# Admin use - quickly check small configs
cat /etc/hostname
cat /etc/resolv.conf

# DANGER: Never cat a large log file! Use less instead.
```

**`less`** - The pager (MANDATORY for logs)

```bash
less /var/log/syslog

# Inside less (these are CRITICAL):
# Navigation:
Space      # Page down
b          # Page up
g          # Go to beginning of file
G          # Go to end of file
/error     # Search forward for "error"
?error     # Search backward for "error"
n          # Next match
N          # Previous match

# Other useful commands:
v          # Open current file in editor (vi)
F          # Follow mode (like tail -f) - Ctrl+C to stop
&keyword   # Show only lines matching keyword
:1000      # Jump to line 1000
q          # Quit

# Admin pattern: view log, search for error, jump to next error
less /var/log/syslog
/ERROR
n  # keep hitting 'n' to see all errors
```

**`head` / `tail`** - View beginnings and endings

```bash
head file.txt              # First 10 lines
head -20 file.txt          # First 20 lines
head -n 5 file.txt         # First 5 lines (verbose form)

tail file.txt              # Last 10 lines
tail -50 file.txt          # Last 50 lines
tail -n 100 file.txt       # Last 100 lines

# THE MOST IMPORTANT ADMIN COMMAND:
tail -f /var/log/syslog    # FOLLOW the log in real-time (Ctrl+C to stop)

# Admin pattern: watch multiple logs at once
tail -f /var/log/{syslog,auth.log,nginx/access.log}

# See last 20 lines and then follow
tail -20 -f /var/log/syslog
```

**`touch`** - Create empty files or update timestamps

```bash
touch file.txt             # Create empty file (or update timestamp if exists)

# Admin pattern: create lock files or test files
touch /tmp/maintenance.lock
touch /etc/nginx/conf.d/test.conf

# Update file timestamp without changing content
touch existing-file.txt
```

**`mkdir`** - Make directories

```bash
mkdir newdir               # Basic
mkdir -p path/to/nested/dirs  # Create parent directories as needed
mkdir -m 755 secret-dir    # Create with specific permissions

# Admin pattern: create log directory structure
mkdir -p /var/log/myapp/{archive,backup,error}
```

### 3. Basic Text Processing (The Coreutils Trinity)

**`grep`** - Global Regular Expression Print (find text patterns)

```bash
grep "error" logfile.txt           # Basic search
grep -i "error" logfile.txt        # Case-insensitive
grep -v "debug" logfile.txt        # INVERT: show lines WITHOUT "debug"
grep -r "error" /var/log/          # Recursive search in directory
grep -A 5 "error" log.txt          # Show 5 lines AFTER match
grep -B 5 "error" log.txt          # Show 5 lines BEFORE match
grep -C 3 "error" log.txt          # Show 3 lines BEFORE AND AFTER
grep -c "error" log.txt            # Count matches (not lines with matches)
grep -l "error" *.log              # List ONLY filenames with matches
grep -n "error" log.txt            # Show line numbers
grep -E "error|warning" log.txt    # Extended regex: OR

# Real admin examples:
# Find failed SSH attempts
grep "Failed password" /var/log/auth.log

# Find IPs that failed SSH (using regex)
grep -oE '[0-9]+\.[0-9]+\.[0-9]+\.[0-9]+' /var/log/auth.log | sort -u

# Find all config files with "Listen" directive
grep -r "Listen" /etc/apache2/

# Show mysql errors with context
grep -B 5 -A 10 "ERROR" /var/log/mysql/error.log
```

**`cut`** - Extract columns/fields

```bash
cut -d: -f1 /etc/passwd           # Use : as delimiter, get field 1 (usernames)
cut -d: -f1,3 /etc/passwd         # Get fields 1 and 3
cut -d: -f1-3 /etc/passwd         # Get fields 1 through 3
cut -c1-10 file.txt               # Get characters 1-10 from each line

# Admin example: Get list of user homes from /etc/passwd
cut -d: -f6 /etc/passwd | grep -v "^$"  # Field 6 is home directory
```

**`sort`** - Sort lines

```bash
sort file.txt                     # Alphabetical sort
sort -n file.txt                  # Numeric sort
sort -h file.txt                  # Human-numeric (1K, 2M, 3G works!)
sort -r file.txt                  # Reverse order
sort -u file.txt                  # Unique (sort + remove duplicates)
sort -t: -k3 -n /etc/passwd       # Sort by field 3 (UID) numerically

# Admin example: Find top 10 IPs accessing your web server
grep "GET" /var/log/nginx/access.log | cut -d' ' -f1 | sort | uniq -c | sort -rn | head -10
```

**`uniq`** - Report or omit repeated lines (requires sorted input!)

```bash
uniq file.txt                     # Remove adjacent duplicates
uniq -c file.txt                  # Count occurrences
uniq -d file.txt                  # Show only duplicates
uniq -u file.txt                  # Show only unique lines

# Admin example: Count error types in log
grep "ERROR" app.log | cut -d: -f2 | sort | uniq -c | sort -rn
```

**`wc`** - Word count

```bash
wc -l file.txt                    # Line count (most common)
wc -w file.txt                    # Word count
wc -c file.txt                    # Byte count
wc -m file.txt                    # Character count

# Admin examples:
wc -l /var/log/syslog             # How many lines in log?
find /etc -name "*.conf" | wc -l  # Count config files
ps aux | wc -l                    # Count running processes
```

**`tee`** - Read from stdin and write to stdout AND file

```bash
command | tee output.txt          # See output AND save to file
command | tee -a output.txt       # Append to file
command | tee file1.txt file2.txt # Write to multiple files

# Admin example: Log AND watch compilation output
make 2>&1 | tee build.log

# Capture output while still seeing it
ping google.com | tee ping-output.txt
```

### 4. Redirection & Pipes (THE MOST IMPORTANT CONCEPT)

**The philosophy:** Everything in Linux is a file or a stream.

**File Descriptors:**

- `0` = stdin (standard input - usually your keyboard)
- `1` = stdout (standard output - normal program output)
- `2` = stderr (standard error - error messages)

**Output Redirection:**

```bash
# stdout redirection
command > file.txt               # Overwrite file with stdout
command >> file.txt              # Append stdout to file

# stderr redirection
command 2> error.txt             # Redirect stderr to file
command 2>> error.txt            # Append stderr to file

# Both stdout and stderr
command &> output.txt            # Redirect BOTH to file (Bash shortcut)
command > output.txt 2>&1        # Traditional way: stdout to file, then stderr to stdout

# Discard output (black hole)
command > /dev/null              # Discard stdout
command 2> /dev/null             # Discard stderr
command &> /dev/null             # Discard everything

# Real admin examples:
# Run a noisy command quietly
./compile-script.sh &> /dev/null

# Separate normal and error logs
./backup-script.sh > backup.log 2> backup-errors.log

# Check if a service is running (no output)
systemctl is-active nginx &> /dev/null && echo "Running" || echo "Stopped"
```

**Input Redirection:**

```bash
command < file.txt               # Use file as stdin
cat < file.txt                   # Same as cat file.txt (but different mechanism)

# Admin example: Count lines in file without cat
wc -l < /var/log/syslog          # More efficient than cat syslog | wc -l
```

**Pipes (`|`)** - The magic glue

```bash
command1 | command2              # stdout of cmd1 → stdin of cmd2

# Classic pipe chains
ps aux | grep nginx              # Find nginx processes
cat /var/log/syslog | grep ERROR | cut -d' ' -f1-3 | sort -u
dmesg | tail -20                 # Last 20 kernel messages

# Real admin pipeline:
# Find top 10 disk-consuming directories
du -sh /home/* 2>/dev/null | sort -rh | head -10

# Find failed SSH attempts and extract IPs
grep "Failed password" /var/log/auth.log | \
  grep -oE '[0-9]+\.[0-9]+\.[0-9]+\.[0-9]+' | \
  sort | uniq -c | sort -rn | head -10
```

**The `/dev/null` Black Hole:**

```bash
# Throw away output you don't care about
./noisy-script 2>/dev/null        # Hide errors only
./cron-job.sh > /dev/null 2>&1    # Completely silent (cron classic)

# Empty a file quickly
> /var/log/large.log              # Or: cat /dev/null > large.log

# Test if command succeeds without seeing output
grep "secret" config.txt &> /dev/null && echo "Found" || echo "Not found"
```

### 5. Process Management

**Foreground vs Background:**

```bash
# Run in foreground (default - blocks terminal)
sleep 100

# Run in background (doesn't block)
sleep 100 &
[1] 12345        # [job number] PID

# Start a process, suspend it, put in background
sleep 100
Ctrl+Z            # Suspend (pause) the process
[1]+  Stopped     # Job stops
bg                # Resume in background
jobs              # List background jobs
fg                # Bring foreground
fg %1             # Bring specific job to foreground

# Real admin: Start long-running backup in background
tar -czf backup.tar.gz /home/ &
```

**`ps`** - Process status

```bash
ps                  # Your processes only (minimal)
ps aux              # ALL processes (BSD style - very common)
ps -ef              # ALL processes (System V style)
ps auxf             # Forest view (shows parent-child)
ps -eo pid,ppid,cmd,%cpu,%mem --sort=-%cpu  # Custom format, sort by CPU

# Admin examples:
# Find a process by name
ps aux | grep nginx

# Get PID of specific process
ps -C nginx -o pid=               # -C for command name, -o for output

# Show process tree
ps -ejH | grep apache2

# Find memory hogs
ps aux --sort=-%mem | head -10
```

**`kill`** - Terminate processes

```bash
kill PID                 # Send SIGTERM (15) - graceful termination
kill -9 PID              # Send SIGKILL (9) - force kill (can't be caught)
kill -15 PID             # Same as kill PID (explicit SIGTERM)
kill -HUP PID            # SIGHUP (1) - often used to reload config
kill -INT PID            # SIGINT (2) - same as Ctrl+C
killall process-name     # Kill all processes with that name
pkill -f "pattern"       # Kill processes matching pattern

# Signal numbers you MUST know:
# 1 - SIGHUP  (hangup/reload config)
# 2 - SIGINT  (interrupt - Ctrl+C)
# 9 - SIGKILL (kill - can't be ignored)
# 15 - SIGTERM (terminate - default)

# Admin examples:
# Gracefully restart nginx (reload config without dropping connections)
kill -HUP $(cat /var/run/nginx.pid)

# Force kill all stuck apache processes
pkill -9 apache2

# Find and kill zombie processes
ps aux | awk '$8=="Z" {print $2}' | xargs kill -9
```

**`jobs`, `bg`, `fg`** - Job control

```bash
# Start three processes
sleep 300 &
sleep 400 &
sleep 500 &
jobs -l            # List jobs with PIDs
[1] 12345 Running  sleep 300 &
[2] 12346 Running  sleep 400 &
[3] 12347 Running  sleep 500 &

fg %2              # Bring job 2 to foreground
Ctrl+Z             # Suspend it
bg %2              # Resume in background

disown %1          # Remove job from shell's job list (won't die when you logout)
```

**`nohup`** - Run command immune to hangups

```bash
# Run process that continues after logout
nohup ./long-script.sh &
# Output goes to nohup.out unless redirected

nohup ./backup.sh > backup.log 2>&1 &
```
