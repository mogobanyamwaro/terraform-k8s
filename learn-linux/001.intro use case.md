# THE BEGINNER'S 18-FOLDER PROJECT

## _"Create ONE File That Visits Every Folder"_

**The Goal:** Create a text file called `my_journey.txt` that proves you visited each folder.

**Time needed:** 1-2 hours
**Skill level:** Absolute beginner (knows only `ls` and `cd`)

---

## BEFORE YOU START

```bash
# Open your Multipass Linux
# Create a place for your project
mkdir ~/my_linux_journey
cd ~/my_linux_journey

# Create your journal file
touch my_journey.txt
```

Now let's visit each folder **one by one**.

## 1. `/bin` - Essential Commands

**What it is:** Contains basic commands like `ls`, `cp`, `mv`

**What you'll do:** List what's inside, then save the list to your journal

```bash
# Go to /bin
cd /bin

# See what's inside (first 10 items)
ls | head -10

# Save the list to your journal
ls | head -10 >> ~/my_linux_journey/my_journey.txt

# Add a note about what you learned
echo "I visited /bin. It has basic commands like ls and cp." >> ~/my_linux_journey/my_journey.txt

# Go back home
cd ~
```

**What you achieved:** You proved you can navigate to `/bin` and understand it holds essential commands.

## 10. `/proc` - Live System Info

**What it is:** Virtual folder showing what's happening RIGHT NOW
`/proc` is one of the weirdest Linux folders the first time you see it, because it looks like a normal directory… but a lot of it isn’t real files on disk.

It’s a **virtual filesystem** created by the Linux kernel.

Think of it as:

**a live control panel showing what the kernel is doing right now**

It exists in memory, not as actual stored files.

---

## What it contains

`/proc` exposes system information like:

* running processes
* CPU info
* memory usage
* kernel settings
* system state

When you read a file there, Linux often generates the content on the spot.

---

## Try this

### See CPU info

```bash id="e1k9vm"
cat /proc/cpuinfo
```

You’ll see details about your processor.

That file doesn’t physically exist on disk.

The kernel creates it when requested.

---

### See memory info

```bash id="v4p8rt"
cat /proc/meminfo
```

Shows RAM stats.

---

### See uptime

```bash id="u9c2wx"
cat /proc/uptime
```

How long your system has been running.

---

## Process folders

The coolest part:

Inside `/proc`, every running process gets a folder named by its PID.

Check:

```bash id="z7h3jq"
ls /proc | grep '^[0-9]'
```

You’ll see numbers like:

```bash id="r5n1bk"
1
245
889
```

Each is a process.

---

If process `245` exists:

```bash id="f8m6zp"
ls /proc/245
```

You’ll see details about it.

---

## Inspect your current shell

Get your shell PID:

```bash id="j2w9ca"
echo $$
```

Suppose it prints:

```bash id="n3x8vt"
412
```

Now inspect it:

```bash id="w6p4yl"
cat /proc/412/status
```

This shows:

* process name
* memory use
* state
* parent process

That’s Linux exposing process internals.

---

## Why `/proc` exists

Programs use it to understand the system.

Commands like:

```bash id="m8q2rv"
ps
top
free
uptime
```

often read data from `/proc`.

So when you run:

```bash id="s5t1ky"
free -h
```

it’s basically reading from:

```bash id="d9v3oz"
/proc/meminfo
```

and formatting it nicely.

---

## Some files can change system behavior

Example:

```bash id="x4k7mf"
/proc/sys
```

Contains kernel settings.

You can sometimes modify them:

```bash id="a6z1qw"
sudo sysctl ...
```

which often writes into `/proc/sys`.

So `/proc` is not just for reading.

Some parts control Linux itself.

---

## Key difference from normal folders

| Folder  | Purpose                 |
| ------- | ----------------------- |
| `/home` | real user files         |
| `/mnt`  | mounted storage         |
| `/opt`  | optional software       |
| `/proc` | live kernel/system info |

`/proc` is more like a dashboard than storage.

## Easy memory trick

**`/proc` = “processes + kernel live data”**

It’s Linux letting you peek under the hood while the engine is running.


**What you achieved:** You read real-time system information.

## 12. `/run` - Temporary Runtime Data

**What it is:** Stuff that only exists until you reboot

`/run` is a **temporary runtime folder** in Linux.

Think of it as:

> “Stuff that must exist while the system is running, but disappears on reboot.”

---

## What `/run` is used for

It stores **live system state**, like:

* process IDs (PIDs)
* sockets (communication between programs)
* locks (to prevent duplicate processes)
* service runtime data (systemd, network, etc.)

---

## Key idea

Unlike `/usr`, `/home`, or `/etc`, nothing in `/run` is meant to be permanent.

It is:

> recreated fresh every boot

---

## Try it in WSL

### 1. Look inside `/run`

```bash id="k8m1qa"
ls /run
```

You’ll see folders like:

* `user`
* `wsl`
* `lock`
* `systemd` (sometimes)

---

### 2. Check your user runtime folder

```bash id="v9x2pn"
ls /run/user/$(id -u)
```

This is where your login session stores temporary stuff.

---

### 3. Example: PID files

Some services write process IDs here:

```bash id="m4c8zt"
/run/nginx.pid
```

This file might contain:

```bash id="q7n3vd"
1234
```

Meaning:

> “nginx is running with process ID 1234”

---

## Why `/run` exists

Before `/run`, Linux used `/var/run`.

But `/var` is supposed to be “variable persistent data”, which is not ideal for temporary boot data.

So modern Linux moved runtime data to:

```bash id="u2p9lx"
/run
```

---

## Compare quickly

| Folder | Purpose                                        |
| ------ | ---------------------------------------------- |
| `/etc` | configuration (static settings)                |
| `/var` | persistent changing data (logs, databases)     |
| `/run` | temporary runtime state (disappears on reboot) |
| `/tmp` | temporary user files                           |

---

## `/run` vs `/tmp` (important)

### `/run`

* system-managed
* cleaned at boot
* used by services
* contains critical runtime state

### `/tmp`

* user + apps temp files
* also often cleared on reboot
* less strict structure

---

## Easy mental model

Think:

* `/etc` → instructions (blueprints)
* `/usr` → installed software
* `/home` → your stuff
* `/run` → “what is happening right now”

---

## One-line memory trick

**`/run` = live system memory on disk (but temporary)**

It’s Linux’s “now state” folder.


**What you achieved:** You understand temporary vs permanent storage.
