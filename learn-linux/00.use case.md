## `/bin` - Essential User Commands

### 🔴 USE CASE: "Binary not found" after PATH corruption

**Scenario:** Your monitoring alert says `curl: command not found` but curl was installed yesterday.

**What happened:** Someone did `export PATH=/custom/bin` instead of `PATH=$PATH:/custom/bin`, wiping your system PATH.

**SRE investigation:**

```bash
# Check if binary actually exists
ls -la /bin/curl
# -> -rwxr-xr-x 1 root root ... /bin/curl

# Check your PATH
echo $PATH
# -> /custom/bin (missing /bin!)

# Fix - but curl command still won't run!
# Because your shell caches command locations:
hash -r

# Now curl works. But why?
which curl
# -> /bin/curl
```

**Real lesson:** `/bin` is in `$PATH` by default. When commands vanish, check:

1. PATH variable (env)
2. Shell hash table (`hash` command)
3. File permissions (`ls -l /bin/curl`)

### 🔴 USE CASE: Container has no shell

**Scenario:** Distroless container crashes. You need to debug but there's no `/bin/bash`, `/bin/sh`, or `ls`.

**SRE investigation:**

```bash
# Attach with different entrypoint
kubectl debug my-pod -it --image=busybox --target=my-container

# Or copy binary from host
kubectl cp /bin/busybox my-pod:/tmp/busybox
kubectl exec my-pod -- /tmp/busybox ls -la
```

**Real lesson:** `/bin` contains **statically compiled** binaries (no libraries needed). Busybox fits here.

### 🔴 USE CASE: Someone replaced `/bin/ps` with a trojan

**Scenario:** Your security scan shows `/bin/ps` has wrong checksum.

**SRE investigation:**

```bash
# Check inode number (should match package manager)
ls -li /bin/ps
stat /bin/ps

# Verify against package database
dpkg -S /bin/ps
# -> procps: /bin/ps

# Reinstall from trusted source
sudo apt install --reinstall procps

# Compare with backup from /var/backups
diff /bin/ps /var/backups/bin_ps.bak
```

**Real lesson:** `/bin` is read-only except during updates. Any unauthorized change = IMMEDIATE incident.

## `/boot` - Startup Essentials

### 🔴 USE CASE: "No space left on device" but disk is empty

**Scenario:** `df -h` shows `/boot` at 100%. Can't install security updates.

**SRE investigation:**

```bash
# See what's eating /boot
ls -lh /boot
# -> vmlinuz-5.4.0-26-generic (8M)
# -> vmlinuz-5.4.0-28-generic (8M)
# -> vmlinuz-5.4.0-29-generic (8M)
# -> vmlinuz-5.4.0-30-generic (8M)
# 20 old kernels!

# Remove old kernels safely
sudo apt autoremove --purge
# Or manually:
sudo dpkg --list | grep linux-image
sudo apt purge linux-image-5.4.0-26-generic
```

**Real lesson:** `/boot` is small (500MB-1GB). Each kernel is ~10MB. Old kernels accumulate. **Always keep 2-3 kernels max.**

### 🔴 USE CASE: Server won't boot after kernel update

**Scenario:** You did `apt upgrade`, rebooted, now server stuck at GRUB.

**SRE recovery (out-of-band):**

```bash
# At GRUB menu:
# Press 'e' to edit boot entry
# Find line starting with "linux"
# Change:
linux /boot/vmlinuz-5.4.0-42-generic ...
# To older version:
linux /boot/vmlinuz-5.4.0-26-generic ...

# Press Ctrl+X to boot
# Once booted, remove bad kernel:
sudo apt purge linux-image-5.4.0-42-generic
sudo update-grub
```

**Real lesson:** `/boot` is your **emergency exit**. Always keep a known-good kernel. Test updates on staging first.

### 🔴 USE CASE: GRUB corrupted after disk resize

**Scenario:** You resized a cloud VM disk. Now server boots to `grub rescue>`.

**SRE recovery:**

```bash
# At grub rescue> prompt:
ls  # Find your boot partition (hd0,msdos1)
set prefix=(hd0,msdos1)/boot/grub
set root=(hd0,msdos1)
insmod normal
normal

# Once booted, reinstall GRUB:
sudo grub-install /dev/sda
sudo update-grub
```

**Real lesson:** `/boot/grub/grub.cfg` is your boot menu. Never edit manually unless disaster.

## `/dev` - Hardware as Files

### 🔴 USE CASE: Disk is missing from `df -h` but still mounted

**Scenario:** Alert says `/dev/sdb` I/O errors. Container can't write logs.

**SRE investigation:**

```bash
# Check if device still exists
ls -la /dev/sdb
# -> brw-rw---- 1 root disk 8, 16 Dec 9 10:30 /dev/sdb
#    ^ 'b' means block device

# Check mount status
cat /proc/mounts | grep sdb
# -> /dev/sdb /data ext4 rw,relatime 0 0

# But I/O errors? Check kernel ring buffer
dmesg | tail -20
# -> [12345.678] buffer I/O error on dev sdb, logical block 1234

# The disk is failing. Remount read-only immediately:
sudo mount -o remount,ro /data
```

**Real lesson:** `/dev` entries are **device interfaces**. No /dev/sdb = no disk. But having it doesn't mean disk works.

### 🔴 USE CASE: Application can't get random numbers

**Scenario:** Your crypto service hangs. SSL handshake never completes.

**SRE investigation:**

```bash
# Check random device
ls -la /dev/random /dev/urandom
# -> crw-rw-rw- 1 root root 1, 8 /dev/random
# -> crw-rw-rw- 1 root root 1, 9 /dev/urandom

# Test random availability
dd if=/dev/random of=/dev/null bs=1 count=10
# HANGS! Not enough entropy.

# Check entropy available
cat /proc/sys/kernel/random/entropy_avail
# -> 0 (bad!)

# Install haveged to generate entropy
sudo apt install haveged
sudo systemctl start haveged

# Now check again
cat /proc/sys/kernel/random/entropy_avail
# -> 4096 (good!)
```

**Real lesson:** `/dev/random` blocks when low entropy. `/dev/urandom` never blocks (but weaker). Cloud VMs often have low entropy.

### 🔴 USE CASE: Finding which disk is using 100% IO

**Scenario:** System slow. `iostat` shows device at 100% but you don't know which physical disk.

**SRE investigation:**

```bash
# Get major:minor numbers
ls -l /dev/sd*
# -> brw-rw---- 1 root disk 8, 0 /dev/sda
# -> brw-rw---- 1 root disk 8, 16 /dev/sdb
#                      ^  ^
#                    major minor

# Check IO stats for each
cat /sys/block/sda/stat
cat /sys/block/sdb/stat
# Field 4 = IO time (milliseconds)
# Higher number = more IO wait

# Real-time monitoring:
watch -n1 'cat /sys/block/sd*/stat | awk '\''{print "Device: " FILENAME " IO time: " $4}'\'
```

**Real lesson:** `/dev` + `/sys/block` = IO forensics. Don't rely only on `iostat`.

## `/etc` - System Control Panel

### 🔴 USE CASE: Can't SSH after someone edited config

**Scenario:** You get paged: "SSH broken". You're remotely connected (thankfully still open).

**SRE investigation:**

```bash
# Check if SSH config is valid
sudo sshd -t
# -> /etc/ssh/sshd_config line 42: Bad configuration option: PermitRootLogin no

# Fix the typo
sudo sed -i 's/PermitRootLogin no/PermitRootLogin yes/' /etc/ssh/sshd_config

# Test again
sudo sshd -t
# -> echo $? (0 means success)

# Reload without killing connections
sudo systemctl reload sshd
```

**Real lesson:** `/etc/ssh/sshd_config` - always run `sshd -t` before reloading. Saved your ass.

### 🔴 USE CASE: DNS resolution failing only inside containers

**Scenario:** `curl google.com` fails inside Docker but works on host.

**SRE investigation:**

```bash
# Check host DNS config
cat /etc/resolv.conf
# -> nameserver 8.8.8.8
# -> nameserver 1.1.1.1

# Check container DNS
docker run ubuntu cat /etc/resolv.conf
# -> nameserver 127.0.0.53 (systemd-resolved stub)

# The problem: systemd-resolved uses /run/systemd/resolve/stub-resolv.conf
# But Docker uses /etc/resolv.conf directly

# Fix: Make /etc/resolv.conf a symlink
sudo ln -sf /run/systemd/resolve/resolv.conf /etc/resolv.conf
# Restart Docker
sudo systemctl restart docker
```

**Real lesson:** `/etc/resolv.conf` can be a symlink. Know your distribution's DNS architecture.

### 🔴 USE CASE: User deleted but processes still running

**Scenario:** HR says "Bob left, delete his account". You did `userdel bob`. But Bob's processes still run.

**SRE investigation:**

```bash
# Check if user still has running processes
ps -u bob
# -> PID 12345  /usr/bin/python3 app.py

# Check /etc/passwd (user is gone)
grep bob /etc/passwd
# (empty)

# How? The process was started before deletion.
# Find processes by UID (numeric)
ps -u $(id -u bob)  # fails - user doesn't exist

# Find preserved UID
grep "bob" /etc/passwd-
# -> bob:x:1001:1001:Bob,,,:/home/bob:/bin/bash
# UID was 1001

# Kill processes by UID
sudo pkill -u 1001
```

**Real lesson:** `/etc/passwd` is a file. Deletion doesn't kill processes. Always check `/etc/passwd-` (backup) for old UIDs.

### 🔴 USE CASE: Cron jobs not running

**Scenario:** Your backup script worked for months, now stopped.

**SRE investigation:**

```bash
# Check system crontab
cat /etc/crontab
# -> 0 2 * * * root /usr/local/bin/backup.sh

# Check user crontabs
ls -la /etc/cron.d/
cat /etc/cron.d/backup

# Check cron logs
grep CRON /var/log/syslog | tail -20
# -> (CRON) INFO (Running @reboot jobs)

# Found it: script can't find config
# Add to crontab:
# SHELL=/bin/bash
# PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
```

**Real lesson:** Cron has minimal PATH (usually just `/usr/bin:/bin`). Always set PATH in crontab.

## `/home` - User Private Desks

### 🔴 USE CASE: Disk quota exceeded but user says "I deleted files"

**Scenario:** User Alice can't save files. `df -h` shows 0% free on `/home`.

**SRE investigation:**

```bash
# Check what Alice has
sudo du -sh /home/alice/*
# -> 50G /home/alice/.local/share/Trash (deleted files!)
# -> 30G /home/alice/.cache

# User deleted but files went to Trash
# Empty trash properly:
sudo rm -rf /home/alice/.local/share/Trash/*

# Set quota to prevent future issues
sudo apt install quota
sudo setquota -u alice 10G 12G 0 0 /home
```

**Real lesson:** `/home/alice/.local/share/Trash` - "deleted" isn't gone until you empty trash.

### 🔴 USE CASE: SSH key permissions prevent login

**Scenario:** Developer can't push to Git server. "Permission denied (publickey)".

**SRE investigation:**

```bash
# Check SSH key permissions on server
ls -la /home/git/.ssh/
# -> -rw-r--r-- 1 git git 400 authorized_keys (MODE IS WRONG!)

# SSH requires:
# .ssh directory: 700
# authorized_keys: 600
# Private keys: 600

# Fix:
sudo chmod 700 /home/git/.ssh
sudo chmod 600 /home/git/.ssh/authorized_keys

# Also check ownership
sudo chown -R git:git /home/git/.ssh
```

**Real lesson:** `/home/user/.ssh` permissions are **security-critical**. SSH refuses too-open permissions.

### 🔴 USE CASE: Find large files owned by departed user

**Scenario:** Disk filling up. You suspect Bob's leftover files (account deleted last month).

**SRE investigation:**

```bash
# Find all files owned by UID 1001 (Bob)
sudo find / -user 1001 -type f -size +100M -exec ls -lh {} \;

# Found: /backup/bobs_project.tar.gz (50GB)
sudo rm /backup/bobs_project.tar.gz

# Also check /tmp
sudo find /tmp -user 1001 -delete

# Better: Use aged flag
sudo find /home -user 1001 -mtime +90 -delete
```

**Real lesson:** Deleting `/etc/passwd` entry doesn't delete files. Always `userdel -r` to remove home directory.

## `/lib` - Shared Code Library

### 🔴 USE CASE: "Command not found" but binary exists

**Scenario:** `/usr/local/bin/myapp` exists but won't run. Error: "error while loading shared libraries".

**SRE investigation:**

```bash
# Check library dependencies
ldd /usr/local/bin/myapp
# -> libmysqlclient.so.20 => not found

# Find where it should be
sudo find / -name "libmysqlclient.so*" 2>/dev/null
# -> /usr/lib/x86_64-linux-gnu/libmysqlclient.so.21 (version mismatch!)

# Create symlink (emergency fix)
sudo ln -s /usr/lib/x86_64-linux-gnu/libmysqlclient.so.21 \
           /usr/lib/x86_64-linux-gnu/libmysqlclient.so.20

# Or set library path
export LD_LIBRARY_PATH=/usr/lib/x86_64-linux-gnu:$LD_LIBRARY_PATH
./myapp
```

**Real lesson:** `/lib` and `/usr/lib` contain **.so files** (Shared Objects = Linux DLLs). Missing or mismatched = binary won't run.

### 🔴 USE CASE: After glibc upgrade, everything crashes

**Scenario:** You updated glibc. Now `ls`, `bash`, everything segfaults.

**SRE emergency recovery:**

```bash
# Even bash is broken! Use busybox (statically compiled)
busybox sh

# Check glibc version
busybox ls -l /lib/x86_64-linux-gnu/libc.so.6
# -> libc.so.6 -> libc-2.31.so (new)

# Revert to backup (if you have it)
busybox cp /var/backups/libc-2.30.so /lib/x86_64-linux-gnu/libc.so.6

# Better: Use LD_PRELOAD to force old version
export LD_PRELOAD=/var/backups/libc-2.30.so
```

**Real lesson:** NEVER upgrade glibc without a rollback plan. Statically compiled binaries (busybox) are your lifeline.

### 🔴 USE CASE: Python can't find module after pip install

**Scenario:** `pip install requests` succeeded but `python -c "import requests"` fails.

**SRE investigation:**

```bash
# Check where pip installed
pip show requests
# -> Location: /home/user/.local/lib/python3.8/site-packages

# Where Python looks
python3 -c "import sys; print(sys.path)"
# -> ['', '/usr/lib/python38.zip', ...]

# Missing /home/user/.local/lib!
# Python user site-packages is disabled
export PYTHONPATH=/home/user/.local/lib/python3.8/site-packages:$PYTHONPATH

# Or enable permanently
python3 -m site --user-site
mkdir -p ~/.local/lib/python3.8/site-packages
echo 'import site; site.addsitedir("~/.local/lib/python3.8/site-packages")' > ~/.pythonrc
```

**Real lesson:** Python's library path is complex. Use `sys.path` to debug import failures.

## `/proc` - Live Kernel & Process Snapshot

### 🔴 USE CASE: Find why process is using 100% CPU

**Scenario:** Load average >10. Find the culprit.

**SRE investigation:**

```bash
# Check top CPU consumers
cat /proc/loadavg
# -> 12.5 8.2 4.1 (1,5,15 minute averages)

# Find high CPU PIDs
for pid in /proc/[0-9]*; do
  echo -n "$(basename $pid): "
  grep -E '^(pid|comm|cpu)' $pid/stat 2>/dev/null | tr '\n' ' '
  echo
done | sort -rn -k2 | head -5

# Check specific process
cat /proc/12345/stat
# -> 12345 (myapp) R 1234 ... 3300 ...
#     ^ State 'R' = Running (CPU-bound)

# Check thread count
ls /proc/12345/task/ | wc -l
# -> 50 threads (high)

# Check which system call it's making
sudo strace -p 12345 -c
```

**Real lesson:** `/proc/PID/stat` field 3 = process state (R=running, S=sleeping, D=uninterruptible sleep - BAD).

### 🔴 USE CASE: Process is stuck in "D" state (uninterruptible sleep)

**Scenario:** `ps aux` shows process with `D` state. Can't kill it with `-9`.

**SRE investigation:**

```bash
# Confirm state
cat /proc/12345/stat | awk '{print $3}'
# -> D (disk sleep)

# Check what it's waiting on
cat /proc/12345/stack
# -> [<0>] wait_on_page_bit+0x...
# -> Waiting on NFS I/O

# Check if NFS server is responding
mount | grep nfs
# -> nfs-server:/export on /mnt/nfs

# Find the hung mount
lsof /mnt/nfs 2>/dev/null

# Only recovery: remount or reboot
sudo umount -f /mnt/nfs
# If that fails, lazy umount:
sudo umount -l /mnt/nfs
```

**Real lesson:** D state = waiting for I/O (usually NFS, FUSE, slow disk). Can't kill because kernel is waiting for hardware.

### 🔴 USE CASE: Containerized app can't see host's `/proc`

**Scenario:** Your monitoring agent runs in container and needs host process info.

**SRE solution:**

```bash
# Mount host /proc as read-only in container
docker run -v /proc:/host/proc:ro my-monitor

# In container, access via /host/proc
ls -la /host/proc/1/

# For Kubernetes
spec:
  containers:
  - name: monitor
    volumeMounts:
    - name: proc
      mountPath: /host/proc
      readOnly: true
  volumes:
  - name: proc
    hostPath:
      path: /proc
```

**Real lesson:** `/proc` is host-specific. Containers have their own fake `/proc` unless you mount host's.

## `/sys` - Kernel Tuning Interface

### 🔴 USE CASE: Network connection drops randomly

**Scenario:** TCP connections reset every few minutes. Application retries but fails.

**SRE investigation:**

```bash
# Check TCP keepalive settings
cat /proc/sys/net/ipv4/tcp_keepalive_time
# -> 7200 (2 hours - default)

# Check connection tracking table (NAT/firewall)
cat /proc/sys/net/netfilter/nf_conntrack_max
cat /sys/module/nf_conntrack/parameters/hashsize

# View current connections
cat /proc/net/nf_conntrack | wc -l

# If table is full, increase it
sudo sysctl -w net.netfilter.nf_conntrack_max=524288
echo "net.netfilter.nf_conntrack_max=524288" | sudo tee -a /etc/sysctl.conf
```

**Real lesson:** `/sys/module/*/parameters` = kernel module settings. `/proc/sys/net/*` = network tuning.

### 🔴 USE CASE: Disk I/O is slow - change scheduler

**Scenario:** SSD performing like HDD. Check I/O scheduler.

**SRE investigation:**

```bash
# Check current scheduler
cat /sys/block/sda/queue/scheduler
# -> noop [mq-deadline] cfq
#     ^ Current scheduler

# For SSD, 'none' or 'noop' is best
echo 'none' | sudo tee /sys/block/sda/queue/scheduler

# Make permanent via udev
sudo tee /etc/udev/rules.d/60-ssd-scheduler.rules << 'EOF'
ACTION=="add|change", KERNEL=="sd*[!0-9]", ATTR{queue/rotational}=="0", ATTR{queue/scheduler}="none"
EOF
```

**Real lesson:** `/sys/block/*/queue/scheduler` - change I/O scheduler without reboot. SSDs need different tuning than HDDs.

### 🔴 USE CASE: Find why system won't sleep/power off

**Scenario:** `systemctl suspend` returns but system stays on.

**SRE investigation:**

```bash
# Check available sleep states
cat /sys/power/state
# -> freeze mem disk (mem = suspend to RAM)

# Check blockers
cat /sys/power/wakeup_count
cat /proc/acpi/wakeup

# See what's preventing sleep
grep -r . /sys/power/*/ 2>/dev/null

# Force to mem
echo mem > /sys/power/state

# Check USB devices that might wake
ls /sys/bus/usb/devices/*/power/wakeup
# Set to disabled
echo disabled > /sys/bus/usb/devices/usb1/power/wakeup
```

**Real lesson:** `/sys/power/state` = write to change power state. `/proc/acpi/wakeup` = what can wake system.

## `/var` - Variable Data

### 🔴 USE CASE: Logs stopped rotating, disk full

**Scenario:** `/var` at 95%. `journald` using 50GB.

**SRE investigation:**

```bash
# Check log sizes
du -sh /var/log/*
# -> 45G /var/log/journal

# Check journal limits
sudo journalctl --disk-usage
# -> Archived and active journals take up 45G

# Rotate and vacuum
sudo journalctl --vacuum-size=2G
sudo journalctl --vacuum-time=7d

# Set permanent limits in /etc/systemd/journald.conf:
# SystemMaxUse=2G
# MaxRetentionSec=7day

# Reload
sudo systemctl restart systemd-journald
```

**Real lesson:** `/var/log/journal` grows forever. Always set max size.

### 🔴 USE CASE: Mail queue backing up (postfix)

**Scenario:** Application sending emails failing. `/var` filling with deferred mail.

**SRE investigation:**

```bash
# Check mail queue
mailq
# -> 5000 messages in queue

# Check why
tail -f /var/log/mail.log
# -> "Connection timed out" to SMTP server

# Flush queue after fixing
sudo postqueue -f

# Delete stuck emails
sudo postsuper -d ALL deferred

# Check spool location
ls -la /var/spool/postfix/
```

**Real lesson:** `/var/spool` = queues for mail, print, cron. If queue fills, service stops.

### 🔴 USE CASE: Package cache consuming space

**Scenario:** `apt` downloads fill `/var/cache/apt/archives`.

**SRE cleanup:**

```bash
# Check cache size
du -sh /var/cache/apt/archives
# -> 15G

# Clean old packages
sudo apt clean
# Removes ALL .deb files

# Or more selective:
sudo apt autoclean
# Removes only outdated

# Set automatic cleanup in /etc/apt/apt.conf.d/02periodic:
APT::Periodic::Clean-Packages "1";
```

**Real lesson:** `/var/cache` holds downloaded packages. Clean regularly on CI/build servers.

## The Other Critical Folders

### `/tmp` - World-Writable Scratch

**Use case:** Attacker fills `/tmp` with files. `noexec` mount prevents exploit.

```bash
# Secure /tmp in /etc/fstab:
tmpfs /tmp tmpfs nosuid,nodev,noexec,size=2G 0 0
```

### `/run` - Runtime State

**Use case:** Container runtime socket missing.

```bash
# Docker socket is here:
ls -la /run/docker.sock
# Permission denied? User not in docker group
```

### `/srv` - Service Data

**Use case:** Move website from `/var/www` to `/srv/www` for backup isolation.

```bash
# Different backup policies per directory
rsync -av /var/www/ /srv/www/
# Now /var gets daily backups, /srv gets weekly
```

### `/opt` - Third-Party Apps

**Use case:** Install Kafka manually.

```bash
# FHS structure:
/opt/kafka/
  bin/
  config/
  logs/
  data/
# Not in /usr (OS managed) or /home (user)
```

### `/media` vs `/mnt`

**Use case:** Automated backup to USB.

```bash
# /media = non-persistent, auto-mounted
# /mnt = persistent, manual mount
# Best: Auto-mount to /media, then bind to /mnt/backup
mount --bind /media/usb-drive /mnt/backup
```
