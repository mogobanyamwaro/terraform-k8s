# 28. Disks And Partitions

**Objectives:** List, create, and delete partitions on MBR and GPT disks.

Storage is the heaviest-weighted domain on the exam, and it is also where a mistake is most expensive: a wrong partition table wipes data, and a bad `/etc/fstab` entry stops the machine booting. **Work carefully and confirm the device name before every destructive command.**

## Concept Refresher

### The storage stack

```text
   ┌─────────────────────────────────────────────────┐
   │  /data          mount point                     │  ← 30.md
   ├─────────────────────────────────────────────────┤
   │  XFS / ext4     filesystem                      │  ← 30.md
   ├─────────────────────────────────────────────────┤
   │  /dev/vg01/lv01 logical volume    (optional)    │  ← 29.md
   │  /dev/vg01      volume group                    │
   │  /dev/sdb1      physical volume                 │
   ├─────────────────────────────────────────────────┤
   │  /dev/sdb1      PARTITION                       │  ← THIS FILE
   │  /dev/sdb       DISK                            │
   └─────────────────────────────────────────────────┘
```

Every storage task walks up this stack. **This file covers the bottom two layers only** — creating the partition. Making a filesystem on it and mounting it is `30.md`; using it for LVM is `29.md`.

### Device names

| Name | Meaning |
| --- | --- |
| `/dev/sda`, `/dev/sdb` | SCSI/SATA/USB disks |
| `/dev/sda1`, `/dev/sda2` | **Partitions** on `sda` |
| `/dev/vda`, `/dev/vdb` | virtio disks (KVM guests) |
| `/dev/nvme0n1` | NVMe disk |
| **`/dev/nvme0n1p1`** | **Partition 1 on that NVMe disk** — note the `p` |
| `/dev/mapper/vg-lv` | LVM logical volume |
| `/dev/sr0` | Optical drive |

**NVMe and loop devices insert a `p` before the partition number.** `/dev/nvme0n1p1`, not `/dev/nvme0n11`.

### Inspecting what you have

```bash
lsblk                              # the tree. Start here, always
lsblk -f                           # plus filesystem type, LABEL, UUID, mountpoint
lsblk -o NAME,SIZE,TYPE,FSTYPE,MOUNTPOINT,UUID
sudo fdisk -l                      # all disks and their partition tables
sudo fdisk -l /dev/sdb
sudo parted -l
sudo parted /dev/sdb print
blkid                              # UUIDs and types of everything formatted
sudo blkid /dev/sdb1
cat /proc/partitions
df -hT                             # mounted filesystems and usage
sudo sfdisk -l /dev/sdb
```

```text
$ lsblk
NAME          MAJ:MIN RM  SIZE RO TYPE MOUNTPOINTS
sda             8:0     0   20G  0 disk
├─sda1          8:1     0    1G  0 part /boot
└─sda2          8:2     0   19G  0 part
  ├─rhel-root 253:0     0   17G  0 lvm  /
  └─rhel-swap 253:1     0    2G  0 lvm  [SWAP]
sdb             8:16    0    2G  0 disk
sdc             8:32    0    2G  0 disk
```

**`lsblk` is the first command of every storage task.** It shows which disks are unused (`sdb`, `sdc` above — no children, no mountpoints), which is how you identify the spare disk a task wants you to use.

**Never assume a device name.** `lsblk` first, every time. Partitioning the wrong disk destroys the system.

### MBR versus GPT

| | **MBR** (msdos) | **GPT** |
| --- | --- | --- |
| Max disk size | **2 TiB** | 8 ZiB |
| Max primary partitions | **4** | **128** |
| Extended/logical partitions | Needed beyond 4 | **Not needed** |
| Partition table copies | One | **Two: start and end** |
| Checksums | No | **Yes** |
| Firmware | BIOS | UEFI (and BIOS with a bios_grub partition) |
| Tool | `fdisk`, `parted` | **`gdisk`, `parted`, `fdisk`** |

```bash
sudo parted /dev/sdb print | grep 'Partition Table'
sudo fdisk -l /dev/sdb | grep -i 'disklabel type'
sudo gdisk -l /dev/sdb 2>/dev/null | grep -i 'partition table'
```

```text
Partition Table: gpt
```

**GPT is the modern default and has no four-partition limit.** Use GPT unless a task specifically says MBR. Modern `fdisk` handles both.

The MBR primary/extended/logical arrangement only matters if a task says MBR and asks for more than four partitions:

```text
   MBR disk with more than 4 partitions:
   sda1  primary
   sda2  primary
   sda3  primary
   sda4  EXTENDED  ── container, holds no data itself
         ├─ sda5   logical
         ├─ sda6   logical
         └─ sda7   logical
```

**Logical partition numbering starts at 5**, always, even if fewer than four primaries exist.

### fdisk

Interactive, and the tool most people use. It works on both MBR and GPT.

```bash
sudo fdisk /dev/sdb
```

| Key | Action |
| --- | --- |
| **`m`** | **Help. Use it whenever you are unsure** |
| `p` | Print the current table |
| **`n`** | **New partition** |
| **`d`** | **Delete a partition** |
| **`t`** | **Change the partition type** |
| `l` | List type codes |
| `i` | Information about a partition |
| `g` | **Create a new empty GPT table** |
| `o` | Create a new empty MBR (DOS) table |
| `F` | Show free space |
| `v` | Verify the table |
| **`w`** | **WRITE the table and exit** |
| **`q`** | **Quit WITHOUT saving — your escape hatch** |

**Nothing is written until you press `w`. `q` discards everything.** If you make a mistake mid-session, press `q` and start again. This makes `fdisk` far safer than it looks.

A complete session creating a 1 GiB partition:

```text
$ sudo fdisk /dev/sdb

Welcome to fdisk (util-linux 2.37.4).
Changes will remain in memory only, until you decide to write them.

Command (m for help): n
Partition number (1-128, default 1): <Enter>
First sector (2048-4194303, default 2048): <Enter>
Last sector, +/-sectors or +/-size{K,M,G,T,P} (2048-4194303, default 4194303): +1G

Created a new partition 1 of type 'Linux filesystem' and of size 1 GiB.

Command (m for help): p
Device     Start     End Sectors Size Type
/dev/sdb1   2048 2099199 2097152   1G Linux filesystem

Command (m for help): w
The partition table has been altered.
Calling ioctl() to re-read partition table.
Syncing disks.
```

**Accept the defaults for the first sector — always.** `fdisk` picks a correctly aligned start. Typing your own number risks misalignment and poor performance.

**Specify the size as `+1G`, not an end sector.** Sector arithmetic is a needless source of error.

### Partition type codes

```bash
sudo fdisk /dev/sdb
Command: t
Partition type or alias: L        # list them
```

The ones that matter:

| Type | GPT alias | MBR hex |
| --- | --- | --- |
| Linux filesystem | `20` / `linux` | `83` |
| **Linux swap** | **`19` / `swap`** | **`82`** |
| **Linux LVM** | **`31` / `lvm`** | **`8e`** |
| Linux RAID | `29` | `fd` |
| EFI System | `1` | `ef` |

```text
Command (m for help): t
Selected partition 1
Partition type or alias (type L to list all): swap
Changed type of partition 'Linux filesystem' to 'Linux swap'.
```

**Set type `swap` (82/19) for swap partitions and `lvm` (8e/31) for LVM physical volumes.** Neither is strictly required by the kernel — `mkswap` and `pvcreate` work regardless — but a task that says "create a partition of type Linux LVM" is checking it, and it documents intent for the next administrator.

You can also use the numeric alias or hex code:

```text
Partition type or alias (type L to list all): 19        # GPT swap
Partition type or alias (type L to list all): 82        # MBR swap
```

### parted

Non-interactive, scriptable, and **applies changes immediately with no confirmation step**.

```bash
sudo parted /dev/sdb print
sudo parted /dev/sdb print free
sudo parted /dev/sdb unit MiB print

# Create a label (partition table) — DESTROYS existing partitions
sudo parted /dev/sdb mklabel gpt
sudo parted /dev/sdb mklabel msdos

# Create partitions
sudo parted /dev/sdb mkpart primary xfs 1MiB 1025MiB
sudo parted /dev/sdb mkpart data xfs 1MiB 1GiB
sudo parted /dev/sdb mkpart primary linux-swap 1025MiB 1537MiB

# Flags
sudo parted /dev/sdb set 1 lvm on
sudo parted /dev/sdb set 1 boot on

# Delete
sudo parted /dev/sdb rm 1

# Resize a partition
sudo parted /dev/sdb resizepart 1 2GiB
```

Interactive mode:

```bash
sudo parted /dev/sdb
(parted) print
(parted) mkpart primary xfs 1MiB 1025MiB
(parted) quit
```

**`parted` has no `w` and no `q`-to-abort. Every command takes effect at once.** That makes it faster for scripting and considerably more dangerous by hand.

| | `fdisk` | `parted` |
| --- | --- | --- |
| Interface | Interactive | **Command-line or interactive** |
| Confirmation | **`w` to write, `q` to abort** | **None — immediate** |
| Size input | **`+1G` from the current point** | **Absolute start and end offsets** |
| Scriptable | Awkwardly | **Yes** |
| Recommended for the exam | **Yes** | For resizing |

**Use `fdisk` on the exam.** The `q` escape hatch is worth a great deal under time pressure. Use `parted` for `resizepart`, which `fdisk` cannot do safely.

Note `parted` offsets are absolute and it starts at `1MiB` for alignment:

```bash
sudo parted /dev/sdb mkpart primary xfs 1MiB 1025MiB    # a 1024 MiB partition
```

Getting the arithmetic wrong produces overlapping or misaligned partitions, and `parted` warns but proceeds. Another reason to prefer `fdisk`.

### gdisk

`fdisk` for GPT specifically. The keystrokes are nearly identical.

```bash
sudo gdisk /dev/sdb
```

| Key | Action |
| --- | --- |
| `p` | Print the table |
| `n` | New partition |
| `d` | Delete |
| `t` | Change type (GPT codes: `8300` Linux, `8200` swap, `8e00` LVM) |
| `i` | Partition information |
| `v` | Verify |
| **`w`** | Write and exit |
| `q` | Quit without saving |
| `r` | Recovery and transformation menu |

```bash
sudo sgdisk -p /dev/sdb                                    # print
sudo sgdisk -n 1:0:+1G -t 1:8e00 /dev/sdb                  # scripted
sudo sgdisk --zap-all /dev/sdb                             # wipe both GPT copies
```

**`sgdisk --zap-all` is the cleanest way to start a disk from scratch**, because it removes both GPT copies and any MBR remnant. Handy when a disk has stale metadata from a previous exercise.

**`fdisk` handles GPT perfectly well on RHEL 9 and 10, so `gdisk` is optional.** Know it exists; use `fdisk`.

### Making the kernel see the change

```bash
sudo partprobe /dev/sdb
sudo partprobe                    # all disks
sudo partx -u /dev/sdb
sudo udevadm settle
lsblk
```

**`fdisk w` normally re-reads the table automatically.** But if the disk has any partition in use — mounted, swapped on, or an active PV — the kernel refuses and you get:

```text
Re-reading the partition table failed.: Device or resource busy
The kernel still uses the old table. The new table will be used at the next
reboot or after you run partprobe(8) or partx(8).
```

Then:

```bash
sudo partprobe /dev/sdb
lsblk /dev/sdb                    # is the new partition visible now?
ls -l /dev/sdb*
```

**Always confirm with `lsblk` that `/dev/sdbN` exists before you try to `mkfs` it.** "No such file or directory" from `mkfs` almost always means the kernel has not picked up the new table.

If `partprobe` also fails because a partition is genuinely in use, unmount it, or reboot.

### Wiping a disk

```bash
sudo wipefs -a /dev/sdb1                # remove filesystem signatures
sudo wipefs -a /dev/sdb                 # remove the partition table too
sudo wipefs /dev/sdb                    # LIST signatures without removing
sudo sgdisk --zap-all /dev/sdb
sudo dd if=/dev/zero of=/dev/sdb bs=1M count=10
```

**`wipefs` without `-a` only lists**, which is the safe way to check what is on a device before destroying it:

```bash
sudo wipefs /dev/sdb
```

```text
DEVICE OFFSET TYPE UUID                                 LABEL
sdb    0x200  gpt
sdb    0x1fffffe00 gpt
```

Stale signatures cause real confusion — `mkfs` warns "found existing xfs signature" and `blkid` reports the wrong type. `wipefs -a` clears them.

### The standard end-to-end workflow

```bash
# 1. Identify the disk
lsblk

# 2. Partition it
sudo fdisk /dev/sdb
#   n, Enter, Enter, +1G, t, <type>, w

# 3. Make sure the kernel sees it
sudo partprobe /dev/sdb
lsblk /dev/sdb

# 4. Filesystem (see 30.md)
sudo mkfs.xfs /dev/sdb1

# 5. Mount point and mount
sudo mkdir -p /data
sudo mount /dev/sdb1 /data

# 6. Persist it (see 30.md) — THE STEP THAT SCORES
sudo blkid /dev/sdb1
echo 'UUID=... /data xfs defaults 0 0' | sudo tee -a /etc/fstab
sudo findmnt --verify
sudo mount -a
```

**Steps 1 to 3 are this file. Steps 4 to 6 are `30.md`, and step 6 is where the marks are.** A partition with no `/etc/fstab` entry scores nothing.

### Safety rules

1. **`lsblk` before every destructive command.** Confirm you have the right disk.
2. **The system disk is usually `/dev/sda` or `/dev/vda` and holds `/`, `/boot`, and swap.** Never touch it unless a task explicitly says to.
3. **In `fdisk`, `q` aborts.** Use it freely if unsure.
4. **`parted` acts immediately.** Prefer `fdisk`.
5. **Check for mounts before deleting a partition**: `lsblk`, `findmnt`, `swapon --show`.
6. **After any partition change, `partprobe` and `lsblk`.**
7. **Remove the `/etc/fstab` entry before deleting a partition**, or the next boot fails.

**Rule 7 is the one that ends exams.** Deleting a partition that is still referenced in `/etc/fstab` gives you a machine that drops to emergency mode at boot. See `15.md` and `16.md` for the recovery, and `30.md` for `nofail`.

```text
Command (m for help): n
Partition number (1-128, default 1): <Enter>
First sector (2048-4194303, default 2048): <Enter>
```

Four keystrokes and a size. The important habits:

- **`p` before `w`** to confirm the table is what you intended.
- **`w` writes; `q` aborts.** Nothing is committed until `w`.

**Task 5.**

```bash
lsblk /dev/sdb
ls -l /dev/sdb*
cat /proc/partitions | grep sdb
```

If `/dev/sdb1` appears, the kernel knows about it and you can proceed to `mkfs`.

If it does not, `fdisk` will have told you:

```text
Re-reading the partition table failed.: Device or resource busy
The kernel still uses the old table. The new table will be used at the next
reboot or after you run partprobe(8) or partx(8).
```

Force a re-read:

```bash
sudo partprobe /dev/sdb
lsblk /dev/sdb
```

Alternatives:

```bash
sudo partprobe                    # every disk
sudo partx -u /dev/sdb            # update
sudo partx -a /dev/sdb            # add
sudo udevadm settle
sudo blockdev --rereadpt /dev/sdb
```

**Why it happens:** the kernel will not re-read a partition table while any partition on that disk is mounted, active as swap, or in use as an LVM physical volume. Find the culprit:

```bash
lsblk /dev/sdb
findmnt | grep sdb
swapon --show
sudo pvs | grep sdb
sudo fuser -m /dev/sdb1 2>/dev/null
```

Release it, then re-read:

```bash
sudo umount /dev/sdb1
sudo swapoff /dev/sdb2
sudo partprobe /dev/sdb
```

**`mkfs` failing with "No such file or directory" almost always means this.** The fix is `partprobe`, not repeating the `fdisk` session:

```bash
sudo mkfs.xfs /dev/sdb1
# mkfs.xfs: cannot open /dev/sdb1: No such file or directory
sudo partprobe /dev/sdb
sudo mkfs.xfs /dev/sdb1          # now works
```

**Make `partprobe` then `lsblk` an automatic reflex after every `fdisk` session.**

**Note the units differ.** `fdisk` reports sectors and GiB/MiB; `parted` reports decimal MB and GB by default. `parted unit MiB print` makes them comparable. **When a task specifies "1 GiB", `fdisk`'s `+1G` gives you exactly that**, whereas `parted` needs `1MiB 1025MiB`.

`sfdisk -d` is useful for backing up a table:

```bash
sudo sfdisk /dev/sdb < /root/sdb-table.txt      # restore
```

**Task 11.**

```bash
sudo parted /dev/sdd mklabel gpt

sudo parted /dev/sdd set 1 lvm on

```

```text

 1      1049kB  525MB  524MB               primary  lvm
```

Or in one line:

```bash
sudo parted -s /dev/sdd mklabel gpt mkpart primary xfs 1MiB 501MiB set 1 lvm on
```

`-s` means script mode: no prompts, no interaction.

```bash
sudo partprobe /dev/sdd
lsblk /dev/sdd
```

The `parted mkpart` syntax:

```text
parted DEVICE mkpart PART-TYPE [FS-TYPE] START END
                      │           │        │     └─ absolute end offset
                      │           │        └─ absolute start offset
                      │           └─ a hint only; does NOT create a filesystem
                      └─ primary | logical | extended, or a name on GPT
```

Three things to be careful about:

- **Offsets are absolute, not sizes.** A 500 MiB partition is `1MiB 501MiB`, not `1MiB 500MiB`. **This off-by-one is the most common `parted` error.**
- **Start at `1MiB`, not `0`,** for correct alignment. `parted` warns about misalignment but proceeds anyway.
- **The `xfs` argument is only a type hint** written into the table. It does not create a filesystem — you still need `mkfs.xfs`.

Flags:

```bash
sudo parted /dev/sdd set 1 lvm on
sudo parted /dev/sdd set 1 boot on
sudo parted /dev/sdd set 1 esp on
sudo parted /dev/sdd set 1 swap on
sudo parted /dev/sdd set 1 lvm off
```

**`parted` writes immediately. There is no `w` and no way to abort.** That is why `fdisk` is the better choice by hand; `parted` earns its place in scripts and for `resizepart`.

**Task 12.**

```bash
sudo parted /dev/sdd print
sudo parted /dev/sdd resizepart 1 1025MiB
sudo parted /dev/sdd print
```

Interactively it warns if the partition is in use:

```text
(parted) resizepart 1
Warning: Partition /dev/sdd1 is being used. Are you sure you want to continue?
Yes/No? Yes
End?  [525MB]? 1025MiB
```

```bash
sudo partprobe /dev/sdd
lsblk /dev/sdd
```

**Growing the partition does not grow the filesystem.** Two separate steps:

```bash
# 1. the partition (here)
sudo parted /dev/sdd resizepart 1 1025MiB
sudo partprobe /dev/sdd

# 2. the filesystem (30.md)
sudo xfs_growfs /data                 # XFS: must be MOUNTED
sudo resize2fs /dev/sdd1              # ext4: mounted or not
```

```bash
lsblk /dev/sdd                        # partition size
df -h /data                           # filesystem size
```

**If `lsblk` shows 1 G but `df` still shows 500 M, you have done step 1 and not step 2.**

Rules and cautions:

- **`fdisk` has no resize command.** Deleting and recreating a partition at the same start sector works, but is risky. Use `parted resizepart`.
- **Only the last partition can grow**, unless there is free space immediately after it. Check with `parted print free`.
- **Shrinking requires shrinking the filesystem first**, and **XFS cannot shrink at all**. On the exam, "shrink" means either ext4 or LVM.
- **Back up the table before resizing** if you can: `sudo sfdisk -d /dev/sdd > /root/sdd.bak`.

**For anything involving resizing, LVM is far easier** — `lvextend -r` handles the volume and the filesystem in one command. See `29.md`.

**Task 13.**

List without changing anything:

```bash
sudo wipefs /dev/sdb1
```

```text
DEVICE OFFSET TYPE UUID                                 LABEL
sdb1   0x0    xfs  4b2c9e1f-3a8d-4e7f-9c1b-2d5a8f3e6b9c data
```

**`wipefs` with no options only reports.** Remove:

```bash
sudo wipefs -a /dev/sdb1
sudo wipefs /dev/sdb1              # now empty
sudo blkid /dev/sdb1               # no output
lsblk -f /dev/sdb1
```

Selectively, by offset:

```bash
sudo wipefs -o 0x0 /dev/sdb1
sudo wipefs -a -b /dev/sdb1        # -b keeps a backup of the signatures
```

**Why this matters.** Stale signatures produce confusing behaviour:

```bash
sudo mkfs.ext4 /dev/sdb1
# /dev/sdb1 contains a xfs file system
# Proceed anyway? (y,N)
```

and `blkid` may report an old type or an old LABEL long after you reformatted, because signatures for different filesystems live at different offsets and one `mkfs` does not necessarily overwrite another's. **`wipefs -a` before `mkfs` gives you a clean start.**

Unmount first — `wipefs` refuses on a mounted device:

```bash
sudo umount /dev/sdb1
sudo wipefs -a /dev/sdb1
```

**Task 14.**

```bash

findmnt | grep sdb

sudo pvs | grep sdb
```

Release everything:

```bash
sudo umount /dev/sdb1 2>/dev/null
sudo swapoff /dev/sdb2 2>/dev/null
sudo vgchange -an vgname 2>/dev/null
sudo grep sdb /etc/fstab           # remove any entries!
```

Then erase:

```bash
sudo wipefs -a /dev/sdb            # signatures and the partition table
sudo sgdisk --zap-all /dev/sdb     # both GPT copies and the protective MBR
```

```bash
lsblk /dev/sdb
```

```text
$ lsblk /dev/sdb
NAME MAJ:MIN RM SIZE RO TYPE MOUNTPOINTS
sdb    8:16   0   2G  0 disk

$ sudo fdisk -l /dev/sdb
Disk /dev/sdb: 2 GiB, 2147483648 bytes, 4194304 sectors
(no partition table, no Device list)
```

**No children under `sdb` and no partition table means the disk is clean.**

| Command | Removes |
| --- | --- |
| `wipefs -a /dev/sdb1` | Filesystem signature on one partition |
| **`wipefs -a /dev/sdb`** | **Partition table and signatures on the whole disk** |
| **`sgdisk --zap-all /dev/sdb`** | **Both GPT copies plus the protective MBR** |
| `dd if=/dev/zero of=/dev/sdb bs=1M count=10` | The first 10 MiB, brute force |

**`sgdisk --zap-all` is the most thorough** because GPT keeps a backup table at the end of the disk. `wipefs -a` handles that too on current versions, but `--zap-all` is unambiguous.

**Remove `/etc/fstab` entries before wiping**, or the next boot fails looking for a UUID that no longer exists:

```bash
sudo cp /etc/fstab /root/fstab.bak
sudo vim /etc/fstab                # delete the lines
sudo findmnt --verify
```

**`dd if=/dev/zero of=/dev/sdb` without `count=` writes over the entire disk and takes a very long time.** Always give a `count`. And check the `of=` target three times — `of=/dev/sda` destroys the system.

**Task 15.**

The correct order matters more than any individual command. **Doing this in the wrong order produces an unbootable system.**

```bash
# 1. Identify what you are removing
lsblk
findmnt /data
grep -n data /etc/fstab
```

```text
$ findmnt /data
TARGET SOURCE    FSTYPE OPTIONS
/data  /dev/sdb1 xfs    rw,relatime,seclabel,attr2,inode64
```

```bash
# 2. Back up /etc/fstab
sudo cp /etc/fstab /root/fstab.bak

# 3. REMOVE THE FSTAB ENTRY FIRST — before anything destructive
sudo vim /etc/fstab
#   delete the line for /data
grep data /etc/fstab               # confirm it is gone

# 4. Validate the file before going further
sudo findmnt --verify
```

```bash
# 5. Check nothing is using the mount
sudo fuser -vm /data
sudo lsof /data 2>/dev/null
```

```bash
# 6. Unmount
sudo umount /data
findmnt /data                      # no output
lsblk /dev/sdb1                    # no MOUNTPOINT
```

```bash
# 7. Now delete the partition
sudo fdisk /dev/sdb
#   p, d, 1, p, w
sudo partprobe /dev/sdb
lsblk /dev/sdb
```

```bash
# 8. Final verification, then reboot to prove it
sudo findmnt --verify
sudo mount -a && echo "mount -a OK"
sudo reboot
```

**Step 3 before step 7 is the whole point.** If you delete the partition while `/etc/fstab` still refers to it:

```text
[FAILED] Failed to mount /data.
[DEPEND] Dependency failed for Local File Systems.
You are in emergency mode.
Give root password for maintenance:
```

**That is an unbootable system.** Recovering it means the emergency-mode procedure from `15.md` and `16.md`:

```bash
mount -o remount,rw /
vim /etc/fstab                     # remove the offending line
findmnt --verify
reboot
```

On the exam that costs ten minutes you do not have — and if you cannot remember `mount -o remount,rw /`, it can cost everything.

**Two habits that prevent it entirely:**

```bash
# Always verify before rebooting
sudo findmnt --verify
sudo mount -a

# Use nofail on non-critical mounts so a missing device cannot block boot
UUID=xxx  /data  xfs  defaults,nofail  0 0
```

`nofail` is covered in `30.md`. **`findmnt --verify` and `mount -a` before every reboot is the single most valuable habit on this exam.**

If `umount` reports "target is busy":

```bash
sudo fuser -vm /data               # which processes
sudo fuser -km /data               # kill them (careful)
sudo lsof /data
cd /                               # your own shell may be inside it!
sudo umount /data
sudo umount -l /data               # lazy: detach when no longer busy
```

**Your own current directory is the most common cause of "busy".** `cd /` first.


One device, one field:

```bash
sudo blkid /dev/sdb1

```

```text
$ sudo blkid -s UUID -o value /dev/sdb1
4b2c9e1f-3a8d-4e7f-9c1b-2d5a8f3e6b9c
```

**`blkid -s UUID -o value` is the form to use when writing `/etc/fstab`**, because it prints the bare UUID with nothing to trim:

```bash
echo "UUID=$(sudo blkid -s UUID -o value /dev/sdb1)  /data  xfs  defaults  0 0" | sudo tee -a /etc/fstab
```

**That one-liner avoids the transcription errors that break `/etc/fstab`** — a mistyped UUID means the mount fails and the machine may not boot.

Distinguish the identifiers:

| Identifier | Belongs to | Changes when |
| --- | --- | --- |
| **`UUID`** | **The filesystem** | You run `mkfs` again |
| `LABEL` | The filesystem | You set it with `xfs_admin -L` or `e2label` |
| `PARTUUID` | The GPT partition | You recreate the partition |
| `PARTLABEL` | The GPT partition | You rename it |

**Use `UUID=` in `/etc/fstab`, not `/dev/sdb1`.** Device names depend on detection order and can change when disks are added, whereas the UUID belongs to the filesystem. This is why the exam expects `UUID=`. See `30.md`.

Note that `blkid` shows **formatted** devices only. A partition with no filesystem does not appear:

```bash
lsblk /dev/sdb                     # shows sdb1
sudo blkid /dev/sdb1               # nothing until you mkfs it
```

**Task 17.**

**The partition table itself is on the disk, so partitions always persist.** There is no service to enable and no configuration file for them.

```bash
sudo fdisk /dev/sdb                # write with w
sudo reboot
lsblk /dev/sdb                     # the partition is still there
```

But a partition alone accomplishes nothing. The full chain:

| Layer | Persistent because | Fails if you forget |
| --- | --- | --- |
| **Partition** | **Written on the disk** | — |
| Filesystem | `mkfs` writes to the partition | Nothing to mount |
| **Mount** | **`/etc/fstab` entry** | **Not mounted after reboot** |
| Kernel awareness | Read at boot | `partprobe` needed only in the current session |

**So the persistence question for storage is always about `/etc/fstab`, not about the partition.**

```bash
# What actually persists a mount (30.md)
sudo blkid /dev/sdb1
echo "UUID=$(sudo blkid -s UUID -o value /dev/sdb1)  /data  xfs  defaults  0 0" | sudo tee -a /etc/fstab
sudo findmnt --verify
sudo mount -a
```

Verification before every reboot:

```bash
sudo findmnt --verify              # is /etc/fstab syntactically sound?
sudo mount -a                      # does every entry actually mount?
lsblk                              # is the layout what you expect?
df -hT                             # are the filesystems the right size?
```

**`findmnt --verify` and `mount -a` succeeding means the reboot is safe.** If `mount -a` fails, **do not reboot** — fix `/etc/fstab` first. This is the difference between a working machine and emergency mode.

And the corollary: **remove the `/etc/fstab` entry before deleting a partition.** The partition change persists whether you want it to or not; the stale fstab line persists too, and that is what breaks the boot.

## Persistence Check

| Change | Persistent because | Also required |
| --- | --- | --- |
| Partition created or deleted | **Written to the disk's partition table** | `partprobe` for the current session only |
| Partition type code | On the disk | — |
| Filesystem | `mkfs` writes to the partition | — |
| **Mounting it** | **`/etc/fstab`** | **`findmnt --verify` + `mount -a`** |

**Partitions persist by themselves. Mounts do not.** The only storage persistence that needs your attention is `/etc/fstab`, covered in `30.md`.

The two traps run in opposite directions:

1. **A partition with no `/etc/fstab` entry** is not mounted after a reboot, and the task scores nothing.
2. **An `/etc/fstab` entry with no partition** stops the boot entirely.

```bash
# Before every reboot
sudo findmnt --verify
sudo mount -a && echo OK || echo "*** FIX FSTAB BEFORE REBOOTING ***"
```

## Exam Tips

- **`lsblk` first, every single time.** Confirm the device name before any destructive command. A disk with no children and no mountpoints is the spare one.
- **Never touch `/dev/sda` or `/dev/vda`** unless a task explicitly says so — it holds `/`, `/boot`, and swap.
- **Use `fdisk`.** `n`, Enter, Enter, `+1G`, `w`. **`q` aborts without writing**, which makes it the safe choice.
- **Express sizes as `+1G` or `+512M`.** Never calculate end sectors.
- **Accept the default first sector** so `fdisk` aligns the partition for you.
- **`p` before `w`** to confirm the table.
- **`g` creates a GPT label, `o` creates MBR.** GPT unless told otherwise.
- **Type codes: `swap` (82/19), `lvm` (8e/31), Linux filesystem (83/20).** You can type the alias name; `L` lists them.
- **`partprobe /dev/sdX` then `lsblk` after every `fdisk` session.** "No such file or directory" from `mkfs` means the kernel has not re-read the table.
- **`parted` writes immediately with no `w` and no abort.** Its offsets are absolute, so a 500 MiB partition is `1MiB 501MiB`. Reserve it for `resizepart`.
- **MBR allows four primaries. Logical partitions start at 5.** Only relevant if a task says MBR.
- **`wipefs` lists; `wipefs -a` removes.** Use it before `mkfs` to clear stale signatures.
- **`sgdisk --zap-all`** erases both GPT copies for a genuinely clean disk.
- **Delete the `/etc/fstab` entry before deleting the partition.** Getting this backwards puts the machine in emergency mode.
- **`umount` says busy? `cd /` first**, then `fuser -vm /mnt`.
- **Growing a partition does not grow the filesystem.** `parted resizepart` then `xfs_growfs` (mounted) or `resize2fs`.
- **XFS cannot shrink.** Shrinking means ext4 or LVM.
- **Use `UUID=` in `/etc/fstab`**, obtained with `blkid -s UUID -o value /dev/sdb1`.
- **`findmnt --verify` and `mount -a` before every reboot.** If `mount -a` fails, do not reboot.
